# 派生市场数据的口径与来源设计

用于“资金流、主力资金、大中小单、情绪、估算持仓”等名称相似、算法可能不同的数据。方案必须先证明可比，再讨论替换、聚合或计算。

## 先判断数据是什么

“资金流入/流出”通常不是市场真实新增或流失的现金。每笔成交同时存在买卖双方，行情软件常按主动买卖方向、成交单或委托单大小推导资金流，并用自有阈值划分“主力、超大、大、中、小单”。名称相同不代表阈值、方向判定、撤单处理、复权、集合竞价、覆盖证券或修订方式相同。

先把数据归入一个语义族，禁止跨族合并：

| 语义族 | 典型数据 | 设计要求 |
| --- | --- | --- |
| `reported_flow` | 交易所、港交所或互联互通公布的成交净买额、额度余额 | 保留官方字段、单位和发布修订语义 |
| `trade_direction_flow` | 按主动买卖方向估算的流入、流出、净额 | 绑定方向判定方法和数据截点 |
| `order_size_flow` | 主力、超大、大、中、小单净额或占比 | 绑定供应商阈值、分桶和主力定义 |
| `financing_activity` | 融资余额、融资买入额、融券余量 | 独立 capability，不命名为普通资金流 |
| `position_change` | 持股数量、持仓市值及其变化 | 区分成交流、价格变化与公司行动影响 |

## 比较与计算的准入门

只有以下条件全部一致或已由可审计转换显式消除差异时，两条序列才允许相加、相减、拼接、回填或比较排名：

- 语义族、上游来源和方法论标识；
- 方法论版本或状态；无法获得算法时标为 `unknown`，不得假装等价；
- 市场、证券范围、样本池和退市/停牌处理；
- 交易日历、时区、交易日、盘中截点和最终态；
- 日频、快照或滚动窗口；供应商报告的“3/5/10/20 日”不是日数据的替代品；
- 币种、原始单位、标准单位、正负号方向；
- 分桶定义、占比分母、缺失值和修订规则。

跨来源差异默认是观测指标，不是“数值应相等”的质量门。没有可验证的方法论等价证据时，禁止：

- 用备用来源静默补主来源的空洞；
- 把不同来源的“主力净流入”拼成一条连续历史；
- 用一个来源的净额和另一个来源的成交额计算占比；
- 把供应商滚动排行当成内部日数据求和结果；
- 将股票级数据直接求和后冒充供应商的行业或全市场口径。

## Canonical 身份与血缘

Provider-neutral port 仍须保留方法论身份。canonical schema 至少包含：

- `adapter_provider`、`upstream_source`、`source_dataset`；
- `semantic_family`、`methodology_id`、`methodology_version`、`methodology_status`；
- `scope_type`、`scope_id`、`universe_id`；
- `trade_date`、`window_type`、`window_size`、`as_of_time`、`finality`；
- `bucket`、`ratio_denominator`；
- `gross_inflow`、`gross_outflow`、`net_amount`、`net_ratio`，源端未提供的字段保持空值，不反推；
- `currency`、`raw_unit`、标准化单位、`observed_at`、source batch/version。

唯一身份必须覆盖来源与方法论，不能只用“证券 + 日期 + bucket”。内部计算写入独立 derived dataset，并记录公式版本、输入数据集版本、覆盖率和计算时间；不要覆盖源端报告值。

## 来源选择与切换

1. 先按消费者问题选语义族。需要官方公布的交易、额度或融资数据时优先官方源；需要行情软件的“主力/大单”信号时，明确它是供应商派生指标。
2. 在同一语义族内按历史深度、层级覆盖、修订能力、稳定性、许可和成本选择一个主来源。
3. 次来源以独立方法论序列保存，可用于可用性旁路、趋势对照或研究，不能自动变成 fallback。
4. 切换主来源属于数据定义变更：创建或更新 ADR，双跑重叠区间，量化结构性偏差，标记断点，决定是否全量回补，并升级消费者契约或指标版本。
5. 主来源缺失时发布 `partial`、`quarantine` 或缺口状态。只有方法论等价已经被证据和验收标准证明时，才允许受控 fallback。

## AKShare 资金流研究基线

以下是基于 AKShare 1.18.78 股票文档在 2026-07-26 的研究基线，不等于生产批准；设计时必须重新验证接口、字段、许可和上游方法论。

| 上游来源 | 当前 AKShare 覆盖 | 建议角色 |
| --- | --- | --- |
| 东方财富 | 个股近约 100 个交易日的日序列；个股排行；行业/概念/地域排行；行业历史；全市场历史；主力及超大/大/中/小单分桶 | A 股供应商派生资金流的主研究源，适合连续采集和分层历史 |
| 同花顺 | 个股、行业、概念即时及 3/5/10/20 日排行；显式流入/流出/净额；大单追踪快照 | 补充 gross flow、20 日排行和大单快照；独立存储，不与东财拼接 |
| 雪球 | 当前股票文档未提供对应资金流接口 | 不纳入此 capability；未来出现接口后重新评审 |

因此，“哪个更全面”必须带场景回答：就可复现的个股—行业—市场历史资金流而言，当前优先东方财富；就显式流入/流出、20 日排行和大单快照而言，同花顺提供补充维度。二者不能因字段中文名相似而合并。互联互通和融资融券等官方/准官方数据另建 capability，不与上述供应商估算资金流混算。

- [东方财富资金流页面](https://datapc.eastmoney.com/emdatacenter/CapitalFlow/index?code=300059)

## 质量规则与验收样例

- 当源端同时提供三项时，校验 `net_amount = gross_inflow - gross_outflow`，容差须基于原始单位和舍入精度。
- 只在上游明确声明层级关系时校验“主力 = 超大单 + 大单”或分桶合计；未知方法论不能创建伪不变量。
- 占比必须记录并验证分母，不允许仅凭字段名猜测。
- 盘中快照与收盘最终值分区或版本化；盘中值不得覆盖 EOD。
- 自行聚合前冻结方法论、样本池、截点和覆盖率；结果使用独立指标名，并与供应商聚合值做差异监控。
- 持续采集短历史接口，并对最近滚动区间重拉以接收修订；不要把接口可见窗口当长期历史保障。
- fixture 至少覆盖：同名异口径、单位突变、分母未知、盘中/EOD 冲突、主源缺失、来源切换和供应商滚动窗口。
- 验收必须证明主源故障不会被次源静默污染，消费者能看到来源、方法论、最终态、覆盖率和质量状态。
