1. 摘要

问题

“行业”不是单一事实

东方财富行业、概念和申万行业有不同代码、层级、成份与调整语义。按名称合并会制造不可审计的伪等价。

决策

scheme 与方法论隔离

每种分类独立保存。东方财富提供当前成份与三套原生周期事实；申万提供三级层级与估值观察。

主要风险

申万接口只提供当前快照

固定版本接口没有日期参数；历史日期只能从已归档中立载荷精确 replay，禁止把当前响应伪装成历史事实。

冻结读取契约 service-data-sync 暴露 GET /internal/v1/sw-industries、 GET /internal/v1/sw-industries/valuations 和 GET /internal/v1/sw-industries/{sectorCode}；service-api 对认证用户暴露对应的 POST /api/v1/market/industries/sw/list、 POST /api/v1/market/industries/sw/valuations 和 POST /api/v1/market/industries/sw/{code}。 规范分别见 OpenAPI 0020 与 OpenAPI 0021。
推荐范围 P0：分类清单、当前成份、日/周/月三套上游周期行情和收盘后横截面快照；P1：申万层级与估值； 周/月线不从日线计算。任何分时接口均不进入实现。
方案归属 成分观测历史以 0013 为实施权威， 收盘后横截面与排行以 0015 为实施权威， 所有日频资金流同步、模型、质量、API 与验收均完整移交 0017，不再属于 0012 的范围或完成条件。
固定版本技术事实 akshare==1.18.78 中三个申万函数均真实存在、签名均为 ()， 源码位于 akshare/index/index_sw.py，实网探针分别返回 31、131、335 行。
当前实施 已交付东方财富行业/概念板块的日、周、月原生行情纵切：独立 capability、adapter 参数、 raw evidence、canonical revision/publication、三张物理表、迁移与有界 CLI。行业/概念分类清单、 内部 HTTP 读取和公开 API 已实现；成份链路由 0013 完成，EOD quote、排行和定向调度由 0015 完成。 申万三级 taxonomy、父级闭包、估值、方法学、raw/replay、双时间修订、双 publication、 checkpoint、质量规则、CLI/Celery、内部 GET、公开 POST 和 OpenAPI 已完成并接入共享装配。 跨服务读取边界见 0003：板块行情 API 访问技术方案。

2. 事实、决策、假设与边界

事实

当前工程基线

  • 已有 provider-neutral DataSourcePort、registry 和 AKShare adapter 边界。
  • 已有 S3 raw evidence、PostgreSQL revision/publication 和受控日线 CLI 闭环。
  • EOD 与申万均有独立 Celery 任务、run/partition/checkpoint；各 capability 保持独立开关和失败边界。
  • 仓库锁定 akshare==1.18.78；申万三级函数已通过源码、fixture 与实网探针交叉验证。
决策

本方案冻结的边界

  • scheme：eastmoney.industry、eastmoney.concept、sw.industry。
  • 未复权日线、周线、月线是三个独立上游事实，各自发布和修订。
  • 收盘后只取一次批量 quote 快照，不构建盘中序列。
  • 申万层级与估值共享一次完整来源观察，但使用互不复用的消费者 dataVersion。
运行参数

不阻断实现的观测项

  • 东方财富板块成交量原始单位。
  • cadence、调用间隔和 raw retention 的容量验证值。
  • 首次历史回填起点及接口可见历史深度。

目标

  • 可按 scheme 查询板块稳定身份、名称修订、层级、当前成份与成份观测历史。
  • 可分别同步、修订、回补行业和概念板块的日线、周线、月线。
  • 可保存收盘后板块横截面、申万三级 taxonomy 与估值观察，同时保留完整方法论血缘。
  • 重复运行、worker 中断、schema 漂移和数据库失败不会产生重复 current 数据或静默缺口。
  • 下游未来只能通过版本化内部 API 或事件读取，不直连数据库或 AKShare。

非目标

  • 不接入 stock_board_industry_hist_min_em、stock_board_concept_hist_min_em 或任何分钟/分时数据。
  • 不自动建立东方财富行业、概念与申万行业之间的语义映射。
  • 不回造首次采集日前的历史成份，不把首次看到日期描述为真实调入日期。
  • 不新增 service-web 页面；读取链路止于 service-api 已认证公开 POST API。

三个周期均固定请求 adjust=""，不保存 qfq/hfq 结果。板块成份调整和指数编制变化属于 上游指数方法的一部分，可能产生序列断点；本服务保留来源版本和修订，不用个股公司行动自行复权板块指数。

3. 数据集与任务契约

市场语义

中国 A 股板块

范围：东方财富沪深京行业/概念，申万一级至三级行业。

时区：Asia/Shanghai；内部时间戳保存 UTC。

日历：依赖已发布的中国 A 股权威交易日历；未知日期不得推断为休市。

研究与未来业务 API

首期服务内研究、策略筛选和数据质量分析；后续由 service-data-sync 内部 API 提供给 service-api。数据库和 raw bucket 不对其他服务开放。

scheduler / manual CLI
        │  只产生 capability + scheme + partition
        ▼
run coordinator ── PostgreSQL lock / checkpoint / status
        │
        ▼
provider router ── source policy + health + capability 技术状态
        │
        ▼
AKShare adapter ── SDK / URL / 原字段 / 单位转换仅存在于此
        │
        ├── raw response ──▶ S3 immutable object
        ▼
provider-neutral batch ──▶ normalize ──▶ quality gate
                                            │
                    reject / quarantine ◀───┼───▶ canonical repository
                                            │          │
                                            └──────────┴──▶ atomic publication
                                                                  │
                                                          internal API → service-api POST
任务定义与协调

SectorSyncCoordinator

职责：生成有界分区、租约、重试与 checkpoint，汇总 release 覆盖率。

输入/输出：capability、scheme、mode、日期窗口 → run/partition 状态。

状态：PostgreSQL 权威；Redis 只投递。

失败边界：单板块失败不丢失其他板块；完整 release 不越过失败分区。

来源隔离

AKShare sector adapters

职责：调用一个上游来源，保留原响应并输出固定 schema 的中立 batch。

输入/输出：标准 scheme/code/window → versioned JSON batch。

状态：无数据库状态；只持有超时和 client 配置。

失败边界：timeout/rate/schema/empty 映射为 ProviderError。

标准化与质量

SectorNormalizer / QualityGate

职责：解析中立 batch、单位转换、身份关联、方法学验证与质量处置。

输入/输出：provider-neutral records → canonical rows + quality results。

状态：不保存；依赖日历和已发布证券目录。

失败边界：schema 漂移隔离整个分区；单条身份失败进入 reject 明细。

证据与持久化

RawPayloadStore / SectorRepository

职责：raw 先写 S3，再事务写 source batch、revision、quality 和 publication。

输入/输出：不可变 raw + canonical batch → data version 和计数。

状态：S3 raw、PostgreSQL canonical/publication。

失败边界：raw 成功 DB 失败时允许从 raw 重放；adapter 永不持有仓储。

周期行情

SectorBarSyncService

职责：按 1d、1w、1mo 三个 capability 分别同步上游行情。

输入/输出：周期、板块和日期窗口 → 对应周期的独立 publication。

状态：每个周期独立 checkpoint、revision 和 data version。

失败边界：一个周期失败不阻断其他周期，也不允许跨周期计算补洞。

版本化读取

SectorReadService

职责：只读取已发布 current revision，向内部 GET 与公开 POST 投影 scheme、版本和质量状态。

输入/输出：有界查询 → provider-neutral DTO。

状态：无。

失败边界：不完整 release 返回显式 stale/partial，不读 raw 或 provider。

ORM 持久化基线 已实现板块目录、三周期、成分与 EOD 仓储均通过短生命周期 Session 和 Declarative 模型表达式访问。 申万能力延续 0018 SQLAlchemy ORM 方案： 一张逻辑表一个模型文件、显式 registry、显式 Alembic migration、PostgreSQL schema parity； repository 不得执行字符串 SQL，物理日期子分区只由 migration 或 partition manager 管理。

6. 执行、幂等、checkpoint 与恢复

状态机

queued → running → succeeded | partial | quarantined | failed | cancelled
  • partial：部分分区成功且覆盖率可量化；不自动推进完整 release。
  • quarantined：数据已保留 raw，但 schema、口径或质量阻止 canonical publication。
  • failed：没有可发布结果；是否重试由中立错误和预算决定。
  • cancelled：停止产生新调用；已进入 DB 事务的分区完成或回滚后退出。
机制 设计 关键约束
幂等键 capability + scheme + source_policy + methodology_id + partition + schema_version 同键只允许一个 active partition；重复消息复用状态，不重复抓取或发布。
租约 PostgreSQL 保存 lease_owner、lease_expires_at；worker 心跳续租。 Redis 丢失不改变权威状态；过期分区由扫描器重排。
checkpoint catalog 按 scheme；membership 按 sector；行情按 sector/period；backfill 按 sector/period/year。 只在 publication 事务成功后推进；raw 写入不是完成信号。
并发 provider 级 semaphore 初始为 1；全局调用间隔由配置控制。 连续探针和容量基准通过前不提高并发；不同上游使用独立预算。
超时 单调用硬超时；分区和 run 另有墙钟预算。 AKShare 阻塞调用通过线程移出事件循环；取消不遗留无限线程。
重试 timeout/unavailable/rate-limited：指数退避 + jitter，最多 3 次；schema/invalid：不重试。 同一次 run 共享 provider 预算，避免 500 个板块同时放大故障。
断路器 连续失败率达到阈值后暂停该 source policy，新分区保持 queued。 不自动切换到另一方法论；恢复需探针成功或人工解除。
全量 release catalog/quote 单批原子；membership 按板块提交，manifest 达到预期覆盖后推进完整 release。 partial release 可诊断，但默认消费者继续读取上一完整版本。

回补与修订

  • 三周期首次回补：分别探测每个 scheme/板块/period 的最早可用日期，再按年倒序分区；不预设文档外历史深度。
  • 日线修订：每个交易日重拉最近 10 个权威交易日；值变化关闭 current revision 并追加后继。
  • 周线修订：每个周周期完成后重拉最近 8 个供应商周周期；不从日线判断 OHLCV。
  • 月线修订：每个月周期完成后重拉最近 6 个供应商月周期；不从日线判断 OHLCV。
  • 跨周期隔离：日/周/月的日期标签、content hash、revision 和 publication 互不复用；任一缺失保持缺口。
  • 成份：接口只有当前快照，不能历史回补。每天完整保存，差异只表示“在两次观测之间发生”。
  • 申万历史：三个函数没有日期参数；当前日直接抓取，历史日必须命中该日 checkpoint 并校验归档摘要后 replay。
  • 手动修复：必须指定 capability、scheme、分区、reason 和幂等键；repair 不覆盖历史审计。

7. 正常与失败流程

正常路径

  1. scheduler 读取已发布交易日历，生成 scheme/date 或 sector/window 分区。
  2. coordinator 获取租约；router 校验 source policy、环境开关、capability 技术状态和断路器。
  3. adapter 调用 AKShare，将原始 DataFrame/字段转换为版本化中立 JSON，同时保留 raw JSON。
  4. raw 以内容 hash 写入 S3；重复内容复用对象。
  5. normalizer 校验 schema、身份、单位、时间、方法论与不变量，生成 quality results。
  6. repository 在单一 PostgreSQL 事务中登记 source batch、追加变化 revision、写质量结果并推进 publication。
  7. coordinator 推进对应 capability checkpoint；完整 manifest 成功后发布该周期 release，并触发未来 API 缓存失效。

关键失败路径

场景检测处置恢复
重复消息/重复运行 幂等键和 active unique index 命中 返回已有状态或比较 content hash；不新增 current revision 无需人工处理
provider timeout/断连/限流 中立错误、调用耗时、HTTP/SDK 异常分类 预算内退避；达到阈值打开断路器，partition 失败/partial 探针成功后重跑原分区；不跨来源补洞
schema drift 字段 fingerprint、必填列、类型转换失败 raw 保留，整个分区 quarantine；上一 publication 继续服务 升级 fixture/adapter/schema 后从 raw 重放
身份无法关联 成份代码无法映射已发布证券目录 item reject；超过阈值则整个 membership 分区 quarantine 主数据补齐后使用同一 raw 重放
DB 事务失败 SQLAlchemy/PostgreSQL 错误 事务回滚，checkpoint 不动；raw 对象保留 恢复 DB 后按 raw URI 重放，不再次请求来源
S3 写入失败 对象写入/校验失败 禁止 canonical 写入，分区失败 恢复对象存储后重试抓取或使用内存批次重试
申万父级缺失或名称歧义 同层名称唯一性、直接父级解析与完整闭包校验 整个快照拒绝 publication；上一 taxonomy 与估值版本保持可读 升级 fixture/adapter 后从精确日期中立载荷重放

8. Canonical 数据模型与时间语义

下列表结构是业务与物理 schema 契约。每张新增逻辑表必须同时落入 infrastructure/database/models/ 对应能力目录和显式 registry.py； 模型描述当前目标 schema，Alembic revision 描述演进步骤。模型不能替代迁移， Base.metadata.create_all() 不能用于运行环境。

核心表

表主身份/分区职责关键字段与约束
sector_scheme scheme_id；scheme_code 唯一 分类体系与方法论身份 owner、kind、methodology_id/version/status；三个 scheme 不互相覆盖。
sector_entity sector_id；唯一 (scheme_id, source_code) 稳定板块身份 industry/concept、current name/status；UUID 对外，bigint 可作内部代理键。
sector_revision (sector_id, revision) 名称、父级和属性修订 parent_sector_id、content hash、source_batch、observed_at、valid_from/to；名称不是身份。
sector_membership_snapshot (sector_id, snapshot_date, revision) 完整成份观测头 observed_at、item_count、content hash、quality、source batch；不声称精确生效日。
sector_membership_item (snapshot_id, security_id) 一次快照中的证券集合 只关联已验证证券；源代码/名称留在 raw，未知证券不猜交易所。
sector_daily_bar (sector_id, trade_date, revision)；按年分区 未复权板块日线 OHLC、volume_value/unit、amount_cny、turnover_rate、finality、content hash、source batch。
sector_weekly_bar (sector_id, source_period_date, revision)；按年分区 供应商未复权板块周线 独立 OHLCV、原始周期日期、finality、content hash、source batch；不引用日线版本。
sector_monthly_bar (sector_id, source_period_date, revision)；按年分区 供应商未复权板块月线 独立 OHLCV、原始周期日期、finality、content hash、source batch；不引用日线版本。
sector_quote_snapshot (sector_id, as_of_time, revision)；按月分区 收盘后横截面 rank、last/change、market_cap、turnover、rise/fall counts、leading security、eod_observed。
sw_sector_methodology (code, version) 唯一 申万 taxonomy 与估值共享的不可变方法学身份 upstream_source、status、semantic_spec_sha256；语义变化必须递增版本。
sw_sector_node_revision / sw_sector_closure (snapshot_date, sector_code, revision)；闭包绑定 taxonomy data_version 三级节点双时间修订与不可变父级闭包 稳定 node UUID、直接父级、成份数、known_from/to、source batch、content hash；完整快照缺失节点必须闭合。
sw_sector_valuation_revision (snapshot_date, sector_code, methodology_id, revision) 同日行业估值双时间观察 static_pe、ttm_pe、pb、dividend_yield_ratio、PROVIDER_OBSERVATION；百分数转换为一比一比例。
sw_sector_publication data_version taxonomy 与 valuation 两个独立消费者版本 capability、snapshot_date、methodology_id、row_count、content_sha256、published_at。
sw_sector_sync_checkpoint / sw_sector_quality_result (capability, partition_key)；质量结果 UUID 精确日期 raw/中立 replay 与低基数质量证据 双摘要、双 URI、adapter/schema 血缘、最近 taxonomy 版本；只在两个 publication 成功后推进。
sync_run / sync_partition UUID；partition 幂等唯一 状态、租约、checkpoint、重试与恢复 queued/running/succeeded/partial/quarantined/failed/cancelled；Redis 非权威。
quality_result (partition_id, rule_code) 质量证据与处置 severity、actual/expected、disposition、sample；不保存敏感 payload。

扩展现有血缘表

  • source_batch 增加 upstream_source、source_dataset、 adapter_version、schema_fingerprint、methodology_id/version/status、 as_of_time、finality 和 raw byte count。
  • dataset_publication 增加 source policy、methodology、coverage、expected/actual partition count、 period、calendar version 和 release_id；旧个股日线字段保持可空兼容。
  • 每个分区先写 immutable raw，再在一个事务内登记 batch、revision、quality 和 publication。 canonical identity 永远包含 scheme；申万发布摘要同时包含方法学身份，避免语义升级复用旧版本。

时间与最终态

概念含义禁止事项
observed_at 本服务看到响应的 UTC 时间 不能替代供应商生效时间。
snapshot_date 由任务目标与已发布交易日历确定的 Asia/Shanghai 日期 日历未知或任务跨截止点时不得猜测。
trade_date 日线源明确返回的交易日期 缺行不自动等于休市。
source_period_date 周/月接口原样返回的周期日期标签 未确认上游定义前，不擅自解释为自然周/月起止日。
finality eod_observed、provider_final、revised 等明确状态 收盘后抓取不自动获得“官方最终”语义。
valid_from/to canonical revision 在本系统内可见的区间 不能当成板块真实调入/调出时点。

三周期独立存储规则

  • 行业接口分别传入 日k、周k、月k；概念接口分别传入 daily、weekly、monthly。
  • adapter 为三个 capability 分别输出固定 schema；原始周期参数、返回日期和 payload 各自留痕。
  • 日/周/月分别写入三张 canonical 表；不读取另一个周期做 OHLCV 聚合、缺口填充或质量修复。
  • 三个周期不做跨周期算术对账；质量规则只检查各自上游序列，禁止用日线计算周/月结果。
  • 周/月是否完成由调度日历和来源 finality 共同判断；未完成周期不覆盖上一已发布完整周期。

9. 质量门、来源可比性与发布处置

规则族可量化检查处置
schema schema id/fingerprint、必填字段、类型、未知列；AKShare 升级前后 fixture diff。 任何身份/数值必填漂移：partition quarantine。
分类身份 scheme 内代码唯一；名称非空；申万 L2/L3 父级必须在同批或上一已发布版本存在。 重复/孤儿父级：reject；超过 0 条关键错误则阻断该 scheme release。
成份 板块内证券唯一；匹配已发布证券目录；空成份；相邻快照 item count 与 Jaccard 差异。 未匹配率 >0.5% 或 active 板块空集合：quarantine；大幅变化先 warn，需人工确认。
三周期行情 每个 period 内 low ≤ open/close ≤ high；值非负；来源日期唯一递增；未来日期拒绝；成交单位必须已认证。 OHLC/单位错误：仅 quarantine 对应周期；gap 仅告警，不用其他周期填补。
横截面 代码唯一、rank 唯一或可解释；涨跌家数非负；领涨代码可解析；总市值非负。 身份错误阻断；非关键展示字段缺失可 warned publication。
申万估值 三级均非空；父级闭包无孤儿；行业代码唯一；估值与节点一一覆盖；PE/PB/股息率为有限数或 null；成份数非负。 任一结构或数值错误拒绝整个完整快照；上一双 publication 保持 current。
完整性 catalog 预期数来自上一完整 release；下降 >10% 阻断；membership release 需覆盖当日全部 active 板块。 不完整 run 标为 partial；上一完整 release 保持 current。

处置等级

  • reject：拒绝单条记录，保留 raw 和质量样本；超过阈值升级为 partition quarantine。
  • quarantine：不写或不发布 canonical current，等待 adapter/schema/口径修复。
  • warn：数据可发布但响应必须携带 quality_status=warned 和规则摘要。
  • publish：所有阻断规则通过，事务推进 partition publication；完整 release 另做覆盖检查。

10. 可靠性、安全与可观测性

运行拓扑

复用现有四类角色

同一镜像运行 scheduler/dispatcher、Celery worker、diagnostics 和内部 API；PostgreSQL 权威，Redis broker，S3 raw。

安全

环境开关 + egress 控制

生产 source policy 默认 false；egress 只允许配置中的上游域名，频率和并发由环境配置控制且不进入任务参数。

数据保护

raw 私有、输出中立

S3 bucket 不对其他服务开放；日志不含响应体、URL 查询秘密或堆栈。API 不暴露 provider 字段、raw URI 或内部代理键。

结构化日志与关联

每条任务日志包含 run_id、partition_id、capability、 scheme、source_policy、provider_id、 source_batch_id、attempt、duration_ms 和稳定错误码。 指标标签禁止 sector_code/run_id 等高基数值。

  • 每个 run、partition、provider request、raw put、DB publication 创建可选 trace span；未决定 exporter 时只传播 trace context。
  • liveness 只验证进程；readiness 验证 PostgreSQL、Redis 和 S3，不把外部 provider 短时失败变成进程重启循环。
  • provider health 由独立探针、断路器和 dashboard 表达；diagnostics 默认不产生外网请求。
  • 每个 partition 设置最大记录数、raw byte 数和 DataFrame 内存预算；超过上限立即 quarantine，禁止整市场结果无限驻留。

配置增量

环境变量用途初始值/约束

DATA_SYNC_SECTOR_DAILY_REVISION_LOOKBACK_PERIODS 日线滚动修订交易日数 初始 10；按交易日历计数，不是自然日。

publication lag dataset、scheme 验证 cadence 后超过目标窗口 检查 provider、队列、quality 和 DB。

保留与清理

  • canonical current 与历史 revision 首期保留；删除策略只能由容量、查询窗口和恢复需求验证后的迁移实施。
  • raw retention 按最大回放窗口、对象存储容量和备份恢复目标配置，不作为同步链路实施前置。
  • raw 与中立 replay 载荷使用独立对象键和显式生命周期；未通过质量门的数据不能混入 consumer publication。
  • sync_run、日志和 quality 明细保留期由运维策略配置；聚合指标可长期保留，run_id 不做指标标签。

12. 验收标准与计划命令

  • 三个 scheme 的代码、名称、层级和来源可追溯，中文同名不会自动合并。
  • 成份快照只表达观测事实；首次采集前没有伪造历史，未知证券不会按代码规则猜交易所。
  • 日线、周线、月线分别重复运行结果一致，值变化只追加对应周期 revision。
  • 周/月 canonical 值来自 AKShare 周/月参数，不读取日线聚合或填补缺口。
  • 分钟接口未注册、无分钟表、无分钟任务、无相关环境变量。
  • provider timeout、限流、schema drift、空响应、重复数据、S3/DB 失败均有自动测试。
  • worker 中断后可从 publication checkpoint 恢复；raw 成功 DB 失败时无需重新访问上游。
  • membership partial 不推进完整 release；消费者仍能读取上一完整版本并看到 stale 状态。
  • 申万三级函数签名、固定版本源码、列 fingerprint、fixture 与实网 31/131/335 行证据一致。
  • 申万二、三级父级名称无歧义解析为代码，完整闭包绑定 taxonomy dataVersion。
  • 估值股息率从来源百分数转换为一比一比例；方法学变化不会复用旧 publication。
  • 内部三条 GET 与公开三条 POST 支持分页、筛选、HMAC 游标、ETag、请求关联和稳定问题响应。
  • 接口稳定性、schema、单位、完整性、容量与恢复测试未通过前，对应 source policy 保持关闭。
  • Alembic upgrade/downgrade、raw replay、publication rollback 和备份恢复经过演练。
  • 每张新增逻辑表有完整中文注释的 Declarative 模型并进入显式 registry；仓储不泄漏 ORM instance 或 Session。
  • alembic check、PostgreSQL schema parity、禁止持久化字符串 SQL的架构测试与 Session 回滚集成测试通过。
