摘要

事实

当前只有服务占位目录

没有 Python 包、锁文件、启动入口、依赖连接、测试命令或容器基线，业务能力无法安全开始。

决策

先交付可运行骨架

选择 Python 3.13 + uv，以显式依赖注入组织代码；本地依赖由根 Compose 统一编排。

硬约束

来源只能经 adapter

核心只依赖 provider-neutral port。具体 SDK、HTTP 地址和字段一旦越层，架构测试直接失败。

完成标准 新环境可按 README 安装；三类依赖可一键启动并通过诊断；空载 worker 可启动退出； fake adapter 可替换；格式化、静态检查、单测、架构测试和镜像 smoke test 可重复通过。

目标、非目标与假设

本次交付

工程基础设施

  • src-layout Python 包、锁定依赖、统一命令。
  • 配置、结构化日志、错误分类、显式 DI。
  • PostgreSQL、Redis、MinIO 本地容器与连接工厂。
  • 诊断 CLI、空载 Celery worker、信号处理。
  • DataSourcePort、SourceRegistry 空实现、fake adapter。
  • 单测、集成测试、架构测试、CI 与容器镜像。
明确排除

本次不做

  • FastAPI app、route、认证、OpenAPI。
  • 任何业务表、控制表、索引、分区和迁移 revision。
  • 定时、重试、补数、幂等、outbox 和任务状态。
  • AKShare、Tushare 或其他真实 adapter/SDK。
  • 标准化、质量校验、对账、入库、查询。
  • service-api 集成和生产部署清单。
非阻塞假设

先按可移植基线推进

  • 开发机提供 Docker Compose v2。
  • 支持 Linux amd64/arm64；不承诺 Windows 原生运行。
  • 生产平台、镜像仓库、OTLP 后端尚未决定。
  • CI 只依赖标准 shell、uv 和 Docker，避免绑定平台。
  • 未来接口、表、调度各自创建后续编号方案。

Application Port

只定义边界

输入：来源无关请求对象。

输出：来源无关批次对象或通用错误。

状态：无。

失败边界：不得 import SDK、DataFrame、数据库或 Celery。

Infrastructure

只包装外部依赖

输入：经过校验的 settings。

输出：client factory、ping、close。

状态：连接池和 SDK client，不保存业务状态。

失败边界：异常转为基础设施错误，不在模块内重试业务操作。

Bootstrap / Entrypoint

负责组合与生命周期

输入：环境变量、进程参数、信号。

输出：diagnostics 结果或 worker 进程。

状态：仅进程级依赖容器。

失败边界：配置错误快速退出；关闭时反序释放资源。

Compose 所有权

根目录统一编排

根 compose.yaml 使用 data-sync-infra profile；build context 只指向 service-data-sync/，不发送其他服务源码。

端口与网络

只绑定 loopback

宿主端口可通过环境变量覆盖；默认只监听 127.0.0.1。Compose network 不声明 external，service-api 不加入。

数据清理

普通停止不删 volume

docker compose down 保留状态；删除 volume 必须用单独、明确、带警告的开发命令，不能成为日常脚本。

镜像基线 多阶段构建；先复制 pyproject/lock 复用依赖层，再复制源码；runtime 使用固定 Python 3.13 slim digest、 非 root UID/GID、无编译器、无 dev 依赖；日志写 stdout/stderr；SIGTERM 由主进程直接接收。

诊断退出码

0=全部通过 · 1=未知内部错误 · 2=配置无效 · 3=PostgreSQL 失败 · 4=Redis 失败 · 5=S3/MinIO 失败 · 6=多个依赖失败
超时

诊断有硬上限

默认总预算 10 秒；单项连接超时不超过 5 秒。诊断不执行无限重试，也不写入依赖。

资源释放

反序关闭、重复安全

close 钩子可调用多次；部分初始化失败时只关闭已创建资源，关闭错误不覆盖原始错误。

多数据源适配边界

本阶段建立最小协议、注册边界和防绕过测试。生产注册表为空；fake adapter 只存在于测试。 不安装 AKShare/Tushare，不实现真实 fetch、路由或 fallback。 

class DataSourcePort(Protocol):
    provider_id: str
    def capabilities(self) -> frozenset[str]: ...
    async def fetch(self, request: SourceRequest) -> ProviderBatch: ...

约束：
- provider_id 是开放字符串，不是 akshare/tushare 枚举
- SourceRequest / ProviderBatch 是冻结、来源无关类型
- 不允许 DataFrame、SDK 类型、数据库 session、Celery task 进入协议
- adapter 只能返回批次或抛出通用 ProviderError
架构规则 检测方式 故意失败样例
application 不得依赖 infrastructure AST import graph 在 port 中 import boto3 应失败
adapter 外不得 import provider SDK AST 扫描禁止模块根 task 中 import akshare 应失败
adapter 不得依赖 persistence/messaging 包路径依赖规则 adapter import repository 应失败
通用 DTO 不得出现供应商字段 源码与类型注解规则 ts_code、供应商 DataFrame 类型应失败
fake adapter 必须可替换 共享 contract test 替换 fake 后 application 测试无需修改
未来策略信息

AKShare → Tushare

AKShare 第一优先级因为免费；Tushare 第二优先级因为仍有半年以上会员权益。顺序未来必须配置化。

当前禁止

不能提前写任何分支

核心、任务、表名、环境变量和协议不得出现“如果 AKShare 失败则调用 Tushare”之类供应商分支。

真实接入前置条件 后续方案必须确认许可、频率、会员权限、字段映射、质量和切换语义；任何结果仍只能从 adapter 进入核心。

CI 分层

  1. static：frozen install、format、Ruff、Pyright、架构测试；最快失败。
  2. unit：无 Docker、无网络单测与覆盖率。
  3. integration：启动 data-sync-infra profile，执行 diagnostics，保存失败日志，始终关闭容器。
  4. image：构建 runtime 镜像，检查用户、依赖、导入、worker 启停和信号。
本地与 CI 使用相同命令 CI 文件只负责排序、缓存和上传日志，不复制另一套脚本。所有命令先写入 README，再接入 CI。

Definition of Done

  • 所有交付文件存在且由 uv lock 驱动。
  • 三类依赖 healthy，诊断输出可被机器解析。
  • worker 无业务 task，可启动并优雅退出。
  • 无 API、OpenAPI、业务表和迁移 revision。
  • 无 AKShare/Tushare 安装、import 或网络请求。
  • fake adapter contract 与架构负例通过。
  • 镜像非 root，build context 不含其他服务和秘密。
  • README 覆盖安装、检查、启动、诊断、停止和故障定位。

回滚

代码、Compose 和 CI 可按提交回退。由于没有业务表、revision 或外部写入，不需要数据回滚。

回滚不得自动删除 named volume；本地产生的 volume 由开发者单独确认后清理。

故障定位最小信息

  • 命令退出码与 diagnostics JSON。
  • Compose service health 状态。
  • 脱敏后的最近启动日志。
  • 锁文件 hash、镜像 tag/digest、Python 版本。
  • 不收集连接 URL、token 或原始环境变量。
