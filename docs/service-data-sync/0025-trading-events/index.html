Service Data Sync · Research Proposal 0025

龙虎榜与大宗交易：保留当时披露事实，不保存事后赢家叙事

本方案把龙虎榜“上榜事实、原因、买卖席位”和大宗交易“逐笔成交”建成两个隔离的数据集。 推荐先接交易所权威披露，再以固定 AKShare / 东方财富接口做候选补充与对账；所有未来收益、 事后成功率、滚动排行和最新价字段在 Adapter 白名单之外硬拒绝。

01 · Recommendation

结论：两个 P0 明细集，一个 P1 派生层，P2 明确不接

P0 · 条件接入

龙虎榜披露与席位明细

建议接入沪、深、北交易所公开信息，按“证券 × 交易日 × 上榜原因”建事件头， 买入榜和卖出榜分别保存席位与名次。东方财富 raw 的 TRADE_ID 可作候选来源关联键，但不能替代内部身份。

P0 · 条件接入

A 股大宗交易逐笔

建议接入成交日期、证券、成交价、数量、金额、买卖营业部及同日参考价。 逐笔与日汇总分离；完全相同的多笔成交可能真实存在，禁止按经济字段哈希直接去重。

P1 · 仅从 P0 派生

机构净额与日度汇总

机构席位聚合、大宗成交均价、折溢价分布由已发布明细在固定 data_version 上计算；不直接保存供应商滚动榜单，避免口径和历史漂移。

P2 · 不建议接入： 上榜后1/2/5/10/20/30日涨跌幅、营业部“成功率”、后续上涨概率、 活跃股/营业部滚动排行、最新价和事后解读。它们不是事件发生时可见的披露事实， 不进入 raw→canonical 映射白名单，也不进入实时或回测 API。
事实：当前仓库没有龙虎榜或大宗交易任务、领域模型、Adapter 或 API。 可复用能力是现有 DataSourcePort、不可变 raw evidence、来源批次、 发布版本、质量隔离、checkpoint 以及 service-api 防腐客户端。 建议：本专题只输出领域输入，跨专题共享表和最终契约由后续统一方案定义。
维度龙虎榜大宗交易
业务事实交易所为何公开一只证券，以及公开的前五买卖席位交易所确认并公开的一笔大宗成交
不可混入大宗成交、普通日行情、供应商事后表现竞价龙虎榜、盘后固定价格汇总、减持公告
主时点交易日 + 市场可见时间 + 平台观测时间成交日 + 交易所披露时间 + 平台观测时间
查询主键证券、交易日、原因、来源事件键成交日、证券、来源逐笔键/重复序号
02 · Value & Scope

业务价值、目标用户与不可越界语义

量化研究员

  • 研究异常交易公开原因、席位集中度和机构专用席位出现。
  • 构建大宗交易折溢价、成交规模和后续事件研究的“事件起点”。
  • 按当时可见信息复现信号，不让结果期数据倒灌。

投研与风控用户

  • 查看证券为何上榜、哪些营业部进入买卖前五。
  • 识别大额协议成交与竞价价格的差异。
  • 关联公司公告时只通过事件 ID，不推断买卖双方最终投资者。

数据运营与 API 消费者

  • 按交易所、交易日、证券、原因和质量状态检索。
  • 复验来源批次、方法学、版本和修订。
  • 监控缺日、空集、分页截断和 schema 漂移。

范围决定

对象本方案处理理由
沪深北 A 股竞价交易公开信息纳入权威披露，具有清晰原因和席位场景
沪深北 A 股大宗交易逐笔纳入事件研究需要逐笔价格、数量、金额和买卖席位
B 股、基金、债券、REITs首期排除币种、数量单位、交易机制和披露栏目不同，不与 A 股静默共表
盘后固定价格交易独立评估规则与公开字段不同，不等同协议大宗交易
龙虎榜供应商解读/胜率排除非官方事实，可能包含事后或不透明模型输入
公司股东通过大宗交易减持公告关联但不混表属于0024 公司事件，披露主体与时态不同
个股/市场资金流独立数据域属于0017 日资金流，不能用席位金额代替
席位不等于投资者：“机构专用”或营业部名称是交易公开信息中的交易单元标识， 不能推断最终账户、股东身份、交易动机或关联关系。API 必须携带这一免责声明。

05 · Temporal Semantics

交易日不是可见时间：双时态与修订必须同时存在

交易发生 / 异常窗口结束（trade_date / window_end） │ 收盘后交易所形成公开信息 ▼ 来源公开（source_published_at，可空） ──▶ 市场安全可见（visible_at） │ 日期级历史披露：保守取下一交易时段开盘 ▼ 平台首次抓到（observed_at / known_from） ──▶ 质量通过并发布（published_at / data_version） │ └── T+1/T+5 内容变化：追加 revision，旧 knownAt 仍返回旧版本
时间字段含义取值规则不得替代
trade_date竞价公开信息结束日或大宗成交日交易所本地日期不是公告时刻、不是抓取时刻
window_start/end_date多日异常波动评价窗口只有来源明确给出才保存不得由文本机械减两天
source_published_at来源明确发布时刻带时区；来源只给日期时为空不得用 HTTP 响应时间伪造
visible_at允许实时/回测消费的最早安全时刻精确发布时刻；否则保守到下一交易时段不得等于当日 00:00
observed_atAdapter 完成该次来源观测的 UTC 时刻每次抓取独立保存不是市场公开时刻
known_from/to平台对某修订版本的知识有效区间半开区间；追加修订关闭旧版本不得覆盖旧知识视图
published_at质量通过并原子发布到消费者的时刻与 data_version 绑定不是来源发布时间

查询语义

  • tradeDateFrom/To 选择事件业务日期，不改变知识版本。
  • asOf 选择业务有效视图；本域默认等于请求的事件日期上界。
  • knownAt 同时限制 visible_at 和平台已知 revision，禁止未来时刻。
  • 不传 knownAt 返回当前已发布版本；传值则返回当时已知且当时可见的版本。
  • 历史回填只有交易日而无发布时间时，使用下一交易时段开盘这一保守界限，并标记 visibility_basis=DATE_ONLY_CONSERVATIVE。

修订、撤回与缺失

内容变化

同一交易所日重新抓取后先比较排序无关的多重集哈希；字段变化形成新 revision，不原地更新。

记录消失

只有完整日快照通过后才追加 tombstone；单页失败、限流或空响应不能解释为官方撤回。

原因规则变化

原始原因字符串永远保留；canonical 原因码按方法学版本解释，不能批量改写历史原文。

同日收盘字段并非盘中可见：收盘价、当日涨跌幅、龙虎榜金额和大宗折溢价只有在 交易所收盘后公开信息形成并达到 visible_at 后才可消费。把 trade_date 00:00 当成可见时刻会产生确定的未来函数。
06 · Sync, Backfill & Recovery

按交易所日发布完整快照，明细抓取可恢复但不可半发布

scheduler / backfill command → venue calendar partition (dataset, venue, trade_date) → provider-neutral request → official Adapter ── or ── Eastmoney-AKShare Adapter → immutable raw payload + request/response metadata → whitelist decoder → identity resolution → multiset dedup → quality gate / quarantine → one transaction publishes event head + seats/executions + data_version → checkpoint advances only after full partition publication
环节龙虎榜大宗交易共同约束
调度 收盘后轮询事件头；再按事件取买/卖席位 收盘后按交易所、单日取逐笔 不预设官方精确发布时间；记录首次非空观测
逻辑分区 dataset/venue/trade_date dataset/venue/trade_date 物理表候选按 trade_date 年度 RANGE 分区，待统一模型定稿
增量 T 日抓取，T+1/T+5 复核；席位任务可断点续跑 T 日抓取，T+1/T+5 复核 空集、未发布、网络错误三种状态分离
分页 summary 全页；seat 按事件两侧抓取 AKShare 1.18.78 函数不翻页，强制单日且检查 raw pages 页数、总数、每页行数、稳定排序键进入批次元数据
回补 按日倒序，优先官方可验证区间；旧历史单独质量等级 按日倒序，不允许跨长窗口触发 5000 行截断 回补不改写当时可见时间；历史发布日期缺失采用保守值
幂等 事件多重集哈希 + TRADE_ID；seat 按 side/rank 经济元组的重数 + occurrence_no，不折叠完全相同行 相同内容复跑不产生新 revision；不同内容追加版本
恢复 头完成但席位未完成时保持 staged，不对外发布 所有页归档、数量核对后才发布 指数退避、抖动、熔断、限速；失败分区入重试队列

写入顺序与事务边界

  1. 创建独立来源观测并写不可变 raw；相同 payload 也不折叠观测。
  2. 解码允许字段，拒绝未知 schema、未来日期和禁用字段进入 DTO。
  3. 按交易日解析证券身份；无法唯一解析的记录进入隔离区，不丢弃整日其他证券。
  4. 构造日分区多重集；保留大宗完全相同成交的重数与来源日序。
  5. 运行字段、对账、完整性、PIT 和跨来源抽样质量规则。
  6. 单事务发布日 release、事件头与全部子项，生成不可变 data_version。
  7. 提交成功后推进 checkpoint；失败回滚 canonical 发布，不删除 raw 证据。

容量与查询假设

2024-04-17 探针有 139 个龙虎榜原因事件；若每个事件最多 10 个席位行， 单日约千级子项。2022-01-04 大宗交易有 135 笔。按 250 交易日和十年估算， 领域明细为百万到低千万级，年度分区和 (security_id, trade_date desc)、(venue, trade_date desc) 索引可覆盖主查询；该估算不是容量承诺，连续样本统计后再定物理分区。

允许清单先于映射；未来字段即使在 raw 中存在也永不发布

禁用字段登记

龙虎榜硬拒绝
  • D1/D2/D5/D10/D20/D30_CLOSE_ADJCHRATE
  • EXPLAIN 中供应商“成功率”与交易叙事
  • RISE_PROBABILITY_3DAY
  • TOTAL_BUYER_SALESTIMES_3DAY 等不透明统计
  • 当前活跃营业部、近月排行和事后席位表现
大宗交易硬拒绝
  • CHANGE_RATE_1DAYS/5DAYS/10DAYS/20DAYS
  • D1/D5/D10/D20_AVG_ADJCHRATE
  • “上榜日后平均涨跌幅”“上涨概率”
  • 随查询日变化的最新价、近月/季/年活跃排名
  • 未来公告中确认的交易对手身份或减持结果
结构性防线：禁用字段不仅“不返回”，还不得进入 provider-neutral DTO、 canonical mapper、领域表、API schema、测试 fixture 或派生视图。raw 可为审计原样保存， 但 raw 下载权限与业务查询权限隔离；列名新增默认拒绝，不能默认透传。

PIT 回归场景

  • 在 visible_at - 1ms 查询，当日事件必须不可见；到达可见时刻后才出现。
  • T+5 来源修订不能改变 knownAt=T+1 的结果。
  • 历史回补不能把回补日观测到的未来收益写入历史版本。
  • 同股同日两个原因必须返回两个事件；席位通过 TRADE_ID 分别挂接。
  • 三笔经济字段相同的大宗交易重放后仍为三笔，且幂等复跑不变成六笔。

dataset_id粒度输入字段组消费者隔离边界

对共享模型的依赖输入

  • 证券身份与生命周期：复用 0014 / ADR-0013，不创建第二套证券表。
  • 交易所日历、来源、批次、raw payload、质量、隔离、checkpoint、publication： 由统一 canonical 方案定义，本专题仅提交所需关系。
  • data_version、方法学版本、known_from/to 和审计字段： 复用0018 ORM 持久化约束的发布模式。

P1 派生需求

龙虎榜机构聚合

从 seat 数据中对官方“机构专用”标签按事件和版本聚合；不以名称模糊匹配扩张机构范围。

大宗日汇总

从逐笔计算笔数、总量、总额、成交均价和折溢价分布，结果绑定输入 data_version。

事件研究输出

未来收益只能由独立研究任务在查询时计算，清楚标注观察窗，永不回写事件事实集。

来源冲突：官方与东财同一日的数据不拼字段生成“更完整的一行”。 官方版本为首选 release；东财作为独立观测做缺口告警或经批准的降级 release， 响应必须显示来源与质量等级。

约束草案

  • 金额、价格、数量均大于或等于零；大宗成交三者必须严格大于零。
  • known_to > known_from 或为空；同一逻辑事件知识区间不重叠。
  • list_side IN ('BUY','SELL')，rank BETWEEN 1 AND 5。
  • occurrence_no >= 1；不允许通过唯一约束抹掉相同经济字段的多笔。
  • 年度 RANGE 分区是容量候选，不在本专题固化；空分区不自动创建“零事件”事实。
10 · Service API Needs

service-api 只经内部客户端读取；外部业务路由一律 POST

禁止直连：service-api 不读取 data-sync 数据库，不访问交易所、东方财富、 新浪或 AKShare；service-web 只访问 service-api。跨服务实际通信方式和机器可读契约由第五批统一设计。
拟议 POST 路由用途筛选默认权限
POST /v1/market-data/dragon-tiger/query 按证券或全市场查事件及可选席位 venue、exchange+symbol、日期、原因族、seatCode/type、side、金额、quality market-data:trading-events:read
POST /v1/market-data/block-trades/query 按证券、营业部、折溢价和规模查逐笔 venue、symbol、日期、buyer/seller seat、notional、premium range、quality market-data:trading-events:read
POST /v1/market-data/trading-events/aggregate P1 固定版本聚合，不返回未来收益 dataset、groupBy、metric 白名单、日期、knownAt、dataVersion market-data:analytics:read

请求约束

  • 请求体支持 tradeDateFrom、tradeDateTo、 asOf、knownAt、dataVersion、字段投影、 server-side 排序白名单、cursor 和 limit。
  • 普通用户默认只读 VERIFIED；QUARANTINED、 raw URI、来源请求参数只对数据运维权限开放。
  • 日期范围、证券数量、席位模糊搜索、字段投影和聚合基数设置配额； 超限返回 429，不把无限查询透传给 data-sync。
  • cursor 必须绑定 dataset、全部筛选、排序、knownAt、dataVersion 和最后唯一位置； 发布版本改变返回 409 snapshot-expired，不静默翻到新版本。
  • 排序至少支持 tradeDate desc + eventId、notional、premium； 任意排序字段不得由用户原样拼入 SQL。

类别必须返回
