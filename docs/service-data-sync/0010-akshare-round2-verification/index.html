AKShare 第二轮独立验证：结论已收敛，生产准入未通过

以 B00 的 65 项 capability 目录为准，在新的只读 Docker 环境中复测候选函数。二轮完成的是独立短探针验证，不是 3–5 个交易日稳定性验收；因此没有任何能力升级为 FULL。

结论

完整支持

0 / 65

没有能力同时通过覆盖、语义、质量、稳定性与来源合规门槛。

受限或不稳定

48 / 65

有局部候选，但存在市场/字段/历史/版本/稳定性缺口，继续由 Tushare 主用。

当前无等价

17 / 65

缺正式等价接口或核心语义无法重建，不能用近似数据替换。

实施决定：不创建生产 AKShare adapter、fallback 路由、同步任务、表、迁移或接口。生产数据读取仍只能经 provider-neutral port；任何来源 SDK、URL 与字段只能留在未来的具体 adapter 内，绝不能进入任务、应用、质量或持久化层。

B00：本轮采用的验收层级

研究短探针（本轮） Docker / 固定 AKShare 版本 / 只读根文件系统 / 每调用 30 秒上限 → 候选函数 → 行数、schema fingerprint、耗时、空结果、错误类型 → capability verdict 未来服务（未实现） 数据源 SDK / HTTP → concrete provider adapter → provider-neutral port → application / task / quality / persistence 禁止：application、task、quality、persistence 直接调用 AKShare、Tushare 或任何具体 adapter

已完成：R2 独立复测

  • 使用新建临时 Docker 依赖卷，固定 akshare==1.18.78。
  • 70 次候选调用：42 次返回非空结构化数据、2 次返回空集、26 次以超时/断连/解析或键错误失败。
  • 记录 schema fingerprint、字段数、行数和错误类型；临时容器、卷和脚本将在交付前删除。

仍未完成：R3 生产准入

  • 连续 3–5 个交易日成功率、空结果率、延迟与 schema 漂移观察。
  • 与持 token 的 Tushare 同日重叠样本做主键、单位、字段与数值容差对账。
  • 底层网站条款、访问频率和再分发边界核查。
状态解释：“第二轮完成”表示 B00 的独立短探针环节结束；不等于服务可以接入数据源。R3 未通过前，所有业务 capability 维持 Tushare 主路由。

二轮最重要的信号

可用性随调用波动

首轮能取到的主题、期权目录、A 股日线、财务指标、回购与十大股东，本轮出现超时、断连、解析或键错误。一次成功不能作为 adapter 准入证据。

非空不代表覆盖

深交所、北交所两融返回空 DataFrame；停牌含未来生效项；日历还出现未来日期。adapter 未来必须把空集、计划/公告、实际状态与网络错误分开表达。

历史与时效存在硬缺口

可转债和期权样本停在历史日期；涨跌停池和筹码接口有近期窗口；快照型主数据缺有效期和版本链。这些不满足旧系统回测/回填默认需求。

语义缺口不能由转换补齐

财务 point-in-time 版本、公司行动状态链、历史涨跌停价、预计算技术因子、完整筹码分布和基金复权因子仍无可验证等价物。

路由与实现边界

现在

  • Tushare：所有现有业务 capability 的主路由。
  • AKShare：仅保留调研证据，未获生产路由资格。
  • API 服务：不直连同步服务数据库，也不直连第三方数据源；接口设计留待后续任务。

以后（仅在 R3 通过后）

  • 按 capability + market + frequency 配置独立路由。
  • AKShare/Tushare 都实现为独立 concrete adapter，返回相同中立 port 契约。
  • 只有已批准的临时故障可回退；空集、字段漂移和语义缺失不得盲目回退。
再次确认：研究容器对 AKShare 的调用不属于服务实现。仓库服务源码中不增加 AKShare 直连、Tushare 直连或任何绕过适配层的代码。

建议的下一步

  1. 先排 R3 观察窗口：在连续 3–5 个交易日自动执行同一份只读探针，记录成功/空集/失败、耗时和 schema fingerprint。
  2. 做最小 Tushare 对账：优先选北/南向、指数权重、基金净值、CPI/PPI/GDP/SHIBOR 四个已有非空候选，明确主键、单位、发布日期和数值容差。
  3. 只为通过项设计 adapter：每一项单独写映射与质量门槛；未通过项保留 Tushare，不用 AKShare “尽力填充”。
  4. 再决定基础设施实现范围：R3 之前不开始表、任务、接口或数据落库，避免把仍不稳定的供应商契约固化进架构。
