1. 结论与优先级

推荐

建议接入，按文档证据分三期

P0 先接官方公告目录、业绩预告与快报； P1 接限售解禁和股本变动； P2 再接股东计划、进展、结果及董监高实际交易。

核心选择

公告不是一行“最新状态”

公告文档有永久身份，业务事件可跨多个文档，事件值按公开顺序追加修订。 更正、补充、结果公告都保留旧版本，不覆盖、不倒填。

最大风险

聚合接口制造历史幻觉

东财业绩和解禁接口常返回当前聚合状态；把当前完成值、解禁后收益或最新价格放回原公告日， 会直接产生未来函数。

2. 业务价值、用户、场景与边界

量化研究者

  • 按市场当时可见版本构造业绩预告变化、快报偏差和更正风险因子。
  • 重建限售解禁供给、股本分母和股东行为，不使用后来才知道的完成值。
  • 把公告事件与行情、财务事实按时间连接，但不静默混算来源或口径。

投研与风控用户

  • 查看原公告、补充、更正、进展和结果的完整链。
  • 识别预告方向变化、解禁规模、股本突变和重要股东减持计划。
  • 通过来源、方法学、质量状态和免责声明判断可用性。

平台与审计维护者

  • 按文档 ID、raw hash、批次和 revision 解释任意 API 结果。
  • 从 raw 重放、隔离 schema drift、回退 publication，不破坏历史。
  • 对缺页、撤回、修订和空结果给出明确状态。

范围与非目标

本方案覆盖
  • 沪、深、北 A 股上市公司公开事件及其文档关系。
  • 公告、业绩预告、业绩快报、限售解禁、股本变动、股东增减持。
  • 真实上游、字段、时间、修订、同步、恢复、质量、拟议领域表和 API 查询需求。
  • 当前代码、身份模型、财务 PIT 和服务边界的兼容影响。
本方案不覆盖
  • 不修改代码、迁移、OpenAPI、配置、依赖或调度。
  • 不承诺抓取全部公告正文、附件、图片 OCR 或自然语言事实抽取。
  • 不把定期报告最终值、行情收益、舆情、诉讼或回购扩入本批。
  • 不定义跨专题证券、来源、批次、质量、publication、checkpoint 共享表。
边界不变量 Provider SDK、URL、中文字段和单位修正只存在于 Adapter。 service-api 不直读 data-sync PostgreSQL、对象存储或 Provider； service-web 只访问 service-api。本方案继承 ADR-0002、 ADR-0004和 ADR-0009。

容量假设 全历史公告目录可能达到百万级文档，数值型领域事件预计十万至数十万级、修订和文档关系进一步放大。 该估算只用于分区与接口上限设计；实施前必须以三所各 100 只证券、至少 10 年样本测量。

3. 权威来源、AKShare 候选与证据

3.1 来源优先级

  1. 公开文档事实：交易所披露站点、巨潮资讯法定披露平台和发行人公告。 文档 ID、标题、公开时间、正文、公告编号和修订说明以此为准。

4. 数据粒度、身份、唯一键与字段字典

4.1 三层身份

证券身份（现有 0014）
  └─ security_id：按事实日期 + known_at 解析

公开文档
  └─ disclosure_document_id：source_code + upstream_announcement_id
       ├─ ORIGINAL
       ├─ CORRECTION
       ├─ SUPPLEMENT
       ├─ PROGRESS / RESULT
       └─ OFFICIAL_WITHDRAWAL（仅有公开证据时）

业务事件
  └─ event_id：稳定 UUID，不随状态和值变化
       └─ revision 1..N：每个公开文档或来源变化追加，不覆盖旧值
  • 建议 一份公告可包含多个业务事件，一个业务事件也可由多个公告推进；使用多对多文档关系，禁止假设一对一。
  • 建议 官方公告 ID 是文档身份，不直接充当业务事件身份；修正公告拥有自己的文档 ID，但关联同一业务事件。
  • 风险 没有稳定上游事件 ID 时，候选 key 只能使用首次公告 ID 加领域维度；状态、数值、最新日期和标题全文不得进入永久 ID。

董监高变动 人员原文、职务、关系、变动日、填报日、变动前后持股、变动数、均价、原因、股票种类、币种 股、CNY/share；若来源明确其他币种则 ISO 4217 三所 AKShare 文档标注单位存在差异，必须按 raw 和官方页逐所校准

5. 交易日、公告、可见、有效与修订语义

5.1 六类时间不可互换

时间定义示例查询用途
report_period会计期末2025-06-30筛报告期；绝不代表当时可见
occurred_on业务发生日/交易日董监高成交日事件回放与交易日对齐
announced_at公告标注发布时间平台毫秒时间或公告日期来源事实；精度单独记录
source_visible_at公开平台首次可见时间公告发布到媒体时刻市场 PIT
effective_on规则或数量实际生效日限售股上市流通日业务有效视图
observed_at / known_from平台抓取成功 / 平台知识开始回补执行时间平台审计 PIT；不能倒填

5.2 保守可见规则

  1. 官方源提供可信精确时间时，保存原始时区和 raw 值，转换为 UTC；visible_time_precision=EXACT。
  2. 只提供公告日期时，标记 DATE_ONLY，默认 public_usable_at = 公告日后的下一交易时段开盘；不得假定公告日在开盘前已公开。
  3. 只有聚合行、没有可信公告时间时，标记 OBSERVED_ONLY， public_usable_at = observed_at；不得按报告期或事件日回填。
  4. known_from 永远不早于本平台首次成功观测。 后来找到历史官方公告时间时，追加知识修订，不改写原平台知识历史。
  5. 回测可选择“市场可见重建”：public_usable_at ≤ T 且使用当前可审计 revision； 若要求重演平台当时知识，则同时要求 known_from ≤ T < known_to。 两种模式必须在响应中标明，不能混称。

5.3 修正、补充、撤回和结果

2025-07-15 原始业绩预告（document A）
  └─ event E / revision 1 / public_usable_at = A 的保守可见时刻

2025-08-30 修正公告（document B，CORRECTS A）
  └─ event E / revision 2 / 新金额只从 B 的可见时刻生效

正式半年度报告（document C）
  └─ financial.statement.reported 的独立事实
     不成为 event E 的 revision 3，不覆盖预告历史
  • 更正公告：若明确修正原事件，关闭旧 revision 的市场可见区间并追加新 revision； 原文档和旧值永久保留。
  • 补充公告：默认只补充指定字段；未被明确替代的旧字段继续有效。 只有版本化字段合并规则可生成“当前视图”，禁止通用整行覆盖。
  • 进展/结果公告：追加事件阶段。计划数量仍是计划事实，累计实际值只从进展或结果公告公开时起可见。
  • 已经媒体确认发布的公告若上游后来缺失，不自动标记撤回或删除。 只有官方公开撤回/取消/作废证据才进入 WITHDRAWN 或 CANCELLED revision。
  • 发布前被撤回的申请没有形成公开市场事件；raw 运维证据若依法取得，只留受限区，不进入 consumer publication。
官方规则支持 上交所 2026 股票上市规则要求业绩预告、快报出现重大差异时及时发布更正公告； 深交所业务指南说明公告经媒体确认发布后不得修改或撤销，已披露错误应通过补充或更正处理。 因此“追加文档 + 追加事件 revision”比覆盖一行更贴合真实披露流程。

6.2 正常写入顺序

  1. 调度创建 run/partition；按 capability、市场、日期、页或证券取得 advisory lock。
  2. Adapter 仅调用对应 Provider，保存原始字节、请求参数摘要、响应头摘要、schema fingerprint 和 observed_at。
  3. raw 持久化成功后才解析；禁止“先写 canonical，随后补证据”。
  4. 公告先按来源文档 ID 去重，再按标题、报告期和领域规则建立业务事件候选关系。
  5. 按事件事实日期调用 0014 date-aware identity resolver；歧义和代码复用进入隔离。
  6. 领域 Normalizer 明确单位、阶段、空值、时间精度和禁用字段；未知列或未来公开时间进入 quarantine。
  7. 同一事务追加 event revision、领域 item、文档关系、质量结果和 publication；成功后推进 checkpoint。
  8. 重复抓取内容相同只追加 observation 证据，不新增业务 revision；文档关系或值变化才追加 revision。

6.3 分页、幂等和快照一致性

  • 页级幂等键建议为 capability|source|market|window_start|window_end|page_no|schema_version； payload hash 只作字节查重，不能折叠独立观测。
  • 第一页记录 total_hits/pages；全部页结束后复核页数、行数、首末排序键、重复 key 和窗口覆盖。 页数在运行中变化时，本批失败并用重叠窗口重跑，不发布混合快照。
  • stock_ggcg_em 无日期参数且全量页数大，不得每次从头盲拉。 未取得稳定上游行 ID、可复验排序键或受控分页水位前保持 P2 关闭。
  • 东财解禁 holder 子请求必须保存父证券、解禁日、父 source batch 和父事件候选 ID； 子行不可脱离请求上下文单独去重。

6.4 回补与恢复

回补

  • 显式给数据集、来源、市场、证券范围、公告/报告/事件日期范围和理由。
  • 公告从近到远按月回补；领域事件按文档触发，聚合接口只作交叉验证。
  • 历史回补保留真实公告时间；若只有日期则使用保守规则，不用回补时间伪装官方时间。
  • 每批形成独立 dataVersion；禁止一次全市场超长事务。

失败恢复

  • 超时/429/断连按 Retry-After 或指数退避加 jitter；最多 3 次，预算耗尽留待下一 run。
  • schema、单位、身份、未来时间、页集合变化不自动重试，直接隔离。
  • DB 事务失败保持上一 publication；raw 可重放，同 partition 新 attempt 不复用 observation sequence。
  • 僵尸任务由 lease/reaper 回收；checkpoint 只在 publication 事务后推进。

6.5 删除、保留与回滚

  • 已发布文档元数据、事件 revision、关系、质量结果和审计证据默认不物理删除。
  • 公告正文/附件是否长期保留由数据权利与容量策略决定；未通过合规门时只存元数据、官方链接和合法取得的 hash。
  • 来源下架只产生来源缺失质量状态，不删除旧事实；官方撤回通过新 revision 表达。
  • 回滚只切回上一 verified publication 或关闭 capability；禁止覆盖 revision、改写可见时间或 destructive downgrade。

7.3 口径隔离

  • 业绩预告的预测区间、业绩快报初步值、正式财报披露值三类物理和方法学隔离。
  • 解除限售表示可流通，不表示卖出；大股东减持计划、董监高实际成交和持股存量不得混为一种“减持”。
  • 股本结构是某生效日的数量状态；解禁是限制状态变化事件。两者可关联，但不把总股本/流通盘静默互算。
  • 沪深北交易所董监高填报分别保留来源方法学，单位校准前不组成一条无标记全市场序列。
  • 东财、新浪、交易所同名字段不自动 fallback；若切源，形成新 methodology/dataVersion 并显式披露。
最小回测不变量 对任意查询时刻 T，响应中的每一个数值都必须指向一份在 T 前公开的文档 revision， 或明确标记为 OBSERVED_ONLY 且平台在 T 前已取得；找不到证据即不得出现在回测/实时视图。

不自行定义共享表 本草案只描述公司事件域。security_id、source batch、raw object、methodology、quality、 quarantine、checkpoint、dataset publication、交易日历和访问审计均引用后续统一模型； 不在 0024 重复建表。

查询与容量取舍

  • 公告详情按稳定 document/event UUID 查询，避免把长 URL、标题或数据库 BIGINT 暴露为公开 ID。
  • 列表主排序为 public_usable_at DESC, event_id, revision，建立覆盖索引；禁止 offset pagination。
  • 文档目录按月分区有利于增量和保留；财务事件按 report/effective year 分区有利于 PIT 扫描。
  • 自由文本标题/原因首期只做前缀或受控全文索引；不得让任意关键词查询拖垮主库。
  • 一份快报/预告的 metric item 保持窄表和受治理字典，避免宽 JSON 绕过单位与 schema 门。

10. 对 service-api 的查询、分页与权限需求

本专题只给第 10 项跨服务契约设计输入，不改现有 OpenAPI。 内部通信选择仍由 data-access-contract 统一方案决定；当前 ADR 基线优先版本化内部 HTTP。

10.2 请求约束

  • families 1–8 个，fieldSelection 只允许受治理公开字段，禁止任意列名或表达式。
  • 默认时间窗 1 年，普通用户最大 10 年；全历史需专门权限或异步导出方案，不在本接口隐式支持。
  • limit 默认 50、最大 100；cursor HMAC 绑定证券、筛选、asOf、knownAt、排序、methodology 和 dataVersion。
  • knownAt 未来时刻拒绝；asOf 与 marketVisibilityMode 必须形成明确组合。
  • 金额、数量、比例和价格均以十进制字符串输出，带 unit、currency、ratio basis；不输出二进制 float。
  • 只有日期精度的公告必须返回 visibleTimePrecision=DATE_ONLY 和推导后的 publicUsableAt。

10.4 鉴权、限额、缓存与错误映射

控制需求
鉴权沿用有效 JWT / ACTIVE 用户；建议权限 MARKET_DATA.CORPORATE_EVENTS.READ，全文/批量导出另设 scope
内部身份service-api → data-sync 使用服务 Bearer/mTLS 候选、最小权限、轮换和审计；不转发用户 token
超时/重试只读内部请求超时、连接错误、502/503 在未响应前安全重试 1 次；429 尊重 Retry-After
限流按用户、证券、窗口、字段数和详情展开计数；大窗口和 includeRevisions 成本加权
