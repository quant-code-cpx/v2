1. 核心结论与固定决策

全量的精确定义 覆盖 CN_A_STABLE 当前与历史身份集合，以及每个来源能提供且通过质量门的完整历史。 上游不存在的历史以可用起点表达，禁止补造记录；research-disabled 资金流不属于当前全量承诺。
统一列表只读冻结 EOD 横截面 新增 equity.discovery.eod；筛选、排序、分页始终绑定一个 dataVersion 和 component manifest，不在查询时 N+1 拼数千只证券。
普通停牌与暂停上市分离 既有 SUSPENDED 只表示交易所明确的暂停上市；新增 equity.trading_status.1d 表达普通停复牌，页面不得混名。
市值只由真实股本 × 未复权收盘价生成 总股本、已上市流通 A 股按生效日选择；价格、股本和计算方法学都写入血缘。 不使用供应商直接“市值”字段静默回填。
方法学不混用 列表默认估值使用已发布的 Eastmoney provider observation； 资金流只有在方法学从 research 晋级 validated 且生产开关开启后才能进入列表。 当前不设生产默认、不发布研究数据；任何晋级或切换都产生新版本。
生产入口只在全链真实发布后开启 开发阶段可以分批交付代码，但包含股票中心入口的 Web 版本必须等三服务 E2E 使用真实来源和真实 publication 通过后才能部署；不能用空壳、fixture 或手填 CSV 验收。

边界

  • 包含 EOD 证券发现与个股详情所需全部数据集；不拆出新的个股独立方案。
  • 不接实时行情、WebSocket、Level-2、分钟线、盘口和盘中资金流。
  • service-data-sync 是市场数据权威层；service-api 只能经版本化内部 HTTP 读取。
  • 来源切换必须新建 adapter policy、重叠比对和新 publication，禁止静默 fallback。

5. 全量回填、增量同步与编排

1. 身份基线三所目录与生命周期；冻结 CN_A_STABLE。
2. 事实回填按证券/日期并发抓取行情、财务、股本和事件。
3. 独立发布每个数据集先完成自己的质量门与 publication。
4. 横截面构建同一 asOf 选择组件版本，计算派生列和原因化空值。
5. 原子可见写 component manifest 后一次推进 discovery 指针。

调度与容量

  • 父任务进入 0031 控制面定义的全局 fencing；所有旧 CLI/Celery 写路径在本模块实施时接入同一 fence。
  • 默认安全速率为每 provider 单并发、每秒 1 请求；真实探针得到配额后只通过配置提高，不写死在代码。
  • 每个证券任务有 20 秒墙钟超时、最多 3 次带抖动退避；schema/单位/身份错误不可重试，直接隔离。
  • 事件首发固定切成最多 31 天的 operation window。10 年闭区间最多 118 个窗口；每个窗口成功后才记录 coverage bundle checkpoint，失败只重跑该窗口。
  • 龙虎榜席位使用与 AKShare 固定接口同源的东财 HEAD、BUY、SELL 日期窗报表批量分页，不按每个 head 再发两次请求。2024-04 真实探针分别为 1,720 / 8,593 / 8,589 行，按服务端约 500 行每页约 37 页；每页独立 HTTP timeout 与有限重试。
  • 事件分页先冻结总页数与总记录数，再按稳定键抓满所有页；跨页重复冲突、孤儿席位、BUY/SELL 缺边或金额不平都使整窗失败。取消后不再调度新页，失败证据保留已抓页的脱敏摘要。
  • 全市场父 run 永久冻结 {instrumentId, exchange, symbol, identityAsOf} roster 和 source snapshot；分区键使用 instrument UUID。retry 只能继承该 roster 的成功分区，不得按当前目录重算或以可复用代码命名。
  • 全量任务分片 100 只证券；单 shard 可恢复。父任务只汇总状态，不持有巨大内存数组。
  • EOD discovery 只在所有必需组件达到目标日或存在合法原因状态后构建；失败不推进当前指针。

6. 质量门、完整性与 publication

六态覆盖，不把缺失伪装成零

DATA真实来源记录通过质量门并进入 publication。
LEGITIMATE_EMPTY有完整来源响应且该证券/日期确实无记录。
NOT_APPLICABLE如亏损证券的 PE、未上市日期行情，业务上不适用。
SOURCE_UNAVAILABLE来源失败、未准入或覆盖不足；不得进入 FULL discovery。
QUARANTINEDschema、单位、身份或质量异常；保留证据，不对外可见。
STALE_LAST_GOOD新任务失败，消费者继续读上一合格版本并显示陈旧。

BASE/PARTIAL 与 FULL discovery 门禁

  • 首个可消费 BASE 由身份、已有来源覆盖的生命周期事实和目标日交易状态组成；未覆盖的 SUSPENDED 必须原因化。BASE 合格即可发布 completeness=PARTIAL，不因可选宽列尚未回填而永久阻断股票中心。
  • bar、股本、估值和 memberships 为独立可选组件；缺失时字段为 null + reason、component 明确不可用，绝不伪造成 FULL。资金流固定不进入当前 capabilities。
  • 身份组件为同一 CN_A_STABLE publication，沪深京 child dataVersion 完整。
  • 每个目标证券在行情、交易状态、股本、估值、行业/概念、申万中均有 DATA、LEGITIMATE_EMPTY、NOT_APPLICABLE 或受控不可用原因。
  • 任何必需语义族存在 SOURCE_UNAVAILABLE 或 QUARANTINED 时不发布新版本；继续保留上一版本。
  • 目标日所有 bar 为最终记录，OHLC、量额、日期、币种和单位校验通过。
  • 总市值与流通市值可以由明确股本输入重算，误差为 Decimal 精确运算的舍入范围。
  • 行业/概念允许多值；申万三级最多一个。未覆盖必须有受控原因，不能填“未知行业”。
  • 估值的 methodology code/version、supplier、观察窗口与 component dataVersion 完整；资金流记录 research/disabled 治理状态，不生成 component dataVersion。
  • 记录数、覆盖率、空值原因分布和上一版本差异均写入 quality result。

Publication 原子性

  1. 在单事务外完成来源抓取、标准化、revision 写入和质量计算；尚不改变消费者指针。
  2. 冻结所有 component publication，生成排序稳定的 manifest 与 SHA-256。
  3. 在一个数据库事务中写 discovery snapshot、availability、membership、release 和 component rows。
  4. 通过当前 fence token 后创建 dataset_publication 并 supersede 旧指针。
  5. 事务提交后发出运维事件；API 不依赖消息及时性，始终以 publication 表为准。

事件窗口 coverage publication

  • 公司行动、预告、快报、龙虎榜和大宗交易都按 securityId + family + [coverageFrom, coverageTo] 保存不可变覆盖证据；provider/source 级事实 publication 不能替另一证券证明空。
  • 来源成功、schema 完整且坏行计数为零时才可写 coverage；网络失败、分页不完整、字段缺失、金额不平或身份无法解析均失败关闭。
  • 合法空窗的 manifest factCount=0，但不向事件事实表写 sentinel；global 累积事实 release 的总记录数可以非零。
  • 长窗口由多个含端日期区间的无缝并集证明；任意一天缺口都返回 PARTIAL / SOURCE_UNAVAILABLE，而不是 AVAILABLE 空页。
  • 存在重叠观察时，以请求边界、coverageFrom 和 coverageTo + 1 切成不重叠 slice，每个 slice 选择当时最新的 coverage；旧宽窗只能补缺口，不能吞掉新纠错窗。
  • 每个 slice 只用自己的 coverage 知识时间读取该日期片的事实，禁止把全窗最大 cutoff 套到其他旧 slice；响应 knowledgeCutoff 报告实际使用证据的最大时间。
  • 实际选中 slice 的 coverageVersion、slice 范围、事实 publication 与 identity version 一起生成 composite dataVersion 和 ETag；新增空窗或纠错窗都必须改变条件读取结果。
  • knownAt 只选择当时已创建且未被当时 supersede 的 coverage；events/query 与 data-status 共用同一事实选择器、来源和方法学投影，不能用一个宽窗的总 recordCount 推断其中某日非空。

无 publication

内部 reader 返回稳定 publication-unavailable，包含 dataset、partition、 availability、reasonCode、observedAt 和可选 lastGoodPublication；不返回 200 空列表， 因为“没有发布”与“发布后查询为空”不是同一业务事实。

7. service-data-sync 内部读取契约

本方案同时是已实施 internal v1 reader 的评审基线；service-api 使用 service bearer、 request id、超时和严格 schema 校验。遵守任务约束，本轮不创建 OpenAPI 文件；后续治理记录只能 additive。

Cursor 与排序

  • cursor 为 data-sync 签发的 opaque base64url；内部包含 contractVersion、dataVersion、filterHash、sort tuple 和 HMAC。
  • 允许排序字段固定：symbol、name、close、changePercent、amountCny、turnoverRate、totalMarketCap、floatMarketCap、peTtm、pb；资金流排序和筛选当前稳定拒绝。
  • 所有排序追加 exchange、symbol 和内部行锚点作为稳定 tie-breaker；锚点只在 HMAC 签名 opaque cursor 内使用，不进入公开正文；nulls 固定 LAST。
  • cursor 的 dataVersion、filterHash 或 sort 不匹配返回 409，禁止悄悄从第一页继续。

8. 生产运行禁止假数据

强约束：fixture、mock、fake adapter、demo seed 只允许存在于 tests/ 或显式 test profile。staging/production 的配置校验、发布门和 E2E 必须共同证明数据来自已登记真实来源批次。
  • 非 test 环境启动时拒绝 providerId、adapter class 或 source policy 中含 fake、fixture、demo、sample。
  • 每条可发布 revision 必须有非空 sourceBatchId，可追溯 provider、upstreamSource、observedAt、adapterVersion 和 schemaFingerprint。
  • discovery 每个非派生值必须绑定 component dataVersion；派生值必须绑定公式版本与输入版本。
  • 真实来源返回空集只能成为 LEGITIMATE_EMPTY，必须有完整请求证据与覆盖判断；异常响应不能转换为空集。
  • 验收环境不执行 demo seed；首发通过真实全量命令生成，并随机抽样回溯到 source batch。
  • 单元和契约测试可用 fixture，但测试报告不得作为生产数据可用性证据。

9. 性能、可靠性、观测与恢复

全量规模按 6,500 只证券、30+ 年日线、全报告期设计；数据按证券/年份切片，禁止单事务全市场写入。
横截面规模单 dataVersion 约 6,500 行；构建内存目标 ≤ 512 MiB，使用 server-side cursor 与批量 COPY/upsert。
查询目标发现列表 P95 ≤ 250 ms、P99 ≤ 600 ms；默认 50、最大 100，压缩响应 ≤ 512 KiB。
发布延迟EOD 必需组件目标在收盘后 120 分钟内完成；不承诺盘中更新。
保留成功 raw 按 0030 策略不长期重复留存；失败证据、manifest、revision、publication 永久审计。
回滚切换到上一 discovery dataVersion ≤ 5 分钟；不删除新 revision，保留复盘证据。

指标与告警

  • sync_run_duration_seconds、source_request_total、source_retry_total、quarantine_total，均按 dataset/provider/reason 标注。
  • publication_lag_seconds、publication_coverage_ratio、discovery_build_duration_seconds、discovery_diff_ratio。
  • 告警：必需组件超过 SLO、连续 3 次来源失败、schema fingerprint 变化、覆盖率下降、异常大版本差异、fence 冲突。
  • 日志只记录内部 ID、dataset、partition、run/attempt、requestId；不记录 bearer、完整响应体或个人数据。

恢复矩阵

故障自动处置消费者状态恢复
来源超时 / 429 / 5xx有界退避，耗尽后失败分区上一 publication stale从 checkpoint 重跑失败 shard
schema / 单位漂移不可重试，隔离 payload 和 fingerprint上一版本继续可读升级 mappingVersion 后 replay

11. 可执行验收标准

  • 三所目录中的每只证券都出现在全量覆盖清单，身份冲突为 0。
  • 普通停牌、暂停上市、退市三个概念在模型、API 和页面文案中互不混用。
  • 日/周/月线各自来自原生上游周期；复权窗口能回溯 bar/factor 两个 dataVersion。
  • 股本历史来自真实 Eastmoney 股本结构，市值可以从同日 close 与有效股本重算。
  • 申万三级成分通过真实接口同步；每条归属能回溯 source batch，不用公司概况行业文本替代。
  • 财务与估值的 provider/methodology/version/knownAt 完整，平台派生指标保留输入 manifest；资金流明确 research/disabled 且筛选、列、排序失败关闭。
  • 龙虎榜、大宗交易、预告和快报按 exchange+symbol 可读，内部 UUID 不泄漏给公开层。
  • BASE discovery 的身份、名称、交易所和生命周期覆盖三所全部证券；可选组件 SOURCE_UNAVAILABLE / QUARANTINED 时 publication 为 PARTIAL，字段为 null 且有 nullReason， 不拿旧日期或其他来源值补齐。
  • 重复执行全量与增量任务不产生重复事实；任一 shard 失败后可从 checkpoint 恢复。
  • component 在构建中变化时不会产生混合版本；cursor 永不跨 dataVersion。
  • 断源、schema 漂移、DB 故障和错误发布均完成演练，上一 publication 可继续读并可回滚。
  • staging E2E 的每条抽样记录都能追溯真实 sourceBatchId；运行态没有 fixture/mock/demo provider。
  • Docker 中通过 Ruff format/check、Pyright、unit、architecture、integration 与镜像构建。
上线判定：只有上述全部通过且 service-api 0007、service-web 0007 的真实 E2E 同时通过，股票中心才允许从关闭状态切为可见。不存在“先用假数据上线、以后再接同步”的路径。
