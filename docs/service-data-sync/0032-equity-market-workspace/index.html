1. 核心结论与固定决策

全量的精确定义 覆盖 CN_A_STABLE 当前与历史身份集合，以及每个已形成真实 sourceBatchId、通过质量门并封存为 publication 的来源历史。上游不存在的历史以可用起点表达，禁止补造记录；资金流未形成可比较的 EOD 来源批次时不属于当前全量承诺。
交易所来源矩阵先于全量结论 身份目录可覆盖沪深京，但当前仅沪深日/周/月行情已有冻结来源批次的正向证据。BSE 周期行情或复权因子在 adapter 尚未产出可核验来源批次时固定为 SOURCE_EXCHANGE_UNAVAILABLE，必须 fail closed， 不能被写进“已完成全量”、合法空集或 PARTIAL 事实。
统一列表只读冻结 EOD 横截面 新增 equity.discovery.eod；筛选、排序、分页始终绑定一个 dataVersion 和 component manifest，不在查询时 N+1 拼数千只证券。
普通停牌与暂停上市分离 既有 SUSPENDED 只表示交易所明确的暂停上市；新增 equity.trading_status.1d 表达普通停复牌，页面不得混名。
市值只由真实股本 × 未复权收盘价生成 总股本、已上市流通 A 股按生效日选择；价格、股本和计算方法学都写入血缘。 不使用供应商直接“市值”字段静默回填。
方法学不混用 列表默认估值使用已发布的 Eastmoney provider observation； 资金流只有在方法学达到 validated、形成完整 EOD 来源批次并通过可比性校验后才能进入列表。 当前不设默认列或排序；任何方法学晋级或来源切换都产生新版本。
生产入口只读取真实发布版本 开发阶段可以分批交付代码；包含股票中心入口的 Web 版本只读取真实 publication。BASE 身份 publication 缺失时页面显示 NO_PUBLICATION；可选数据集按独立 PARTIAL/STALE/ SOURCE_UNAVAILABLE 处理。不能用空壳、fixture 或手填 CSV 验收。

5. 全量回填、增量同步与编排

1. 身份基线三所目录与生命周期；冻结 CN_A_STABLE。

3. 独立发布每个数据集先完成自己的质量门与 publication。
4. 横截面构建同一 asOf 选择组件版本，计算派生列和原因化空值。
5. 原子可见写 component manifest 后一次推进 discovery 指针。

调度与容量

  • 父任务进入 0031 控制面定义的全局 fencing；所有旧 CLI/Celery 写路径在本模块实施时接入同一 fence。
  • 默认安全速率为每 provider 单并发、每秒 1 请求；真实探针得到配额后只通过配置提高，不写死在代码。此默认值不是生产容量实测结论。
  • 全市场目录请求有 600 秒墙钟异常上限；超过即保留失败证据并停止该分区。600 秒不能被当成目录的 p95、常态时延或 EOD 通过证明。
  • 每个拟公开 dataset/capability + exchange + period 要在生产等价 egress 留存真实来源 p50/p95、成功率、重试次数、样本量与 adapter/schema 版本；未采到实测值的 cell 固定 PENDING。
  • 同一次全量/增量压测必须记录 DB 写入/事务 p50/p95、WAL bytes、checkpoint 写入时间/失败、锁等待，且记录对象存储 raw/manifest 的 PUT/HEAD p50/p95、字节量和可读回校验。
  • worker 记录已配置 CPU/memory limit、CPU throttling、RSS 峰值、OOMKilled=0 和实际并发；不允许用开发机空载或未限额容器推断生产容量。
  • 以实测并发、各 stage p95 与重试余量建立 EOD 临界路径：目录、来源抓取、DB/WAL、对象存储、discovery build、publication 的合计必须在收盘后 120 分钟内。任一阶段无实测、超预算或不可复盘即不创建新 public current 指针。
  • 每个证券任务有 20 秒墙钟超时、最多 3 次带抖动退避；schema/单位/身份错误不可重试，直接隔离。
  • 事件首发固定切成最多 31 天的 operation window。10 年闭区间最多 118 个窗口；每个窗口成功后才记录 coverage bundle checkpoint，失败只重跑该窗口。
  • 龙虎榜席位使用与 AKShare 固定接口同源的东财 HEAD、BUY、SELL 日期窗报表批量分页，不按每个 head 再发两次请求。2024-04 真实探针分别为 1,720 / 8,593 / 8,589 行，按服务端约 500 行每页约 37 页；每页独立 HTTP timeout 与有限重试。
  • 事件分页先冻结总页数与总记录数，再按稳定键抓满所有页；跨页重复冲突、孤儿席位、BUY/SELL 缺边或金额不平都使整窗失败。取消后不再调度新页，失败证据保留已抓页的脱敏摘要。
  • 全市场父 run 永久冻结 {instrumentId, exchange, symbol, identityAsOf} roster、source matrix 与精确 release/dataVersion；分区键使用 instrument UUID。retry 只能继承该 roster 的成功分区，不得按当前目录重算或以可复用代码命名。
  • 计划为低基数、可分页的 sealed child 拓扑；每页有上限且 child 只保留可恢复 partition key/manifest 引用，父任务不持有全市场巨大内存数组。HOLD 后必须按封存 release 与 knowledge cutoff 读取，不因 current 指针推进而失败或串读。
  • EOD discovery 只在所有必需组件达到目标日或存在合法原因状态后构建；失败不推进当前指针。

6. 质量门、完整性与 publication

六态覆盖，不把缺失伪装成零

DATA真实来源记录通过质量门并进入 publication。
LEGITIMATE_EMPTY有完整来源响应且该证券/日期确实无记录。
NOT_APPLICABLE如亏损证券的 PE、未上市日期行情，业务上不适用。
SOURCE_UNAVAILABLE来源失败或 coverage 不足；不得被伪装成 FULL discovery。
QUARANTINEDschema、单位、身份或质量异常；保留证据，不对外可见。
STALE_LAST_GOOD新任务失败，消费者继续读上一合格版本并显示陈旧。

BASE/PARTIAL 与 FULL discovery 规则

  • 任何面向 API/Web 的 AVAILABLE component 同时需要真实 source batch、raw/object 摘要或可读失败证据、质量通过、完整 coverage 和当前 dataset_publication；代码、adapter、模型、reader 或单次 probe 均不足以替代。
  • 首个可消费 BASE 由身份、已有来源覆盖的生命周期事实和目标日交易状态组成；未覆盖的 SUSPENDED 必须原因化。BASE 合格即可发布 completeness=PARTIAL，不因可选宽列尚未回填而永久阻断股票中心。
  • bar、股本、估值和 memberships 为独立可选组件；缺失时字段为 null + reason、component 明确不可用，绝不伪造成 FULL。资金流固定不进入当前 capabilities。
  • 身份组件为同一 CN_A_STABLE publication，沪深京 child dataVersion 完整；这不表示 BSE 已具备 K 线或复权 coverage。
  • 每个目标证券在行情、交易状态、股本、估值、行业/概念、申万中均有 DATA、LEGITIMATE_EMPTY、NOT_APPLICABLE 或受控不可用原因。
  • 任何必需语义族存在 SOURCE_UNAVAILABLE 或 QUARANTINED 时不发布新版本；继续保留上一版本。
  • 目标日所有 bar 为最终记录，OHLC、量额、日期、币种和单位校验通过。
  • 总市值与流通市值可以由明确股本输入重算，误差为 Decimal 精确运算的舍入范围。
  • 行业/概念允许多值；申万三级最多一个。未覆盖必须有受控原因，不能填“未知行业”。
  • 估值的 methodology code/version、supplier、观察窗口与 component dataVersion 完整；资金流记录方法学未完成 validated 的治理状态，不生成 component dataVersion。
  • 记录数、覆盖率、空值原因分布和上一版本差异均写入 quality result。

Publication 原子性

  1. 在单事务外完成来源抓取、标准化、revision 写入和质量计算；尚不改变消费者指针。
  2. 冻结所有 component publication，生成排序稳定的 manifest 与 SHA-256。
  3. 在一个数据库事务中写 discovery snapshot、availability、membership、release 和 component rows。
  4. 通过当前 fence token 后创建 dataset_publication 并 supersede 旧指针。
  5. 事务提交后发出运维事件；API 不依赖消息及时性，始终以 publication 表为准。

事件窗口 coverage publication

  • 公司行动、预告、快报、龙虎榜和大宗交易都按 securityId + family + [coverageFrom, coverageTo] 保存不可变覆盖证据；provider/source 级事实 publication 不能替另一证券证明空。
  • 来源成功、schema 完整且坏行计数为零时才可写 coverage；网络失败、分页不完整、字段缺失、金额不平或身份无法解析均失败关闭。
  • 合法空窗的 manifest factCount=0，但不向事件事实表写 sentinel；global 累积事实 release 的总记录数可以非零。
  • 长窗口由多个含端日期区间的无缝并集证明；任意一天缺口都返回 PARTIAL / SOURCE_UNAVAILABLE，而不是 AVAILABLE 空页。
  • 存在重叠观察时，以请求边界、coverageFrom 和 coverageTo + 1 切成不重叠 slice，每个 slice 选择当时最新的 coverage；旧宽窗只能补缺口，不能吞掉新纠错窗。
  • 每个 slice 只用自己的 coverage 知识时间读取该日期片的事实，禁止把全窗最大 cutoff 套到其他旧 slice；响应 knowledgeCutoff 报告实际使用证据的最大时间。
  • 实际选中 slice 的 coverageVersion、slice 范围、事实 publication 与 identity version 一起生成 composite dataVersion 和 ETag；新增空窗或纠错窗都必须改变条件读取结果。
  • knownAt 只选择当时已创建且未被当时 supersede 的 coverage；events/query 与 data-status 共用同一事实选择器、来源和方法学投影，不能用一个宽窗的总 recordCount 推断其中某日非空。

K 线窗口 coverage

  • 只在 SSE/SZSE 形成有效来源批次后建立 K 线/复权 coverage。BSE 尚未形成该 coverage；任意 BSE bars/factor 请求都返回 SOURCE_EXCHANGE_UNAVAILABLE 或 coverage-unavailable，不得写 ZERO_RECORD_COVERAGE。
  • 每个 bars 响应按 securityId + identifierVersionId + period + [start,end] + dataVersion 精确选择一个 current、passed 且与 publication dataVersion 完全相等的 coverage；旧身份版本、旧 dataVersion 或窗口不完整均失败关闭。
  • DATA coverage 的事实行数必须与 manifest 一致；ZERO_RECORD_COVERAGE 才能返回空 items。无 coverage、错窗口或行数不符返回 409 coverage-unavailable，不把 legacy availability 或来源失败诊断伪造成空行情。
  • 成功响应始终携带 coverageVersion、publicationKind、sourceBatchId 和 dataVersion；API/Web 用它们显示可审计 lineage，并将其纳入分页链一致性检查。

无 publication

内部 reader 返回稳定 publication-unavailable，包含 dataset、partition、 availability、reasonCode、observedAt 和可选 lastGoodPublication；不返回 200 空列表， 因为“没有发布”与“发布后查询为空”不是同一业务事实。

publication 事实选择：质量状态为通过、sourceBatch/raw/object 摘要或失败证据、manifest 与 coverage 可追溯，且 current pointer 由真实运行原子提交时，reader 才可把 AVAILABLE 交给 service-api。否则按数据集返回 NO_PUBLICATION、PARTIAL、STALE_LAST_GOOD 或 SOURCE_UNAVAILABLE，不把观察值或半成品 revision 当事实。

7. service-data-sync 内部读取契约

本方案同时是已实施 internal v1 reader 的评审基线；service-api 使用 service bearer、 request id、超时和严格 schema 校验。遵守任务约束，本轮不创建 OpenAPI 文件；后续治理记录只能 additive。 internal reader 只返回来源绑定完整、质量通过且与请求 dataVersion 一致的真实 publication； 未发布观察、隔离 revision 与运维证据不会投影给 service-api。

Cursor 与排序

  • cursor 为 data-sync 签发的 opaque base64url；内部包含 contractVersion、dataVersion、filterHash、sort tuple 和 HMAC。
  • 允许排序字段固定：symbol、name、close、changePercent、amountCny、turnoverRate、totalMarketCap、floatMarketCap、peTtm、pb；资金流排序和筛选当前稳定拒绝。
  • 所有排序追加 exchange、symbol 和内部行锚点作为稳定 tie-breaker；锚点只在 HMAC 签名 opaque cursor 内使用，不进入公开正文；nulls 固定 LAST。
  • cursor 的 dataVersion、filterHash 或 sort 不匹配返回 409，禁止悄悄从第一页继续。

8. 生产运行禁止假数据

强约束：fixture、mock、fake adapter、demo seed 只允许存在于 tests/ 或显式 test profile。staging/production 的配置校验、发布门和 E2E 必须共同证明数据来自已登记真实来源批次。
  • 非 test 环境启动时拒绝 providerId、adapter class 或 source policy 中含 fake、fixture、demo、sample。
  • 每条可发布 revision 必须有非空 sourceBatchId，可追溯 provider、upstreamSource、observedAt、adapterVersion 和 schemaFingerprint。
  • 可读事实由 sourceBatch、coverage、质量结果、冻结 manifest 与原子 current pointer 共同判定；代码、adapter 名称、单次 probe 或手工标记均不能替代这些证据。
  • discovery 每个非派生值必须绑定 component dataVersion；派生值必须绑定公式版本与输入版本。
  • 真实来源返回空集只能成为 LEGITIMATE_EMPTY，必须有完整请求证据与覆盖判断；异常响应不能转换为空集。
  • 验收环境不执行 demo seed；首发通过真实全量命令生成，并随机抽样回溯到 source batch。
  • 未完成质量或方法学校验的观察只保留在隔离/运维证据域；不可被 internal reader、service-api 或 service-web 当成已发布数据或 sourceLabel。
  • 单元和契约测试可用 fixture，但测试报告不得作为生产数据可用性证据。

9. 性能、可靠性、观测与恢复

全量规模按 6,500 只证券、30+ 年日线、全报告期设计；数据按证券/年份切片，禁止单事务全市场写入。
横截面规模单 dataVersion 约 6,500 行；构建内存目标 ≤ 512 MiB，使用 server-side cursor 与批量 COPY/upsert。
查询目标发现列表 P95 ≤ 250 ms、P99 ≤ 600 ms；默认 50、最大 100，压缩响应 ≤ 512 KiB。
发布延迟EOD 必需组件目标在收盘后 120 分钟内完成；不承诺盘中更新。
保留成功 raw 按 0030 策略不长期重复留存；失败证据、manifest、revision、publication 永久审计。
回滚切换到上一 discovery dataVersion ≤ 5 分钟；不删除新 revision，保留复盘证据。

指标与告警

  • sync_run_duration_seconds、source_request_total、source_retry_total、quarantine_total，均按 dataset/provider/reason 标注。
  • publication_lag_seconds、publication_coverage_ratio、discovery_build_duration_seconds、discovery_diff_ratio。
  • 告警：必需组件超过 SLO、连续 3 次来源失败、schema fingerprint 变化、覆盖率下降、异常大版本差异、fence 冲突。
  • 日志只记录内部 ID、dataset、partition、run/attempt、requestId；不记录 bearer、完整响应体或个人数据。

10. 实施顺序、发布与回滚

PHASE 0

契约与控制面落座

任务禁止新增 ADR/OpenAPI；以服务内 strict schema 与契约测试固化边界，将股票中心写任务接入既有 0031 全局 fence，并保持非 test 假数据路径关闭。

校验：架构测试与 POST/GET 边界固定
PHASE 1

缺失 canonical 数据链

实现普通停复牌、申万 membership、历史股本及专用事件身份 reader；完成 migration、adapter、CLI/Celery、质量与 publication。

校验：真实 probe + replay + integration
PHASE 2

全量历史首发

先封存身份 reference bundle，再按已有来源 coverage 回填 bars、factor、action 与 events；BSE K 线/复权在尚无 coverage 时固定返回来源不可用。profile、financial、valuation、memberships、share capital 作为独立 CURRENT_AT_EXECUTION refresh，记录自己的 observedAt 与 dataVersion，绝不写入历史 sealed plan。资金流在方法学与来源批次完成前不进入首发。

校验：交易所 frozen source matrix、非空原始响应、全市场覆盖清单无未解释缺口
PHASE 3

Discovery 构建与内部 API

生成同日冻结横截面、component manifest、availability 与索引；实现三条内部查询并完成 cursor/ETag/回滚测试。

校验：BASE 全身份 publication；可选组件 PARTIAL 可解释 + 性能预算
PHASE 4

三服务真实 E2E 与排程

API 和 Web 只读本次封存的真实 publication；人工比对来源样本、质量、容量和 API/Web E2E，通过后启用收盘后增量 schedule，最后部署包含股票中心入口的 Web 版本。BSE K 线/复权尚无 coverage 时固定返回来源不可用，而非等待未来 probe 后暗中放开。

校验：无 fixture 请求、无跨库、无 N+1、无未验证交易所冒充全量、容量通过

回滚

  • 先回滚到上一 Web 构建产物，再关闭 discovery 增量 schedule；现有单数据集 API 保持可用。
  • 将 equity.discovery.eod 当前指针切回上一通过版本，不删除被撤回版本和源 revision。
  • 新 adapter 单独通过 source policy 关闭；关闭不会触发替代来源或空 publication。
  • 数据库 migration 在未写入生产数据时可 downgrade；已有数据时优先前向修复和指针回滚。

11. 可执行验收标准

  • 三所目录中的每只证券都出现在全量覆盖清单，身份冲突为 0。
  • 普通停牌、暂停上市、退市三个概念在模型、API 和页面文案中互不混用。
  • 仅 SSE/SZSE 的日/周/月线来自原生上游周期；复权窗口能回溯 bar/factor 两个 dataVersion。BSE K 线/复权固定 fail closed，不能出现空 coverage 或替代序列。
  • 股本历史来自真实 Eastmoney 股本结构，市值可以从同日 close 与有效股本重算。
  • 申万三级成分通过真实接口同步；每条归属能回溯 source batch，不用公司概况行业文本替代。
  • 财务与估值的 provider/methodology/version/knownAt、sourceBatch 与 coverage 完整，平台派生指标保留输入 manifest；资金流在方法学和 EOD 批次未完成时明确 UNAVAILABLE，筛选、列、排序失败关闭。
  • 龙虎榜、大宗交易、预告和快报按 exchange+symbol 可读，内部 UUID 不泄漏给公开层。
