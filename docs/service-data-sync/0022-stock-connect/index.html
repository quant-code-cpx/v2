Service Data Sync · Technical Proposal 0022

沪深港通市场数据技术方案

建议接入交易所披露的沪股通、深股通与两路港股通日终统计、成交活跃证券和持股快照， 但按方向、通道、披露制度和时间粒度分离发布。北向净买与日频持股在 2024 年披露调整后 不再是连续可得事实；任何缺失、占位零、供应商“资金流入”或估算增持都不得补成连续官方序列。

1. 结论与优先级

问题

同名“资金”跨制度并不连续

北向、南向、沪股通、深股通、港股通沪、港股通深同时混合方向、通道、币种、 成交流量、额度与持股存量。2024 年披露机制变化又改变了字段和频率。

推荐

官方事实优先，三类数据隔离

分别发布通道级成交统计、成交活跃证券、持股快照；交易所官方来源为主， AKShare/东方财富只做研究与缺口诊断，不作为无条件生产主源。

最大风险

把未披露映射为零

固定版本探针显示北向历史在新规后仍有日期行，但买入、卖出、净买字段为 NaN；即时汇总却返回 0。若写成真实零值，会系统性污染因子和回测。

优先级 能力 接入结论 消费者价值 关键边界
P0 官方日终通道统计、前十大成交活跃证券、互联互通交易日历 建议接入 市场热度、通道成交、南向买卖结构、事件研究、仪表盘 2024-08-19 前后方法学分段；北向新规后只保留总成交，不制造买卖/净买
P1 南向日频持股、北向季度持股、历史官方文件回补 条件接入 机构持仓、拥挤度、跨境配置、point-in-time 暴露 北向季度末仓位在季度后第 5 个北向交易日才可见；港股身份必须先无歧义解析
P2 东方财富历史“资金流入”、累计净买、持股市值、排行与增持估计 不建议生产接入 仅用于来源研究、断点诊断、方法学对照 语义、授权、披露断点和估算方法未闭环；不得与官方序列拼接

推荐答案 以 SSE/SZSE 主场官方披露承接各通道当前事实，以 HKEX 官方日历和获授权历史文件承接跨市场日历、对账与回补。 所有来源经独立 adapter 进入 provider-neutral port；未确认许可或稳定性的能力保持 research，不阻断其他官方能力实施。

2. 业务价值、目标用户与边界

目标用户

  • 量化研究员：构建不含未来信息的跨境成交、持仓和拥挤度因子。
  • 投资分析用户：观察北向/南向通道活跃度与重点证券。
  • 数据运营：监控披露延迟、字段断点、历史缺口和来源修订。
  • API 消费者：按通道、方向、日期、证券和可见时间查询已发布数据。

核心场景

  • 比较沪股通与深股通总成交，不把其错误称为净流入。
  • 分析两路港股通买入、卖出、总成交与前十大证券。
  • 按真实披露时间重建北向季度持股和南向日频持股。
  • 识别 2024 年制度断点，阻止跨制度回归和排名静默混算。

非目标

  • 不提供交易建议、实时逐笔、订单流或投资者身份数据。
  • 不把额度余额、资金净流入、成交净买和持仓变化视为同一指标。
  • 不在本专题定义跨资产证券主表、日历表、来源表或 publication 支撑表。
  • 不修改生产代码、迁移、OpenAPI、配置、依赖或 Docker。

事实、推断、建议、未决的标记

事实来自交易所规则、官方页面、AKShare 文档或固定版本探针； 推断由多项事实推导但尚无生产证据； 建议本方案拟议设计； 未决需后续技术、合规或消费契约验证。

与现有系统的关系 复用 0014 证券身份与上市生命周期 的日期感知 A 股身份解析，复用 0017 日频资金流 的方法学隔离、raw evidence、revision、quality、publication 与 knownAt 读取模式；不复用其供应商资金流语义。

3.3 交易日历与节假日

  • 事实 2023-04-24 起日历增强，使互联互通可在香港与内地市场共同开放的交易日运行； 清算仍有 H-1 等安排，不能只取 A 股或港股单一日历。
  • 建议 每年导入 HKEX 官方 Stock Connect CSV/PDF，按 direction + connect_venue + trade_date 校验；交易状态公告可形成更正观测，但本专题不自行定义共享日历物理表。
  • 建议 缺少数据行不能推断休市；只有官方互联互通日历或临时停市公告能把分区标为 NOT_SCHEDULED。
  • 事实 上海与香港当前均为 UTC+8 且无夏令时；业务时区仍需分别保留 Asia/Shanghai 与 Asia/Hong_Kong，因为交易时段和日历不同。 瞬时时间统一按 UTC 存储，展示与交易日归属必须按对应市场业务时区换算。

5. 粒度、身份、时间与修订语义

5.1 三类数据绝不静默混算

reported_turnover

通道成交流量

粒度为通道 × 方向 × 统计周期。买卖、总额、笔数是交易所披露的成交事实； 南向可计算净买，北向断点后不可。

position_snapshot

证券持股存量

粒度为通道 × 方向 × 持仓日 × 证券。是时点库存，不是当日成交流； 北向季度、南向每日。

security_turnover

个股成交明细

粒度为通道 × 方向 × 统计日 × 证券，当前仅纳入官方前十大； 不用行情总成交冒充互联互通成交。

5.2 候选实体身份与唯一键

实体 领域身份 候选事实键 修订键 身份失败处置
通道统计 connect_venue + direction venue + direction + statistic_period + period_end + methodology_id 事实键 + revision_no / 知识时间区间 未知通道、方向或币种整分区隔离
成交活跃证券 共享证券身份 + 事实日期 venue + direction + period_end + instrument_id + methodology_id 事实键 + revision_no 代码不解析、代码复用冲突或榜单重复时隔离
持股快照 共享证券身份 + position date venue + direction + position_date + instrument_id + methodology_id 事实键 + revision_no 不创建专题私有证券；A 股走现有 resolver，港股待统一身份模型

上述为候选逻辑键，不是最终 PostgreSQL DDL。跨专题共享的证券、来源、批次、质量、publication、 checkpoint 与日历结构由统一 canonical data model 方案定义。

visible_at 消费者最早可见时刻 可信 published time 与首次 observed time 的较晚者 同左；北向季度不得早于第 5 个北向交易日披露 knownAt < visible_at 时必须不可查询
effective_from / effective_to 市场事实有效区间，结束不包含 通常覆盖对应统计周期 该快照代表的仓位时点，不推断到下一快照 不得用下一快照倒填中间日期
known_from / known_to 系统知识版本区间，结束不包含 修订追加新知识版本 修订追加新知识版本 旧版本保留，支持重建当时所知
revision_no 同一事实键的单调修订序号 内容变更才递增 内容变更才递增 后见更正不覆盖旧记录
data_version 冻结 publication 的稳定消费者版本 分数据集/分区生成 分数据集/分区生成 游标和缓存必须绑定该版本
可见时间保守规则 若来源不给可信发布时间，visible_at = first_observed_at。历史文件在 2026 年回补 2018 年事实时，不能把 visible_at 写成 2018 年；否则会把后获得的数据送入过去回测。

5.4 空值、零值与无行

表现 语义 例子 消费者处理
数值 0 来源在当前披露制度下明确报告真实零 某南向通道实际无成交，官方报告总额 0 可参与计算

6.5 关系与共享基础设施需求

  • 三张领域表都引用共享的来源批次、方法学、质量结果和 publication，但不在本专题重复定义。
  • 活跃证券与持股引用共享证券身份；A 股沿用既有日期感知解析，港股身份由统一模型补齐。
  • 市场统计 publication 与前十大榜单 publication 应绑定同一来源批次或声明关联批次，防止跨日混版。
  • 持股 snapshot 不与市场统计同事务强绑定；其披露频率、到达时间和失败边界不同。
  • 数据版本按 dataset + venue + direction + period/frequency 独立推进，任一路失败不污染其他稳定版本。

7. 同步模式、分区、幂等、回补与恢复

7.1 任务定义

任务 触发与新鲜度建议 分区 增量/回补 消费者
P0 日终市场统计 官方 Stock Connect 交易日；收市后延迟执行，HKEX 文件说明约 18:00；实际发布时间待探针校准 dataset/venue/direction/trade_date 每日增量；最近 5 个交易日滚动重拉接收更正；历史按月有界回补 市场概览、跨境成交因子、API
P0 前十大成交活跃证券 与对应市场统计同批或紧随其后 dataset/venue/direction/trade_date 每日增量；与统计批次一起回补 活跃榜、个股事件研究
P1 南向日频持股 港股通交易日收市后；发布时间由连续探针校准 dataset/venue/SOUTHBOUND/position_date 每日完整快照；最近 5 日滚动重拉 持仓、拥挤度、机构配置
P1 北向季度持股 季度末后第 5 个北向交易日；当日披露后抓取 dataset/venue/NORTHBOUND/quarter_end 季度完整快照；历史按季度回补 季度持仓、point-in-time 因子
P0 日历 每年官方日历发布/修订后；运行前按年加载 calendar_year 全年快照；公告修订追加版本 所有任务准入

7.2 正常写入顺序与事务边界

  1. scheduler 或受控 CLI 以中立 partition 创建 run，获取同分区租约；不在任务中导入 SDK。
  2. adapter 拉取唯一来源，返回标准载荷与原始响应；供应商 URL、字段、认证和错误留在 adapter。
  3. 先把 raw payload 写入 S3/MinIO，记录 SHA-256、schema fingerprint、adapter version 和 observed time。
  4. decoder 验证通道、方向、日期、披露制度、单位与逐字段 availability，不进行跨来源补洞。
  5. 证券级数据按事实日期调用共享 identity resolver；未解析记录进入 quarantine。
  6. 单个分区事务写入来源观测引用、domain revisions、quality results 和 candidate publication。
  7. 全部阻断规则通过后原子推进 publication 与 checkpoint；任何失败保持上一稳定版本。

7.3 幂等、并发与重复

幂等键

run 键为 capability + provider_policy + partition； canonical 内容键为事实键 + 方法学 + 规范化内容 hash。 相同内容重跑不创建新 revision 或 dataVersion。

观测不折叠

每次外部拉取仍是独立 source observation；相同 raw 字节可按 hash 复用对象， 但必须保留每次 observed time、HTTP 元数据和 run 关系。

并发锁

同 dataset/venue/direction/date 只允许一份写租约；租约含过期时间和 fencing token。 僵尸任务不能在新任务发布后推进旧 checkpoint。

7.4 错误、重试和部分成功

失败 分类 重试 结果
超时、连接重置、HTTP 429/5xx retryable 指数退避 + 抖动，最多 3 次；尊重 Retry-After 不推进 checkpoint；耗尽后 failed
鉴权/权益失败 terminal_for_policy 不自动重试 该 provider capability 停止；其他官方能力继续
schema 漂移、单位未知、制度不匹配 terminal_data 不重试同一载荷 raw 保留、整分区 quarantine
单只证券身份失败 partial 身份修复后 replay 对完整榜单/持股快照默认阻断 publication，不静默丢行
一个通道失败 partition_failure 仅重试该分区 其他 venue/direction 可独立发布；聚合查询不得混新旧
数据库事务失败 retryable_if_safe 从已归档 raw replay 事务回滚，publication/checkpoint 不变

7.5 历史回补与不可比边界

  • 回补按来源产品许可、通道、方向、月份拆分；每批有明确起止日期和最大页数。
  • 沪港通启动前、深港通启动前不创建零记录；标为 capability 尚未存在。
  • 2024-05-13 与 2024-08-19 两个断点两侧使用不同方法学版本，不做平滑、插值或连续累计。
  • HKEX 获授权历史文件、SSE/SZSE 页面和东方财富同日值分别保存来源身份；没有等价证据不拼接。
  • 北向日频持股历史到 2024-08-16 后直接结束；之后接季度快照时标注频率断点，不前向填充。
  • 南向两路通道只有在币种、position date、证券身份、范围和披露时间全部一致后，才可另建派生汇总。

7.6 恢复、回滚与保留

  • raw replay：按 source batch hash 校验后重新 decoder/quality，不访问上游。
  • publication rollback：只把消费者指针切回已通过质量的旧 dataVersion；不删除新 revision 或 raw。
  • checkpoint repair：只能从已验证 raw 与事务账本重建；禁止人工改业务表日期或伪造成功。
  • 来源字段/单位修复：发布新 adapter/methodology version，全量 replay 受影响分区并保留旧知识版本。
  • 保留期由统一模型与许可决定；在修订和审计周期未冻结前，不清理已被 publication 引用的 raw/revision。

8. 数据质量、时序防未来函数与可观测性

8.1 质量规则

8.2 明确排除的未来函数与事后字段

禁止进入可回测事实

  • 季度末北向持股在第 5 个北向交易日前的任何可见性。
  • 后续修订值回写到原 trade/position date 并覆盖旧版本。
  • 回补时把 2026 年 observed time 伪造成历史 published time。
  • 未来 1/5/10 日市值变化、滚动增持排行或事后领涨股表现。
  • 下一持股快照反推前一日至下一日之间每日仓位。

禁止口径混淆

  • 把成交净买、资金净流入、额度余额和持股变化当成同一“资金流”。
  • 把 CNY 北向与 HKD 南向金额直接相加。
  • 把日频持股与季度持股拼成等频连续序列。
  • 把公司行动造成的持股数量跳变解释为买卖。
  • 用东方财富字段补官方未披露的北向买卖拆分。

8.3 状态与处置

状态 含义 可否 publication
passed 所有阻断规则通过，字段 availability 与制度一致 可以
warned 跨源差异、到达延迟等非破坏性异常，事实仍完整 按 policy 可发布并显式返回质量状态
quarantined schema、单位、身份、完整性、制度字段或时序失败 不可
research 方法学、许可或生产稳定性未通过 公开 API fail-closed

8.4 指标、日志与告警

  • 日志关联 task_id/run_id/batch_id/partition/provider/methodology/data_version，不记录 token 或完整 raw。
  • 指标：分区成功率、到达延迟、schema fingerprint 变化、字段 availability、quarantine 数、身份失败数。
  • 指标：榜单行数、持股覆盖证券数、交易日缺口、修订次数、同内容幂等命中率。
  • 告警：官方交易日 T+1 仍无 P0 publication；北向隐藏字段被写成非空/零；单位或币种突变。
  • 告警：北向季度持股在预期披露日后仍缺失；南向日频覆盖率较前一日异常下降超过待校准阈值。
  • 阈值需在 shadow 连续样本后冻结；未校准阈值只产生诊断，不以猜测值阻断全部能力。

  • 所有 public operation 只能声明 POST；查询参数可在 JSON body，禁止新增 GET 路由。
  • start/end 为包含端；日频默认最大 366 日，扩大窗口需更高权限或异步导出另案。
  • 默认 limit 100，最大 500；游标不透明且绑定全部筛选、sort、fields、knownAt 与 dataVersion。
  • 排序仅允许白名单：日期升/降序、rank 升序、持股数量升/降序；稳定次序追加证券身份。
  • knownAt 选择系统当时所知；asOf 选择市场有效切片；二者不得混为同一时间。
  • 字段选择不能隐藏解释字段：currency、unit、availability、methodologyVersion、source、qualityStatus、visibleAt、dataVersion 必须保留。
  • 条件读取沿用 POST-only 决策：ETag 命中返回 204；下游 internal GET 的 304 不直接暴露。

9.3 鉴权、权限与失败映射

主题 需求
认证 默认有效 Bearer Session；禁止匿名和 @Public()
授权 至少 market-data:stock-connect:read；历史深度或持股横截面可按数据许可细分 scope
限流 按用户、IP、路由、日期窗和返回行数计费；横截面持股比单证券查询更严格
缓存 只缓存已发布 dataVersion 的私有投影；Redis 不成为行情权威存储
下游失败 timeout/schema drift/unavailable → 503 Problem Details；无未标记 stale fallback
数据不存在 合法查询无事实 → 404 或空页按最终契约统一；NOT_DISCLOSED 字段仍返回空值和状态
版本冲突 旧 cursor/dataVersion 不匹配 → 409，客户端从第一页重启
审计 记录 actor、route、范围、rows、dataVersion、requestId；不记录 token 和大 payload

9.4 最新与 point-in-time 能力

  • 通道统计、活跃榜：支持 latest 与 knownAt 历史视图。
  • 持股：必须支持 positionDate + knownAt；否则不能用于可信回测。
  • 供应商 research 字段：公开 API 不可见；internal 运维诊断另由授权合同决定。
  • 响应免责声明需说明披露频率、2024 断点、币种、数据仅供参考且不构成投资建议。

11. 实施路线、回滚与验收

11.1 分阶段路线

  1. P0-A：制度与 source contract 冻结。 固定官方字段、披露断点、币种、单位、日历、许可范围和 adapter 中立载荷； 对 2024 断点前后建立 fixture。退出：G1、G5 的目标 P0 capability 通过。
  2. P0-B：日终统计与活跃榜 shadow。 只写 raw/candidate/quality，不对消费者发布；连续观察到达时间、缺行、修订、限流。 退出：G4、G6 通过。
  3. P0-C：受控 publication 与内部读取。 按 venue/direction 独立发布；内部契约返回 dataVersion、来源、方法学、质量和 visible time。 退出：契约测试、point-in-time 查询和回滚演练通过。
  4. P1-A：持股快照。 先南向日频，再北向季度；完成港股身份、公司行动边界和披露延迟验证。 退出：G2、G3 通过。
  5. P1-B：授权历史回补。 按制度分段、按月/季有限回补；返回 coverage，不追求伪连续。 退出：抽样对账、幂等、恢复、容量和索引计划通过。
  6. P2：供应商研究。 仅在业务明确需要且方法学、许可、稳定性全部闭环后再另案；当前不进入生产路线。

11.2 回滚策略

  • 来源异常：关闭该 provider policy，保留上一稳定 publication；不把次源自动升为同一方法学。
  • schema/单位错误：隔离新 batch，回滚 publication 指针；修复 adapter 后从 raw replay。
  • 身份错误：冻结证券级 publication，修复共享 identity 后 replay；不改写历史外键。
  • 公开 API 错误：service-api 关闭投影或回滚 client；data-sync raw/revision 保留。
  • 制度解释错误：创建新 methodology/revision 并重放受影响范围；旧 dataVersion 继续可审计。

11.3 验收清单

文档与设计验收

  • 事实、推断、建议、未决可区分。
  • P0/P1/P2、接入/不接入结论明确。
  • 来源、真实上游、函数、字段、单位、历史、许可和限流有记录。
  • 三类数据粒度、唯一键、空值和修订语义完整。
  • 2024 披露断点和未来函数防护可执行。
  • 技术门禁与非技术风险分离，四要素完整。
  • 本地链接、外部引用、访问日期和待决项完整。

未来实现验收（计划执行，未运行）

  • 固定 adapter fixture 覆盖断点前后与全部通道。
  • 同分区双跑不新增 revision/dataVersion。
  • provider timeout、429、空响应、schema drift、DB 失败可恢复。
  • 北向占位零不会成为真实数值。
  • knownAt/visibleAt 测试证明历史回补无未来可见性。
  • 内部/公开 contract test、游标、ETag、503/409 路径通过。
  • Docker Ruff、Pyright、pytest、架构测试、迁移和两服务构建通过。
