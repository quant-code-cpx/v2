1. 摘要

问题

当前值不能回答历史

P0 equity_instrument 只有当前名称和单值状态；行情可先建 PENDING，但没有目录同步、状态证据、有效期或知识时间。

决策

保留身份锚 + 双时间历史

保留现有 equity_instrument 及其 BIGINT/UUID 身份， 标识、名称、上市状态各自追加双时间版本；目录与显式生命周期来源独立取证、校验、发布。

最大风险

来源语义与生产许可未定

AKShare 接口存在超时、TLS、空结构和字段误名。方案可实施，生产 source policy 必须等许可、 字段语义与连续稳定性评审。

不可违反的不变量 上市目录中暂时缺少一只证券，只能形成“缺席观测/质量异常”；不能关闭 LISTED， 不能写 DELISTED。退市必须来自显式退市来源，并通过身份、日期、语义和批次完整性质量门。

2. 目标、非目标与任务定义

目标

  • 覆盖 SSE、SZSE、BSE A 股身份、交易所、六位代码和名称修订。
  • 表达 LISTED、SUSPENDED、恢复为 LISTED、DELISTED 及后续更正；未知/未确认仅为内部 PENDING，不对外发布。
  • 支持 asOf 市场有效时间与 knownAt 知识时间。
  • 为行情、公司行动、财务和板块成份提供唯一内部证券解析。
  • 提供可分页、版本绑定的 internal/public API。

非目标

  • 不提供分钟行情、实时盘口或普通交易停牌状态。
  • 不按名称、代码前缀或行情缺失推断退市。
  • 不让 adapter 写 canonical DB，不让 API 直连同步库或供应商。
  • 不在 service-api Prisma/Redis 保存权威证券副本。
  • 不在本方案批准生产数据许可或最终交易日历。

依赖与消费者

  • 上游：按交易所目录、显式生命周期来源、raw object store。
  • 下游：个股行情、板块成份、公司行动、财务、service-api。
  • 时区：Asia/Shanghai；知识时间保存 UTC timestamptz。
  • 日历：权威来源待决；未冻结前不得据日期缺口自动改状态。

4. 功能划分与所有权

Provider adapter

来源隔离与字段映射

职责：调用单一上游，保存其接口/字段/错误知识，输出 provider-neutral batch。

输入 / 输出：exchange、snapshot kind、目标日 → raw payload + 标准候选行。

状态：无 canonical 状态；不能写 PostgreSQL。

失败边界：超时、限流、TLS、空响应、schema drift 映射为中立错误。

Master application

身份解析、质量与发布

职责：归档 raw、解析 PENDING、做差异和质量门、追加双时间版本、原子发布。

输入 / 输出：标准候选批次 → exchange/aggregate dataVersion。

状态：run、checkpoint、snapshot、identity、history、quality、publication。

失败边界：分区隔离；不改变上次已发布版本。

Internal read API

版本化 canonical 投影

职责：按 asOf/knownAt 查询已发布身份、名称、状态和历史。

输入 / 输出：服务凭据 + 查询 → ETag/dataVersion/cursor JSON。

状态：只读；不公开 raw、PENDING、quarantine 或 DB 行。

失败边界：无稳定聚合或读库故障返回 503。

service-api

用户访问投影

职责：JWT、授权、DTO、限流、下游 client、Problem Details、字段最小化。

输入 / 输出：公开 exchange+symbol → internal HTTP → 公共 JSON。

状态：无证券权威 Prisma 表；Redis 只可放短期防滥用计数。

失败边界：下游超时/合同漂移统一 503，不泄漏 internal UUID。

行情与公司行动

身份消费者

职责：以 `security_id` 关联，历史数据不因退市删除。

输入 / 输出：exchange+symbol → 已确认或 PENDING identity。

状态：各自数据集；不能反向改主数据状态。

失败边界：未解析身份隔离，不按名称关联。

板块成份

发布依赖

职责：只发布能解析到已确认证券的成份关系。

输入 / 输出：来源成员代码 → master identity。

状态：成份有效期独立；不拥有证券名称或上市状态。

失败边界：PENDING/冲突成员进入隔离，不创建公开幽灵证券。

5. 同步、幂等、恢复与修订

5.1 Provider-neutral port

EquityMasterSource.fetch_catalog(
  exchange,
  target_date,
  request_context
) -> MasterSnapshotBatch

EquityLifecycleSource.fetch_explicit_lifecycle(
  exchange,
  window,
  request_context
) -> LifecycleEvidenceBatch

MasterSnapshotBatch:
  raw_payload
  upstream_source_id
  adapter_version
  schema_fingerprint
  observed_at
  rows[exchange, symbol, name, listed_on, candidate_status?, effective_date?]

AKShare 函数名、URL、中文源字段和异常类型只在 adapter。application 只理解标准 exchange、symbol、 name、日期、证据类型和完整性；provider-neutral 不抹除 upstream source 与 adapter version 血缘。

5.2 正常全量目录流程

  1. CLI/调度创建 sync_run，为 SSE、SZSE、BSE 建三个 partition；每个分区单独领取 15 分钟 lease，30 秒心跳。
  2. adapter 获取完整响应。每次网络观测都创建独立 source_batch；即使 payload hash 相同也不折叠观测。
  3. 先把原始字节写对象存储；对象内容可按 SHA-256 去重，但多个 batch 可以引用同一 raw URI。
  4. 标准候选行写 snapshot staging；保存 schema fingerprint、adapter version、upstream source、observed_at、行数。
  5. 执行 schema、代码、唯一性、数量变化、身份冲突、日期和来源完整性质量门。
  6. 在分区事务与 advisory lock 内按事实日期解析标识：已有 PENDING 保留 security_id，关闭其占位知识版本并追加主数据已确认版本；新证券建立 UUID；代码复用绝不按名称合并；名称/状态只追加变化版本。
  7. 写 exchange publication 与 checkpoint 后提交。相同业务哈希不新增事实版本，但仍保留本次 source batch 观测。
  8. 协调器确认三所同一 target run 全部成功后，写 child version manifest 并原子推进 equity.master.cn-a。

5.3 差集与状态转换

输入情形允许动作禁止动作
完整目录出现新代码 新建或确认 PENDING；可靠在册/上市证据通过后写标识、名称和 LISTED 版本。 按名称合并另一证券。
同代码名称变化 有官方生效日则用官方日；否则从观测日开始且标 OBSERVATION_DATE。 回写覆盖旧名称；猜测历史生效日。
历史代码被新证券复用 关闭旧证券标识有效期，以明确生效日为新证券追加标识版本；标识历史排斥约束决定唯一身份。 按相同代码或相似名称合并证券；从 equity_instrument 当前列直接取第一行。

显式恢复上市证据 关闭暂停区间并追加 LISTED。 从重新出现于目录自动推断历史恢复日。
显式退市证据 四道门通过后追加 DELISTED；历史行情继续保留。 从名称含“退”、发现源或目录差集推断。

5.4 分区、幂等、锁与 checkpoint

  • 请求幂等键：capability:exchange:snapshot_kind:target_date:mode:request_revision； 重复提交复用 run 结果，显式 --revision 才创建新请求。
  • 观测身份：source_batch_id 每次获取唯一；不能用 payload hash 当观测幂等键。
  • 事实幂等：标准业务内容 SHA-256 相同则不追加 identity/name/status version，也不推进该分区 dataVersion。
  • 并发：同 capability+exchange+target 只有一个有效 lease；发布事务再用 PostgreSQL advisory xact lock 防双提交。
  • checkpoint：记录最后成功 target、publication UUID、lifecycle watermark、schema fingerprint； 仅与 publication 同事务推进。下载成功但发布失败不能越过 checkpoint。
  • 超时与取消：worker 软超时 10 分钟、硬超时 12 分钟为首期运行默认值；平台评审可调整。 取消只停止未提交分区；已提交 publication 不回滚。

5.5 重试、失败与恢复

可重试

连接、TLS、读取超时、429、5xx：最多 3 次，指数退避 2/8/30 秒加全抖动；尊重 Retry-After。

终止 / 隔离

鉴权、非法参数、字段缺失、schema drift、重复身份、语义冲突：不盲重试，partition 标 failed/quarantined。

恢复

repair --run-id --partition --reason 从最后未提交 checkpoint 重跑；复用已归档 raw 时创建新的 repair batch 关联原对象。

  • 状态：queued → running → succeeded | partial | failed | cancelled；quarantine 是质量处置，不伪装成功。
  • DB 失败：事务全回滚，source batch/raw 保留，checkpoint 不动；重跑可从 raw 标准化，无需再次请求供应商。
  • schema drift：保存 raw、fingerprint 和最小样本，阻断 publication；adapter fixture 更新并评审后 repair。
  • 部分失败：成功交易所可推进自身版本；全市场 aggregate 保持上一稳定 child version 集合。首次无稳定集合返回 503。
  • 回补：按 exchange + lifecycle 年份/窗口从近到远；历史更正追加新的 knowledge version，不覆盖旧行。

6. 身份、状态机与双时间语义

市场有效时间

effective_from 包含、effective_to 不包含。官方明确日期使用 OFFICIAL_DATE；只有首次观测日时使用 OBSERVATION_DATE，禁止回填猜测。

系统知识时间

known_from 包含、known_to 不包含；修订到来时关闭旧知识版本并追加后继。 observed_at 保留来源观测时刻，不等于生效日或发布时间。 

PENDING（内部占位，不发布）
   └─ 明确在册/上市证据 ▶ LISTED

LISTED ── 明确暂停上市 ─▶ SUSPENDED
SUSPENDED ── 明确恢复 ─▶ LISTED
LISTED / SUSPENDED ── 明确终止上市 ─▶ DELISTED

DELISTED 为市场事实终态；只有官方更正 + 人工审批可产生新的知识版本。
普通停牌、目录缺席、行情缺席、名称文本均不触发任何箭头。

当前没有通过验证的预上市权威来源，因此不新增 PRELISTED。本方案的 SUSPENDED 严格表示交易所明确的暂停上市，不表示普通停牌。

查询语义

  • asOf=D：选择 effective range 包含 D 的标识、名称和状态。
  • knownAt=T：只选择 knowledge range 包含 T 的版本，避免回测看到后来修订。
  • 列表未传 asOf 时使用所选 publication 的 effective date；未传 knownAt 时使用其 knowledge cutoff，不使用 API 进程当前时间拼接。键式接口的 asOf 缺省规则见下一条。
  • 键式详情/历史未传 asOf 时，只解析当前知识下 effective_to/known_to 均为空的唯一开放标识； 没有开放标识返回 404。代码已被复用时，该规则返回当前证券；读取旧证券必须显式传 asOf。
  • 传入 asOf 后没有匹配身份返回 404；底层历史若异常地解析出多只证券则返回 409 并阻断发布， 不按名称、状态或任意排序挑选一只。
  • 列表 cursor 绑定 filters、asOf、knownAt、sort key 与 dataVersion；版本失效返回 409，不跨版本续页。

标识解析器与写入纪律

  • 新增 provider-neutral EquityIdentityResolver.resolve(exchange, symbol, factDate, knownAt)； 只查询 equity_identifier_version 的双时间范围，结果严格为 resolved、not_found 或 conflict。
  • 日线以 trade_date，周线/月线以各自上游事实的 period_end 解析 security_id；公司行动、财务、板块成员及其他写入者也必须传自身事实日期。 禁止再以 equity_instrument.exchange/symbol 直接 get_or_create。
  • 只有明确的当前快照读取可调用 resolveCurrentOpen；历史写入不得用“当前开放标识”替代事实日期。 not_found 时，行情只能经专用 PENDING 保留流程创建候选；conflict 必须隔离并使该分区失败。
  • PENDING 保留流程在 exchange+symbol advisory lock 内运行：首次未知代码建立 PENDING anchor 与 identity_state=PENDING 的占位标识版本；重复事实复用该 security_id。主数据确认时关闭占位 knowledge range，并以主数据 batch 追加 CONFIRMED 版本。publication 始终过滤 PENDING。
  • 若事实日期解析到已退市证券，且行情日期晚于明确退市日，解析器返回 possible_code_reuse 冲突并隔离，不能把新行情绑到旧 security_id，也不能仅凭行情创建新证券； 必须等待主数据证据关闭旧标识并建立新身份。
  • 代码复用从不依据名称判断是否同一证券。最终身份唯一性由标识历史的双时间排斥约束保证； 生命周期状态只描述证券状态，不参与标识唯一性。
-- 所有历史写入必须提供 fact_date；known_at 使用该任务冻结的知识截止时间。
SELECT security_id, identity_state
FROM equity_identifier_version
WHERE exchange = :exchange
  AND symbol = :symbol
  AND effective_range @> :fact_date
  AND knowledge_range @> :known_at;

-- 0 行：进入受控 PENDING/隔离决策；1 行：使用该 security_id；>1 行：conflict，禁止写事实。

7. PostgreSQL 表、约束、索引与事务

PostgreSQL 为唯一 canonical store；raw bytes 归对象存储。迁移启用 btree_gist， 用双 range 排斥约束阻止同一知识时刻的有效期重叠。所有结束时间采用不包含端。

7.1 业务表

7.4 发布事务

事务外：fetch → raw object durable put → source_batch/snapshot staging

SERIALIZABLE transaction + pg_advisory_xact_lock(capability, exchange):
  1. 再读当前 publication / checkpoint
  2. 校验 lease、snapshot COMPLETE、quality PASSED
  3. SELECT identity/current versions FOR UPDATE
  4. 解析 PENDING；关闭旧 known_to；插入新 identifier/name/status version
  5. 写 presence anomaly / quarantine
  6. 内容变化时关闭旧 publication，写新 dataVersion
  7. 更新 checkpoint 与 partition succeeded
COMMIT

聚合事务：
  锁 equity.master.cn-a → 验证同 target 的三所 child passed
  → 写 3 条 publication_component → 原子切换 aggregate publication

任一步失败整体回滚 canonical、publication、checkpoint；raw/source batch/snapshot 证据保留。 事务不包含外部请求，避免长时间持锁。

规则阈值 / 判定处置
响应与 schema非空；必需列齐全；fingerprint 在允许集合；日期/编码无损解析。失败：snapshot REJECTED，保留 raw，阻断发布。
代码唯一同 snapshot `(exchange,symbol)` 唯一，symbol 六位数字。重复/非法：quarantine，分区失败。
数量完整性相对上次稳定目录下降 >1% 为硬门；新增/减少绝对量同时记录。阈值须以 pilot 校准。下降异常：不发布；无论阈值内外，单只缺席都不改状态。
名称trim 后 1–200；同一代码多个名称须有可解释版本顺序。空/冲突隔离；禁止按名称合并身份。
标识冲突同双时间 `(exchange,symbol)` 不能映射多个 security；一个 security 不能有重叠标识。整条身份隔离；已有 publication 保持。
状态转换必须符合状态机；DELISTED 必须 explicit evidence；普通停牌不接受。非法转换硬失败；证据样本进入 issue。
日期effective_to>from；delisted_on≥listed_on；未来官方日不能直接当已生效。隔离；未知日使用 observation precision，不猜。
SSE DELIST_DATEAKShare 重命名与接口语义冲突；未完成交易所字段验证。只存 raw，quality issue 标 FIELD_SEMANTICS_UNVERIFIED。
跨所聚合同 target run 的 SSE/SZSE/BSE 三分区均 PASSED，child versions 唯一。否则不推进 aggregate；保留上一稳定版。

退市四道门

  1. 来源门：明确标识为交易所终止上市/退市来源；发现、行情、名称和目录差集不合格。
  2. 语义门：源字段含义、日期口径和接口集合经 fixture/官方字段说明确认；SSE 当前未过。
  3. 身份门：exchange+symbol 在相关有效期只解析一只 security；未知/复用冲突进入 quarantine。
  4. 批次门：响应非空、schema 通过、完整性合理、日期合法；随后才允许 append DELISTED。

质量结果

  • reject：payload 无法解析、必需列丢失、身份/日期硬冲突；整分区不发布。
  • quarantine：少量未知代码或语义待审；若影响身份唯一/退市则阻断，否则可在明确阈值内 partial，但 aggregate 不接收 partial。
  • warn：发现源差异、名称观察日精度、单只缺席；发布可继续，告警与 issue 必须可追踪。
  • publish：完整快照、全部硬门通过、无未解决 blocking issue。

service-api 模块与安全

  • 新增 EquityInstrumentModule，只依赖配置、全局 Auth Guard、Problem Details 和专用 DataSync client；禁止 forwardRef()。
  • 现有 ACTIVE USER/ADMIN/SUPER_ADMIN 可读是首期提案，最终 permission 是发布门；controller 不得标记 Public。
  • client 只调用 0009 internal HTTP，使用运行时 service Bearer；响应先做严格 schema 校验，再投影公开 schema。
  • 必须删除 instrumentId、任何 securityId、raw URI、provider、batch、quality detail；公开身份只用 exchange+symbol。
  • GET 仅在请求尚未收到响应头的连接错误上安全重试一次；超时、5xx、合同漂移、断路器打开统一映射 503。
  • 401/403 不暴露账号、角色或资源存在性；Problem Details 不返回下游 body、URL、token、SQL 或 stack。
  • Bearer header API 不依赖 cookie，因此本能力无额外 CSRF 状态；沿用全局 CORS/proxy trust。限流具体额度待流量测量。

分页、缓存与兼容

  • cursor 为服务端签名的 opaque token，绑定规范化 filters、asOf、knownAt、最后 sort key 和 dataVersion；篡改 400，版本过期 409。
  • ETag 是 request projection + dataVersion 的强校验；返回 private, max-age=0, must-revalidate。
  • v1 只允许新增 optional 字段；改变状态枚举、双时间语义、公开身份或 cursor 规则需 v2。
  • 不使用 offset；公开页最大 100、internal 最大 200，避免深分页扫描与 payload 放大。
  • 若 internal 无首次稳定全市场版本，service-api 返回 503；不拼接各所“最新”值。

11. 迁移、发布、回滚与验收

11.1 保留 equity_instrument 的兼容 expand

当前 equity_instrument 已同时提供内部 BIGINT 与稳定 UUID，且行情外键已引用 security_id。没有已决跨资产统一身份需求，拆成两表只会增加 FK、双写与回滚成本。 因此保留该表为身份锚，新增历史和快照；当前列在兼容窗口内作为事务内维护的 current projection。 该投影在 Contract C1 后允许因历史代码复用而出现相同 exchange+symbol，任何身份解析不得读取它。

  1. Expand E1：向 equity_instrument 增加 nullable master_confirmed_at/current_master_version；创建 identifier/name/status version、 snapshot、anomaly、quarantine 和 publication component 表。现有行情 FK 不变。
  2. 历史种子：PENDING 只写内部 PENDING 标识占位，不写已发布名称/状态历史； 非 PENDING 行分别建立 CONFIRMED 标识、名称和状态三条种子版本。 每组只有官方生效日时才用 OFFICIAL_DATE；没有权威日期时以迁移观测日为 OBSERVATION_DATE，各组独立保存，绝不把 created_at 伪装成真实生效日。
  3. Deploy D1：部署日期感知标识解析器；主数据仓储在一个事务中追加三类版本，并更新 equity_instrument.exchange/symbol/name/listing_status current projection。日线、周线、月线及 所有公司行动、财务、板块成员写入者先按事实日期解析 security_id；删除直接查询当前列的 get_or_create(exchange,symbol)。行情先到时仍可走专用 PENDING 流程，但不得与历史证券按名称合并。
  4. 回填校验：security_id/UUID 数量必须不变；每个非 PENDING 当前投影恰有一组可解析的 current identifier/name/status；所有行情外键仍有效；双时间排斥约束无冲突。
  5. 读切换：新 internal API 从 version 表按 asOf/knownAt 查询；无 asOf 的键式读取只走开放标识索引。 旧仓储在兼容窗口仅可把 current projection 用于展示，不得据此解析身份。contract test、shadow 比对与 “禁止当前列解析”架构测试通过后才开放 public route。
  6. Contract C1：确认日/周/月线和所有其他消费者、写入者均使用日期感知解析器， 开放标识唯一索引已验证且线上遥测无旧查询后，删除 equity_instrument_exchange_symbol_key（即旧绝对 UNIQUE(exchange,symbol)）， 再允许代码复用事实发布。保留 current projection 列和大表 FK；不得用 listing_status partial unique 代替标识约束，因为生命周期与代码有效期是不同维度。

  DROP CONSTRAINT equity_instrument_exchange_symbol_key;

11.2 source_batch expand 与不可恢复边界

  1. 新增 nullable run_id、partition_key、observation_seq、upstream_source、adapter_version、schema_fingerprint。
  2. 为每条历史 source_batch 建 synthetic legacy run/partition 并回填；既往已被唯一键折叠的观测次数无法重建，必须在迁移报告声明。
  3. 删除 UNIQUE(provider_id,capability,payload_sha256)，改为普通查重索引；新增 UNIQUE(run_id,partition_key,observation_seq)。
  4. 部署新 insert-only 仓储：每次 fetch 新建 batch，不再 ON CONFLICT ... DO UPDATE；raw store 仍可按 hash 返回既有对象 URI。
  5. 完成新行非空验证后收紧新增列；migration downgrade 只允许在新语义 batch 尚未产生时执行。

11.3 分阶段发布

  1. 阶段 0 — 门槛：评审 ADR-0013、0009/0010；确认来源许可路径、SSE 字段语义负责人、日历负责人和 API 权限候选。
  2. 阶段 1 — 存储：执行 expand、PENDING/CONFIRMED 历史种子与 current projection 校验；实现 raw observation 修复与 provider-neutral ports。
  3. 阶段 2 — 解析器切换：先切日/周/月线，再切公司行动、财务、板块成员和其他调用点；开启旧 current-column 查询告警与架构测试。
  4. 阶段 3 — 单所 pilot：先 BSE，再 SZSE/SSE；只运行 shadow publication，验证 10 个连续计划批次和失败恢复，次数是验收候选而非生产 SLA。
  5. 阶段 4 — 生命周期：显式来源、状态机、SSE 语义隔离、退市四道门、代码复用隔离、历史回补与修订测试。
  6. 阶段 5 — API：先 internal，再 service-api client/public；验证字段剥离、ETag、cursor/identity 409、503、权限与 schema drift。
  7. 阶段 6 — Contract C1：全部切换证据满足后删除旧绝对 exchange+symbol unique；在此之前禁止发布代码复用。
  8. 阶段 7 — 启用：生产许可和连续验收均通过后才打开 source policy；最后建立 scheduler。

11.4 回滚

  • 应用回滚：关闭新同步任务与公开路由，回滚 API/worker；保留的 equity_instrument current projection 只可展示；不得回滚到按当前列解析身份的旧日线写法。
  • 数据回滚：已发布的 identity/history 不做 destructive downgrade；将错误 publication 标记 superseded， 用已审计 repair batch 追加官方更正并推进新版本。
  • 迁移回滚：只有尚未产生新 canonical/history/source batch 时才允许 drop expand 表并恢复旧 unique； 产生代码复用行后不得恢复绝对 exchange+symbol unique，只能 roll forward 修复解析器；产生新观测后禁止恢复 hash unique，否则会再次折叠证据。
  • API 回滚：internal v1 在兼容窗口保留；public route 可关闭但不能让 service-api 转而直连 DB。
  • 错误退市：禁止直接 UPDATE 回 LISTED；必须保留错误知识版本，追加 OFFICIAL_CORRECTION， 记录 operator、reason、evidence 和受影响 publication。

11.5 验收标准

功能 / 数据

  • 三所目录分别成功/失败可独立重放；失败所保留上一版本。
  • 同一 snapshot 重跑不新增事实版本；每次 fetch 都有独立 source batch。
  • 目录缺席、空响应、SSE 误名字段均不能产生 DELISTED。
  • PENDING 原地确认并保留 security_id/UUID；身份冲突隔离。
  • 退市后出现的新行情进入 possible_code_reuse 隔离，主数据关闭旧标识前不能误绑或擅自建新证券。
  • 日/周/月线均按事实日期解析；历史代码复用不会按名称合并或误绑，所有旧 current-column get_or_create 均被架构测试阻断。
  • asOf/knownAt 能重建名称和状态修订，无重叠双时间行。
  • 全市场响应只含一个稳定三所 child-version 集合。

API / 运行

  • 公开响应无 instrumentId/securityId/raw/provider/batch 字段。
  • 无 asOf 的当前开放解析、历史代码复用必须 asOf、无匹配 404、冲突 409，以及 401/403/429/503、ETag/304、cursor 篡改均有测试。
  • 下游超时、schema drift、DB 失败、lease 过期、checkpoint 恢复可注入。
  • 0009/0010 可机器解析；internal/public contract test 通过。
  • 迁移 upgrade、双写回填、FK validate、允许条件下 rollback 演练通过。
  • Docker 格式、静态检查、测试、架构测试、镜像与 health/ready 通过。
