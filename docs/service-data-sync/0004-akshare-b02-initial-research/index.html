结论

事实

11 / 12 有候选返回

股票、指数、可转债、ETF、期权、交易所概览与同花顺板块均有至少一个响应；只有历史日度指标未找到可用的等价候选。

决策

Tushare 保持主路由

首轮不得替换任何既有来源优先级。AKShare 仅保留为 provider-neutral adapter 的候选证据，尚未创建 adapter。

主要风险

“返回”不等于“可入库”

复权因子为稀疏事件序列；多项缺前收、估值或成交指标；东方财富和上交所各出现断连或超时。

本轮决定：所有 B02 能力维持 PARTIAL 或 NO_EQUIVALENT。只有连续 3–5 个交易日复测、字段级映射、单位核验和来源合规核查通过后，才可讨论受限 fallback；本轮不建表、不建接口、不建同步任务。

必须先冻结的字段与语义

不可静默推导前收

从相邻收盘价推导 pre_close 看似简单，但停牌、首日、除权除息、不同频率聚合及缺失交易日都需要明确规则。未获字段级批准前，adapter 不得把推导值伪装成来源原值。

复权因子不是日线价格

稀疏 qfq_factor 需要先定义展开、哨兵过滤、日期对齐和数值转换。官方数据提示也警告部分后复权历史可能出现负价，不能用一次样本证明复权可靠。

量纲必须逐来源确认

旧 Tushare 模型将股票成交量记为手、成交额记为千元；AKShare 不同候选的同名字段不自动同量纲。中证和腾讯官方文档还分别标注万手/亿元与手，转换须有来源级测试。

缺失指标不能补零

估值、持仓量、换手率、转债溢价和板块均价缺失时，不能用零值、当前快照或其他日期替代。应记录为缺失并继续使用 Tushare 主路由。

映射约束：本报告只提供调研映射，不修改 canonical schema。未来 adapter 必须输出 provider 原始字段、标准化字段、单位、复权口径、交易日期和 provenance；应用、任务、质量与持久化层仍只依赖 provider-neutral port。

可靠性与合规信号

来源波动

同批次已出现断连

东方财富 A 股现货、指数日线、ETF 日线均远端断连；上交所概览 45 秒超时。它们必须作为未来 adapter 的可观测 provider 事件，不能吞掉。

接口维护

版本并非稳定承诺

AKShare 变更记录曾多次修复腾讯和东方财富指数接口。这支持固定版本、schema 指纹、退避重试与来源级熔断的基础设施要求。

使用边界

代码许可不等于数据许可

AKShare 官方仓库为 MIT，但其数据使用声明与各底层来源条款仍需逐项核查；没有明确结论的来源不可提升为生产 fallback。

禁止推断：AKShare 免费、MIT、文档列出接口或单次成功，都不能推导可长期稳定、可商业使用、可再分发，或可取代 Tushare。

B02 继续条件

  1. 连续复测：未来 3–5 个交易日，在同一镜像和版本重跑成功候选；记录成功率、空结果、耗时分位、日期滞后和 schema fingerprint。
  2. 字段级对照：选 10 个证券、3 个指数、3 个 ETF、3 只转债与跨月/除权区间，同 Tushare 逐日比对价格、单位、前收、涨跌和复权。
  3. 覆盖与退市：重测活跃、停牌、新上市、退市/到期样本，明确历史边界和缺失行为。
  4. 来源合规：为东方财富、新浪、腾讯、同花顺、上交所、深交所、中证逐项保存访问限制与再分发结论。
  5. 架构保持：若后续批准实现，只能在 infrastructure/providers/akshare/ 写具体 adapter；任何上层都不得直接调用 AKShare 或底层 URL。

下一优先验证

先验证 equity.bar.1d、index.bar.1d、fund.bar.1d：它们历史覆盖较好，但都需要严格字段和量纲对照。

明确不做

不创建业务表、迁移、接口、定时任务、真实 adapter、fallback 路由或 API 服务依赖；不把探针作为服务代码提交。
