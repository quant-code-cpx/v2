SERVICE-DATA-SYNC · IMPLEMENTED

0030｜同步失败留证与成功载荷零归档

个人自用模式：成功同步只保存 canonical 数据和来源摘要；AKShare 原始字段只在同步失败时写入私有 S3，兼顾成本和排障。

结果

成功路径
不写 S3 原始对象

保留 canonical、SHA-256、来源身份和不可回放标记。

失败路径
写入失败证据包

归档 raw、标准化载荷与最小 manifest，原始异常不被掩盖。

取舍
新成功批次不可 raw replay

需要回填时重新抓取；已存在的旧对象可在清理前处理。

运行流程

AKShare 返回
ProviderBatch
→
仅内存暂存 raw / normalized
→
校验、质量门、canonical 发布
→
成功：丢弃
失败：failures/…

内存暂存发生在解码前，schema 漂移也能获得失败证据；同一摘要和内容类型会去重。

存储与表影响

位置变更后含义是否保存 AKShare 原始大字段
canonical / revision / publication唯一长期业务事实否
source_batch.raw_uri、lineage、checkpoint成功时为 unretained:// 摘要标记；失败时可指向失败证据否
raw_payload_manifest只保存 URI、SHA-256、大小等索引元数据否
私有 S3 failures/仅失败批次的排障原始载荷和 manifest是，仅失败

迁移与回滚

  • 无需数据库迁移：现有 URI 列继续保存留证标记或失败证据位置，避免大范围 schema 破坏。
  • 历史成功归档位于 raw/ 与 normalized/ 前缀；确认不再需要旧 raw replay 后可清理。不得删除 failures/。
  • 回滚仅恢复旧版本写入策略；不会自动恢复已删除的历史对象，因此清理操作必须先做清单与备份确认。

验证

单元测试验证成功不调用 put_object、失败写入载荷与 manifest、以及解码失败发生在业务归档前时仍留存原始字节。入口与 Celery 组合测试覆盖主同步路径。
