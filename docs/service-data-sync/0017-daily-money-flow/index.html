1. 摘要

问题

同名资金流不等价

“主力”“大单”“净流入”是供应商算法产物。算法、阈值、样本池和分母未知时， 自动 fallback 或拼字段会得到不可解释序列。

决策

强方法学身份，两类数据分离

daily source observation 与 supplier rolling ranking snapshot 分表、分发布、分 API。 每次查询必须显式选择方法学、版本、scope、bucket 和窗口。

最大风险

生产 publication 当前关闭

2026-07-28 当日探针记录了 RemoteDisconnected、502 与 JSON 解码失败；AKShare 排行合并结果也不能证明页连续或 supplier total。对应方法学固定为 research， productionEnabled=false，公开层不会泄漏值。

硬边界 完全排除分钟、分时、盘中轮询、实时推送和 WebSocket。任务在每个目标交易日最多执行一次计划抓取； 有界失败重试不构成盘中采样。接口、schema、单位、方法学和完整性技术校验未通过时不产生公开 publication。
事实

固定版本形态已核对

仓库测试镜像锁定 akshare==1.18.78；函数签名与源码字段映射已核对。

决策

缺失保持缺失

源端不提供 gross inflow/outflow 时恒为 null，禁止通过净额反推。

已实现

capability 按技术证据 fail closed

adapter、raw、revision、质量和 API 已实现；未通过稳定性、单位或完整性门禁时拒绝 publication。

2. 任务定义与边界

项目决策可验证条件
业务目的 为研究、筛选和详情页提供可解释的供应商派生日频资金流。 消费者可看到来源、方法学、窗口、bucket、分母、单位和最终态。
数据集 money-flow.daily-series 与 money-flow.supplier-ranking。 两类表、publication、checkpoint 和 API 不互相回填。
市场 / 时区 中国 A 股；使用同步服务统一交易日历；调度时区 Asia/Shanghai，存储 UTC。 日历未知时不推断休市、不推进目标日。
粒度 交易日日频来源事实；供应商 day/3/5/10/20 日排行快照。 不存在分钟表、分钟 checkpoint 或盘中触发器。
scope equity、sector、market；每条 series 只绑定一种稳定身份。 跨 scope 不加总；行业/概念不由成份股计算。
新鲜度 初始候选为目标交易日 18:00 后一次；最终截点由连续样本校准。 响应携带 observedAt/finality；不承诺实时。
历史深度 只保存上游当前可见窗口并持续采集；不虚构首次采集前历史。 接口窗口消失后缺口可见；回补 knownFrom 不回写历史。
消费者 service-api 的只读 MoneyFlowModule。 只经内部 HTTP；无 DB/S3/provider 直连。

目标

  • 可重复、可恢复、raw-first 的同步闭环。
  • 修订和 point-in-time 查询不产生未来信息。
  • PostgreSQL 约束阻止跨方法学混写。
  • 内部与公开契约可直接驱动实现。

非目标

  • 不解释供应商秘密算法。
  • 不计算“真正市场现金流”。
  • 不接互联互通、融资融券或持仓变化。
  • 不提供跨来源综合排名。

依赖

  • 0014 证券主数据：时点身份解析。
  • 0013 成份历史：只解释 universe/覆盖。
  • 已落地的 0014 共享 source_batch expand 与运行账本。
  • 0018 ORM 基线：模型、Session、迁移与分区边界。
  • 同步服务统一交易日历：目标日解析与日期质量校验依赖。

语义族

trade_direction_flow

按主动买卖方向估算的流入、流出和净额。必须绑定方向判定、数据截点和 universe。

主力、超大、大、中、小单。必须绑定供应商阈值、主力定义、bucket 和算法版本。

Source policy & adapter

外部形态隔离

输入：中立 capability、scope、窗口。

输出：标准 batch + 不可变 raw。

状态：无 canonical 状态。

失败：映射为中立 unavailable/rate/schema/auth；不写 DB。

Daily series pipeline

日序列修订

输入：源端带日期的历史窗口。

输出：一 scope/bucket 的 point-in-time revision。

状态：series、observation、checkpoint、publication。

失败：只阻断当前 partition，保留上一发布。

Ranking pipeline

输入：一次 SDK 合并排行观测；完整性证据单独判定。

输出：header/items/metrics/merged-observation evidence manifest。

状态：不可变 snapshot revision。

失败：SDK 错误、身份未解析或生产完整性无证据时整份不发布。

Identity & methodology gate

阻止伪等价

依赖：0014 时点证券 resolver、稳定 sector identity。

状态：methodology/universe/bucket 受控版本。

失败：代码复用、多解、名称歧义进入 quarantine。

Publication & read model

版本化可见性

职责：原子推进 current publication，生成 ETag/cursor。

依赖：PostgreSQL；不读 provider。

失败：事务回滚，不暴露 candidate。

service-api

只读防腐层

职责：鉴权、DTO 校验、内部 client、公开字段裁剪。

状态：无 Prisma canonical copy，无 Redis 权威缓存。

失败：下游错误统一映射 Problem Details 503。

6. 同步逻辑

任务与分区

任务逻辑分区cadence / 调用形态checkpoint
money-flow-daily-equity methodology version + canonical security + target cycle 每选中证券每交易日最多一次；接口回拉当前约 100 日接受修订。 最后 accepted source window、publication、business hash。
money-flow-daily-sector methodology version + sector key + target cycle 单行业调用；有界 universe 分片，概念不得冒用行业接口。 最后窗口、源目录版本和 sector identity。
money-flow-daily-market methodology version + market code 每交易日一次；历史窗口整体重拉。 最后窗口和 publication。
money-flow-supplier-ranking methodology + universe + scope + window + target date 每个已配置窗口一次合并观测；现有 SDK 形态先运行有界探针，失败重试但不轮询。 最后完整 snapshot/dataVersion。

初始候选时间为 18:00 后。cadence、并发、速率和截点由连续探针冻结； 全市场约 5,500 次单证券请求/日必须先通过调用容量测试，未通过时只启用可承载的有界 universe。

正常路径

  1. 调度器从统一交易日历解析目标日；读取 capability 技术状态、调用预算和 methodology version。
  2. dispatcher 创建 0014 统一的 sync_run/sync_partition，按 partition key 获取租约和 fencing token。
  3. adapter 经 provider-neutral port 获取；每次外部观测登记独立 observation sequence。
  4. raw bytes 先写 S3，再登记 0014 权威 expand 后的 source_batch；canonical 失败可离线重放。
  5. adapter 只做供应商字段解析与标准 DTO；application 校验 methodology、窗口、单位和最终态。
  6. 个股每条 observation 按其 trade_date 调用 0014 date-aware identity resolver。 禁止按 current (exchange,symbol) get-or-create；历史代码复用、多解或单批跨身份均 quarantine。
  7. 行业排行仅按目标日同源 sector catalog 解析；名称零解/多解不发布，不做模糊匹配。
  8. 质量通过后计算 canonical business hash。相同内容只记录 source observation，canonical/publication no-op。
  9. 内容变化在一个事务中追加 revision、关闭旧 current、写质量结果、推进 publication/checkpoint。

并发、重试与恢复

锁与 fencing

  • 同 partition 仅一个 lease owner；租约 15 分钟，30 秒 heartbeat 为 shadow 初值。
  • 每次续租递增 fencing token；旧 owner 不能提交 publication。
  • reaper 只回收过期 running partition，不修改已提交 revision。
  • 取消停止未提交工作；已发布事务不反向撤销。

错误分类

  • 连接、429、可重试 5xx：最多 2 次指数退避 + jitter。
  • schema、单位、身份、完整性、方法学不一致：terminal quarantine。
  • 数据库失败：从 raw 重放，不再次访问上游。
  • 重试计数属于 sync_partition.attempt，不进入 source-batch 身份。

回补、修订与 late data

  • 历史接口可见窗口全量重拉；旧日期变化追加 knowledge revision，known_from=实际发布时间。
  • 回补只能覆盖源端仍可见区间；超出窗口标记 unrecoverable gap，不用排行反推。
  • 排行同日重抓内容变化时追加 snapshot revision；旧 cursor 失效并返回 409。
  • repair 优先选择 source batch/raw URI；仅 raw 丢失且策略允许时才重新抓取。
  • provider failure、空响应或页面不全不推进 checkpoint，不把无数据解释为休市。

7. PostgreSQL 详细设计

PostgreSQL 是 canonical、knowledge revision、checkpoint 和 publication 的唯一权威；S3/MinIO 保存 raw。 金额使用精确 NUMERIC，不进入 binary float。业务事实禁止落入未治理 JSON/EAV。

ORM 实施约束 本节每张新增逻辑表必须在 infrastructure/database/models/money_flow/ 中拥有一个 Declarative 模型文件，并显式加入 registry.py。repository 通过 DatabaseClient.transaction() 获取短生命周期 Session，使用模型字段与类型化 select/insert/update；不得执行字符串 SQL，不向 application/domain 泄漏 ORM instance。 模型表达当前目标 schema，Alembic revision 表达演进历史；复杂 PostgreSQL 索引与分区必须另做 schema parity。

series 强唯一键

UNIQUE (
  methodology_version_id,
  scope_type,
  COALESCE(security_id, 0),
  COALESCE(sector_key, 0),
  COALESCE(market_code, ''),
  universe_version_id,
  bucket_id,
  window_type,
  window_size
)

实现时优先使用三种 scope 的部分唯一索引，避免 PostgreSQL 对表达式唯一键与 FK 的维护成本。 Declarative 模型使用 Index(..., unique=True, postgresql_where=...) 分别表达三种 scope； 显式 Alembic migration 必须创建完全相同的谓词、表达式和列顺序，并由 PostgreSQL parity 测试核对。 source_batch 唯一键固定为 (run_id, partition_key, observation_seq)；payload hash 只建非唯一查重索引。

publication 与事务

  • daily partition key：methodology/version/series；publication 覆盖该 series 当前知识视图。
  • ranking partition key：methodology/version/universe/window/bucket/trade_date。
  • 事务锁定 current publication；插 revision、quality、关闭旧 current、插新 publication、推进 checkpoint 一次提交。
  • quality_status=partial 或 quarantine 不进入消费者 publication。
  • API cursor 绑定 dataVersion、所有过滤条件、canonical security identity 和最后稳定位置。

容量与保留

假设 5,500 只证券、5 个 bucket、252 交易日，current daily observation 约 693 万行/年； 修订系数 1.2 时约 832 万行/年。全量 supplier ranking 在多窗口下数量级相近。 因此日事实和排行 header/items 按月分区，读索引只覆盖 current revision；旧分区可转冷存。 ORM 只声明父分区逻辑表，不为每个月复制 class；物理子分区由 migration 或专用 partition manager 创建。 raw 可能达数十 GB/年，保留期由重放窗口、备份能力、存储容量和恢复目标联合校准； 在重放与备份验证完成前不自动清理。

关键失败路径

provider failure

保留上一发布，记录缺口；绝不改路由到另一供应商。

schema drift

raw + fingerprint + 最小样本入隔离；更新 fixture、评审方法学后新版本。

raw 成功 / DB 失败

checkpoint 不推进；由 run/source batch 从 raw 重放，避免重复外部调用。

publication 事务失败

全部回滚，旧 current 保持；fencing 防止僵尸 owner 补提交。

identity conflict

记录 tradeDate、候选身份和 0014 dataVersion；人工修复身份后 replay。

late revision

追加 knowledge revision；旧 knownAt 查询仍读旧值，当前查询读新 publication。

10. 部署、监控与安全

部署

  • 复用 worker、PostgreSQL、S3/MinIO、internal FastAPI。
  • migration 由独立 job 执行；应用启动不迁移。
  • AKShare 版本固定；升级重跑 fixture/单位/失败注入。

配置与 egress

  • source policy、预算、并发、截点通过环境变量/受控配置。
  • production flag 初始 false；无真实 token 写仓库。
  • egress 只允许配置清单中的上游域名；同花顺 adapter 未通过稳定性与恢复测试前禁用。

资源

  • 每来源配置独立并发上限、调用预算和 circuit。
  • 合并观测先写 raw，限制单 batch bytes/rows。
  • DB connection 与查询 page 上限固定，避免大范围扫描。

运行手册入口

  1. 按 request/run id 定位 partition、source policy、lease owner 和 source batch。
  2. 先判断 provider、schema、identity、DQ、raw storage 或 DB transaction 层级。
  3. provider 故障保持上一 publication，不开备用来源；schema/identity 故障进入 quarantine。
