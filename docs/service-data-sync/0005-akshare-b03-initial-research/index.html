结论

事实

3 项有受限候选

中证成分权重、东财停复牌和东财涨/跌/炸板池均返回结构化数据；仅限特定日期、指数或近期窗口。

决策

不替换 Tushare

AKShare 只保留 provider-neutral adapter 的研究证据。没有创建 adapter、数据表、任务、接口或 fallback 路由。

最大风险

不可复算字段与窗口短

价格限制依赖证券状态和规则；筹码算法不透明且近 90 日；技术指标无同构来源，不能将近似值写为旧 Tushare 字段。

本轮决定：所有 B03 结论维持 PARTIAL、UNSTABLE 或 NO_EQUIVALENT。没有完成稳定性窗口、历史覆盖、字段语义、单位与来源合规核查前，任何候选不得进入生产路由。

关键语义与架构边界

涨跌停价是历史规则结果

不能用固定 ±10% 规则回填。ST、新股、创业板、科创板、北交所、停复牌和价格精度都依赖证券在当日的状态；B01 主数据与交易日历缺口也会直接影响此项。

停复牌事件不等于日频事实

开始、截止和预计复牌是事件信息。若未来需要 SuspendD，必须定义“全天/盘中”、跨日展开、修订、撤销与空结果的 canonical 规则，并保留原始事件 provenance。

技术因子应是版本化派生

若未来确有需求，应在 B02 原始行情和复权语义稳定后，由内部确定性计算器产出；固定公式、参数、预热长度、缺失处理、价格口径和版本。它不是直接调用 AKShare 的理由。

筹码不可从区间伪造分布

90/70 成本区间与集中度不能反推出每个价格桶的持仓比例；获利比例与旧 winner_rate 的量纲也必须先比对。缺失字段必须保持缺失。

适配层约束：所有未来外部读取只能放在 infrastructure/providers/akshare/ 的具体 adapter 内；任务、应用、质量和持久化层只依赖 provider-neutral port。内部技术因子计算须与外部 provider adapter 分开，不允许上层直接调用 AKShare 或底层 URL。

可靠性与合规信号

运行时

依赖需纳入准入

Linux ARM / Python 3.13 基线中，AKShare 根包导入要求 py_mini_racer；pip 本次解析到源码构建并超出探针容忍时间。临时 stub 仅用来检查不依赖该库的候选，不能用于服务。

来源波动

同批即有接口失败

东财 A 股全市场快照断连，雪球个股快照缺少预期 JSON 字段，深证指数权重触发 Excel 解析错误。未来 adapter 必须区分网络、上游格式和空结果。

数据边界

近期窗口不能当历史

涨跌停池官方声明仅近期数据；筹码汇总官方声明近 90 个交易日。它们不满足旧项目按日全量回填和回测历史的默认需求。

禁止推断：一次调用成功、AKShare 免费或代码许可证，都不能推导历史完整、指标算法一致、可稳定运行、可商业使用或可再分发。底层东方财富、中证、腾讯、雪球等来源仍需单独核查。

B03 继续条件

  1. 连续复测：对停复牌、权重、三类涨跌停池连续 3–5 个交易日重跑；记录成功率、schema fingerprint、耗时、空结果、最早可查日期和日期滞后。
  2. 权重覆盖：对旧任务的 19 个核心指数逐一验证代码转换、返回日期、成分数和权重和（容差）；确认中证快照不能满足的指数与历史来源。
  3. 事件映射：用涨停、跌停、炸板各 10 个样本对照 Tushare，逐字段给出“直接、转换、缺失、语义不明”；禁止合并三池时丢失事件类型。
  4. 停牌语义：确认 stock_tfp_em(date) 的实际筛选行为；定义事件到交易日的展开策略前，不准写入日频 canonical 事实。
  5. 派生因子评审：只有业务确认需要、B02 价格与复权已通过后，才单独提交公式版本、回看窗口、容差和防未来函数验证方案。
  6. 合规核查：记录中证、东方财富、腾讯、雪球的访问频率、使用与再分发结论；无证据不得升级 verdict。

下一优先验证

优先完成指数权重覆盖和涨跌停三池字段矩阵：它们已有响应，但快照/近期窗口与统一事件模型的缺口最大。

明确不做

不建业务表、迁移、接口、定时任务、真实 adapter 或来源路由；不将临时 import stub、依赖 volume 或探针提交到仓库。
