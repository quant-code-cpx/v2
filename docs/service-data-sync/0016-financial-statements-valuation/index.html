1. 摘要

问题

报告期不等于当时可见

今天抓到旧报表，若只按 reportPeriod 存储，回测会错误认为历史当时已知； 供应商指标、派生指标和估值混表还会掩盖方法学变化。

决策

四数据集、双时态、追加修订

报表事实、供应商指标、平台派生指标、估值观察独立。每条修订保存业务有效区间、 系统知识区间、来源方法学和精确单位，只发布通过治理的数据。

最大风险

上游宽表字段可能漂移

AKShare 东财宽表可能新增、删除或重命名列；adapter 保留原始表头和 evidence，并以 schema fingerprint 让 drift 在同步与测试中可见。

执行顺序 已落 schema、迁移、fixture、任务、内部 API 与公开 API；单证券同步先归档 raw，再分别推进三类 provider publication。平台派生任务只读取已发布报表快照，以独立方法学、revision、输入血缘和 publication 对外可见，不覆盖供应商值。

2. 目标、非目标与任务合同

目标

  • 沪、深、北 A 股及明确退市证券的三大报表修订。
  • 治理后的供应商指标、可重算的平台派生指标。
  • 来源与方法明确的日日期估值观察序列。
  • asOf + knownAt 无前视查询和版本化 API。

非目标

  • 不接分钟、分时、盘中估值或实时推送。
  • 不抓财务公告正文，不做 OCR 或会计准则自动转换。
  • 不把供应商指标反推为报表披露事实。
  • 不在 service-api 复制 canonical 表或建立 Redis 权威缓存。

固定约束

  • 市场：A 股；交易所：SSE、SZSE、BSE。
  • 业务时区：Asia/Shanghai；存储时间：带时区 UTC。
  • 金额、比例与估值：精确十进制，不用 float。
  • 证券身份依赖 0014 证券主数据。

Adapter

只负责供应商翻译

输入：中立 capability、证券、报告类型或日期窗。

输出：中立 batch、raw payload、observedAt、schema fingerprint。

失败：映射 unavailable/rate-limited/auth/invalid/schema；禁止写 DB。

Application

检测、规范、修订与发布

状态：run、partition、checkpoint、修订、质量、publication。

依赖：ports、repository、raw store；禁止 import AKShare adapter。

失败：分区隔离，旧 publication 保持可读。

Serving

两个契约、一个权威

内部：FastAPI 读取已发布视图，不返回 raw/quarantine。

公开：NestJS 做 JWT、角色、DTO、限流和字段裁剪。

禁止：service-api Prisma 复制同步表、直连 S3/provider、Redis 权威缓存。

四类数据不可互相 fallback。供应商指标的 ROE 与平台公式 ROE 即使名字相同，也使用不同 methodologyCode/version；估值不同来源也不拼接为连续序列。

5. 同步、幂等与恢复

5.1 正常增量

  1. 外部编排或 CLI 创建 sync_run；按报告期与报表类型抓 change index。 摘要只生成候选证券及来源变更摘要，不写 canonical 报表值。
  2. 与 financial_change_checkpoint 比较摘要 hash、公告/更新时间和上次发布版本。 新证券、字段变化、来源更新时间前移/变化或人工 repair 才创建完整报表分区。
  3. 每个分区键为 capability|EXCHANGE.SYMBOL|statementType。 按报告/观测适用日期调用 0014 date-aware identity resolver；禁止对当前 (exchange,symbol) 直接 get-or-create。唯一解析后取得 PostgreSQL advisory lock， 再调用普通或明确退市函数；歧义进入 quarantine，缺席、空响应绝不推断退市。
  4. raw 先以内容寻址写 S3 兼容存储，再记录独立 source_batch 观察。 adapter 输出经 schema、身份、时间、单位和字典校验；未知字段进入 quarantine。
  5. 以逻辑键和 canonical content hash 对比。相同值只增加观察证据，不增加修订； 值或时间依据变化时关闭旧区间并追加修订。
  6. 同一 DB 事务写修订、事实、质量结果和 publication。全部硬门禁通过才推进 dataVersion；随后提交 checkpoint。任一步失败保留上一发布。
  7. 供应商指标、平台派生指标和估值使用各自 run/publication，不能因报表成功而一起标记成功。

5.2 分区、并发与昂贵调用预算

控制方案不变量
锁 对规范化 partition key 取 PostgreSQL advisory lock；同一证券/能力串行，不同证券可并行 锁失败回到 queued，不并发写同一开放修订
幂等 依赖 0014 扩展后的 source_batch： UNIQUE(run_id, partition_key, observation_seq) attempt 只属于 sync_partition； payload hash 非唯一，仅用于查重与 raw 对象复用
重试 unavailable/rate-limited 最多 3 次指数退避加 jitter；服务端 Retry-After 优先 schema、鉴权、无效请求不自动重试，直接 quarantine/failed
checkpoint 每个摘要分区保存 hash、水位和最后 publication；只在发布事务完成后推进 中断后从未发布分区恢复，不跳过 raw 已写但 DB 未发布的批次
调用预算 生产必须显式配置并发、每分钟请求数、超时和每日完整报表上限； 无配置拒绝启用。摘要先过滤，退市独立队列低并发。 不能靠无限重试追赶；超预算分区留到后续 run
取消 / 僵尸 取消只在 raw/事务边界生效；心跳超期由恢复器标记 failed，再以新 partition attempt 重跑 不复用旧 observation_seq，不删除已存证据

5.3 全量回补与修订

  • 回补必须显式给证券集合、报告期范围、capability、source policy 和理由；默认无“全市场全部历史”。
  • 按交易所、证券、报表类型切块；旧到新处理，但发布仍以每证券/能力完整质量门禁为单位。
  • 三表接口返回全历史时只保存请求实际响应；不能把请求范围伪装成上游支持范围。
  • 新修订通过 canonical hash 识别；同一报告期旧值保留，knownTo/effectiveTo 半开关闭。
  • 平台派生指标在输入 publication 或公式版本变化时重算到新版本；旧派生结果不覆盖。
  • 估值按候选接口支持的 period 分窗抓取，重叠日期用于对账；同值观察不生成无意义修订。

5.4 失败路径

失败状态 / 影响恢复
provider 超时、断连、限流partition retryable；旧发布继续；不把空值写成事实预算内重试，耗尽后下次 run 或人工 repair
schema 漂移 / 未知字段quarantined；该分区不发布；告警含 fingerprint，不含 raw 值评审字典与 fixture，升级 adapter 后重放 raw
适用日期身份无法唯一解析 硬失败并 quarantine；禁止按 current symbol 建临时公开证券 先修复 0014 身份区间或 resolver，再重跑
DB 事务失败canonical 与 publication 全回滚；raw 可能已存在同分区重跑；孤立 raw 按保留策略清理
部分报表成功各 capability 独立；成功能力可发布，失败能力保留旧版只重跑失败能力，不伪造“整套财务完成”
source policy 被关闭或接口能力失效立即停止新抓取/发布；已发布版本保持可追溯，读取策略显式配置修复 adapter 或记录来源切换 ADR；不能自动切换来源

6. 点时、口径与版本语义

报告期 2025-12-31
  ├─ 上游公告日：未知
  ├─ 平台首次取得：2026-03-28T22:10:00+08:00
  ├─ effectiveFrom：2026-03-28（保守）
  ├─ knownFrom：2026-03-28T14:10:00Z
  ├─ knowledgeBasis：OBSERVED_AT
  └─ knowledgeConfidence：CONSERVATIVE

2026-07-27 回补同一报告：
  不得把 knownFrom 写成 2025-12-31；
  不得因后来发现公告日而原地改旧修订；
  追加新知识修订并保留历史判断。

查询语义

  • reportPeriod 只筛会计期。
  • asOf 选择业务有效版本。
  • knownAt 选择平台当时已知版本。
  • 默认值来自选中 publication 的 effective/knowledge cutoff。
  • 未来 knownAt 拒绝；cursor 绑定两个时间和 dataVersion。

口径边界

  • 资产负债表：POINT_IN_TIME。
  • 利润、现金流源报表：YEAR_TO_DATE。
  • SINGLE_QUARTER/TTM 只在派生数据集。
  • 合并/母公司、币种、报告类型、审计状态未知时写 UNKNOWN，不猜。
  • 单位转换记录原单位、标准单位、scale 和符号规则，禁止静默换算。

可信官方公告日期可作为 effectiveFrom，但系统 knownFrom 不能早于平台首次成功取得。只有供应商更新时间时，需先通过语义 fixture；否则仍以 observedAt 保守处理。详细决策见 ADR-0015。

7. PostgreSQL 详细表设计

沿用 equity_instrument.security_id 作为内部 FK，不再建证券副本。 复用 0014 已落地的 sync_run、sync_partition 和独立观测 source_batch。raw payload 仍由 S3 兼容对象存储持有；canonical 表不存宽 JSON。

8. 内部与公开 API 设计

Contract 0013

service-data-sync 内部只读

OpenAPI 0013 使用运行时 service Bearer，只读 production publication。报表头和行项目已用 publication 冻结 双时态视图、HMAC cursor 和 ETag 200/304；行项目只投影 active 字典认可的字段。携带内部 instrument correlation ID 供防腐 client 校验，但不返回 raw URI、batch、数据库键或 quarantine。

Contract 0014

service-api 认证公开

OpenAPI 0014 使用 JWT；初始允许 ACTIVE USER、ADMIN、SUPER_ADMIN。公开身份为 exchange + symbol，报表使用 public-safe reportRef。

9.2 日志、指标与告警

  • 结构化日志关联 runId、partitionKey、observationSeq、sourceBatchId、 capability、providerCode、instrument、reportPeriod、dataVersion、requestId； 不记录 token、raw payload、财务整行或真实 URL 参数。
  • 指标：run/partition 状态、请求次数/耗时/重试/429、raw bytes、schema fingerprint、 detected/unchanged/revised/quarantined 数、publication lag、knownAt 保守率、API p95/错误率。
  • 告警：已关闭 source policy 仍产生任务立即 page；schema drift、身份缺失、DB 事务失败、 分区缺失、当前区间重叠立即 page；连续任务失败、积压、publication lag 走 warning。 具体时间阈值在连续运行基准后配置，不在本文虚构。
  • trace 贯穿 service-api requestId → internal requestId → dataVersion；离线 run 用 runId/span， raw evidence 只通过受限运维工具定位。

9.3 安全与配置

  • 凭据只由 environment/secret 注入；adapter egress allowlist；research 与 production 凭据、bucket、DB 隔离。
  • 计划配置： DATA_SYNC_FINANCIAL_ENABLED=false、 DATA_SYNC_FINANCIAL_SOURCE_POLICY、 DATA_SYNC_FINANCIAL_MAX_CONCURRENCY、 DATA_SYNC_FINANCIAL_REQUESTS_PER_MINUTE、 DATA_SYNC_FINANCIAL_REQUEST_TIMEOUT_SECONDS。 实现时同步更新 .env.example；production 缺预算值时 fail closed。
  • 内部 Bearer 常量时间比较、可轮换、禁止日志；公开 JWT 沿用全局 guard 和 securityVersion。
  • API 只提供必要数据；无 provider URL、raw、source batch、内部主键或 quarantine 详情。

9.4 性能目标与验证方式

  • 写入默认使用 Session.execute(insert(Model), rows) 按报表 revision 批量提交，保持单 partition 事务且不跨全市场开长事务。只有 pilot 基准证明 ORM 批量表达式无法满足容量目标，并记录独立 ADR 后， 才允许在同一事务边界内引入受控 COPY 例外。
  • API 先解析 exchange/symbol 和 publication，再按分区键、时间和覆盖索引读取；禁止 offset pagination。
  • 请求 payload 由 limit、metric 数和日期跨度硬限；详情通过 cursor 分页，不返回任意宽表。
  • 上线门槛以 pilot EXPLAIN ANALYZE 为准：索引命中、无全表扫描、无磁盘 sort；延迟 SLO 待真实数据测量后冻结。

10.1 Expand → shadow → production

  1. 前置（已满足）：0014 证券主数据与共享 source_batch expand 已实施： 增加 runId、partitionKey、observationSeq，唯一键为三者；attempt 保留在 sync_partition； 移除 payload hash 唯一性，raw 对象继续按内容寻址。

10.2 回滚

无 publication

禁用 feature/source policy，回滚 API 路由，再按 Alembic downgrade 删除空新表。 0014 的共享 source_batch expand 不由本方案回滚。

已有 publication

停任务、将当前指针切回上一 verified dataVersion、回滚公开路由。 保留所有修订、quality 和 raw；禁止 destructive downgrade。

接口能力失效

立即停止 egress 与新发布，保留上一可读 dataVersion； 若 schema 或方法学不兼容则显式返回 503，不能静默换源。

10.5 可执行验收标准

  • 同一分区连续运行两次不产生重复 canonical revision；每次观察仍有独立 sourceBatch。
  • 任意回补报告的 knownFrom 不早于平台首次成功观测；asOf + knownAt fixture 无前视。
  • 未知字段、单位未知、身份未解析、时间冲突、部分响应均不能推进 publication。
  • 源报表累计值、供应商单季指标、平台 TTM 和估值观察四类物理隔离，API 方法学明确。
  • 日期感知身份解析按 publication 的 effectiveAsOf/knowledgeCutoff 选择 CONFIRMED 标识；证券代码不充当永久身份。
  • 公开响应无 instrumentId、provider/sourceBatch/raw/quarantine；service-api 无 canonical Prisma 表。
  • 全部新增逻辑表有 Declarative 模型并进入显式 registry；仓储只返回领域结果，不泄漏 Session 或 ORM instance。
  • alembic check、PostgreSQL schema parity、upgrade/downgrade 和持久化字符串 SQL 架构门通过。
  • 默认 feature flag 保持关闭；启用时必须显式选择 akshare-eastmoney 并配置三项资源预算。
