1. 执行摘要

本方案建立一条可追溯、可重跑、可版本化发布的个股数据链路。核心原则是： 同一 canonical 数据集在同一发布时间点只允许一种明确口径，来源切换必须显式产生新版本， 不能在失败时静默混入另一来源。

后续细化： 证券身份、目录和上市生命周期以 0014 证券主数据方案为实施权威； 财务报表、财务指标和估值以 0016 财务与估值方案为实施权威。 本文中与二者重叠的早期表和接口草案不再单独实施，行情、复权与公司行动等未重叠范围继续有效。
实施事实： 腾讯未复权日线、东财周/月线直采、新浪累计后复权因子、东财公司行动和巨潮公司概况 adapter 已落地； raw evidence、独立 revision/publication/checkpoint、全历史 CLI、六类 Celery 调度、内部读取、 service-api 公开 POST 代理和 HMAC 稳定游标已经打通。财务与估值实施状态由 0016 独立维护。 现有持久化统一采用 0018 SQLAlchemy ORM 基线。
事实基线
1d raw
日、周、月分别保存上游直接返回的独立行情事实，禁止跨周期派生。
复权基线
F(d)
保存稳定的累计后复权因子；前/后复权查询时按版本计算。
服务边界
HTTP
service-api 仅通过内部版本化 API 读取，不直连同步库。
交付边界：本方案只负责行情、复权、公司行动与公司概况的技术闭环。 证券身份由 0014 提供，财务与估值由 0016 提供；实时行情、分钟线、资金流、股东与资讯不在本期。
技术门槛：每个 AKShare capability 必须通过固定版本 fixture、schema、单位、 日期边界、连续样本和失败恢复验证。未通过的 capability 不注册，不阻塞其他已通过数据集实施。

3. AKShare 研究结论与来源路由

AKShare 是聚合库，不是单一数据源。相同领域接口背后可能分别来自交易所、东方财富、腾讯、 新浪或巨潮资讯；可用性、单位和修订语义不同。适配器必须按 capability 路由， 而不是按“AKShare”整体降级。

能力AKShare 接口 / 上游角色实测与约束

未复权周/月线 stock_zh_a_hist(period="weekly"|"monthly", adjust="") / 东方财富 已实现 AKShare 1.18.78 精确签名和源码已核对；两种周期独立调用、独立表、独立发布，不读取日线。

公司资料 stock_profile_cninfo / 巨潮资讯 已实现 实测返回 26 个字段；版本化保存，空字段不覆盖已发布非空值，除非来源明确删除。

禁止静默 fallback：主来源失败时分区进入 failed/quarantined， 对外保持上一已发布版本并标记 stale。切换来源必须更新受控配置、执行重叠窗口全量比对、 升级数据版本并重新发布。

日线生产认证门槛

  1. 覆盖沪深北、主板/科创板/创业板/北交所、ST/停牌/退市样本，至少 300 只证券、连续 5 个交易日。
  2. 与交易所可核验样本或独立可信基准比对 OHLC、成交量、成交额；分板块输出偏差分布。
  3. 成交量单位修复必须以 instrument_type 判断，不以代码字符串特判。
  4. 认证结果固定到 provider_version + adapter_version + methodology_version；任一变化重跑。

5. 数据同步逻辑

5.1 通用状态机与幂等

调度器按 capability 枚举已确认证券并发送单证券 Celery 消息。每次成功来源观察通过 source_batch 回链 sync_run/sync_partition；canonical 内容哈希和 (capability, partition_key) 检查点共同保证重复投递不制造新修订。

queued → running → source fetched → raw archived → canonical published → checkpoint advanced
         ↘ Celery Retry（最多 3 次）→ running
         ↘ failed（checkpoint 不推进）
  1. broker 将一只证券的一个 capability 作为独立任务分发；行情与参考数据使用独立队列。
  2. 请求成功后先写 S3 raw，记录 SHA-256、provider/adapter 版本和观测时间。
  3. 标准载荷执行 schema、单位、日期、身份和重复键校验；失败不会写 canonical。
  4. 通过后在单个事务中关闭旧版本、插入新版本并切换 dataset_publication；相同业务哈希不产生新修订。
  5. publication 成功后推进 capability checkpoint；失败或 Celery Retry 不推进。

5.3 抓取节流、重试与变更探测

  • 行情与参考数据使用独立 Celery 队列；两类单证券任务均设置每 worker 30 次/分钟的硬限速。
  • 连接、超时与 adapter 明确标记的瞬时失败最多重试 3 次，指数退避加全抖动；字段缺失或解析漂移立即失败，不盲重试。
  • 达到最大重试次数后任务终止，checkpoint 保持原值；下一调度窗口按 capability 独立恢复，不拖住其他数据集。
  • 完整上游响应以 canonical 内容哈希判断是否修订；网络重试不会制造重复 current revision。

5.4 初始回填与修复

  1. 先加载交易日历与证券主数据，冻结 instrument_id。
  2. 日线按“证券×年份”分区，从最近 2 年向历史倒推；近年先服务 API，历史后台补齐。
  3. 公司行动与因子完成后才开放 adjusted 查询；否则只开放 adjust=none。
  4. repair 只针对已知分区，必须填写 reason；不允许无边界的全市场人工重跑。

6. 复权与日/周/月上游直连

canonical 只保存未复权价格 P(d) 与稳定的累计后复权因子 F(d)。 AKShare 源码语义经实测确认：后复权价为 raw × hfq factor；前复权价可由后复权累计因子相对锚点得到。

hfq(d) = P(d) × F(d)
qfq(d, A) = P(d) × F(d) ÷ F(A)
none(d) = P(d)
其中 A = adjustAsOf；默认 min(请求 end, 最新已发布交易日)
  • F(d) 使用 numeric(38,18) 保存，禁止 float；每次因子修订生成新的 factor_version。
  • 查询响应必须返回 factorVersion、formulaVersion=cumulative-hfq-v1 和 adjustAsOf。
  • 成交量、成交额不复权；换手率为小数，0.01 表示 1%。
  • 复权结果在 API 查询层按 publication 版本计算，不落一套不断漂移的 qfq 表。

周/月线

周线和月线分别由 equity.bar.1w.raw、equity.bar.1mo.raw capability 调用 AKShare 对应周期接口获取。adapter 必须把周期参数封装在供应商边界内； application、quality 和 persistence 不读取日线计算周/月 OHLCV。

1d upstream → equity_daily_bar revision → daily publication
1w upstream → equity_weekly_bar revision → weekly publication
1mo upstream → equity_monthly_bar revision → monthly publication
  • 三个周期拥有独立 source batch、幂等键、checkpoint、质量结果和 data version。
  • 日线失败或修订不阻断、不重算周/月线；每个周期按自身上游返回独立修订。
  • 上游没有直接周期接口时，该 adapter 不声明对应 capability，禁止以日线聚合作为 fallback。
  • 周/月 raw K 线必须来自上游对应周期接口；可选 qfq/hfq 只在查询层对该 raw K 线应用已发布累计因子，不重构 OHLCV。
  • 停牌或无成交周期按上游原始语义保存，不造零值 K 线。

7. 数据质量、口径与发布闸门

数据集硬失败 / 隔离告警 / 观察
日/周/月行情 low ≤ min(open,close) ≤ max(open,close) ≤ high；负成交量/额；周期或单位校验失败；重复 period_end。 长时间缺失；收益异常；成交额/成交量隐含 VWAP 超出 OHLC 容差。
复权因子 因子 ≤0；日期乱序；重建源 qfq/hfq 误差 >0.02 元；锚点缺失。 因子跳变却无公司行动；公司行动存在但因子未变。
公司行动/概况 事件业务键重复；日期或十进制字段非法；公司名称缺失；schema 漂移。 公司行动与因子变化时间不一致；概况字段从非空异常变空。
成交量 100 倍错误的自动识别：对成交量>0的样本计算 implied_vwap = amount_cny / volume_shares。若其不在 [low×0.99, high×1.01]，该分区隔离。此规则可以捕获“手被误当成股”的常见错误。

缺失、零值与修订

  • 来源缺失是 null，绝不写 0；只有来源明确报告 0 才写 0。
  • 每个版本保留 observed_at/source_updated_at/valid_from/valid_to/source_batch_id；API 默认只读 current。
  • 跨来源比对只产生质量证据，不按字段“择优拼接”；来源差异应在 adapter/methodology 升级中解决。

8. PostgreSQL 表设计、分区与索引

使用 PostgreSQL canonical schema；金额和价格不使用浮点数。对外 instrument_id UUID 永久稳定，对内关联使用 security_id bigint 降低大表索引体积。

ORM 落地约束： 每张逻辑表必须在 infrastructure/database/models/ 下拥有一个 Declarative 模型文件并登记到 显式 registry.py；repository 通过短生命周期 Session 和模型表达式访问。 模型表达当前目标 schema，显式 Alembic revision 表达演进历史；禁止用 Base.metadata.create_all() 管理运行环境。年度物理子分区不创建独立 ORM class， 由 migration 或专用 partition manager 管理。

  valid_from        timestamptz     NOT NULL,
  valid_to          timestamptz,
  PRIMARY KEY (security_id, trade_date, revision),
  CHECK (low_price <= LEAST(open_price, close_price)),
  CHECK (high_price >= GREATEST(open_price, close_price)),
  CHECK (low_price <= high_price)
) PARTITION BY RANGE (trade_date);

CREATE TABLE equity_daily_bar_2026 PARTITION OF equity_daily_bar
  FOR VALUES FROM ('2026-01-01') TO ('2027-01-01');

CREATE UNIQUE INDEX uq_equity_daily_bar_2026_current
  ON equity_daily_bar_2026 (security_id, trade_date)
  WHERE valid_to IS NULL;

CREATE INDEX ix_equity_daily_bar_2026_read
  ON equity_daily_bar_2026 (security_id, trade_date DESC)
  INCLUDE (open_price, high_price, low_price, close_price,
           volume_shares, amount_cny, turnover_rate, final, revision)
  WHERE valid_to IS NULL;

8.4 方案边界

证券身份表由 0014 维护，本方案只以 security_id 外键引用；财务与估值表由 0016 维护， 不再作为方案 0011 的实现或验收项。这样行情链路不会因其他领域状态被阻塞。

  • 预计约 5,500 只在册证券，current 日线 2,500–4,000 万行；达到 8,000 万行或单年分区 >20GB 时复评月分区。
  • 以上容量为规划假设，运行后以真实平均行宽、索引命中率和 VACUUM 指标修正。

9. API 设计

使用两层契约：service-data-sync 暴露服务间 API，service-api 暴露认证用户 API。 路径与数据模型已落入 OpenAPI；禁止 controller 直接读取同步库。

公开端点（均为 POST）职责关键限制
/api/v1/equities 0014 提供的代码/名称前缀搜索 不属于方案 0011 实现。
/api/v1/equities/{exchange}/{symbol}/company-profile 当前已发布公司概况 exchange + symbol 精确身份；provider 字段和数据库键不外露。
/api/v1/equities/{exchange}/{symbol}/bars 1d/1w/1mo，none/qfq/hfq start/end 必填；默认 500、最大 2,000；HMAC 游标；调整锚点显式返回。
/api/v1/equities/{exchange}/{symbol}/adjustment-factors 稀疏累计因子序列 最大 500；HMAC 游标；只返回 current revision 与 factorVersion。
/api/v1/equities/{exchange}/{symbol}/corporate-actions 分红、送股、转增及状态 最大 100；HMAC 游标；日期范围过滤。

9.1 数据语义

  • 每个响应含 dataVersion、publishedAt、qualityStatus、stale 和可选 methodologyVersion。
  • 价格、成交额、换手率、因子和公司行动数值均以十进制字符串返回；数据库使用 numeric，不经过浮点数。
  • cursor 是不透明、带签名的查询位置，绑定过滤范围和 publication version；范围不匹配返回 400，版本变化返回 409。
  • ETag = hash(normalized_query + data_version + factor_version + formula_version)；公开 POST 命中 If-None-Match 返回 204。
  • 只读已发布 final 数据；请求区间含隔离/未发布分区时返回 409，而不是悄悄缺行。

9.2 service-api 行为

  • 沿用全局 bearer 鉴权；有效 USER、ADMIN、SUPER_ADMIN 均可读。同步控制端点不公开。
  • StockModule → DataSyncClient 单向依赖；默认请求预算 2 秒，财报详情 5 秒。
  • service-api 对内部同步服务的幂等 GET 可在总预算内重试 1 次；公开入口始终为 POST。熔断开启或下游失败统一映射 503 Problem Details，并返回 Retry-After。
  • 首期不在 service-api 建业务缓存或读模型，直接透传 ETag；Redis 仅可保存短期滥用计数，不能成为行情权威副本。
  • 所有错误采用现有 Problem Details 结构，保留 requestId，不返回上游 URL、异常栈或服务凭证。

9.3 内部同步控制

仅内部服务凭证可调用 POST /internal/v1/sync-runs，请求必须带 Idempotency-Key、能力、模式和最多 1,000 个有界分区。API 用户和前端不具备该权限。 

{
  "capability": "equity.bar.1d.raw",

  ],

10. 可靠性、可观测性与运行手册

SLO 与新鲜度预算

数据集目标新鲜度完整性 / 可用性目标
日/周/月行情各自调度窗口结束后三个周期独立成功或保留上一 publication；周/月失败不回退日线聚合。
复权/公司行动除权日前一晚或事件观测后 4 小时调整查询只有完整 factor publication 才开放。
公司概况每周刷新后内容哈希无变化不创建新 revision；字段清空受合并规则保护。
查询 API读取已发布数据月可用性 99.9%；列表/日线 p95 <300ms（同步服务内网）。

指标、日志与告警

  • 指标：run/partition 状态数、抓取延迟、重试率、上游错误率、raw 字节、解析行数、DQ 失败、publication lag、API p50/p95/p99。
  • 标签只使用 provider、capability、exchange、status、error_code；不得用 symbol/run_id 作为指标标签造成高基数。
  • 结构化日志包含 request_id、run_id、partition_id、source_batch_id；请求参数脱敏，响应体不进日志。
  • 告警：日/周/月 publication 延迟、VWAP 单位规则失败、因子覆盖不完整、schema drift、断路器持续 15 分钟。

恢复规则

  1. worker 崩溃：租约过期扫描器依据 PostgreSQL 重排，不依赖 Redis 中残留状态。
  2. raw 已写、canonical 未写：使用同一 source_batch 重放归一化，无需再次访问上游。
  3. 坏 publication：原子回指上一 data_version；已发布事实不原地 UPDATE。
  4. provider 漂移：打开断路器、隔离新批次、保留上一版本、升级 adapter/schema 并用 raw 回放验证。
  5. 灾难恢复：PostgreSQL 恢复 publication/catalog 后，按 raw URI + checksum 重建 canonical；Redis 可直接清空重建。

11. 安全与配置

  • 内部 API 使用可轮换 service bearer；只注入 service-api，浏览器永远不可见。健康检查无需认证但不输出依赖细节。
  • 对外 API 继续使用 service-api 现有 JWT、全局守卫和用户状态校验；记录用户级限流审计，不记录查询结果。
  • S3 raw bucket 默认私有、服务身份最小权限、生命周期按容量、重放窗口和备份策略配置；raw URI 不进入公开 API。
  • 新增环境变量同时更新 .env.example；生产 secret 不入库，不在日志或 Problem Details 出现。

13. 验收标准与上线清单

  • AKShare 日/周/月接口均有固定版本 fixture、schema、单位与失败样本。
  • 周/月 adapter 明确调用 period="weekly" 与 period="monthly"，测试断言 capability 和标准载荷周期一致。
  • 任何 provider/adapter/schema/methodology 版本变化都会产生可追溯新版本。
  • 重复任务、Redis 丢失、worker 崩溃不会重复写 current 数据或丢失权威状态。
  • 成交量 100 倍、OHLC 违反、因子不一致和 schema drift 均会阻止对应数据集发布。
  • 日、周、月各自重拉和修订；源码及架构测试证明不存在从日线聚合周/月路径。
  • 前/后复权响应返回锚点、因子和公式版本；周/月仅在上游存在对应直接接口时提供复权查询。
  • 关键查询在预期容量下使用分区裁剪和目标索引，EXPLAIN 无全表扫描。
  • 全部新增逻辑表均有 Declarative 模型并进入显式 registry；仓储只返回领域结果，不泄漏 ORM instance 或 Session。
  • 显式 Alembic migration、alembic check、PostgreSQL schema parity 与 upgrade/downgrade 验证通过。
  • service-api 只通过内部 HTTP 读取，认证、超时、503、冲突、ETag 和 HMAC 分页测试通过。
  • 迁移可回滚，上一 publication 可恢复，raw 可重放，告警和运行手册经过演练。

Go / No-Go

代码交付以接口签名、同步、建表、发布、分页、API 契约和自动化验证通过为完成条件。 目标环境的连续样本与容量观测仅决定 capability 开关是否启用，不再作为技术方案或其他数据集的阻塞项。
