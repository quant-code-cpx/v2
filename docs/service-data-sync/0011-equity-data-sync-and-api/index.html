个股数据同步、存储与查询 API 技术方案

面向沪深北 A 股，落地个股主数据、日/周/月行情、复权因子、公司行动、估值及财务报表。 方案以 AKShare 1.18.78 官方文档与 2026-07-26 独立容器实测为依据，不沿用 Tushare 或旧项目口径。

1. 执行摘要

本方案建立一条可追溯、可重跑、可版本化发布的个股数据链路。核心原则是： 同一 canonical 数据集在同一发布时间点只允许一种明确口径，来源切换必须显式产生新版本， 不能在失败时静默混入另一来源。

事实基线
1d raw
原始未复权日线是唯一行情事实；周/月线内部派生。
复权基线
F(d)
保存稳定的累计后复权因子；前/后复权查询时按版本计算。
服务边界
HTTP
service-api 仅通过内部版本化 API 读取，不直连同步库。
推荐立项：P0 先落地主数据、交易日历和未复权日线；P1 接入复权、公司行动、 三大财务报表与财务指标；估值作为 P1.5。实时行情、分钟线、资金流、股东与资讯不在本期。
上线前硬门槛：AKShare 明确主要用于学术研究，上游网站也可能存在授权限制。 生产使用前必须由法务/合规确认许可、访问频率和再分发边界；未通过时只允许研发环境使用。

3. AKShare 研究结论与来源路由

AKShare 是聚合库，不是单一数据源。相同领域接口背后可能分别来自交易所、东方财富、腾讯、 新浪或巨潮资讯；可用性、单位和修订语义不同。适配器必须按 capability 路由， 而不是按“AKShare”整体降级。

能力AKShare 接口 / 上游角色实测与约束
交易日历 tool_trade_date_hist_sina / 新浪 主 8,797 行，覆盖 1990-12-19 至 2026-12-31；年底前验证下一年覆盖。
证券主数据 stock_info_{sh,sz,bj}_name_code / 交易所 主 分交易所独立抓取与发布；单一交易所失败不得影响另两家，也不得把缺失误判为退市。

财务指标 Eastmoney financial analysis / 东方财富 主 单股实测约 0.8 秒、141 字段；区分 provider-reported 与内部派生方法。
历史估值 stock_value_em / 东方财富 主 实测单股 2,076 行，覆盖 2018-01-02 至 2026-07-24；保留方法版本。
禁止静默 fallback：主来源失败时分区进入 failed/quarantined， 对外保持上一已发布版本并标记 stale。切换来源需要配置审批、全量比对、数据版本升级和重新发布。

日线生产认证门槛

  1. 覆盖沪深北、主板/科创板/创业板/北交所、ST/停牌/退市样本，至少 300 只证券、连续 5 个交易日。
  2. 与交易所可核验样本或独立可信基准比对 OHLC、成交量、成交额；分板块输出偏差分布。
  3. 成交量单位修复必须以 instrument_type 判断，不以代码字符串特判。
  4. 认证结果固定到 provider_version + adapter_version + methodology_version；任一变化重跑。

5. 数据同步逻辑

5.1 通用状态机与幂等

调度器先在一个事务中创建 sync_run 与确定性 sync_partition， 再发送 Celery 消息。消息采用至少一次投递；worker 使用 (capability, partition_key, requested_window, methodology_version) 生成幂等键。

queued → running → succeeded → published
         ↘ quarantined
         ↘ retry_wait → running
         ↘ failed
run = succeeded | partial | failed | cancelled
  1. worker 通过 SELECT … FOR UPDATE SKIP LOCKED 获取租约；同分区只允许一个有效 worker。
  2. 请求成功后先写 S3 raw，记录 SHA-256、provider/adapter 版本、请求参数和观测时间。
  3. 归一化到 staging；执行 schema、单位、业务和跨批次校验。
  4. 通过后在事务中关闭旧版本、插入新版本、更新分区计数；相同业务哈希不产生新修订。
  5. 整批质量闸门通过后原子切换 dataset_publication；查询永远不读 staging。

5.3 抓取节流、重试与变更探测

  • 每个上游建立独立 Celery 队列和 token bucket；初始安全值为并发 1、请求间隔至少 2 秒并加抖动，压测与授权确认后再调整。
  • 连接/超时/5xx 最多重试 3 次，指数退避加全抖动；4xx、字段缺失或解析漂移直接隔离，不盲重试。
  • 财务单股接口按实测设置连接/读取总预算 90 秒，单任务软上限 120 秒；队列不得占用日线 worker。
  • 连续 10 次或 5 分钟窗口 50% 失败打开 circuit breaker；半开探测成功后逐步恢复。
  • 全市场摘要只产生“可能变化”的 manifest，最终仍以单股完整响应的业务哈希判断是否修订。

5.4 初始回填与修复

  1. 先加载交易日历与证券主数据，冻结 instrument_id。
  2. 日线按“证券×年份”分区，从最近 2 年向历史倒推；近年先服务 API，历史后台补齐。
  3. 公司行动与因子完成后才开放 adjusted 查询；否则只开放 adjust=none。
  4. 财务先回填最近 12 个报告期，再补全历史；每个 statement_type 独立发布。
  5. repair 只针对已知分区，必须填写 reason；不允许无边界的全市场人工重跑。

6. 复权与周/月线算法

canonical 只保存未复权价格 P(d) 与稳定的累计后复权因子 F(d)。 AKShare 源码语义经实测确认：后复权价为 raw × hfq factor；前复权价可由后复权累计因子相对锚点得到。

hfq(d) = P(d) × F(d)
qfq(d, A) = P(d) × F(d) ÷ F(A)
none(d) = P(d)
其中 A = adjustAsOf；默认 min(请求 end, 最新已发布交易日)
  • F(d) 使用 numeric(38,18) 保存，禁止 float；每次因子修订生成新的 factor_version。
  • 查询响应必须返回 factorVersion、formulaVersion=cumulative-hfq-v1 和 adjustAsOf。
  • 成交量、成交额不复权；换手率为小数，0.01 表示 1%。
  • 复权结果在 API 查询层按 publication 版本计算，不落一套不断漂移的 qfq 表。

周/月线

未复权周/月线从日线聚合。复权周/月线必须先逐日复权，再聚合，不能先聚合 raw OHLC 后只乘期末因子； 周/月内发生除权时，后者会产生错误的开高低收。

open = first(adjusted_open)
high = max(adjusted_high)
low = min(adjusted_low)
close = last(adjusted_close)
volume_shares = Σ daily_volume_shares
amount_cny = Σ daily_amount_cny

停牌日不造零值 K 线；周期的 session_count 是实际有行情记录的交易日数量。

7. 数据质量、口径与发布闸门

数据集硬失败 / 隔离告警 / 观察
主数据 交易所内代码重复；代码格式非法；单次在册数量下降 >1%；上市日晚于退市日。 腾讯发现表与交易所集合差异；名称变化未在历史表出现。
日线 low ≤ min(open,close) ≤ max(open,close) ≤ high；负成交量/额；非交易日记录；单位校验失败。 长时间缺失但证券状态为 LISTED；日收益异常；与影子来源偏差。
复权因子 因子 ≤0；日期乱序；重建源 qfq/hfq 误差 >0.02 元；锚点缺失。 因子跳变却无公司行动；公司行动存在但因子未变。
财务 报告期非法；主键字段缺失；未知字段比例超阈值；结构漂移；数值无法无损解析。 资产=负债+权益误差超过 max(1元, 资产×1e-6)；公告日异常。
估值 日期无 final 行情；分母语义缺失；单位未知。 市值与价格×股本偏差 >1%；负 PE 允许但需保留，不改为 null。
成交量 100 倍错误的自动识别：对成交量>0的样本计算 implied_vwap = amount_cny / volume_shares。若其不在 [low×0.99, high×1.01]，该分区隔离。此规则可以捕获“手被误当成股”的常见错误。

缺失、零值与修订

  • 来源缺失是 null，绝不写 0；只有来源明确报告 0 才写 0。
  • 财务利润表/现金流量表保持来源的年初至今（YTD）语义；单季度和 TTM 是带方法版本的派生指标。
  • 每个版本保留 observed_at/source_updated_at/valid_from/valid_to/source_batch_id；API 默认只读 current。
  • 跨来源比对只产生质量证据，不按字段“择优拼接”；来源差异应在 adapter/methodology 升级中解决。

  close_price       numeric(20,6)   NOT NULL CHECK (close_price >= 0),
  volume_shares     bigint          NOT NULL CHECK (volume_shares >= 0),
  amount_cny        numeric(24,4)   NOT NULL CHECK (amount_cny >= 0),
  turnover_rate     numeric(16,10),
  final             boolean         NOT NULL,
  content_hash      bytea           NOT NULL,
  source_batch_id   uuid            NOT NULL REFERENCES source_batch(source_batch_id),
  valid_from        timestamptz     NOT NULL,
  valid_to          timestamptz,
  PRIMARY KEY (security_id, trade_date, revision),
  CHECK (low_price <= LEAST(open_price, close_price)),
  CHECK (high_price >= GREATEST(open_price, close_price)),
  CHECK (low_price <= high_price)
) PARTITION BY RANGE (trade_date);

CREATE TABLE equity_daily_bar_2026 PARTITION OF equity_daily_bar
  FOR VALUES FROM ('2026-01-01') TO ('2027-01-01');

CREATE UNIQUE INDEX uq_equity_daily_bar_2026_current
  ON equity_daily_bar_2026 (security_id, trade_date)
  WHERE valid_to IS NULL;

CREATE INDEX ix_equity_daily_bar_2026_read
  ON equity_daily_bar_2026 (security_id, trade_date DESC)
  INCLUDE (open_price, high_price, low_price, close_price,
           volume_shares, amount_cny, turnover_rate, final, revision)
  WHERE valid_to IS NULL;

8.4 财务 facts 取舍

三表接口单表可达 200–319 列。第一阶段采用“版本头 + canonical JSONB facts”，数值以十进制字符串保存， 避免 JSON float 精度损失；常用且需时间序列查询的指标另写 financial_metric_value。 这比全量 EAV 少一个数量级的行数和索引写放大。

  • 不对 facts 建通用 GIN；财报详情按 report_id 读取整行。
  • 只有进入公开契约的 canonical item code 才写 facts；未知源字段保留在 raw，不自动进入 API。
  • 预计约 5,500 只在册证券，current 日线 2,500–4,000 万行；达到 8,000 万行或单年分区 >20GB 时复评月分区。
  • 以上容量为规划假设，P0 pilot 后以真实平均行宽、索引命中率和 VACUUM 指标修正。

9. API 设计

使用两层契约：service-data-sync 暴露服务间 API，service-api 暴露认证用户 API。 路径与数据模型已落入 OpenAPI；禁止 controller 直接读取同步库。

公开端点（均为 GET）职责关键限制
/api/v1/equities 代码/名称前缀搜索，交易所与状态过滤 cursor；默认 50，最大 100；稳定排序 exchange,symbol,instrumentId。
/api/v1/equities/{instrumentId} 主数据和当前公司资料 UUID 标识；provider 字段不外露。
…/{instrumentId}/bars 1d/1w/1mo，none/qfq/hfq start/end 必填；默认 500、最大 2,000；调整锚点显式返回。
…/{instrumentId}/adjustment-factors 稀疏累计因子序列 最大 500；只返回 current revision 与 factorVersion。
…/{instrumentId}/corporate-actions 分红、送股、转增及状态 最大 100；日期范围过滤。
…/{instrumentId}/financial-reports 财报版本头列表 三表过滤；默认 20、最大 50。
…/financial-reports/{reportId} 单张报表 canonical items 最大 500 项；缺失值为 null。
…/{instrumentId}/financial-metrics reported / single-quarter / TTM 指标 最多 50 个 metric code；最大 500 行；返回 methodologyVersion。

9.1 数据语义

  • 每个响应含 dataVersion、publishedAt、qualityStatus、stale 和可选 methodologyVersion。
  • 金额与财务精确数值在财报 item/factor 使用十进制字符串；行情价格为 JSON number，数据库仍用 numeric。
  • cursor 是不透明、带签名的查询位置，编码排序键、过滤哈希和 publication version；版本变化时旧 cursor 返回 400。
  • ETag = hash(normalized_query + data_version + factor_version + formula_version)；支持 If-None-Match/304。
  • 只读已发布 final 数据；请求区间含隔离/未发布分区时返回 409，而不是悄悄缺行。

9.2 service-api 行为

  • 沿用全局 bearer 鉴权；有效 USER、ADMIN、SUPER_ADMIN 均可读。同步控制端点不公开。
  • EquityModule → DataSyncClient 单向依赖；默认请求预算 2 秒，财报详情 5 秒。
  • 幂等 GET 可在总预算内重试 1 次；熔断开启或下游失败统一映射 503 Problem Details，并返回 Retry-After。
  • 首期不在 service-api 建业务缓存或读模型，直接透传 ETag；Redis 仅可保存短期滥用计数，不能成为行情权威副本。
  • 所有错误采用现有 Problem Details 结构，保留 requestId，不返回上游 URL、异常栈或服务凭证。

9.3 内部同步控制

仅内部服务凭证可调用 POST /internal/v1/sync-runs，请求必须带 Idempotency-Key、能力、模式和最多 1,000 个有界分区。API 用户和前端不具备该权限。 

{
  "capability": "equity.bar.1d.raw",
  "mode": "repair",
  "partitions": [
    { "key": "SSE.600519/2026-07-01..2026-07-24" }
  ],
  "reason": "DQ-2026-071: repair certified volume-unit normalization"
}

10. 可靠性、可观测性与运行手册

SLO 与新鲜度预算

数据集目标新鲜度完整性 / 可用性目标
主数据交易日 07:00 前三个交易所独立成功；上一版可读。
日线95% 在 17:30 前，最终修订在次日 07:00 前在册可交易证券成功或有解释性缺失 ≥99.5%。
复权/公司行动除权日前一晚或事件观测后 4 小时调整查询只有完整 factor publication 才开放。
财务来源公告可见后 24 小时manifest 命中证券三表独立追踪，不因一表失败丢失另两表。
查询 API读取已发布数据月可用性 99.9%；列表/日线 p95 <300ms（同步服务内网）。

指标、日志与告警

  • 指标：run/partition 状态数、抓取延迟、重试率、上游错误率、raw 字节、解析行数、DQ 失败、publication lag、API p50/p95/p99。
  • 标签只使用 provider、capability、exchange、status、error_code；不得用 symbol/run_id 作为指标标签造成高基数。
  • 结构化日志包含 request_id、run_id、partition_id、source_batch_id；请求参数脱敏，响应体不进日志。
  • 告警：日线 17:30 未发布、交易所主数据下降 >1%、VWAP 单位规则失败、财务 schema drift、断路器持续 15 分钟。

恢复规则

  1. worker 崩溃：租约过期扫描器依据 PostgreSQL 重排，不依赖 Redis 中残留状态。
  2. raw 已写、canonical 未写：使用同一 source_batch 重放归一化，无需再次访问上游。
  3. 坏 publication：原子回指上一 data_version；已发布事实不原地 UPDATE。
  4. provider 漂移：打开断路器、隔离新批次、保留上一版本、升级 adapter/schema 并用 raw 回放验证。
  5. 灾难恢复：PostgreSQL 恢复 publication/catalog 后，按 raw URI + checksum 重建 canonical；Redis 可直接清空重建。

11. 安全、配置与合规

  • 内部 API 使用可轮换 service bearer；只注入 service-api，浏览器永远不可见。健康检查无需认证但不输出依赖细节。
  • 对外 API 继续使用 service-api 现有 JWT、全局守卫和用户状态校验；记录用户级限流审计，不记录查询结果。
  • S3 raw bucket 默认私有、服务身份最小权限、生命周期按许可和审计要求配置；raw URI 不进入公开 API。
  • 新增环境变量同时更新 .env.example；生产 secret 不入库，不在日志或 Problem Details 出现。

13. 验收标准与上线清单

  • AKShare 与上游许可、频率、保留和再分发范围已有书面结论。
  • 日线来源认证覆盖 300 只证券、四类板块、特殊状态和连续 5 个交易日。
  • 任何 provider/adapter/schema/methodology 版本变化都会产生可追溯新版本。
  • 重复任务、Redis 丢失、worker 崩溃不会重复写 current 数据或丢失权威状态。
  • 主数据异常下降、成交量 100 倍、OHLC 违反、因子不一致、财务 schema drift 均会阻止发布。
  • 日线修订能只重算受影响周/月；前/后复权响应返回锚点、因子和公式版本。
  • 财报保留报告期、公告/更新时间、YTD 语义和历史修订；缺失不转换为 0。
  • 关键查询在预期容量下使用分区裁剪和目标索引，EXPLAIN 无全表扫描。
  • service-api 只通过内部 HTTP 读取，认证、限流、超时、熔断、503 和 ETag 测试通过。
  • 迁移可回滚，上一 publication 可恢复，raw 可重放，告警和运行手册经过演练。

Go / No-Go

只有“来源合规、日线认证、数据质量、故障回滚、API 契约”五项同时通过才允许生产发布。 任一项未通过，系统只能继续 shadow 抓取或仅提供上一已认证版本。
