结论

事实

6 项有成功返回

公司概况、交易日历、可转债、同花顺目录、基金目录、上交所期权分片均取得结构化结果。

决策

Tushare 仍为 B01 主路由

AKShare 只保留候选证据；未配置任何生产 fallback，也未创建真实 adapter。

主要风险

多底层站点当前不稳定

上交所、乐咕乐股、东方财富部分请求出现 45 秒超时、断连或 TLS EOF。

本轮决定： B01 继续调研，不提前宣告 AKShare 可主用。结论来自一次执行，仅用于缩小下一步验证范围； FULL 仍要求连续 3–5 个交易日观察、字段映射评审与底层来源使用边界确认。

与旧 Tushare 基线的共性差异

身份与历史有效期

AKShare 多数候选只给当前目录或日期列表。旧模型常要求上市/退市、进入/退出、是否最新和来源版本；这些不能靠“本次快照”推导。

全量与详情拆分

可转债最明显：全量列表轻量，条款详情逐债取得。后续需评估首次回填时长、并发、限流、断点和增量识别。

板块与期权并非统一目录

同花顺板块只观测到概念/行业目录；期权接口按交易所、标的、到期月切片。不能把若干局部接口包装成“完整 master”。

静态 schema 不等于稳定契约

同一 AKShare 版本中，部分来源可返回大量数据，部分站点直接超时或断连。adapter 需要把来源失败、空结果与 schema 漂移分开处理。

映射约束： 这些仅是研究映射方向，不是 canonical schema 决策。缺少的字段不得以默认值、抓取时刻或反向猜测填充； 例如交易日历的闭市日、申万成分退出日、基金管理人和期权行权信息必须由明确来源提供。

可靠性与合规

事实

来源脆弱性已实测

本轮出现 SSE 超时、乐咕乐股超时、SZSE TLS EOF、东方财富远端断连。它们应在未来 adapter 中归为 provider 可观测事件，不可吞掉。

事实

AKShare 本身为 MIT

官方仓库采用 MIT；但官方声明数据仅供学术研究参考，接口可能被移除。代码许可证不替代各底层网站的数据使用条款。

决策

没有授权结论就不进生产

每项最终路由仍需核查巨潮、交易所、同花顺、东方财富、新浪、乐咕乐股等底层来源的使用与再分发边界。

禁止推断： AKShare 免费、MIT 或一次调用成功，都不能推导出可商业使用、可再分发、可长期稳定运行或可替代 Tushare。

B01 继续条件

  1. 稳定性窗口：在未来 3–5 个交易日，以相同镜像和 AKShare 版本重跑成功候选；记录成功率、空结果、耗时分位和 schema fingerprint。
  2. 失败复测：将上交所、深交所、乐咕乐股、东方财富失败项按来源拆分复测，确认是站点临时异常、网络策略还是接口失效。
  3. 语义矩阵：对可转债、公司概况、日历、基金与期权完成字段级映射；为每个缺失字段标注“可由其他 AKShare 正式接口补足”或“只能由 Tushare 提供”。
  4. 合规核查：记录每个底层来源的页面、条款、访问频率限制和再分发结论；没有证据的项不得升级为 FULL。
  5. 架构保持：后续若提交探针或真实接入，只能位于 infrastructure/providers/akshare/；应用、任务、质量、持久化层仍只依赖 DataSourcePort。

下一优先项

先深挖可转债：它已有全量清单和详情双源，最有机会在 B01 稳定性与全量成本验证后获得可用的受限结论。

明确不做

本轮不建业务表、不接 Celery、不改 API、不创建生产 adapter、不改来源路由，也不把临时探针作为服务代码提交。
