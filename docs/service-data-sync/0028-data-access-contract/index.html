Technical solution · service-data-sync · 0028

高价值市场数据访问契约

由 service-data-sync 统一发布八类 canonical dataset，并通过两个版本化、 POST-only 内部 HTTP 端点供 service-api 发现与查询。方案固定 dataVersion、PIT 可见性、质量与来源边界；不共享数据库、不访问 Provider、 不引入事件平台或 API 自有完整读模型。

1. 结论与评审摘要

建议

v1 只采用内部 HTTP

新增 dataset catalog 与 query 两个 POST 端点。事实由 data-sync 发布，API 只消费显式合同。

关键不变量

一页一个发布版本

dataset schema、dataVersion、方法学、来源集合、质量与排序都绑定游标，禁止混页。

不采用

不做事件与完整读模型

当前没有 durable broker、outbox、registry、DLQ、replay 或 inbox；事件需新 ADR。

可评审结论 建议批准“合同方向与边界”，但保持全部产物为 Proposed。只有机器合同、认证隔离、PIT golden fixture、过载恢复与无直连门禁全部通过，某个 dataset 才能进入实现与灰度。
标记内容对方案的影响
事实 现有数据访问遵循 data-sync owning + 版本化内部 HTTP；API 客户端已有 Bearer、超时和运行时 DTO 校验模式。 复用边界与模块模式，不修改既有 GET 合同。
事实 当前跨服务环境没有可承担事实流的 durable broker、transactional outbox、schema registry、DLQ/replay/inbox。 事件不能作为本期生产路径；Celery/Redis 不冒充事件总线。
拟议初值 总 deadline 5s、请求 64KiB、响应 2MiB、身份 100、字段 64、最大页 500、日频窗口 366 天。 压测后可收紧或按 dataset 分级；不表示已满足生产 SLO。
未决 工作负载身份采用短期 JWT、mTLS 绑定 token 或服务网格身份。 不阻断文档评审；进入预发前必须满足安全门禁。

3. 通信方式裁决

候选优势主要代价/风险契合现状裁决
内部 POST HTTP 查询 按需筛选；可固定版本；合同与客户端可独立测试；无需复制事实 多一次网络跳转；需要分页、限流、熔断和 data-sync 查询容量 已有内部 HTTP、Bearer、DTO 校验和 Problem 映射模式 v1 采用
完整事实事件 + API 读模型 读性能高；消费者运行时解耦；可推送 顺序、修订、撤回、重放、双存储、灾备复杂；PIT 投影很难证明 缺 broker/outbox/registry/DLQ/inbox/read model 不采用
发布通知事件 + HTTP 拉取 减少轮询；事实仍由 data-sync 查询 仍需完整可靠事件基础设施，收益要由多个消费者或低延迟需求证明 可作为平滑演进方向 另 ADR
共享 DB / 只读账号 少一次网络跳转；SQL 灵活 绕过 publication/质量；schema、权限、迁移、恢复强耦合 违反仓库边界和 ADR-0002 永久排除

3.1 service-api 的实际消费路径

  1. 公开领域 Controller 完成用户认证、权限、参数与成本校验。
  2. 领域 Service 把公开 DTO 映射为 dataset code、canonical UUID、业务时间、PIT 和字段白名单。
  3. DataSyncModule 中的 MarketDataAccessClient 调用内部 POST；用户 JWT 不出站。
  4. 客户端严格校验响应，拒绝未知 record type、质量未知、版本变化、超限或 schema drift。
  5. 领域 Service 只投影公开字段、来源摘要、版本、质量、可见时间与免责声明。

API 影响详见 0005 市场数据访问影响方案。

机器可读定义：data-sync-market-data-v1.yaml （OpenAPI 3.1.1，info.version: 1.0.0，Proposed，命名按用户指定， 因而不沿用既有编号 + .openapi.yaml 文件名）。

POST endpoint用途成功重要约束

7. 服务身份、授权与审计

现状差距（事实） 当前内部认证是单一静态 bearer，尚不是可轮换的细粒度工作负载身份；游标签名也不能继续复用同一字节。 这不是调研阻断，但属于进入预发前的安全硬门禁。
层拟议控制失败行为
传输与网络TLS；仅 service-api workload/网络 allowlist 可达；生产不暴露公网握手或来源不可信直接拒绝并告警
身份专用 service identity，audience=data-sync，scope=market-data:read；不转发用户 JWT内部 401；API 对外 503，不泄漏身份细节
dataset 权限身份 → dataset/domain/PIT/replay/字段/批量成本策略；默认拒绝403；不做旧路径回退
游标签名独立 HMAC keyring：current/previous + keyId + TTL；轮换演练篡改/过期/未知 key 返回 409，不降级 offset
日志脱敏记录 requestId、caller、dataset、范围摘要、dataVersion、耗时、结果码、成本；不记 token、完整标识列表、raw payload检测到秘密/PII 即阻断发布并清理日志
来源许可字段级 redistribution 状态与 scope；响应只给真实发布者摘要许可未知时字段不可公开，不以 AKShare 可调通代替授权

审计日志只证明“谁在何时以何参数摘要读取了哪个发布版本”，不作为业务事实或幂等存储；读取本身无副作用、可安全重试。

8. 超时、重试、限流、熔断、缓存与恢复

8.1 Proposed 起始预算

控制初始值设计理由校准/兜底
总 deadline客户端 5s；首尝试最多 2s给一次短抖动重试留预算，避免每次 attempt 重新计时按 dataset 压测；超时返回 504，无部分页
重试最多 1 次，50–150ms full jitter仅读取且版本稳定；network/timeout/502/503/504429、4xx 不重试；总预算耗尽即停止
请求/响应64KiB / 2MiB保护 JSON 解析、网络和内存超限 413；缩字段/身份/时间，不做局部结果
查询上限1 dataset、100 identities、64 fields、3 sort、500 rows保持单发布语义和有界成本批量/导出另行合同，不扩大交互 API
默认日频窗口366 天覆盖常见一年分析且限制扫描catalog 可按域收紧；长回补走离线流程
熔断按 dataset 成本桶；阈值压测后定衍生品/批量 PIT 不拖垮 P0 latest高成本桶熔断，低成本桶继续；无陈旧伪数据

8.2 限流与成本

采用“caller + dataset + visibility mode + 时间跨度 + 身份数 + 字段数”的加权令牌桶，而不是只看 QPS。 PIT、OPERATIONAL_REPLAY、衍生品期权链与大窗口成本更高。data-sync 返回 429 和有界 Retry-After；API 不在同一用户请求中自动重试 429，防止放大。

8.3 缓存与幂等

  • data-sync 查询不产生业务副作用；规范化 body、选定 UUID dataVersion 与版本绑定 cursor 使重试稳定。
  • knownDataVersion 命中可返回 204，是私有应用协议；没有 If-None-Match/ETag 共享缓存承诺。
  • API 仅可使用非权威有界私有缓存，key 必须包含权限投影 hash、规范化请求、dataset schema、方法学和 dataVersion。
  • CURRENT 缓存短 TTL 并重查版本；固定 dataVersion/PIT 可延长，但 publication 归档后要安全 miss。
  • Redis 当前只承载安全状态，不能未经独立设计变为权威市场数据缓存；缓存故障必须退回 HTTP 或 503。

8.4 故障与恢复矩阵

故障检测运行行为恢复数据完整性保证

添加 optional 字段也采用 consumer-first：先让严格消费者接受，再由 provider 发送。字段删除、必填增加、 类型/单位/空值/时区/可见性变化、枚举收窄、排序/游标、权限和错误语义变化都需 major。Proposed 弃用基线为并行 ≥90 天、≥2 个稳定发布周期且旧版连续 30 天调用量为 0。

9.2 事件何时重新评估

以下任一信号只触发新 ADR：生产消费者 ≥3 且持续 30 天；批准的发布可见 P95 <60s 而轮询无法满足； 去除无效轮询后探测仍连续 5 个交易日占读取容量 >20%；或 HTTP 优化后连续 5 日违反已批准 SLO。

候选只能是 publication notification（dataset、partition、dataVersion、publishedAt）+ HTTP 拉取。 新 ADR 必须先补齐 broker、transactional outbox、AsyncAPI/registry、每键顺序、至少一次投递、 retention/replay、DLQ、inbox/消费幂等、读模型和灾备测试；本方案不接受 topic 或 schema。

9.3 灰度与回滚序列

  1. 冻结 YAML 与八域 fixture；执行 provider/consumer 合同校验。
  2. data-sync 只部署 catalog/query，dataset 默认 DISABLED；不注册公开路由。
  3. service-api shadow 双读旧 GET 与新 POST，对比 rows、业务时间、来源、质量、dataVersion；不向用户返回新结果。
  4. 按 dataset allowlist 开启内部读取，再按公开路由 1% → 10% → 50% → 100% 放量。
  5. 观察错误率、P95、429、熔断、schema drift、PIT 差异和缓存命中；逐域独立推进。
  6. 回滚 feature route 到旧 client 或 fail-closed 503；保留不可变历史，不删除 publication、不改写 raw。

12. 假设、未决事项与引用

12.1 显式假设

  • A1 API 消费是交互式有界查询，首期不需要批量导出或秒级推送。
  • A2 0027 的 UUID publication、dataset catalog 和质量发布模型先于本合同实现。
  • A3 每个公开字段都能映射到 typed domain value；不能映射的字段不进入 v1。
  • A4 Proposed 上限与 90 天弃用基线可由压测和实施评审调整，但不得弱化不变量。

12.2 未决事项

  • 短期 JWT、mTLS 绑定 token 或服务网格身份的最终选择；

  • 具体公司事件子 dataset 与衍生品辅助 dataset 的最终 code；
  • 授权受限字段的用户 entitlement 与免责声明文本。

空数据不是故障 依 ADR-0022，已注册 capability 的首个同步可以没有事实：data-sync 记录 EMPTY 或 SOURCE_UNAVAILABLE observation，读取仍返回 200 与空记录集。 事实表不写全空行，业务主键、金额、日期和单位约束保持不变。
