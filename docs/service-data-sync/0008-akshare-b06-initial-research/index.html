Research note · 0008

AKShare B06 资金流与特殊交易首轮调研

以旧项目十项 Tushare 能力为基线，验证 AKShare 的资金流、沪深港通、两融、龙虎榜与大宗交易候选。结论是：连通、两融、龙虎榜和大宗交易已有可映射候选；三类资金流在同一隔离环境连续两轮失败，暂不具备同步准入条件。

摘要

问题

同一批能力的底层来源差异很大

旧系统把十项能力都交给 Tushare；AKShare 则分散在东方财富、上交所、深交所、北交所与新浪。字段相似不代表日期、币种、单位或稳定性相同。

决策

按能力，而不是按 SDK 整体准入

本轮只确认候选与限制。未来必须由 provider-neutral port 选择 provider adapter；任何任务、领域或持久化层都不允许直接调用 AKShare。

主要风险

资金流候选不可稳定读取

个股、板块、市场三类资金流均在两轮中失败。即使官方文档列出接口，也不能作为可调度同步能力。

本轮没有任何生产变更未创建表、迁移、接口、同步任务或 AKShare adapter。探针为临时 Docker 容器，只读取公开数据，结束后销毁。

旧 Tushare 基线与本轮问题

能力清单来自 0002 数据总纲，旧 Prisma 模型与同步任务只作为字段、日期和调度基线，不复用其实现。金额、数量与百分比的单位必须逐字段确认，不能以列名推断。

逐项准入结论

条件候选 表示已看到字段与样本，仍需连续性、单位和全量范围验证；部分候选 表示只能覆盖部分旧契约；暂不准入 表示稳定性或时间范围已阻断当前使用。三种状态都不是“已上线”。

Capability首轮结论映射/缺口进入实现前的退出条件
equity.moneyflow暂不准入文档候选缺旧买卖双边量/额；两轮断连。交易日连续窗口内成功、确认分单阈值与字段补齐方案。
sector.moneyflow暂不准入当前排名与单板块历史均失败；行业/概念/地域与旧分类未对齐。三类分类均可读，冻结分类版本与代码映射。
market.moneyflow暂不准入两轮断连；历史窗口、单位未实测。固定样本成功且与旧市场范围、金额单位对账。
connect.moneyflow条件候选日终汇总与北向历史可读；旧模型需要多个方向并且单位不同。验证 沪股通/深股通/北向/港股通沪/港股通深/南向 六路拼装及缺失日。
connect.ggt_daily部分候选港股通沪历史含买/卖成交额；不含旧模型买/卖笔数。确认港股通深同构、币种与笔数的替代来源或契约降级 ADR。
margin.detail部分候选沪/深/北交易所接口不同，深市本轮失败，且字段不等价。三所交易日复验；为每个缺失字段定义允许空值、派生规则或回退 provider。
connect.stock_holding暂不准入个股历史截至 2024-08-16，不能满足当前日常同步。找到持续发布来源，或明确只能作为历史回填而非增量任务。
market.top_list条件候选东方财富详情覆盖旧买/卖/净额、占比、原因等核心字段。验证长日期区间分页、同股多原因去重键、量纲和交易所覆盖。
market.top_institution部分候选只有机构汇总，缺席位名称、成本与方向明细。定位明细候选；若只保留汇总，先以 ADR 修改 canonical 契约。
market.block_trade条件候选字段覆盖旧模型，新增折溢率和流通市值占比。验证近期交易日、全市场范围、成交量/额单位与跨日幂等键。

架构边界与路由原则

scheduler / manual trigger
          │
          ▼
application use case ──▶ provider-neutral DataSourcePort
                                  │
                  provider router │ capability + date + market
                     ┌────────────┴────────────┐
                     ▼                         ▼
              AKShare adapter            Tushare adapter
                     │                         │
                     └──── raw response ───────┘
                                  │
                                  ▼
                   canonical mapper / quality gate / repository
不变规则

外部调用只在 adapter

供应商 SDK、HTTP 地址、原始字段名只能留在对应 adapter。adapter 只返回 provider DTO，不写 canonical 数据库。

路由

优先级不等于强行调用

AKShare 仍是默认优先 provider；但被标为“暂不准入”的能力必须由路由配置直接选择其他可用 provider，不能把失败当成业务正常路径。

数据质量

先记录来源，再做换算

canonical 映射要保存 provider、接口版本、抓取时间、原始日期与换算规则；金额、数量、币种与时区在 quality gate 前显式校验。

与用户约束一致这张图是未来实现边界，不是本轮代码。禁止业务任务直接 import akshare，也禁止 adapter 直接入 canonical 表。

下一步与验收

  1. 交易日连续复验：对 47–49、深市两融及 50–56 候选固定样本各跑至少 5 个交易日；记录成功率、耗时、最新数据日与重试后结果。
  2. 口径对账：选择同一交易日，与旧 Tushare 样本逐字段比对。金额统一单位、证券代码规范、零/空值、买卖方向和缺失日必须有明确规则。
  3. 只为通过者设计 adapter 契约：先写 provider DTO、mapper、质量规则与 adapter 测试；再决定是否需要新增 canonical 字段或 ADR。仍不创建同步任务、表或 API。

首要风险

东方财富资金流候选连续失败。它们需要独立监测，且不能拖累其他可读能力的调研与后续实现。

待定

港股通买卖笔数、机构席位明细、两融缺失字段是否由 Tushare 保留为能力级回退，需在字段对账后决定。

外部证据

AKShare 股票数据文档列出了本轮候选、参数、字段、单位与持股历史截止日；版本更新记录显示部分龙虎榜接口曾修复，故需固定版本并持续复验。
