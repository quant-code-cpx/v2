1. 结论：数据有价值，来源与点时语义必须先收紧

建议

P1 有条件接入

主营构成适合基本面归因、业务集中度、毛利结构和同公司历史变化分析。 先形成年报、半年报的保守 point-in-time 数据集；不把季度、预测值或后续重述提前纳入。

方案

官方披露定时，结构化来源取数

官方交易所/巨潮定期报告是内容与首次公开时间的证据；结构化 Provider 是采集通道。 两者按明确证据键关联，来源不等价时保持独立 revision，不静默拼接。

最大风险

今天的历史全量不是历史当时版本

stock_zygc_em 返回当前可见的全历史快照，却不返回公告日、更新时间或修订编号。 历史回补若把报告期当可见日，将直接制造未来函数。

优先级 范围 接入结论 退出条件
P0 来源证据、字段映射、公告时间、raw snapshot、点时规则和质量 fixture 建议立即做技术验证；只产 research/shadow，不对策略发布。 技术门禁 G1–G4 有可验证证据。
P1 A 股年报/半年报，行业/产品/地区三类报告值，point-in-time 查询 建议接入；这是首个 production 候选范围。 幂等、恢复、修订、对账、契约和权限验收通过。
P2 销售模式、经营分部附注、跨语言标签映射、季度与跨市场扩展 暂不接入；与本数据集相邻但口径不同。 独立方法学和消费者需求明确后另行评审。
不可违反的不变量 报告期仅表示业务归属期，不表示市场已经看到；行业、产品、地区是同一经营结果的三种观察维度， 不能跨维度相加；管理层讨论中的“主营构成”也不能与《企业会计准则第 35 号》的经营分部附注静默混成一套事实。

2. 业务价值、目标用户与边界

目标用户

  • 基本面研究员：识别收入来源、成本结构和毛利驱动。
  • 量化研究员：构建业务集中度、结构迁移、毛利稳定性因子。
  • 投研产品用户：查看公司历期行业/产品/地区构成。
  • 数据运营：追踪披露缺口、修订、单位和来源差异。

首期消费场景

  • 按报告期查看主营收入、成本、利润和毛利率结构。
  • 同一公司、同一维度、同名披露项的历史变化。
  • 截至指定 asOf + knownAt 的无前视快照。
  • 与同口径财务报表收入做覆盖率与差异对账。

明确非目标

  • 不自动把公司自定义产品标签映射为统一产业分类。
  • 不把主营构成替代财务报表或经营分部附注。
  • 不计算未来收益、公告后表现或事后行业归因。
  • 不在本文定义共享证券、来源、任务或 publication 表。

3. 事实、推断、建议与未决

事实

现行年报规则要求结构披露

证监会公告〔2025〕3 号自 2025-07-01 施行。对营业收入或营业利润占比 10% 以上的 行业、产品、地区、销售模式，要求分项列示营业收入、营业成本和毛利率并分析变动。

事实

AKShare 字段不含可见时间

固定版本 1.18.78 的 stock_zygc_em(symbol="SH688041") 输出 11 列；没有公告日、更新时间、币种、范围或修订编号。

建议

独立于三大报表建模

主营构成来自管理层讨论或 Provider 整理视图，行身份与三表 metric dictionary 不同。 复用财务点时、来源和 publication 基础设施，但使用独立领域表。

未决

生产结构化主源

AKShare/东方财富、Tushare 或官方披露解析均未在本文被批准为生产主源。 选源须通过语义、授权、稳定性和恢复门禁，不影响先完成 schema 与 fixture。

4. 数据粒度、身份、候选唯一键与字段字典

实体与粒度

Statement

一份主营构成披露

由证券、报告期、报告类型、披露章节、报表范围、币种和方法学共同识别。 它不是三大报表，也不与财务报告 reportRef 共享业务身份。

Dimension

行业 / 产品 / 地区

三个维度独立。相同报告期可以有三组各自接近 100% 的构成； 只能在一个维度内部分析占比，不允许跨维度求和。

Line revision

披露项的一个知识版本

公司自定义标签只在“证券 × 报告期 × 维度 × revision”内唯一。 跨期同名可用于精确标签比较，但不能自动视为永久产品/行业实体。

5. 报告期、公告、可见、有效、知识与修订语义

时间字段定义来源与回补规则查询作用
report_period 经营数据归属的会计期末。 来自报告或 Provider；永不推导为可见时间。 筛选与同报告期比较。
announcement_date 官方定期报告或更正公告的披露日。 只接受交易所/巨潮公告元数据或语义等价的可审计来源。 说明披露日，不单独决定盘中可用性。
visible_at 官方平台向全体市场公开的精确时间。 有精确时间则保存；只有日期时保持 null。 精确事件回放和日内策略截止。
available_from 策略可保守使用该 revision 的最早时刻。 精确 visible_at 可用时取该时刻；只有公告日时取下一交易时段开盘；均缺失时取 observed_at。 asOf 业务有效切片。
observed_at 平台成功取得该 payload 的 UTC 时刻。 每次 Provider fetch 新建 source observation，不因内容相同折叠。 审计采集时点与来源延迟。
known_from / known_to 平台实际知道某 revision 的半开知识区间。 known_from 不早于首次成功 observed_at；回补不能回写到历史公告日。 knownAt 防止事后信息进入历史查询。
effective_from / effective_to 该披露 revision 作为市场公开版本的半开有效区间。 由 available_from 和下一官方更正/撤回确定；未知更正时间不重写旧区间。 重建市场当时公开版本。
provider_updated_at Provider 声明的更新时间，仅作来源事实。 AKShare 东财主营接口没有；Tushare 只有 update_flag，不是时间。 不得直接代替公告或可见时间。

修订状态机

首次观测 payload A
  → raw evidence A
  → 语义/质量通过
  → revision 1：known_from = observed_at(A)
  → publication V1

相同 payload A 重跑
  → 新 source observation
  → canonical content hash 相同
  → revision 不增加，publication 不推进

后续 payload B / 官方更正
  → raw evidence B + correction reference
  → 关闭 revision 1 的 known/effective 区间
  → revision 2：known_from 不早于 observed_at(B)
  → publication V2

撤回或无法证明的改变
  → quarantine / partial
  → 保留 V1；不删除 revision 1，不把 B 覆盖回过去
历史可得性边界 一个“当前全历史”接口只能建立从首次可信观测开始的知识历史。若要重建更早的 point-in-time， 必须逐份处理官方原始定期报告和更正公告；没有历史版本证据的区间明确标记 pit_coverage=OBSERVATION_ONLY，不能对外宣称完整历史 PIT。

6. 同步模式、增量、幂等、去重、回补与恢复

功能划分

Provider adapter

供应商隔离

职责：调用 SDK/URL、解释供应商字段与错误，输出中立批次。

状态：无 canonical 写权限；只返回 raw + normalized candidate。

失败边界：超时、429、空响应、缺键、schema drift 映射为中立错误。

Composition sync

点时编排与质量

职责：身份解析、raw 归档、公告证据关联、标准化、质量和修订判定。

状态：run、partition、checkpoint、revision candidate。

失败边界：单证券/报告期隔离；失败不推进 publication。

Publisher / reader

不可变发布与读取

职责：只发布通过门禁的完整报告期版本，按 asOf + knownAt 读取。

依赖：共享 publication、来源、质量和身份基础设施。

失败边界：无 production 版本时 fail closed，不返回 research。

正常路径

公告元数据或受控触发
  → 建立 run / partition，获取 security lease
  → DataSourcePort.fetch(capability, instrument)
  → adapter 调用一个已配置 Provider
  → 先写 S3 raw evidence + schema fingerprint
  → 解析全历史快照，按 report_period 拆分候选
  → 日期感知 security_id 解析
  → 关联官方 disclosure evidence（有证据才声明公告时间/范围）
  → 单位、币种、范围、唯一性、时间与勾稽质量
  → PostgreSQL 单报告期事务追加 revision
  → 推进对应 report_period publication
  → checkpoint / run 成功

执行语义

项目 设计 失败与恢复 可验证证据
触发 定期报告官方元数据变化、手工回补、低频滚动复核；不在本文冻结 beat schedule。 重复触发复用同一幂等语义；过期任务由 lease reaper 回收。 同一 partition 并发测试只有一个 writer。
全量 / 增量 东财接口每次取单证券全历史；应用层按报告期 content hash 选择性追加。 上游无法按日期裁剪不等于每次重写全部历史。 全 payload 变化只影响发生变化的报告期 revision。
分区 source_dataset/exchange.symbol/report_period；抓取锁可提升到证券级。 一个报告期失败不污染其他已发布报告期。 部分失败 fixture 保留旧 publication。
幂等键 capability + provider + security_id + report_period + normalized_content_sha256。 内容相同不建新 revision；每次 fetch 仍留独立 source observation。 连续运行两次 canonical 行数和 dataVersion 不变。
去重 批内候选键去重；完全重复允许折叠并告警，冲突重复隔离。 相同标签不同维度合法；规范化标签冲突不能任意选一行。 duplicate-equal / duplicate-conflict 双 fixture。
checkpoint 保存 source batch、raw URI、全响应 hash、已提交报告期集合和最后成功 publication。 DB 失败从 raw 重放；不再次访问 Provider、不改变 observed_at。 中断点覆盖 raw 后、normalize 后、commit 前、publish 前。
重试 超时、429、5xx 指数退避加抖动，最多 3 次；遵守 Retry-After。 schema/语义/身份错误不可重试，直接 quarantine。 失败注入验证重试次数与终态。
任务终态 queued/running/succeeded/partial/failed/cancelled。 取消在安全点生效；僵尸 lease 过期后回到 queued。 run/partition/batch 可按 ID 关联。
回补 按证券清单与报告期窗口受控回补；历史已知时间从实际观测起。 没有官方历史版本时标记 observation-only，不伪造完整 PIT。 回补结果的 known_from 均不早于 source observation。

关键失败路径

  • 空响应：区分合法无披露、上游返回空、解析失败；没有官方证据时默认失败，不发布空报告。
  • schema drift：保存 raw、schema fingerprint 和字段差异；对应分区 quarantine，旧版本继续可读。
  • 公告关联歧义：同证券/报告期有多份年报或更正时全部保留候选，不能按“最新标题”自动选。
  • 持久化失败：整个报告期事务回滚，checkpoint 不推进；从已归档 raw 重放。
  • 来源切换：新来源独立 methodology 和 publication；双跑对账后才迁移消费者，不逐格 fallback。

7. 数据质量、可比性与未来函数防护

发布质量规则

规则阈值 / 判定处置原因
证券身份 按报告期/知识时间唯一命中 CONFIRMED security_id，覆盖率 100%。 未命中或冲突 quarantine，阻断分区。 防止退市、代码复用或当前代码误绑。
必需语义 reportPeriod、reportKind、dimension、itemLabel、source/methodology 100% 已知。 未知字段阻断 production。 避免同名异义序列。
金额精度 非空值均可解析为 Decimal；currency/rawUnit/scale 可追溯。 无法证明单位时金额隔离，不猜 CNY/元。 避免万元、元和币种静默放大。
空值 每个可空数值与受控 null reason 二选一；不允许 NaN/空串进入 canonical。 不完整可标 partial；0 只表示来源明确的零。 样本成本/利润/毛利率存在大量空值。
逻辑键 同 revision/维度/source_item_key 冲突数 0；双时间当前区间重叠 0。 事务失败并告警。 保证幂等与点时唯一。
金额勾稽 三项齐全时检查 revenue - cost ≈ reported_profit；容差由原始精度版本化。 小偏差 warn，大偏差 quarantine；不改来源值。 舍入和来源定义可能不同。
毛利率 收入非零且三项齐全时与 (revenue-cost)/revenue 比较。 只做差异证据；异常不自动重算覆盖。 来源毛利率可能有舍入或特殊定义。
占比合计 仅当来源证明维度完整时才要求合计接近 1；否则只记录 coverage。 默认 warn，不作通用硬门。 监管规则允许按重要性披露，可能省略小项。
财报对账 只在报告期、scope、currency、unit、methodology 完全相同时对账营业收入。 差异作为质量指标；不可比时明确跳过。 主营收入未必等于利润表全部营业收入。
时间不变量 known_from ≥ first_observed_at；只有日期的公告按下一交易时段可用。 违反即阻断发布。 核心未来函数门。
跨来源 provider/methodology 不同的行不进入同一 publication 或连续序列。 主源缺失发布 partial；不静默补洞。 同名字段不证明同口径。

未来函数与口径混淆清单

严禁进入历史可见切片

  • 今天获取的“最新历史值”回填到原报告期或原公告日。
  • 后续更正、重述、撤回版本覆盖首次披露版本。
  • 公告后收益、未来收益、后续股价表现和事后行业标签。
  • 只有日期却假设在当日开盘前已公开的报表。
  • Provider 的 update_flag 当作精确公告时间。

严禁静默混算

  • 行业、产品、地区三个维度相加或共享占比分母。
  • 管理层主营构成与 CAS 35 经营分部附注合并。
  • 合并口径与母公司口径拼成一条历史。
  • 人民币元、万元和外币未经可审计转换直接比较。
  • 一个来源的收入与另一来源的成本计算毛利率。
因子使用条件 因子引擎只能消费固定 dataVersion、明确 available_from、 同一来源/方法学/范围/币种/单位的输入。报告期增长、集中度和毛利变化均在独立 derived dataset 计算， 保存公式版本、输入 revision 集合与计算时间；不能回写 reported 数据集。

10. 对 service-api 的查询、分页与权限需求

边界 本文只给消费需求，不改现有 OpenAPI，也不把候选路径写成已接受契约。 最终 endpoint、DTO 和错误码由后续 data-sync → service-api 契约方案统一确定。 service-api 不得读取 data-sync PostgreSQL、对象存储或 Provider；service-web 只访问 service-api。

候选公开 POST 查询

POST /api/v1/equities/{exchange}/{symbol}/business-composition/query
Authorization: Bearer <user-session>
Content-Type: application/json

{
  "reportPeriodFrom": "2021-01-01",
  "reportPeriodTo": "2025-12-31",
  "reportKinds": ["ANNUAL", "HALF_YEAR"],
  "dimensionTypes": ["INDUSTRY", "PRODUCT", "REGION"],
  "statementScope": "CONSOLIDATED",
  "itemQuery": "处理器",
  "methodologyCode": "provider.methodology",
  "methodologyVersion": 1,

方面消费需求边界 / 失败语义
身份 路径使用 exchange + symbol；代码复用时 asOf 参与解析。 无身份 404，身份歧义 409；不暴露 security_id。
筛选 报告期、报告类型、维度、scope、币种、标签、methodology、质量状态。 单请求只选一个 methodology 版本；不同来源不合页。
点时 最新查询可省略时间；回测/审计支持 asOf + knownAt。 未来 knownAt 拒绝；observation-only 响应必须显式提示覆盖边界。
分页 键集分页，默认 100、最大 200；cursor 绑定 filters、sort、time 和 dataVersion。 游标篡改 400；版本不可再选 409，从第一页重启；不用 offset。
排序 首期固定 reportPeriod desc → dimensionType → sourceRank → lineRef。 不开放任意表达式或数值排序，避免昂贵扫描。
响应 statementRef、reportPeriod/kind、dimension、label、数值/空值原因、currency/unit、scope、公告/可见/可用时间、revision、dataVersion、methodology、quality、pitCoverage。 不返回 raw URI、Provider URL、source batch、数据库键或 quarantine 样例。
权限 最低要求有效 JWT、ACTIVE 用户；是否增加市场数据 entitlement 由 API 评审明确。 未定前不得匿名公开；401/403 不泄露资源存在性。
限额 按用户、IP、route 和日期跨度限流；最大 20 年窗口，body/response 大小硬限制。 429 携 Retry-After；超大导出不复用在线查询。
缓存 ETag 绑定 query projection + dataVersion；私有、必须重新验证。 公开读取型 POST 命中条件请求返回 204，无 body。
下游故障 service-api client 严格校验内部 schema，幂等查询超时/502/503 最多安全重试一次。 无 publication 或依赖不可用映射脱敏 503；不隐式返回旧值。

11. 实施路线、迁移兼容与回滚

本文不创建 migration、配置、依赖、OpenAPI 或生产代码。以下均为计划执行， 由后续统一 canonical 与契约方案收敛后才进入实现。

  1. P0-1 来源与 fixture：冻结一个候选 adapter 版本；采集沪深北、制造/金融/服务、 年报/半年报、空成本、币种/单位、修订等最小样本；保存官方文档证据和 raw payload。
  2. P0-2 语义与点时：验证 MAINOP_TYPE、金额/比率单位、scope、披露章节、 公告关联、修订和历史覆盖；完成 G1–G4。
  3. P1-1 Expand：新增本域 Declarative 模型与 additive migration，登记共享 registry； feature/source policy 默认关闭，不改现有 0016 表与接口。
  4. P1-2 Shadow：raw、candidate、quality、checkpoint、replay、幂等和 publication 全链路运行；不对 service-api 可见。
  5. P1-3 Backfill：小证券集、有限报告期回补。缺历史公告版本的记录从实际观测时点起可见， 并标 observation-only。
  6. P1-4 Serving：内部契约、service-api POST、防腐 client、JWT/限流、契约测试和 E2E 通过后，按 dataVersion 灰度开放。
  7. P2：销售模式、CAS 35 segment note、标签分类和跨市场分别建方法学，不修改 P1 历史语义。

迁移与兼容原则

  • Expand-only：新表、新枚举/字典和新读取路径，不修改 0016 已实现字段或历史 publication。
  • 应用先兼容“表不存在/功能关闭”，独立 migration job 再部署；生产应用启动不自动迁移。
  • 首次 backfill 不回写旧报表表，不向 service-api Prisma 复制 canonical 数据。
  • v1 只允许新增可选字段；改变金额、时间、维度或 scope 语义需新 schema/methodology 版本。

回滚策略

尚无 production publication

关闭 source/capability，停止任务和 API 路径；可在确认新表为空后执行 migration downgrade。

已有 publication

停止新同步，把 publication 指回上一已验证 dataVersion；保留 raw、revision 和质量证据，禁止删表降级。

来源或方法学失效

撤销该 methodology 的新发布，API 对无合格版本返回 503；新来源以新版本双跑，不能逐格替换旧历史。

12. 技术硬门禁与非技术风险分离

技术硬门禁

门禁仅阻止受影响 capability 进入 production publication；不阻止文档、schema、fixture、 research/shadow 和其他来源继续推进。

门禁 准入条件 可验证证据 验证人 退出条件
G1 点时可见性 production revision 都有 OFFICIAL_VISIBLE_AT、OFFICIAL_DATE 保守转换或 OBSERVED_AT 三者之一；known_from 不早于 observed_at。 年报/半年报/更正 fixture；只有日期按下一交易时段可见的测试；历史回补无 known_from 倒灌 SQL。 数据架构负责人 + 回测负责人 100% production 行有可审计 knowledge basis，所有未来函数回归测试通过。
G2 口径、单位与范围 dimension、金额/比率单位、currency、scope、disclosure section 映射有证据；异口径物理隔离。 三所、至少 5 行业、年/半年、空值/外币/万元样本矩阵；与官方原表逐字段对账。 财务数据治理负责人 必需语义覆盖 100%，未知单位/币种不进入 production，跨口径测试无静默合并。
G3 可恢复与接口稳定 来源在披露窗口可完成 bounded fetch，schema drift 可检测；raw replay 可重建同一 canonical hash。 至少 30 日 shadow、覆盖 20 只证券和一次披露窗口；成功率/429/超时/schema 指标；四个中断点恢复演练。 data-sync 负责人 + SRE 目标成功阈值由实测冻结且达标；schema 未知漂移 0；replay 结果一致，旧 publication 始终可恢复。
G4 来源合规（来源级） 所选 production 来源允许自动化访问、必要 raw 留存、内部计算和 API 投影；秘密与 egress 受控。 有效合同/条款记录、数据保留矩阵、secret/egress 检查；不以 AKShare MIT 许可替代数据权利。 合规验证人 + 安全负责人 该来源具备书面可验证使用边界，或替换为通过同一门禁的官方/许可 adapter；未通过来源保持 research。
G5 身份与修订完整性 每行唯一解析 security_id；逻辑键、双时态区间、修订链和 publication 原子性满足约束。 代码复用、退市、冲突重复、迟到更正、DB 失败与并发 fixture；约束验收 SQL。 数据架构负责人 + DBA 身份覆盖 100%、冲突/重叠 0；重复运行、并发和恢复均不产生重复或混版。
