1. 结论：值得接入，但不能扩写成“股票行情的另一张表”

架构结论

独立衍生品资产域

期货和期权有产品、月份、到期、行权、交割、合约单位、结算价与夜盘交易日语义。 不复用 A 股 security_id，不把合约代码送入股票身份解析器。

来源结论

交易所为数值与规则证据锚

六家期货交易场所及 SSE/SZSE 股票期权页面是首选权威证据。 AKShare 是采集库；新浪、东方财富连续/快照只能作为 research/shadow 候选。

最大风险

连续序列制造未来函数

用当日收盘后的持仓量选择当日主力、按未来换月回调全部历史价格， 或把连续价当作可成交结算价，都会污染回测和实时消费。

优先级范围建议生产退出条件
P0 产品/合约主数据、衍生品交易日历、单合约交易所日行情、结算价和持仓量 建议接入；先实现可回放的真实合约事实。 身份、夜盘交易日、单位、官方来源、恢复和发布门禁通过。
P1 期权链、交易所风险指标、成交持仓排名、仓单、交割、期转现和行权统计 建议有条件接入；各数据集独立发布。 粒度、历史覆盖、空值、修订和场所差异逐项验收。
P2 主力/指数连续、前后调整连续、平台计算 Greeks/隐含波动率 暂不作为 reported 数据接入；独立 derived methodology。 因果换月、版本化、可复算和消费者免责声明通过 G4。
不可违反的不变量 股票、ETF、指数只能作为期权的 underlying reference，不能让期权合约继承股票代码身份； 真实月合约、主力连续、指数连续和后调整连续是四种不同对象； 收盘价、结算价、交割结算价也不得静默互换。

2. 业务价值、消费者与独立资产域边界

目标用户

  • 期货研究员：期限结构、基差、持仓和换月分析。
  • 期权研究员：期权链、波动率曲面、到期与行权分析。
  • 量化研究员：无未来信息的合约/连续序列回测。
  • 数据运营：交易所覆盖、规格变化、仓单与交割质量审计。

首期消费场景

  • 按场所、品种、月份检索存续合约与生命周期。
  • 读取真实合约 OHLC、结算价、成交量和持仓量。
  • 在指定 asOf + knownAt 下重建期权链。
  • 对比仓单库存、交割量与持仓变化，不混成一个“库存”。

明确非目标

  • 不建设分钟、Tick、实时交易或订单簿。
  • 不提供交易、下单、保证金计算或组合风险引擎。
  • 不把 Provider 连续代码当交易所合约代码。
  • 不在本文定义跨域统一 instrument 或共享运行表。

3. 权威来源、AKShare 函数、历史与授权

事实

交易所发布合约与结算行情

CFFEX 规则明确发布合约、开高低收、结算、成交量、持仓量及排名，交易信息所有权归交易所。

事实

夜盘跨自然日

郑商所指引把交易日定义为前一工作日 21:00 至当日 15:00；上期所资料给出同类边界。

建议

官方直源优先

交易所日数据与规则是 production 首选；AKShare 官方交易所 wrapper 可作为 adapter 候选。

未决

统一商业主源

官方站点、Tushare 或商业行情源尚未被批准；按 capability 独立门禁，不阻断 schema 和 fixture。

6. 字段字典、单位和空值语义

字段组Canonical 字段单位/类型真实上游空值与约束
身份 asset_class / venue / product_code / contract_code 受控枚举 + 原始代码 交易所合约信息、交易参数；Provider 代码先经 adapter。 不可空；未知场所或冲突代码隔离。
期权结构 underlying_kind/ref, call_put, strike_price 显式类型；价格单位随产品 交易所当日/挂牌合约和合约条款。 期权 production 必填；不得只靠简称猜测。
规格 contract_multiplier, trade_unit, quote_currency, price_unit, tick_size Decimal + 单位码 交易所规则/参数；Tushare fut_basic 可作结构化候选。 未知单位时行情只进 research，不默认“元/吨”。
生命周期 list_date, last_trade_date, expiry_date, exercise_date, delivery_start/end 交易所业务日期 官方合约参数与调整公告。 规则更正追加 revision；日期不同义，不相互填充。
结算方式 exercise_style, settlement_type, delivery_method EUROPEAN/AMERICAN；CASH/PHYSICAL 等 合约条款。ETF 期权通常实物交割；股指期权现金交割。 UNKNOWN 不进入行权/交割 production 查询。
行情时间 trade_date, session_start_at, session_end_at date + UTC timestamp 交易所日行情和品种交易时间公告。 trade_date 不从 UTC 日期截断；夜盘按交易所业务日。
价格 open/high/low/close, pre_close Decimal；quote price unit 交易所日行情；AKShare get_futures_daily。 无成交可为空并带 reason；不以前一行 close 强补 pre_close。
结算价格 settlement, pre_settlement, delivery_settlement Decimal；同合约报价单位 交易所结算/日统计；CFFEX 明确交割日今结算有特殊语义。 三者独立；不得用 close 替代 settlement。
量额 volume_lots, open_interest_lots, oi_change_lots, turnover_amount 手；金额需 currency + raw unit 交易所日统计。CFFEX 量/持仓按单边，金额万元。 统计方向和单位必须来源化；无值不写 0。
期权指标 exercise_volume, delta, gamma, theta, vega, rho, implied_volatility 手或方法学数值 交易所风险指标/日行情；SSE 指标按当日收盘计算。 exchange-reported 与 platform-derived 分 methodology，不补算覆盖。
仓单 receipt_quantity, change_quantity, location, grade 来源单位：吨/张/手等 各商品交易所仓单日报。 地点/品级未知不聚合；库存来源不同不得拼接。
交割 delivery_type, delivery_period, delivery_quantity, delivery_amount 来源量纲 + 币种 交易所交割、期转现、行权交收统计。 实物、现金、期转现、行权分别编码。

7. 交易日、可见时间、修订与连续合约因果性

时间轴

字段定义规则消费作用
trade_date交易所归属业务日。夜盘属于次一业务日；不可用自然日推断。行情、排名、仓单主筛选。
effective_from/to合约规格或生命周期事实有效区间。上市、到期、交易时间和合约单位调整均版本化。asOf 选择当时规则。
published_at交易所公开该批数据的可验证时刻。只有日期时保持 null，不猜 15:00。事件回放和最终性。
observed_atadapter 成功取得 payload 的 UTC 时刻。每次 fetch 独立 source observation。来源延迟与审计。
known_from/to平台实际知道 revision 的知识区间。known_from 不早于 observed_at；回补不倒灌。knownAt 防未来信息。
finalized_at平台在质量/等待窗口后发布最终版本的时刻。表示平台 finality，不宣称交易所永不修订。final-only 查询和缓存。

连续序列方法学

允许的因果换月

  • 只使用截至 T 日收盘已发布的成交量/持仓量。
  • T 日判定，最早 T+1 生效；不把新主力回写到 T 日。
  • 保存候选合约、阈值、旧/新合约和 roll reason。
  • 每个连续 bar 携带真实 source_contract_ref。

必须隔离的序列

  • 简单拼接：价格跳空保留，量/持仓来自当日所选合约。
  • 差值/比例后调：历史价格会随未来 roll 改写，只用于研究。
  • 全合约加权指数：量价聚合规则与主力不同。
  • Provider 连续：方法不透明时仅 research/shadow。
T 日收盘前
  → 当前主力沿用，不查看 T 日完整持仓终值

T 日官方日行情已发布且 quality passed
  → 计算 roll candidate
  → 保存 signal_known_from = 实际 observed_at
  → 若规则满足，effective_trade_date = next_exchange_trade_date(T)

T+1 发布
  → continuous bar 引用 T+1 真实月合约
  → 保存 source_contract_ref / rule_version / data_version

未来新换月
  → UNADJUSTED 历史不改
  → BACK_ADJUSTED 形成新 immutable dataVersion
  → 旧 knownAt 仍选择旧版本，禁止把未来 adjustment 注入过去
未来函数清单 禁止用全样本最活跃月份回标历史主力；禁止 T 日收盘持仓决定 T 日整根 K 线； 禁止用未来 roll 因子覆盖旧 knownAt；禁止把当前合约目录回填为历史当时已挂牌； 禁止把行权后标的表现、到期结算结果或后续修订放进更早切片。

8. 同步、分区、回补、恢复与质量

正常路径

exchange calendar / controlled backfill trigger
  → 建立 run + dataset/venue/trade_date partition
  → 获取 venue/date lease
  → DataSourcePort.fetch(provider-neutral capability)
  → adapter 内调用唯一批准的交易所/Provider
  → raw evidence 先落对象存储 + schema fingerprint
  → 合约身份、业务交易日、单位与枚举标准化
  → 批内唯一性、OHLC、结算、量额、生命周期与覆盖质量
  → 单 partition 事务追加 canonical revision
  → 推进 immutable dataVersion / publication
  → checkpoint + 指标 + run terminal state

执行语义

项目设计失败与恢复验收证据
任务 contract catalog、daily bar、option、rank、warehouse、delivery 分 capability；不做万能任务。 一个数据集失败不推进该 publication，不阻止其他独立数据集。 run/partition/source batch 可全链关联。
分区 dataset/venue/trade_date；合约详情可再按 product 分片。 单场所失败保留上一版本，不形成跨场所混合“全市场”。 部分失败 fixture 和 publication 指针测试。
增量 按交易日拉行情；目录每日快照做 content diff；显式公告触发规格 revision。 目录缺失不代表合约退市；需要到期/摘牌证据。 缺席合约不被误关的回归测试。
幂等 capability + provider + venue + partition + payload_sha256。 同 payload 新增 observation，不重复 canonical/dataVersion。 连续运行两次业务行数不变。
去重 完全重复折叠并告警；同键异值 quarantine，不以最后一行获胜。 不同来源不在同一 publication 逐行补洞。 duplicate-equal/conflict 双 fixture。
回补 按 venue × date window 限速回补；从 raw replay；历史 known_from 从实际观测起。 无历史版本证据标 OBSERVATION_ONLY。 known_from 不早于 source observed_at。
重试 timeout/429/5xx/TLS 可指数退避加抖动，最多 3 次并遵守 Retry-After。 schema、单位、身份冲突不重试，直接隔离。 失败注入验证次数、延迟和终态。
恢复 checkpoint 保存 raw URI、hash、已提交分片和上一 publication。 DB 失败从原 observed_at 的 raw 重放，不再次调用 Provider。 raw 后、normalize 后、commit 前、publish 前中断演练。

发布质量规则

规则阈值/不变量处置原因
合约身份production 行 100% 命中唯一 venue/contract；期权结构字段齐全。未解析或冲突阻断分区。避免股票/期货/连续代码误绑。
交易日必须存在于该 venue/product session calendar；夜盘归属已验证。未知日历只进 research。避免自然日错位和重复。
价格high ≥ open/close/low；非负规则按产品；结算价独立。异常 quarantine，不自动改值。价差与结算用途不同。
量额volume/open interest 非负整数手；金额单位、单双边口径可追溯。未知单位阻断 production。跨场所同名字段不等量纲。
覆盖与当日官方合约清单对账；到期/停牌/无成交需受控原因。部分覆盖发布 partial 或保留旧版。空集可能是来源失败。
期权链underlying、expiry、call/put、strike 唯一；行权价精度符合规格。链冲突隔离。不能靠显示简称构链。
仓单/交割产品、地点、品级、单位、日期完整；汇总值与明细容差对账。不可比不聚合。仓单、库存、交割是不同事实。
连续T 日信号最早 T+1 生效；每行引用真实合约和规则版本。违反即阻断 derived publication。核心未来函数门。

10. 领域表草案：不定义跨专题共享表

下表仅作为统一 canonical 方案输入；不创建 migration，不重定义 source_batch、raw、quality、 checkpoint、calendar 或 publication。最终共享 identity 与物理 DDL 由后续统一数据模型方案收敛。

拟议表粒度与候选唯一键核心字段关系与隔离
derivative_product venue × product_code；唯一 (venue, product_code) product_ref、asset_class、名称、underlying_kind、currency、default_unit 本域产品锚；不复用 equity_instrument。
derivative_contract venue × contract_code；唯一 (venue, contract_code) contract_ref、product_id、asset_class、underlying_ref、call_put、strike、expiry 期权可引用期货或外域 underlying；引用类型显式。
derivative_contract_revision contract × known_from；双时态无重叠 list/last trade/exercise/delivery dates、multiplier、tick、session、known/effective 区间 规格和日期更正追加，不覆盖。
derivative_daily_bar contract × trade_date × methodology；唯一 OHLC、pre_close、settlement/pre_settlement、volume、OI、turnover、source_batch 真实合约 reported 数据；不存连续行。
derivative_option_risk_daily option contract × trade_date × methodology delta/gamma/theta/vega/rho/IV、exercise_volume、calculation_basis 交易所 reported 与平台 derived 不同 methodology。
derivative_member_position_rank venue × date × contract/product × side × rank × member volume/long/short lots、change、rank_scope、member_label 会员展示名不是跨场所统一机构身份。
derivative_warehouse_receipt_daily venue × date × product × location × grade × methodology quantity、change、unit、warehouse/region、subtotal_flag 仓单与商业库存、库存周报隔离。
derivative_delivery_stat venue × period/date × product/contract × delivery_type PHYSICAL/CASH/EFP/EXERCISE、quantity、amount、unit、settlement price 不同交割类型不聚合；可空合同引用需受控原因。
derivative_continuous_series product × series_kind × methodology series_ref、selection rule、threshold、adjustment mode、version P2 derived identity；不是交易所 contract。
derivative_continuous_bar series × trade_date × data_version source_contract_id、OHLC、volume/OI semantics、roll_signal_ref、adjustment 每行必须回溯真实合约；back-adjusted 版本不可变。

约束、索引和规模输入

  • 价格和金额使用 Decimal/NUMERIC；volume/OI 使用非负 BIGINT，禁止 float。
  • 行情候选索引 (contract_id, trade_date DESC) 与 (venue, trade_date, product_id)。
  • 期权链候选索引 (underlying_ref, expiry_date, trade_date, strike_price, call_put)。
  • 日行情超过 2,000 万行或 50GB 后再考虑按 trade_date 年/月分区；先以基准测试决定。
  • raw payload 留在对象存储；不把 Provider JSON 塞入 canonical JSONB 绕过字段治理。

13. 实施路线、回滚、未决与验收

本文不创建表、migration、配置、依赖、OpenAPI、任务或 adapter；以下全部是计划执行。

  1. P0-1 证据：冻结产品/合约/bar fixture，覆盖六期货场所、SSE/SZSE、夜盘、到期和无成交。
  2. P0-2 Shadow：接入一个通过 G6 的官方/许可来源，跑 raw、schema、质量、replay 和 publication。
  3. P0-3 Serving：只开放真实合约目录与日行情；point-in-time、权限、限流和契约测试通过后灰度。
  4. P1：期权链、风险指标、排名、仓单、交割各自独立 capability 和 publication，不绑成同批上线。
  5. P2：独立评审连续合约方法学；先发布 unadjusted，再决定 back-adjusted 和加权指数。

迁移与回滚原则

Expand

新增独立 derivatives 表和读取路径；不修改 equity identity、行情表、OpenAPI 或历史 publication。

故障回滚

关闭 capability，把 publication 指回上一验证 dataVersion；保留 raw、revision、质量和 roll lineage。

不可逆边界

已有 production revision 后禁止删表降级；来源或方法失效时停止新发布并 roll forward。

未决事项

问题触发条件当前安全默认
生产主源是官方直源还是 Tushare/商业源？G3/G5/G6 证据完成。均为 research/shadow。
跨资产统一 identity 是否需要共享根？统一 canonical 方案评审。derivative 独立 ID，显式 underlying reference。
连续序列选持仓、成交量还是阈值切换？P2 回测和稳定性比较。不发布平台连续序列。
期权 Greeks 采用交易所值还是平台计算？来源覆盖和定价模型评审。只保留来源值；derived 另版本。
仓单、库存和可交割资源如何聚合？地点、品级、单位和历史完整性验证。按来源独立展示，不给“总库存”。
