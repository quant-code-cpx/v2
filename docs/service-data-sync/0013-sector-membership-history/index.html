板块成分股与观测历史技术方案

每日保存东方财富行业/概念板块的完整当前成分快照，形成可复验的观测历史。 只在完整健康快照上闭合缺席关系；首次看到和首次缺席都不伪装成真实调入、调出日期。 service-api 只经版本化内部 HTTP 提供板块→成分及证券→板块查询。

1. 摘要

问题

只有当前集合，没有真实生效日

AKShare 候选接口只返回调用时成分。把抓取时间写成调入/调出日期，会给回测制造虚假精度。

决策

完整快照 + 观测区间 + release

原始快照不可变；健康差分形成半开观测区间；不可变 manifest 固定 API 的 dataVersion。

主要风险

来源断连与证券身份覆盖

2026-07-27 live 探针再次断连。公开发布还硬依赖证券主数据先完成唯一身份解析。

硬边界 超时、空响应、分页/结构异常、重复代码、PENDING、身份 quarantine 或质量阻断时，不新增、不闭合任何观测关系。 PENDING 与 quarantine 永不进入内部消费投影或公开 API。
生产准入待决 AKShare/东方财富的商业使用、调用频率、原始数据保存期和再分发许可尚未批准。 所有生产开关默认关闭；本文 cadence 与容量均为显式工程假设，不是已获授权事实。

2. 业务价值、目标与非目标

业务价值

  • 按历史观测版本做板块选股，减少使用今天成分回测过去的幸存者偏差。
  • 支持成分变动监控、覆盖诊断、板块行情与个股集合联查。
  • 保留每次来源证据，可解释某次研究为何包含或排除一只证券。

目标

  • 行业、概念按 scheme 独立采集完整当前快照。
  • 重复、失败、修订、重放均不产生重复或伪关闭。
  • 提供稳定 asOf、游标、ETag、dataVersion 查询。

非目标

  • 不回造首次观测前历史，不推断真实调入/调出日。
  • 不合并行业与概念，不做跨 scheme 自动映射。
  • 不接分钟/分时、行情字段或成分权重。
  • 不让 API 直连同步库、S3 或供应商。

公开能力依赖 0014：证券主数据技术方案。 0013 可先 shadow 积累 raw、快照和 PENDING，但首次公开 release 前必须达到本文身份质量门。

eastmoney.concept stock_board_concept_cons_em(symbol: str = "融资融券")
  • 事实 两接口都接受板块名称或 BK... 代码；实现调用东方财富分页列表，页面大小 100。
  • 事实 AKShare helper 从第一页 data.total 算页数，逐页请求并合并；任一页异常会抛错。helper 不把预期总数返回给调用方。

  • 实测失败 2026-07-27 在同一镜像调用行业 BK0475 与概念 BK0816，均以 RemoteDisconnected 失败，没有取得 live DataFrame。
完整性含义 “完整健康”是本系统质量判定，不是供应商承诺。SDK 成功抓完其计算出的全部页、非空、结构/唯一性通过、 身份无 quarantine、数量与变动阈值通过后，快照才可驱动差分。

5. 任务、同步逻辑与恢复

项目设计约束
市场/时间中国 A 股；业务时区 Asia/Shanghai，数据库存 UTC。只在已发布交易日历确认开市后自动生成日分区。
逻辑分区scheme/sector_code/observation_date；scheme run 冻结 ACTIVE 板块集合。目录未发布时不猜板块集合。
cadence假设 research 每个开市日 18:30 后一次；生产待许可与探针批准。生产开关默认 false；不采盘中序列。
幂等键capability|scheme|sector|date|sourcePolicy|schemaVersion 的 SHA-256。active 部分唯一索引；重复消息返回已有 partition/snapshot。
并发/锁provider semaphore=1；partition lease；提交时按 sector 获取 PostgreSQL advisory xact lock。过期 lease 可回收；Redis 不保存权威锁或 checkpoint。
重试SDK 已有每页 3 次；外层 UNAVAILABLE 只额外重排 1 次，延迟 60 秒。SCHEMA/空响应/身份 quarantine 不重试；防止分页重试乘法放大。
checkpoint每个 sector 保存最后已提交完整快照；scheme 保存最后 release。raw 成功不推进；canonical 事务与 release 成功后分别推进。
状态queued → running → succeeded | quarantined | failed | cancelled；run 可 partial。partial/quarantined 不自动关闭关系。

单分区正常路径

  1. coordinator 冻结 scheme 目录版本，创建 sync_run 与板块分区，获取租约。
  2. adapter 拉取全部分页；标准 JSON 与完整供应商 DataFrame JSON 分开输出。
  3. raw 按内容 hash 写 S3；随后登记“本次观测”的独立 source_batch。
  4. 解析代码/名称，调用 0014 身份解析 port。唯一命中→VERIFIED；可确定但未确认→PENDING；其他→quarantine。
  5. 执行非空、schema、唯一性、数量、变动、身份质量门；任何阻断只写快照头、独立 PENDING staging/quarantine 和质量证据，不更新正式 item 或观测区间。
  6. 只有 VERIFIED=100%、无 PENDING/quarantine/重复且其他质量门通过时，才在 sector 锁与单事务内写可发布 snapshot/items，关闭此次缺席的 open interval，插入此次新增 interval，推进 partition checkpoint。
  7. scheme reducer 为每个目录板块选择本次完整快照或阈值内上一完整快照，生成不可变 release manifest；原子推进 dataset_publication。
相同 payload 仍是不同观测 当前 source_batch 的 payload-hash 唯一约束会折叠不同日期的相同集合。本方案依赖 0014 的 expand migration：每次抓取拥有独立 batch/observed_at，payload hash 仅用于 raw 对象去重与查找， 不再充当观测唯一键；membership snapshot 自身也保存 observed_at。

差分不变量

previous = 当前 open observed interval 集合
current  = 完整健康 snapshot 中 100% VERIFIED 的集合

present  = previous ∩ current  → 不改 observed_from
added    = current - previous  → observed_from = snapshot.observed_at
missing  = previous - current  → observed_to   = snapshot.observed_at

若 snapshot 非完整健康：三组均不应用，上一关系原样保留。

observed_to 仅表示“首个完整后续观测中缺席”，不得命名或展示为真实移出日。 回补只能从首次采集向前继续；当前接口无法提供首次观测前历史。迟到/修订快照不直接插入区间， 必须从最早受影响快照受控重放并发布新版本。

事务边界

  • raw put 先于 DB；S3 失败禁止 canonical 写入。DB 失败保留 raw，checkpoint 不动，可按 batch 重放。
  • 完整快照头、items、interval 差分、quality 与 partition checkpoint 在单一事务内提交。
  • release、manifest rows、旧 release superseded 与 dataset_publication 指针在另一单一事务内提交。
  • 隔离级别采用 SERIALIZABLE 或 sector advisory xact lock + READ COMMITTED； 首实现选后者并依靠 exclusion/unique 约束兜底。
  • 相同 idempotency key/content 重跑返回已有 snapshot；相同集合的新日期仍创建新观测，不创建重复 interval。

7. 质量门、发布与修订

初始阈值假设 下列数字用于首轮实现和 fixture 验收；30 个成功交易日后必须用分布复核。调整阈值走配置、评审和变更记录，不静默改历史。

规则passed / warned阻断与处置
结构/分页必填列完整、非空、代码格式 100%、代码唯一 100%；SDK 完成全部计算页。任何失败→snapshot QUARANTINED；不差分。
身份可发布板块快照要求 VERIFIED=100%、PENDING=0、quarantine=0、重复=0。任一未解析或重复→该板块不发布、不差分；沿用上一完整快照，首次无版本则不可读。
数量波动与上一完整快照比 70%–150%；成分 churn ≤10% passed，10%–25% warned。数量越界或 churn>25%→quarantine，人工确认真实大调整后受控重放。
scheme releasefresh=100% passed；fresh≥98%、无首次未覆盖板块且其余显式 carry-forward→warned。fresh<98% 或任一板块从未有完整快照→不发布，继续上一 release。
公开身份覆盖所有发布均为 VERIFIED=100%，excludedIdentityCount=0。不允许排除少量未解析后发布，避免制造有偏成分集合。
时间顺序新完整 snapshot.observed_at 严格晚于该板块 checkpoint。迟到/倒序→保存证据，转 repair/rebuild，不在线差分。

release 允许在小比例来源失败时引用上一完整快照，但必须返回 qualityStatus=warned、carriedForwardSectorCount 和每个板块的 snapshotObservedAt。消费者不得把 carry-forward 当成目标日重新确认。

修订、回补与保留

  • 当前接口无历史参数，不能回补首次观测前成分；所谓 backfill 只可从已存 raw 重放或修复漏处理分区。
  • adapter/schema 修复后从 raw 重放；若影响既有区间，从最早受影响完整快照顺序重建，发布新 dataVersion。
  • snapshot/interval/release 为审计数据不自动删除；raw 保存期、压缩、归档和再分发边界待许可决定，未决定前禁止生产启用。
  • 不跨来源 fallback，不用名称相近板块或另一 scheme 补洞。

8. 内部与公开 API 设计

机器契约： 0007 internal OpenAPI、 0008 public OpenAPI。 两者分别是现有 0005 与 0006 的增量扩展； 不复制或替代目录/K 线能力。

公开接口查询语义成功结果错误
GET /api/v1/market/sectors/{scheme}/{sectorCode}/constituents 可选 RFC3339 asOf；limit≤500；cursor。 仅 VERIFIED 成分、观测区间、snapshotObservedAt、release、coverage、dataVersion。 400/401/403/404/409/429/503；ETag/304。
GET /api/v1/market/equities/{exchange}/{symbol}/sectors 必填 scheme；可选 asOf；同一响应仅一个 release。 该证券在 manifest 中出现的板块；已知但无归属返回空页。 400/401/403/404/409/429/503；ETag/304。
  • asOf：选择 release_as_of ≤ requested asOf 的最近 release；省略时取 current。早于 coverageStart 返回 404，不伪造空集合。
  • 游标：绑定 route、scheme、身份、asOf、排序键和 dataVersion；发布切换后旧游标返回 409，调用方从第一页重启。
  • 缓存：强 ETag；private, max-age=0, must-revalidate；304 无响应体。
  • 鉴权：internal 使用现有专用静态 Bearer 和常量时间比较；public 使用现有全局 JWT/ACTIVE 会话，禁止 @Public()。只读能力不改变 securityVersion 规则。

  • 日志关联 run_id、partition_id、scheme、sector、source_batch_id、snapshot_id、release_id、request_id；不记录 raw、token 或高基数 symbol 指标标签。
  • 指标：fetch 成功率/延迟/页数、snapshot 状态、row/churn/pending/quarantine、fresh/carry coverage、release age、API p95/错误/409/503。
  • 告警：15 分钟 provider 失败率≥20%；任何误闭合保护触发；交易日次日 09:00 release age>18h；公共身份覆盖<100%；503 5 分钟≥5%。
  • /health 仍表示进程；/ready 不因某个业务 release 过期重启服务。过期由业务指标、503/旧版本标记和 runbook 处理。

故障恢复

  • provider 故障：断路器暂停新分区；上一 release 继续服务；恢复探针后重跑原幂等分区。
  • DB 故障：事务回滚、checkpoint 不动；恢复后从 raw 重放，不重复请求来源。
  • S3 故障：禁止 DB canonical 写入；恢复后重新 put/校验 hash。
  • 错误发布：原子切回上一 release 指针；保留错误 release 和 raw 供审计，随后 roll forward。

10. 实施、迁移、回滚与验收

  1. 阶段 0 — 前置：评审 ADR-0012；落地 0014 证券主数据和每次观测独立 source_batch expand；冻结许可、raw retention、cadence。
  2. 阶段 1 — shadow 采集：新增 capability/adapter/application/CLI、raw、sync/quality/snapshot/PENDING/quarantine；不更新 interval，不发布 API。
  3. 阶段 2 — 观测历史：启用完整快照质量门、interval 差分、月分区、repair/rebuild；连续 30 个交易日验证零伪闭合。
  4. 阶段 3 — internal：生成首个 100% 身份/板块基线 release，实现 0007、ETag、cursor 409、内部 contract test。
  5. 阶段 4 — public：扩展 IndustryModule，实现 0008、Zod 防腐、认证/限流/503；灰度后开放。

迁移与回滚

  • Expand：0014 先修改 source batch 观测唯一性；0013 再创建 btree_gist、snapshot/items 月分区、PENDING staging、quarantine、interval、release/manifest 和索引。生产应用不自动迁移。
  • 兼容：先部署 migration 与 writer，再 internal，最后 public；0005/0006 保持不变。旧服务忽略新表，新 API 在无 release 时返回 404/503。
  • 回滚：先关 public/internal 与 publication flag，指针切回上一 release，再回滚应用。只有确认无消费者和已备份 raw/DB 后，Alembic 才按 manifest→release→interval→quarantine→PENDING staging→item partitions→snapshot 顺序删除；btree_gist 仅在无其他依赖时删除。
  • 不可回滚共享前置：0014 的 source_batch expand 属于共享兼容迁移，不由 0013 downgrade 反向收紧，避免再次折叠其他数据集观测。
