结论

事实

7 项完成短探针

分红、回购、两类十大股东、股东户数、质押和解禁父子查询均取得结构化响应。股东增减持候选在 28 秒短窗口内仅推进至 292 页中的第 11 页。

决策

Tushare 保持主路由

本轮 FULL 为 0。AKShare 只保留 provider-neutral adapter 的研究证据；不创建真实 adapter、fallback、表、接口或任务。

最大风险

快照不能替代事件链

“最新公告日期”和“实施进度”不足以标识方案修订。若覆盖历史状态或把抓取时刻当公告时点，将破坏 point-in-time 数据。

本轮决定：公司行动要以事件与状态演进建模，股东披露要以报告期、公告期和持有人身份建模。未来 adapter 只能返回标准化结果；不得让 SDK、原始字段或事件特例进入 task、application、质量或持久化层。

事件身份与状态：本批不可跳过

分红不是一行静态记录

同一证券、报告期和方案可能从预案到实施，后补登记/除权/派息日期，或产生修订。旧迁移已特意把实施日期排除出自然键。canonical 设计必须区分方案身份、状态快照和来源观察时间。

回购需区分计划与执行

计划数量/金额/价格区间、起始日、实施进度和已回购数会变化。“最新公告日期”无法独立表示首次公告、计划修订或完成事件；未知时不能覆盖旧值。

十大股东是披露快照

最小身份至少包括证券、报告期、股东、持股类别和公告/可得版本。AKShare 个股函数把报告期放进请求而不回传，adapter 必须保存 request provenance，且不得伪造公告日期。

解禁是父子事件

批次给出证券、解禁日、总数量和类型；股东明细依赖批次日期。父子均要保留来源字段、请求参数和观测时间，不能把子级行当作独立、无上下文的解禁计划。

映射约束：未来 canonical 记录至少需区分 source event key、证券、报告期或生效日、公告/可得日期、状态、单位/币种、来源、原始请求与观察时间。观察时间可追溯抓取，不能充当公告日、实施日或首次披露日。
禁止推断：当前列表、最新公告日、输入的报告期和一次成功返回，均不能证明事件全历史、修订链、精确单位、实际发生时间或底层来源再分发边界。

可靠性与运行信号

分页成本

全量接口不可视为轻任务

回购 11 页、47.47 秒；股东增减持启动即要求 292 页，短探针未完成。后续若批准实现，必须先定义分页、断点、限流、超时、缓存和失败恢复；本轮不设计这些任务。

时间语义

快照日期受来源限制

质押比例函数只接受底层网站认可的交易日。它可作为某一时点快照候选，不能据此承诺连续日频或任意历史日覆盖。

依赖风险

临时可装不等于服务准入

本次 ARM/Python 3.13 将 py-mini-racer 从源码构建成功。构建可重复性、镜像时间、漏洞扫描和目标平台兼容性仍需在服务依赖准入时独立验证。

B05 继续条件

  1. 事件生命周期矩阵：选择已预案、股东会通过、实施、撤销/修订和完成回购样本，跨 3–5 个披露日记录方案键、状态、公告日期和数值变化。
  2. 字段与单位对照：与 Tushare 重叠样本逐字段核对分红“每股/每十股”、税前税后、回购数量/金额/价格上下限、质押万股、解禁股数及比例；没有明确来源不得转换。
  3. 股东版本验证：对银行、制造、ST、北交所证券跨两个报告期对照十大股东与户数；确认请求报告期、实际公告日、证券编码和持有人身份如何组成不丢修订的键。
  4. 增减持降级复核：在可控时段观察 stock_ggcg_em 完整分页、覆盖范围和字段；若无日期过滤或无法覆盖旧范围，保持 UNSTABLE，不以高管数据替代全量股东交易。
  5. 解禁父子完整性：以批次总数与股东明细和为例核对，确认 parent/child 关联、公告时间和取消/未解禁状态；不得把聚合批次复制到每个股东。
  6. 合规与架构：逐项记录东方财富/新浪等底层来源条款。仅当稳定性、语义、质量和合规均通过，才可讨论独立 AKShare adapter；任务和应用层仍只调用 provider-neutral port。

下一优先验证

先验证分红与回购事件状态链，再验证十大股东/户数的点时版本；这两项决定公司行动和持股数据能否用于回测。

明确不做

不建业务表、迁移、API、定时任务、真实 adapter、fallback 路由或公告文本/PDF 解析；不提交临时 Docker volume、脚本或探针依赖。
