Service Data Sync · Proposal 0002

同步数据总纲与 AKShare 分批调研计划

以旧项目已运行的 Tushare 数据能力为基线，先建立供应商无关的 65 项数据目录， 再逐批验证 AKShare 的覆盖、语义、质量、稳定性与授权边界，为后续适配器实现提供可验收依据。

状态：Draft · B00/R2 已完成，R3 待验收 日期：2026-07-26 Owner：service-data-sync 范围：总纲与调研，不建表、不写接口
问题 旧系统数据较全，但模型、任务和运行表均以 Tushare 命名，不能直接成为多数据源服务的目标设计。
结论 保留其 65 项业务能力作为基线，改用中立 capability key；AKShare 是否主用按单项调研结论决定。
首要风险 AKShare 聚合多个网站，接口存在字段漂移、限流、历史范围变化和底层来源授权差异。
2026-07-26 更新：65 项目录已完成 B01–B07 的第二轮独立短探针；结果见 0010 第二轮验证汇总。这不替代 3–5 个交易日稳定性观察、Tushare 同日对账与底层来源合规核查，故尚无 FULL 准入。
结论 旧系统盘点 边界 数据总纲 调研批次 调研方法 路由规则 交付验收 待确认项

Decision summary

先确定“同步什么”，再决定“由谁同步”

数据能力不属于 AKShare 或 Tushare。新服务先定义稳定的业务契约，再由适配层把不同来源映射到该契约。 “AKShare 第一优先级”表示成本与可用性目标，不代表所有能力都必须强行切换到 AKShare。

65

业务数据能力

B00–B07

八个调研批次

先定方法，再从主数据、核心行情扩展到财务、资金流、基金和宏观。

逐能力

供应商路由

每个 capability 独立配置首选与备用来源，不设置一个覆盖全服务的固定顺序。

硬约束： 调度、应用、领域、质量和持久化层只能调用 provider-neutral port。 AKShare/Tushare SDK、HTTP 地址、原始字段和来源特例只能存在于对应 adapter； adapter 只返回标准化结果，绝不直接写 canonical 数据库。

Legacy evidence

旧项目能证明什么

本次读取了旧项目 prisma/tushare、质量模型、Tushare API 服务和同步注册表。 它可以证明 Tushare 侧的数据范围和运行经验，但不等同于新系统的数据模型。

数据覆盖

68 个 Tushare 目录模型，其中 65 个是外部业务数据， 3 个是同步日志、进度和重试队列。

任务能力

65 个任务均支持手动触发；64 个定时任务；63 个参与初始化；64 个支持全量同步。

运行经验

已有定时、补偿、分布式锁、并发组、进度、重试、质量检查、缓存失效等可参考能力。

不能照搬： 旧系统的 TushareSyncLog、TushareSyncProgress、 TushareSyncRetryQueue 和任务枚举都绑定供应商。新系统后续应采用中立的运行模型， 并单独记录实际 provider 与 provenance。
已发现的数据建模风险： 旧财务报表模型大量使用代理主键，缺少明确的业务唯一约束。 后续设计 canonical schema 前，必须先确定“证券 + 报告期 + 报表类型 + 公告版本/修订版本”的身份和去重语义。

Scope & ownership

目录边界

纳入本总纲

  • 证券、指数、基金、期权等主数据与交易日历。
  • 日/周/月行情、复权、每日指标、停复牌和涨跌停。
  • 财务报表、财务指标、业绩、股东与公司行动。
  • 资金流、互联互通、融资融券和特殊交易榜单。
  • 基金净值/持仓、宏观指标、机构调研。

不纳入业务同步目录

  • 用户、权限、自选股、组合、策略、AI 对话等 API 业务数据。
  • 同步运行日志、进度、锁、重试队列；这些属于平台运行控制。
  • 质量检查结果；它们属于质量域，不是外部数据 capability。
  • 分钟线、逐笔、期货、数字货币、完整港美股；旧项目未形成同等基线，留作后续扩展。

Research roadmap

AKShare 分批调研计划

批次按依赖和业务价值排序，不按旧代码目录排序。B00 是所有后续批次的前置； B01、B02 通过后，B03–B07 可按资源并行，但每批仍需独立验收。

批次范围项数目标退出条件
B00方法与基线— 冻结 Tushare 参考契约，统一样本、证据、容差和判定模板。 模板、版本策略、样本集和 verdict 定义评审通过。
B01主数据与参考数据10 解决代码、身份、状态、日历和分类。 关键标识可稳定映射，历史有效期缺口已记录。
B02核心日频行情12 形成 A 股核心行情最小闭环。 主键、单位、复权、停牌、收盘时效和容差可落地。
B03市场规则与因子7 补齐交易规则、权重、技术和筹码类数据。 不可复算字段有来源说明；不稳定接口已降级判定。
B04财务核心9 确定报表语义、版本身份和修订保留策略。 关键报表跨报告期比对通过，版本与去重规则明确。
B05股东与公司行动8 覆盖事件生命周期与持股披露。 事件唯一性、状态变化、日期和单位均有映射结论。
B06资金流与特殊交易10 评估来源分散、分页、口径和稳定性。 每项底层来源、历史窗口、限流和替代路线明确。
B07基金、宏观与调研9 完成第一版目录的剩余能力。 统计期、发布日期、修订和基金日期语义明确。
建议节奏： 每个业务批次先做 1–2 个代表接口的短探针，再展开全批次；完成字段映射后至少观察 3–5 个交易日的成功、空结果、延迟和 schema fingerprint。宏观月/季频接口以多期历史样本替代连续日观察。

Research protocol

每项能力怎么调研

1. 建立可追溯证据

  1. 固定 Python 与 AKShare 版本。
  2. 记录候选函数、文档/源码位置和底层网站来源。
  3. 记录参数、最大返回量、分页、频率、更新时间和时区。
  4. 保存最小化样本的 schema fingerprint、元数据与哈希，不保存大体积原始行情。

2. 做边界样本探针

  1. 正常交易日与非交易日。
  2. 停牌、新股、退市股和无结果。
  3. 单日、跨年和尽可能长的历史窗口。
  4. 分页临界点、重复请求和失败恢复。

3. 与 Tushare 基线对照

  1. 比较证券与日期覆盖率、主键一致率。
  2. 比较字段完整度、空值分布、单位与枚举。
  3. 按字段定义数值容差，不用一个全局误差。
  4. 比较修订行为、历史回补和重复数据。

4. 评估可运营性

  1. 观察成功率、空结果率、错误类型、延迟和字段漂移。
  2. 区分可重试失败、永久缺失和来源变更。
  3. 按底层数据网站核查使用条款与再分发边界。
  4. 给出主用、备用或暂不接入建议。
调研代码也必须遵守适配层边界：探针放在 AKShare adapter 的 research/实验区域， 不得从应用层直接调用 AKShare，不得写 canonical 数据库。结果以报告、schema 和最小样本元数据交付。

Provider verdict & routing

结论代码与后续路由

FULL
覆盖、语义、质量、稳定性和授权均满足，可将 AKShare 配为该 capability 首选。
PARTIAL
只能覆盖部分市场、字段或历史；可承担受限范围，其余由 Tushare 补充。
UNSTABLE
有等价数据但稳定性不达标；保留 adapter，可作为低优先级备用或人工恢复来源。
NO_EQUIVALENT
未找到语义等价接口；该 capability 继续以已验证的 Tushare 为首选。
BLOCKED_LICENSE
技术上可取但使用或再分发边界不满足；不进入生产路由。
配置粒度： 路由键至少包含 capability，必要时增加市场和频率。 例如 A 股日线可首选 AKShare，而财务报表仍首选 Tushare；不能用一个全局开关表达全部数据源顺序。

可以自动回退

超时、连接错误、限流、明确的临时服务失败；回退结果仍需通过 capability 质量门槛。

不能盲目回退

空数据、字段缺失或 schema 漂移不一定是临时故障。必须先分类，防止备用来源用不同口径悄悄污染数据。

Deliverables & acceptance

每批交付物和验收标准

每批必须交付

  • capability 调研矩阵与最终 verdict。
  • AKShare 候选接口、底层来源、版本和调用约束。
  • 供应商字段到中立字段的映射草案。
  • 主键、日期、时区、单位、枚举、空值和修订语义。
  • 样本元数据、对照指标、失败记录和稳定性观察。
  • 质量门槛、首选/备用建议与未解决缺口。

批次完成定义

  • 批次内每项能力都有结论，不能只列候选函数。
  • 结论可由脚本和证据复现，版本已固定。
  • 差异被解释，不以“数据看起来接近”代替语义确认。
  • 授权边界按底层来源核查，而非只看 AKShare 开源许可。
  • 不确定项明确归档，不在实现阶段临时猜测。
检查维度最低要求说明
契约主键、字段、类型、单位、日期/时区完整字段少不等于不可用，但必须明确能力边界。
覆盖市场、证券、日期和历史深度有量化结果按 capability 定目标，不设伪统一比例。
质量与 Tushare 重叠样本完成一致率和字段容差比较Tushare 是参考，不默认任何一方绝对正确。
稳定完成规定观察窗口并记录 schema fingerprint出现漂移必须重新判定。
合规底层来源和使用边界可追溯不明确时结论不得为 FULL。
路由给出 AKShare/Tushare 的明确优先级与失败策略结论落实到 capability 粒度。

Open decisions

进入实现前仍需确认

这些问题不阻塞本轮调研启动，但会影响后续 canonical schema、存储成本和首次回填范围。

历史深度与保留

各数据域首次回填到哪一年；是否永久保留供应商原始响应或只保留标准化值与 provenance。

财务版本策略

保留全部公告修订，还是仅保留最新版本并记录变化；回测通常需要 point-in-time 版本。

首个实现切片

建议调研通过后按 B01 + B02 的最小闭环实施，而不是一次性建完 65 项表和适配器。

未来市场范围

分钟线、期货、完整港美股等不在本版基线；出现明确业务需求时新增目录批次和 ADR。
