Technical solution · service-data-sync · 0015

板块 EOD 横截面快照与排行技术方案

每个交易日收盘后，对东方财富行业和概念各执行一次批量观测，保存不可变完整横截面； 按请求字段从同一发布版本确定性重算排行，经内部 HTTP 提供给 service-api。 不是盘中、分时或 K 线派生数据，也不宣称上游官方终态。

1. 摘要

问题

缺少可复验横截面

已有目录与日、周、月 K 线，但没有某交易日全板块同批次观测； 页面临时请求或逐板块抓取会产生跨时点、缺行和不可复验排行。

决策

一批一快照，读取时排行

每 scheme 采用一次 stock_board_*_name_em 批量响应； 完整快照原子发布。排行只在一个 immutable dataVersion 上按请求重算。

主要风险

上游无日期与终态

批量响应不含 trade_date、行情时间或 is_final； 真实探针还发生断连。只发布“策略截点后观测”，生产 source policy 默认关闭。

选择理由 批量接口一次返回身份、价格变化、总市值、换手、涨跌家数和领涨名称， 调用量固定、横截面同源。逐板块 spot 只做诊断；供应商“排名”只进 raw，不进入 canonical 或 API。
最大语义边界 tradeDate 来自权威交易日历； finality=post_close_observation 只说明观测晚于内部截点， 绝不表示交易所、东方财富或 AKShare 已确认最终值。

2. 目标、非目标与任务契约

决策

目标

  • 行业、概念按交易日保存两套完整、不可混用的 EOD 横截面。
  • 重复、修订、迟到与 raw replay 可审计，发布始终原子。
  • latest / 指定交易日、排行页和单板块读取有冻结契约。
  • null、并列、升降序、分页和 revision 冲突均可复验。
非目标

明确排除

  • 不采集盘中、分钟、分时或实时推送。
  • 不从日 K、周 K、月 K 拼出横截面。
  • 不逐板块 spot 补缺失字段，不跨来源 fallback。
  • 不把领涨名称解析成证券外键。
约束

生产阻断项

  • 来源商业使用、保存、频率和再分发许可待决。
  • 最新值、涨跌额、总市值单位与缩放待独立对账。
  • 2027 及以后权威 A 股交易日历必须在年度公告后更新并重新核验。
  • 连续探针与阈值校准完成前仅 local/research/shadow。

4. 功能划分与边界

Provider adapter

EastMoneySectorEodAdapter

职责：将 scheme 映射为固定 AKShare name 函数，隔离中文列、SDK 与异常。

输入 / 输出：中立 request → normalized batch + 完整 SDK 行 raw。

状态：无 canonical 状态；只记录 adapter/schema 版本。

失败边界：超时、断连、限流映射 retryable；空表、缺列、类型漂移映射 schema failure。

Application

SectorEodSnapshotSyncService

职责：校验日历/截点、归档 raw、标准化、执行质量门和发布协调。

输入 / 输出：scheme + target trade date → published/no-op/quarantined 结果。

状态：checkpoint、source batch、candidate revision。

失败边界：不导入 AKShare；失败不推进 publication。

Persistence

SectorEodRepository

职责：append revision、完整行写入、质量证据、原子 publication 和版本化读取。

输入 / 输出：中立 snapshot → PostgreSQL current/history；读 query → immutable page。

状态：canonical 唯一权威。

失败边界：事务回滚；raw 与 checkpoint 保留供 replay。

Read API

service-data-sync 内部 HTTP

职责：解析 latest/exact date、动态排名、cursor/dataVersion、ETag 与服务鉴权。

输入 / 输出：内部 v1 GET → 含 sectorId 的严格 JSON。

状态：无副本；只读已发布版本。

失败边界：无版本 404/503；cursor 过期 409。

Public projection

service-api IndustryModule

职责：JWT/授权、DTO、Zod 下游校验、剥离内部 UUID、Problem Details。

输入 / 输出：公开 v1 GET → 最小市场字段。

状态：无 Prisma 表、无 Redis 权威缓存。

失败边界：下游超时/漂移映射 503，不返回未标记 stale。

Run control

Scheduler / Worker / Checkpoint

职责：日历触发、分区租约、retry budget、raw replay 和人工恢复。

输入 / 输出：交易日事件 → 两个 scheme partition。

状态：PostgreSQL checkpoint；Redis 只投递，不做权威状态。

失败边界：worker 崩溃后租约到期接管；成功分区不重复轮询。

5. 调度、同步、幂等与恢复

正常流程

  1. scheduler 读取已发布交易日历；目标日必须明确为开市日。初始 shadow 于 16:20 Asia/Shanghai 为两个 scheme 各建一个 partition。
  2. worker 原子获取 scheme/trade_date 租约；已 succeeded 且无强制 revision 请求时安全 no-op。
  3. 校验当前时间不早于 16:15 policy cutoff；构造只含 scheme 和 target date 的 SourceRequest。
  4. adapter 调用一次对应 name 函数；完成时生成带时区 observed_at，输出标准载荷与完整 SDK 行证据。
  5. 每次调用先创建独立 source_batch_id，以 run/observation_seq 唯一路径写 S3；checkpoint 进入 raw_archived。
  6. 应用从标准载荷构造完整候选，按当前 catalog publication 计算 coverage，执行 schema、范围、时序和异常质量门。
  7. 内容 hash 与当前 revision 相同：记录新观测与质量结果，partition succeeded，不创建新 dataVersion。
  8. 内容变化且质量通过：在一个 DB 事务中追加 header/rows、关闭旧 current、推进 dataset_publication，最后标记 checkpoint succeeded。

分区、锁与 checkpoint

设计项规则
分区键sector.quote.eod.snapshot/{scheme}/{trade_date}
幂等键scheme + trade_date + normalized_content_sha256 + normalizer_version
并发不同 scheme/date 可并行；同分区仅一个未过期租约。
租约初始 5 分钟；worker 每 60 秒续约。原子 UPDATE 仅允许 owner/token 匹配或过期接管。
阶段requested → fetched → raw_archived → normalized → quality_passed → published
状态queued/running/succeeded/partial/failed/cancelled；EOD 完整发布不接受 partial。
checkpoint保存最新完成阶段、source batch、raw URI、attempt 和稳定错误码；raw_archived 后恢复不再访问 provider。
僵尸任务租约到期由 reaper 标记 retryable；旧 owner 的 fencing token 不能提交 publication。

失败、重试与迟到

场景处置publication
timeout / 断连 / 429 / 5xx最多 3 次，退避 5、15、30 分钟并加 jitter；不跨到下一交易日自动改目标日。保持上一发布。
空响应 / 缺列 / schema fingerprint 未批准terminal quarantine；保存 raw、字段差异和 fixture，需 adapter 修复后 replay。不推进。
S3 失败不写 canonical；在 retry budget 内重试 raw put。不推进。
raw 成功、DB 失败从 checkpoint/raw replay；禁止再次抓上游制造不同观测。事务回滚。
worker crash租约到期接管；按 checkpoint 最近阶段恢复，fencing token 阻止旧 worker。最多一次 current。
同日更正显式 rerun；相同内容 no-op，不同内容追加 revision。原子替换同日 current。
历史迟到/人工回补必须显式 --trade-date；沿用同一质量门和 revision 机制。只替换目标日期，不改变更晚日期。
partial coverage重试仍不足则 quarantine；合法退役需 catalog 先确认，再重跑。绝不发布 partial 横截面。
“每日一次”的准确含义 正常路径每 scheme 一个成功批量观测，不做盘中轮询。只有 provider/quality 失败或明确修订操作才重试； 每次尝试都留下独立 source batch 和 observed_at。

6. PostgreSQL 表与发布事务

PostgreSQL 是 canonical、checkpoint 和 publication 的唯一权威。S3 保存 raw； Redis 只承载可丢失任务投递。预计单日横截面小，不先做物理日期分区； 达到 500 万 quote 行或表超过 20 GiB 时再评审按 trade_date 分区，避免过早增加迁移成本。

依赖 0014 的 source_batch expand

共享表变更只由优先级更高的 0014 证券主数据方案 拥有并实施；本方案只声明所依赖的最终契约，不重复创建迁移，也不在回滚时收紧共享表。

变更类型/约束原因
移除唯一约束删除 UNIQUE(provider_id, capability, payload_sha256)不同日期/尝试的相同 payload 也是独立观测，不能折叠。
run_idUUID NOT NULL关联任务运行。
partition_keyVARCHAR(240) NOT NULL关联 scheme/date 分区。
observation_seqINTEGER NOT NULL CHECK (observation_seq > 0)运行分区内单调递增的观测编号；不同 retry 是否发起新观测由此表达。
schema_fingerprintCHAR(64) NOT NULL，小写 SHA-256 checkschema drift gate。
查重索引INDEX(provider_id, capability, payload_sha256)，非唯一快速发现同内容但保留观测事件。
观测唯一UNIQUE(run_id, partition_key, observation_seq)保证运行内观测身份稳定；payload hash 仍非唯一。
运行索引INDEX(run_id, partition_key)诊断与 replay。

原子发布事务

  1. 以 SELECT ... FOR UPDATE 锁定 scheme/date checkpoint 与当前 publication，验证 fencing token。
  2. 再次校验 source batch、quality passed/warned、行数等于 record_count、coverage=1。
  3. 相同标准 hash 则提交 no-op 状态；否则分配 revision=max+1，插入 snapshot、全部 quote 与 quality 结果。
  4. 把旧 snapshot 标为 superseded 并设置时间；把旧 dataset_publication 关闭。
  5. 新 snapshot 置 published，插入新 publication，更新 checkpoint succeeded；任一步失败整笔回滚。

7. 完整性、覆盖与异常质量门

质量阈值以 quality_policy_version 固化在运行与日志中。以下是可执行 shadow 初值； 生产前需用至少 5 个交易日样本校准，但未批准前不能放宽阻断规则。

规则阈值处置
响应与 schema非空；所需 12 列齐全；fingerprint 已批准；每 scheme ≤2,000 行、raw ≤5 MiB。任一失败 quarantine。
身份唯一code/name 非空且合法；scheme+code 无重复；所有行可解析。任一失败 quarantine。
catalog coverage分母为运行开始时 ACTIVE catalog；publish 必须 100%，无未知 code。99.5%–<100% 且缺 ≤2：retryable quarantine；更低：terminal quarantine。
新增/退役新 code 或缺 active code 不由 EOD 推断分类变化。先走 catalog 质量与发布，再重跑 EOD。
字段可用率latestValue、changePercent 各 ≥99%；其他可排序数值各 ≥95%。主字段不足 quarantine；可选字段不足 warned，null 仍保留。
数值域所有数值 finite；latest/market/turnover/count 非负。任一非法值 quarantine。
涨跌一致性latest、change 非空且前值>0 时，计算校验差 ≤0.05 个百分点；不写计算值。异常行占比 >1% quarantine，否则 warned。
异常涨跌|changePercent| >20 warned；>50 quarantine。阈值触发并保留样本；不得截断。
换手异常turnoverPercent >50 warned；>200 quarantine。同上。
市值跳变同 code 较上一发布日比例不在 [0.5,2] warned；不在 [0.1,10] quarantine。单位待决前只做稳定性检测，不做跨板块加总。
全批跨日重复标准内容 hash 与上一交易日完全相同。疑似 stale，quarantine；人工确认后显式 override 并审计。
时间门目标为权威开市日，observed_at ≥ source_cutoff_at。失败不发布；不改写 trade_date。
完整快照定义 “完整”表示一个批量响应中的合法行全部进入同一 snapshot，且覆盖运行开始时的 ACTIVE catalog 100%。 任何缺板块都不发布 partial。字段 null 不删行，而由字段可用率和 API null-last 语义处理。

8. 确定性排行与 snapshot 一致性

排行不落物化 rank 表。读取时从一个 immutable published snapshot 重算， 避免保存 8 字段 × 2 方向的派生副本，也避免把供应商默认“排名”当作通用事实。

sort值方向语义null
changePercent涨跌幅 %desc 为涨幅高优先；asc 为低优先最后
turnoverPercent换手率 %按数值升/降最后
marketValue原生总市值仅同 scheme、同快照内排序；不声明跨 scheme 单位可比最后
latestValue原生最新值仅同 scheme 排序最后
advancers / decliners非负家数按整数升/降最后
leaderChangePercent领涨股票涨跌幅 %按数值升/降最后
code板块代码C collation 字节稳定升/降不允许
 
WITH ranked AS (
  SELECT quote.*,
         CASE WHEN :sort_value IS NULL THEN NULL
              ELSE RANK() OVER (
                ORDER BY :sort_value :order NULLS LAST
              )
          END AS rank,
         ROW_NUMBER() OVER (
           ORDER BY :sort_value :order NULLS LAST,
                    sector.sector_code COLLATE "C" ASC,
                    sector.sector_id ASC
         ) AS position
  FROM sector_eod_quote quote
  JOIN sector_entity sector USING (sector_key)
  WHERE quote.snapshot_id = :snapshot_id
)
SELECT *
FROM ranked
WHERE position > :after_position
ORDER BY position
LIMIT :limit_plus_one;

实现必须使用受控 sort → SQL column 映射，不能把客户端字符串插入 SQL。 非 null 相同值使用 competition rank：1, 1, 3；null 的 rank=null，但仍获得唯一 position 并排在尾部。

cursor 是签名/不透明 Base64URL 结构，绑定 scheme、resolvedTradeDate、sort、order、dataVersion、position。 任一查询维度不符返回 400；publication 被 revision 替换返回 409 snapshot-expired。cursor 不包含 raw 值或 DB 自增主键。

9. 内部与公开 API 设计

两份 OpenAPI 是现有 0005/0006 的增量扩展，只新增 EOD 快照/排行，不复制或修改目录和 K 线： 0011 内部合同、 0012 公开合同。

边界方法与路径用途
内部GET /internal/v1/sectors/eod-snapshotsscheme + optional asOf + sort/order + cursor/limit 的排行页；含内部 sectorId。
内部GET /internal/v1/sectors/{scheme}/{sectorCode}/eod-snapshotlatest 或指定交易日的单板块快照。
公开GET /api/v1/market/sectors/eod-snapshots已认证用户排行页；剥离内部 UUID。
公开GET /api/v1/market/sectors/{scheme}/{sectorCode}/eod-snapshot已认证用户单板块快照。

查询与一致性

  • scheme 必填；仅 industry/concept。
  • asOf 缺省取该 scheme 最新 published trade date；传入时必须精确匹配，不向前回退。
  • sort=changePercent、order=desc 为默认；limit 1–500，默认 100。
  • 排行响应携带 resolved tradeDate、cutoff、observedAt、非官方 finality、qualityStatus、dataVersion、publishedAt。
  • 强 ETag 绑定 dataVersion 与请求投影；If-None-Match 命中返回 304。

错误、鉴权与 service-api

状态场景公开处理
400scheme/date/sort/order/cursor/limit 无效RFC 9457 Problem Details，稳定 code，无内部堆栈。
401 / 403内部 service Bearer 无效；公开 JWT/权限无效沿用现有 guard；内部凭据绝不透传浏览器。
404指定 exact date 或 sector observation 未发布不回退旧日期。
409cursor dataVersion 已 supersededsnapshot-expired，客户端从第一页重启。
429服务或用户读预算超限返回 Retry-After。
503内部存储/合同不可用；latest 无可发布快照不返回 candidate、quarantine 或未标记 stale。

service-api 扩展现有 IndustryModule 的 Controller、DTO、Service、 HTTP Client 和 Zod contract。依赖方向保持单向；只执行安全 GET，使用现有内部 base URL、 Bearer 和有界 timeout。内部 404/409/429 映射冻结公开状态；网络失败、5xx 或 schema drift 统一 503。 不新增 Prisma model，不把 snapshot 放进 Redis，不修改 securityVersion 规则。

安全与部署

  • 复用现有 data-sync image；adapter 只在 DATA_SYNC_AKSHARE_ENABLED=true 与独立 EOD source policy 同时开启时注册。
  • 生产 source policy 默认 false；环境变量/secret 注入，不记录 Bearer、完整 URL 或响应体。
  • data-sync 内部 API 仅 Compose/服务网段，专用 Bearer 常量时间比较；service-api 使用用户 JWT。
  • raw bucket 不对 service-api/web 开放；数据库账号按 migrate、writer、reader 最小权限分离。
  • liveness 只看进程；readiness 看 PostgreSQL/Redis/S3。provider 失败通过业务指标表达，避免重启循环。

阶段交付退出条件回滚

5. Shadow/启用16:20 scheduler、5 分钟 reaper、受控 rollback、2026 沪深公告日历与结构化任务日志已实现；默认都关闭。尚缺 5+ 交易日 probe、许可证与生产观测验收（指标导出、dashboard、告警路由）；未选择具体平台，不能启用；下一年度公告前日历也保持未知。停 scheduler；上一 publications 仍可读。

迁移顺序与兼容

  1. 先执行 0014 拥有的共享 expand：新增 source_batch nullable 列并回填既有行，再设 NOT NULL；创建非唯一 hash 索引，最后删除旧唯一约束。
  2. 创建新表和索引；不修改目录、三周期行情表或既有 0005/0006 API。
  3. 确认 0014 的 insert-only writer 与共享迁移已完成并通过兼容验收，再部署 EOD writer；生产应用启动不自动迁移。
  4. shadow 只写 candidate/quality，不推进 consumer publication；通过门后启用 publish。
  5. 回滚 publication 时，在事务中把分区 current 指回上一 passed revision；不删除错误 revision 或 raw。
