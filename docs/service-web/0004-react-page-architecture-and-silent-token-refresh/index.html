摘要

事实

页面与组件平铺且职责混合

最大路由页同时持有 URL、查询、权限、表格、Dialog 与表单副作用；共享组件根目录也以单文件 平铺，局部能力的所有权不清晰。

决策

按路由与复用边界归档

每个路由页使用独立目录，单文件组件保持扁平。只有组件拥有多个强关联文件时才建立功能目录； 页面私有 UI、Hook、纯函数就近放置，不使用 barrel。

主要风险

401 重放与非幂等请求

每个业务请求最多重放一次；新 token 仍返回 401 时立即清会话。禁止无限刷新或无限重放。

业务理解

Actor 与入口

PC 桌面浏览器中的匿名登录者、已认证分析用户与管理员；入口为现有 `/login`、`/`、 `/users`、`/instruments/:symbol`。

首要任务

维护者能快速定位页面状态与组件；用户在 access token 轮换时继续当前任务，不看到路由闪变、 白屏或数据丢失。

边界

保持路由、信息层级、API 契约、权限语义与视觉不变。没有新页面，因此不触发视觉原型门禁； 不新增移动端、实时协议或未冻结 endpoint。

目录与职责

views/<PageName>/
├── <PageName>.tsx             页面信息顺序与组合
├── components/<Name>.tsx      页面私有单文件组件
├── hooks/use*.ts               页面状态、副作用与动作
└── utils/*.ts                  无 React 状态的纯函数

components/
├── <SharedName>.tsx           单文件跨页面组件
└── <CompoundName>/           拥有多个强关联文件的功能组件
    ├── <CompoundName>.tsx
    ├── components/
    └── hooks/
模块 职责与状态 依赖与失败边界
路由页 信息顺序、页面级分支、私有组件组合；首次等待显示统一 HydrateFallback。 依赖页面 Hook；懒加载失败交给路由错误边界，不出现空白文档。
页面 Hook URL、TanStack Query、本地表单与动作协调；密码仅保存在对应 Hook 内存。 依赖冻结 API client；错误转换为可恢复 UI，不泄露 Problem detail。
AuthSession 内存 access token、身份缓存、refresh 单飞 Promise 与一次重放。 refresh 401 或重放 401 清状态；网络/403 保留既有身份并上抛。
MUI 与图表 视觉值来自 theme/design tokens；图表高频状态保留在引擎实例。 重型引擎动态加载；销毁失败不得泄漏 Canvas 或监听器。

双 Token 静默刷新

业务请求 ── access token ──▶ service-api
   │                                │
   │                         首次返回 401
   │                                │
   └──── 保持页面与 URL ─────────────┤
                                    ▼
                         共享 refresh Promise
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
            refresh 成功 + /users/me          refresh 返回 401
                    │                               │
             新 token 重放一次                清会话并发布事件
                    │                               │
              返回业务结果                 React Router 站内跳登录
并发与安全边界 同一旧 token 引发的并发 401 只发起一次 refresh；若其他请求已更新 token，后到的 401 直接使用 新 token。每个 operation 只重放一次，避免写请求产生无限副作用。

实施与验收

实施

  1. 仓库内安装 Vercel React 与 MUI 官方 Skill。
  2. 迁移所有路由页到独立目录，并扁平化单文件组件。
  3. 按真实职责拆分用户管理、登录、AppShell、市场和图表能力，合并单次使用的微型组件。
  4. 实现单飞 refresh、一次重放与站内终态跳转。

验收

  • `views/` 根目录无平铺页面；单文件组件不额外套同名目录。
  • access token 过期时 URL、壳层与查询缓存不被清除。
  • 并发 401 只执行一次 refresh。
  • refresh 401 才进入登录恢复路径。
  • 初始 lazy/loader 等待阶段显示可访问的路由加载状态。
  • `vp check`、单元测试与生产构建通过。

回滚

目录迁移可按 Git 变更整体回滚，不改变 API 与数据。鉴权异常时可单独回滚 AuthSession 重放逻辑；服务端 refresh 契约无须迁移。
