Apex数据智能分析平台 · Technical solution · service-web · 0003

登录、受保护应用骨架与用户管理

为“Apex数据智能分析平台”建立无注册入口的自定义账号登录页、默认拒绝的受保护路由、白色应用骨架和分层用户管理工作台。 前端已接入 service-api 的已实施 Contract 0002：会话与权限由服务端权威判定，SUPER_ADMIN、ADMIN 和 USER 的可见动作与目标边界保持一致。

问题

实施前只有公开市场 fixture 路由；无登录、会话、用户信息、权限门或用户 CRUD 页面。

选择

已落地独立 AuthShell + 受保护 AppShell；TanStack Query 管会话/用户，URL 管筛选与用户弹窗入口。

理由

沿用 React Router Data Mode、MUI Theme 和现有 qv tokens；服务器继续是唯一安全边界。

主要风险

API 0002、Contract 0002 和 ADR-0008 已协同实施；后续演进不得弱化默认拒绝、目标级授权或敏感数据边界。

业务理解与页面分类

Actor / entry

匿名访问者与三类登录用户

匿名访问者只从 /login 输入系统分配账号和密码。登录用户从 / 进入工作区；ADMIN、SUPER_ADMIN 从导航进入 /users。

Primary task

安全进入与最小权限管理

用户需要确认“我能否进入系统”；管理员需要确认“哪些账号存在、状态如何、我能对谁执行什么动作”。

Success / failure

可恢复且不泄露

成功后返回原目标路由；失败保留非敏感输入、提供重试。401 清理敏感缓存，403 不渲染受限数据， 登录错误不暴露账号是否存在。

决策

消费已实施的真实 API

生产实现已接入 Contract 0002， 通过构建期 VITE_API_BASE_URL 调用真实 Auth/User API，运行时不使用 fixture/MSW。现有 Contract 0001 只代表已实现基线，不能满足 SUPER_ADMIN、验证码、详情、筛选、软删除和并发控制。

需求歧义已由 ADR-0008 解释 “未登录不允许访问登录接口和验证码接口”会使登录不可达。本方案采用 ADR-0008 的显式解释： 安全例外仅包含登录、常驻图形验证码、Refresh Cookie 刷新与同源幂等退出清理；健康探针是受部署网络 限制的运维例外。

路由、Shell 与页面架构

/login
Anonymous-only AuthShell。未认证可访问； 已认证访问时重定向到安全的 returnTo 或 /。不显示注册、忘记密码或其他未设计流程。
/
Protected AppShell index。首期显示最小占位， 未来在同一路由原位替换为“今日市场”；个人资产与虚构行情不得占据首页首屏。
/users
Protected + users:read。 查询、角色、状态、排序、cursor 和 pageSize 写入 URL；结果由 TanStack Query 持有。
/users?dialog=create
Protected + users:create。 URL 打开 720px Dialog，使返回键恢复列表；可选角色按服务端 permissions 与 actor role 收敛。
/users/:id?dialog=edit
Protected + target policy。 URL 打开 720px Dialog；详情从 Query 获取 ETag，提交 update/delete/reset 动作时带 If-Match。
403 / route error
壳层内失败边界。 403 不渲染受限数据；未知路由、可恢复数据错误和全局启动失败分别处理，不让一个子路由替换整个 AppShell。
AuthShell

自定义账号登录

输入/输出：账号、密码、captchaId/captchaAnswer → 当前用户；不提供注册或首次改密门。

状态：表单本地状态、login mutation、页面打开即加载的短期 challenge。

失败边界：失败留在登录页；不加载业务导航或数据。

Protected AppShell

导航、用户与反馈骨架

输入/输出：route matches + me.permissions → 可见菜单、用户菜单和 Outlet。

状态：账号菜单和未开放功能的短期提示；不保存 token 或服务端响应。

失败边界：会话失效清缓存回登录；子页错误保留壳层。

User workspace

列表、编辑 Dialog 与危险确认

输入/输出：URL filters + permissions + User page/ETag → CRUD mutations。

状态：远程数据进 Query，表单与删除确认留组件。

失败边界：每个 mutation 独立处理 400/401/403/404/409/412。

核心流程与失败恢复

登录与常驻图形验证码

打开登录页 → POST captcha（空 body）
  → 原样显示后端 PNG；用户可刷新
  → 提交 account/password/captchaId/captchaAnswer
  ├─ 200 → token 仅存内存
  │        → POST /users/me
  │        → 校验 returnTo
  │        → 进入受保护路由
  ├─ 422 captcha-invalid → 刷新图片并聚焦验证码
  └─ 400/401/403/429/503 → 通用错误 / 凭据错误 / 跨站拒绝 / 冷却提示 / 可恢复重试
每次提交后 challenge 作废，再次提交前重新获取。

刷新、深链与会话失效

访问受保护深链
  → 内存无 token
  → POST refresh（HttpOnly Cookie）
  ├─ 200 → GET me → require permission
  │        ├─ allow → 渲染页面
  │        └─ deny  → 壳层内 403
  ├─ 409 refresh-race → 等待跨标签页轮换完成后重试一次
  └─ 401/403 → 清敏感 Query
              → /login?returnTo=安全相对路径

用户创建/修改

Actor 打开 720px Dialog
  → 前端按 permissions 收敛字段
  → API 再做 actor/target 校验
  → POST /users/{id}/update + If-Match
  ├─ 2xx → 清空密码、关闭 Dialog、invalidate list/detail、提示成功
  ├─ 409 → 账号冲突，定位字段
  ├─ 412 → 保留草稿、重取详情、提示已被修改
  └─ 403/404 → 关闭受限详情，不泄露目标

软删除与退出

删除：行操作 → 明确对象 Dialog
  → POST /users/{id}/delete + If-Match
  → 204（含目标已删除）→ 移除缓存、回列表、toast

退出：POST logout
  → 精确 Origin；服务端不区分缺失/无效/已撤销 Cookie，始终清 Cookie 并返回 204
  → Web 清 token 与敏感 Query
  → replace 到 /login
  → 禁止返回键恢复受保护内容
路由守卫不是安全边界 React Router 的匹配 loader 可能并行执行。每个受保护数据 loader 必须通过共享 requireSession/requirePermission 前置函数，且 service-api 对每个请求独立鉴权； 不能只依赖父 loader 或菜单显隐。

PC 桌面、无障碍、安全与性能

PC desktop

固定桌面信息密度

  • 产品范围只覆盖 PC 桌面浏览器；默认设计与视觉验收视口为 1440×900。
  • 300px sidebar、72px appbar；内容区在 1200/1440/1920+ PC 桌面宽度使用 24/32/40px 内边距，宽表工作区最大 1536px。
  • 表格最小宽约 900px；默认视口全部核心列可读，必要时仅表格容器内部横滚。
  • 创建与编辑统一使用居中 Dialog，宽 720px；header/footer 可见，超高时仅内容区滚动。
  • 所有交互仅定义桌面鼠标、键盘与可见焦点反馈。
Accessibility

WCAG 2.2 AA

  • 持久 label、错误文本、自动完成属性、Enter 提交与密码显示可访问名称。
  • 验证码提供键盘可达的刷新、过期和错误说明；按产品约束不提供音频功能。
  • 导航 aria-current、skip link、可见 focus、40px 最小目标。
  • 角色/状态 Chip 含文字；Toast 用 live region；Dialog 管理焦点进入与返回。
  • 尊重 reduced-motion；Skeleton 接近最终几何。
Security

前端最小暴露

  • 不持久化 access token、密码、captcha 答案、challenge ID、Cookie 或完整 Problem detail。
  • 密码输入默认掩码且不预填；显示明文需主动触发，失焦、提交或关闭 Dialog 自动恢复掩码并清空。
  • 编辑 Dialog 不展示密码字段；重置密码走独立确认。日志、埋点与错误上报中的账号显示为 ad***01。
  • returnTo 仅接受同源相对路径，拒绝协议、host 与双斜线。
  • 401 清所有身份相关 Query；403 不清会话，不渲染受限数据。
  • 退出使用 history replace；缓存和浏览器返回不能恢复敏感页面。
  • 客户端显隐不替代 API actor/target policy。
