  │             └─ Market Stream Client ── WebSocket ──▶ service-api

DTO decimal string ── validate / normalize once ──▶ chart number
stream gap ── mark stale ── REST backfill ── resume live

HTTP 历史分页语义

  • init：取目标时间附近或最新一页，按开盘时间升序返回。
  • forward：按 KLineChart 语义加载更早数据；请求 before。
  • backward：加载更新数据；请求 after。
  • 服务端显式返回两侧 hasMore，不能用“返回数量不足”猜测结束。
  • Query key 包含 market、symbol、period、边界、方向和 limit，禁止跨周期复用。

实时增量语义

  • 服务端推送已聚合到周期的 Candle，不向图表灌入逐笔成交。
  • 相同 openTime 原位更新，更大时间追加，更旧或重复序号丢弃。
  • Stream Client 按 symbol + period 复用连接并做订阅引用计数。
  • 切换标的、周期、重置或销毁会释放旧订阅；组件不自行创建 WebSocket。
  • 重连检测序号缺口：先标记 stale，再 REST 补洞，成功后恢复 live。

interface CandleDto {

  interval: string
  openTime: string       // RFC 3339，含时区或 Z
  open: string
  high: string
  low: string
  close: string
  volume: string
  turnover?: string
  sequence: string       // 超出 JS 安全整数范围也保持 string
  isClosed: boolean
}

interface Candle {
  timestamp: number      // 仅前端规范化后使用的 Unix 毫秒
  open: number
  high: number
  low: number
  close: number
  volume: number
  turnover?: number
}
契约项 建议语义 前端处理
历史接口 GET /api/v1/market/candles；参数含 symbol、interval、 before/after、limit；返回 items 与双向 paging。 由生成 client 调用，经 Query Client 去重和缓存。
实时事件 market.candle.upsert；含 eventId、sequence、occurredAt、 symbol、interval 与 CandleDto。 验证 envelope 后按 key 分发；图表只收到已规范化 Candle。
Symbol ticker、exchange、timezone、pricePrecision、volumePrecision。 传入 setSymbol，价格精度不可由历史数据临时猜测。
Period 前端统一 1m/5m/15m/1h/1d/1w 等枚举。 用穷尽映射转为 KLineChart span/type；不支持值立即拒绝。
数值与时间 decimal 与 unsafe integer 使用 string；时间使用 RFC 3339。 图表边界校验 finite、OHLC 关系、升序和重复值，再转 number； 展示采用交易所时区。
契约状态 上表是 service-api 的实现要求，不是已存在接口。 开发纵向切片前，应把最终 HTTP 与实时 schema 分别落到 docs/contracts/ 和 OpenAPI；字段未确认时仅使用 MSW fixture。

KLineChart DataLoader 适配

const dataLoader = {
  async getBars({ type, timestamp, symbol, period, callback }) {
    const request = toCandlePageRequest(type, timestamp, symbol, period)
    const generation = currentGeneration
    const contextKey = toContextKey(symbol, period)

    try {
      const page = await marketDataGateway.getCandles(request, abortSignal)
      if (!isCurrentContext(contextKey, generation)) return
      callback(page.items.map(toKLineData), {
        forward: page.hasMoreBefore,
        backward: page.hasMoreAfter,
      })
      publishStatus({ state: 'ready', updatedAt: Date.now() })
    } catch (error) {
      if (!isCurrentContext(contextKey, generation) || isAbort(error)) return
      callback([], { forward: false, backward: false })
      publishStatus({ state: 'error', error })
    }
  },
  subscribeBar({ symbol, period, callback }) {
    marketStream.acquire(symbol, period, candle => callback(toKLineData(candle)))
  },
  unsubscribeBar({ symbol, period }) {
    marketStream.release(symbol, period)
  },
}
  • marketDataGateway 内部调用 queryClient.fetchQuery； Query Cache 是历史响应的权威缓存，KLineChart 只持有渲染数据。
  • 每次 symbol/period 变化递增 generation 并中止旧 HTTP 请求； 即使底层请求不能取消，旧 callback 也不能写入新图。
  • DataLoader 没有错误 callback；适配器通过旁路 status 通知 React 显示重试条。 用户重试调用 chart.resetData()，不静默无限重试。
  • 实时事件直接调用引擎 callback，不逐条写 React state；Query Cache 仅在 Candle 收盘或节流后更新，供其他组件读取。

故障策略 历史加载失败保留最后成功数据；实时断流显示“数据可能延迟”和最后更新时间； 恢复时按 sequence 补洞。异常、乱序或不满足 OHLC 不变量的数据进入观测日志， 不传给任一图表引擎。

共享 ChartVisualTokens

由 MUI theme 派生 background、surface、textPrimary、textSecondary、gridLine、 positive、negative、neutral、seriesPalette、fontFamily 与 fontSize。

首期面向中国市场，默认“涨红跌绿”；模型内部使用 positive/negative 语义， 未来切换国际配色只改映射。图标、正负号和文本同时表达涨跌，不能只靠颜色。

实例更新

KLineChart 主题变化调用 setStyles；ECharts option builder 注入新 tokens 后调用 setOption。MUI toolbar 与画布分离，画布有确定最小高度。

K 线页和分析面板各自 route-level lazy import；同页需要两种图时，再按面板可见性加载， 避免应用外壳提前下载双引擎。

质量、可靠性与安全

测试

Vitest + Testing Library + MSW + Playwright

  • Candle 校验、Period 映射、排序/去重、option builder：Vitest。
  • DataLoader 的 init/forward/backward、取消、旧响应和错误状态：Vitest + MSW。
  • 订阅 acquire/release、乱序、重复、断流、重连和补洞：可控 fake stream。
  • KLineChart init/dispose/指标协调、ECharts init/resize/dispose：引擎边界 mock。
  • 标的/周期切换、加载历史、主题、1440×900 桌面交互和恢复流程：Playwright。
  • Canvas 不做大面积脆弱像素断言；验证数据、交互和少量稳定截图。
性能

按路由切包，图表隔离

  • 应用外壳不得静态导入任一图表；KLineChart 与 ECharts 生成独立异步 chunk。
  • ECharts 使用 echarts/core 按需注册；构建报告验证无 candlestick 模块。
  • 同页双引擎按面板可见性加载；不通过 shared barrel 造成意外预加载。
  • 列表达到规模阈值再引入 MUI X Data Grid/虚拟化。
  • 基准：5,000 根 Candle 首次可交互 ≤ 1.5s；单根增量更新 ≤ 100ms。
  • 基准环境、数据 fixture 和结果进 CI artifact；升级后体积或耗时退化超过 10% 阻断。
安全与隐私

浏览器不是可信边界

  • VITE_* 只允许公开配置，绝不放密钥。
  • 优先 HttpOnly + Secure + SameSite cookie；CSRF 策略与 API 一起设计。
  • 不把 token、账户敏感数据或完整响应持久化到 localStorage。
  • ECharts HTML tooltip 与服务端文案按不可信输入处理，禁止执行远端 chart option。
  • KLineChart 指标、overlay 和样式只能从本地白名单重建，拒绝远端函数配置。
  • 生产 source map 私有上传；日志过滤 token、cookie、账户和持仓明细。

故障与恢复

  • 路由级 Error Boundary 区分 401/403/404/429/5xx/离线。
  • 查询只对幂等请求有限重试；429 尊重 Retry-After。
  • 行情断流时保留最后数据，明显显示更新时间和 stale 状态。
  • mutation 默认不自动重试；避免重复创建告警或订单类操作。

可观测性与可访问性

  • API 错误附 request/correlation id，前后端日志可串联。
  • 记录图表 init、首批数据到首次渲染、流延迟、重连、补洞和丢弃事件计数。
  • 错误采集供应商经轻量 adapter 接入；不上传原始持仓、策略参数或全量行情。
  • 目标 WCAG 2.2 AA；键盘焦点、对比度、reduced motion 纳入验收。
  • ECharts 注册 AriaComponent；两引擎都提供文本摘要、数据表入口和键盘工具栏。
  • 颜色不是涨跌唯一表达；tooltip 与状态同时显示正负号和文字。

实施、发布与验收

  1. 阶段 0｜契约冻结： 确认 market/symbol/period、复权、交易所时区、历史双向分页、实时 sequence 和错误模型； 更新 OpenAPI 与实时 schema，产出固定 MSW fixture。
  2. 阶段 1｜工程骨架： 用 vp create 在临时目录生成 React + TypeScript 模板，再安全合并到已有 service-web/；固定 Node/pnpm/Vite+/TS 版本，补 README、环境示例、CI、 Data Router、MUI theme、Query Client、MSW 和 Playwright。 已完成（2026-07-26）。
  3. 阶段 2｜图表基础设施： 加入 ChartVisualTokens、KLineChart 动态加载、ECharts 按需注册、useECharts、 图表错误边界和统一 loading/empty/error/stale 外壳；构建确认双引擎独立 chunk。 基础设施已完成；真实数据状态待 API 契约。
  4. 阶段 3｜K 线历史纵向切片： 实现 DTO 校验、Period 映射、Market Data Gateway、DataLoader 和 KlinePanel； 打通标的 → 初始页 → 向前分页 → 周期切换 → 失败重试。 目前仅 fixture DataLoader；不将其标记为完成。
  5. 阶段 4｜K 线实时与专业能力： 实现共享 Stream Client、订阅释放、乱序/重复/缺口处理、补洞； 加入 MA/VOL/MACD、指标选择和首批 overlay，完成桌面鼠标、键盘交互专项回归。
  6. 阶段 5｜ECharts 分析纵向切片： 先交付市场宽度、资金流和回测净值/回撤三类图； 每类具备独立 DTO mapper、dataset、option builder、空态、错误和数据表入口。
  7. 阶段 6｜发布门禁： 运行全量 check/test/build/e2e、bundle report、5,000 Candle 基准、断网恢复、深浅主题、 1440×900 PC 桌面与可访问性检查；灰度开启实时和画线能力。
