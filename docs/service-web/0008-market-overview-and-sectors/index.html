真实来源、许可与 HTTPS 门禁

无凭证不启动市场生产链：DATA_SYNC_MARKET_OVERVIEW_ENABLED=true 同时要求 DATA_SYNC_TUSHARE_ENABLED=true、DATA_SYNC_TUSHARE_TOKEN、不低于 6000 的 entitlement 配置和非 disabled 的 license scope；staging/production 进一步要求 commercial-redistribution-approved 与非空 license reference。adapter preflight 会真实调用全部 required 端点，校验目标开市日、字段 schema、全量行数和响应上限；未通过时在第一个 canonical 写入前失败。当前工作区没有合法 token/license，故没有执行也没有虚报这项实盘验证。
  • provider 出站固定 https://api.tushare.pro，使用系统 CA 与 hostname 校验；重定向处理器只允许 HTTPS → HTTPS，禁止 token 降级到明文。

  • 本地 Compose 的 service-api → data-sync 默认基址允许私有 HTTP 以便开发。生产若跨主机、跨命名空间或经过不可信网络，必须改用 HTTPS/mTLS 或受控 service mesh；未满足时部署 readiness 失败，不能以 Bearer 代替传输加密。

发布与补洞
  • 只以 Tushare trade_cal 中 SSE/SZSE 共同开市日为资格集合；当前交易日到 Asia/Shanghai 17:20 后才具备 EOD 组件发布资格，但官方个股 moneyflow 在 19:00 更新，完整 bundle 不在 19:20 前启动。
  • Data Operations incremental run 在最近 25 个共同交易日中查找缺失 bundle，按日期升序补齐；fencing、幂等 content hash 和 terminal write 防止失租任务推进指针。
  • 当前 Data Operations 以 datasetCode 唯一约束每个 dataset 只有一个持久化 schedule，仓库不 seed 默认值；部署必须通过 0022 /schedules/upsert 配置交易日 19:20。adapter 在同次运行内最多做 3 次有界网络重试；仍失败时由运维调用 /commands/retry，或由次日 incremental 的 25 交易日窗口补洞。19:35、19:50 自动二次触发不存在，20:00 未成功只触发运维告警。未配置 19:20 schedule 视为部署门禁失败。
原子与历史 revision
  • component release、bundle 和 pointer transition 均 append-only；首页 latest 只解析 active current pointer，精确 asOf 读取不可变历史 bundle。
  • 来源修订创建新 component/dataVersion 与新 bundle；rollback 只切换指针，旧内容、质量报告和 transition 保留。
  • 指数/SW bars 的 lineage 最多 7500 个唯一输入版本；sector EOD、SW 成分和 SW 估值使用两个唯一组件生成 composite dataVersion，浏览器显示输入版本数。

  5. 行业/概念强弱：两个独立排行；点击进入板块详情。
  6. 股票排行：涨幅、跌幅、成交额、活跃摘要切换；每项仅 5–10 条并深链 0007。

  • 一级页签固定为“东财行业 / 东财概念”，URL 保存 scheme；两套结果不合榜。

8.4 错误、可靠性与容量

  • 指定日期没有 complete bundle：404 publication-not-found，附 latestAvailableDate；最新指针也不存在：503 dataset-unavailable。永不返回 200 + 零值。
  • 参数非法 400、未认证 401、无权限 403、游标版本变化 409、限流 429、下游超时/契约漂移 503；Problem Details 只含稳定 code、requestId、retryAfter。
  • overview 目标 p95：warm ≤350ms、cold ≤1200ms，响应 ≤256KB；排行 limit≤50，bars 单页 limit≤1000。指数/SW bar lineage 上限 7500 个唯一 input dataVersion，内部最大响应 2MiB；内部 client timeout 1.5s，公开总预算 2s。
  • 同一用户 + route 使用既有网关限流；ETag 命中返回 204 且不带 body。日志记录 route、duration、status、dataVersion、requestId，不记录响应行情明细。
  • 连续 5 次下游网络失败/30s 打开 circuit，15s 后 half-open；circuit 期间 503，不由 API 内存缓存伪装成功。已发布数据仍可由 data-sync 读端正常服务。

10. 跨 publication、跨来源与部分失败

首页：写时组合，读时原子

  1. 同日完整：bundle coordinator 只接受 tradeDate=T、production、final、quality=passed 的必需组件。组件版本可以不同，但都被同一不可变 manifest 固定；assembledAt 不是行情时间。
  2. 不推进不等于丢数据：T 日任一组件失败时，各组件 publication 仍可供运维和详情使用，但首页 current pointer 保持 T-1 完整包；页头明确“最新完整数据 T-1 / T 日仍在校验”。
  3. 无读时拼接：service-api 不并发拉取“各自最新”，所以不会产生指数 T、资金 T-1、板块 T-2 的伪同屏。requested asOf=T 且 bundle 不存在时返回 404，不自动改日期。
  4. 来源隔离：行业、概念、申万和不同资金流方法学分别成组；不在 envelope 内做相加、平均、交叉排名。
  5. 质量优先：被隔离、research、coverage 不足或 incomplete 的 publication 不因页面需要而放行。
  6. 修订可见：publication rollback 后缓存键/ETag 变化；页面刷新显示新版本，并在详情元信息中保留 revision/原因。

14. 降级、发布与回滚

配置门禁与发布切换

  • 数据侧以 DATA_SYNC_MARKET_OVERVIEW_ENABLED、Tushare enable/token、license scope/reference 作为强门禁；未满足时进程或执行在写 publication 前失败。
  • 当前 service-api/service-web 没有虚构的 market 专用运行时 feature flag。发布切换使用可回滚镜像、入口路由/访问策略与 data-sync current pointer；若未来增加 flag，首页 20 项仍必须作为一个 release unit，不能关闭失败卡后把不完整页面称为 complete。
  • 数据侧 production provider 只允许 tushare-pro，publication 指针是唯一事实；API/Web 部署开关不能绕过同步质量与许可门禁。

降级顺序

  1. T 日完整包构建失败：保持 T-1 current pointer，页头显示“最新完整数据 T-1”；不让 T 日半包进入首页。
  2. 详情派生解释卡失败：仅该卡显示错误，保留同页已成功的真实 publication。
  3. 资金流过期/失败：不推进首页 bundle；详情不替换为沪深港通、融资融券或成交额。
  4. 单个 scheme 失败：另一个 scheme 正常，页级标记 partial。
  5. 从未有完整包：路由显示系统级 unavailable 与重试/运维 requestId，不展示任何行情或 fixture。

回滚

  • service-data-sync：回退 current publication 指针；保留失败 revision、raw 与质量报告，禁止覆盖历史。
  • service-api：新字段先可选扩展、真实回填验证后收紧；overview 不回退到现有细粒度 API 现场拼装。
  • service-web：回退到上一已验证镜像或在入口撤下市场路由；TanStack 缓存随 ETag/dataVersion 失效，不能继续显示被撤回 publication 为“最新”。详情组件局部失败保持独立，不需要为一张增强卡回退整个首页。
  • 数据库：新增表/列迁移要求可回滚；publication rollback 与 schema rollback 分开演练。

真实数据逐层对账

  1. Provider → canonical：抽取四指数全部行、每场所 30 只股票、5 个行业/5 个概念、5 个 SW 节点，逐字段核对 source response、单位转换、identity 和 digest。
  2. Canonical → 派生：用冻结 input publication 重算 breadth、turnover、limit、四类股票排行和 5/20 日 sector strength，结果逐项相等；无 request-time 扫表。
  3. Publication → internal API：manifest 中 component dataVersion 与内部 GET body/ETag 一致；撤回一个 component 后新 bundle 不生成。
  4. Internal → public API：公开 overview 必填 20/20、四指数长度=4、breadth 恒等式成立、金额 decimal string 无精度损失、敏感字段未暴露。
  5. API → browser：拦截网络请求确认只访问 service-api；页面显示的 tradeDate/dataVersion/source 与 API 一致；刷新命中 204 后 DOM 数值不清空。
  6. 反假数据检查：production build 对 mocks/market-overview、demoMarketOverview、MSW market handler 做依赖图/文本双检，命中即失败；预发断开 provider 时只能显示已发布真实版本或 unavailable。

发布质量阈值

连续 20 个开市日 bundle 成功率 100%；首页 required component coverage 100%；身份未解析 0；breadth unknown 0；API schema 失败 0；跨服务 E2E 100%；overview p95 达到第 8 节预算；桌面视觉差异经评审批准。外部源临时失败可导致当日 bundle 延迟，但不能导致错误数值或半包上线。
