1. 核心结论

01 / RUNTIME

调研起点的开发库没有 publication

初始只读查询确认 dataset_publication 总行数为 0，因此实现保留了“数据尚不可用” 的稳定状态。隔离联调环境只通过真实来源建立 publication，任何环境都不能退回 fixture、 可变表最新行或自行推断数据。

02 / DETAIL

个股详情与 typed API 代码链已接通

身份、生命周期、日/周/月线、复权、公司行动、公司概况、财务、估值、分类和事件已有 service-web → POST API 代码路径；运行审计尚未形成可读 current publication。资金流只接状态边界， 因方法学尚未完成 validated 而明确不可用。

03 / DISCOVERY

统一横截面代码链已落地

POST /api/v1/equities/search 只读取 equity.discovery.eod 的单一冻结 publication，在服务端完成筛选、排序和游标分页； 浏览器不再通过逐证券 N+1 请求拼接股票列表；无 current publication 时该路由返回稳定 NO_PUBLICATION，而非空列表或示例数据。

04 / GAPS

剩余缺口被显式关闭而非伪造

交易所“暂停上市”仍没有已验证 producer，资金流仍没有 validated 方法学和生产 publication； 两项都以 NOT_COVERED / UNAVAILABLE 原因化。普通停牌、申万成分、历史股本和市值链已独立实现， 不拿普通停牌冒充生命周期，也不从供应商市值字段反推股本。

最重要的产品语义： 页面展示的是“最近一个已发布、可复验的 EOD / 报告数据版本”，不是实时行情。 本方案不引入 WebSocket、Level-2、实时盘口或任何未冻结 endpoint。

实施后仍明确非目标

  • 本方案已作为三服务生产实现基线；只实现冻结股票中心范围，不顺带重构其他市场模块。
  • 不修改 Token、既有方案、ADR 或 OpenAPI；依赖与 lockfile 仅保留真实异步来源、已验收供应商版本及全量回填入口所需的最小变更。
  • 不承诺实时行情、推送、盘口、Level-2 或供应商未冻结能力。
  • 不把公司概况中的自由文本“行业”当作行业 taxonomy。
  • 不把不同资金流方法学或不同估值来源静默合并。

证据优先级

  1. 运行时只读数据库查询：只证明本机开发环境当前 publication 状态。
  2. 公开/内部契约与 Controller：证明可消费边界和 HTTP 语义。
  3. Repository、publication 与 ORM：证明存储、读取和冻结机制。
  4. 同步入口与来源批次证据：证明能力可执行条件，不等于当前已发布。
  5. README 与既有方案：补充设计背景；与运行代码冲突时以代码和契约为准。

当前 Web 事实

  • service-web 使用 React 19、React Router 7、MUI 7、TanStack Query、KLineChart 10 和 ECharts 6；股票中心列表、详情和旧路由解析均使用真实 API，生产路径没有市场 fixture 回退。
  • /market/equities/:exchange/:symbol 是唯一详情身份边界； /instruments/:symbol 只查询稳定目录并在唯一命中时携带 effectiveAsOf 跳转，不按代码前缀猜交易所。

4. 股票列表信息架构与路由

/market/equities

股票中心默认入口；固定桌面壳内展示检索、筛选、结果表、publication 摘要与 cursor 分页。

/market/equities/:exchange/:symbol

唯一个股 canonical URL；exchange 为 SSE|SZSE|BSE， symbol 为六位代码，身份解析不依赖代码前缀猜测。discovery 每行同时返回 identityAsOf；历史退市或代码复用行必须导航为 ?asOf=identityAsOf，当前唯一身份可省略。URL 不暴露内部 UUID。

列表页面层级

  1. 页面标题与发布摘要：“股票中心”、目录 publishedAt、 effectiveAsOf、dataVersion 和 quality。
  2. 主检索：代码 / 名称前缀；交易所作为显式筛选，不把“上交所”自由文本解析成身份。
  3. 一级筛选：交易所、上市状态、普通停牌状态、行业体系、行业/概念/申万节点； production 入口只在真实 SW membership 完成后开放，不伪用公司概况 industry。
  4. 结果表：身份列固定在左侧，EOD 行情与可选分析列右对齐；列头显示排序方向和口径。
  5. 页尾：pageSize、cursor 翻页、单位、asOf 和横截面版本。

  • 默认链接只保存查询意图；用户选择“复制精确快照”时加入 API 0007 已冻结的 dataVersion。版本已清理返回 snapshot-expired，不由 Web 伪造历史结果。

排序、筛选和分页边界

  • 搜索代码/名称前缀。
  • 单交易所或已通过冻结来源矩阵的交易所稳定聚合；当前沪深行情仅完成来源正向 probe，仍待 E2E；北交所身份可见但周期行情不进入可消费聚合。

  • 固定 exchange + symbol + instrumentId 顺序。
  • 服务端 cursor，每页默认 50、最多 100。

  • 冻结全市场同一 asOf 的 discovery snapshot。
  • 服务端完成行业集合过滤和跨列排序。
  • 所有可排序字段都有明确空值位置与方法学。

真实全量与失败语义

  • “全量”表示覆盖三所当前与历史身份，以及每个交易所由冻结来源矩阵实际验证可提供的完整历史； K 线与复权当前只有 SSE/SZSE 的有效 coverage。BSE 的日/周/月或复权为 SOURCE_EXCHANGE_UNAVAILABLE，只能失败关闭，绝不能写成合法空集、PARTIAL 数据值或完成全量。 上游没有历史时显示 coverage start，不生成补造行。
  • BASE discovery 的身份、名称、交易所和生命周期必须全覆盖；可选组件存在 SOURCE_UNAVAILABLE / QUARANTINED 时以 PARTIAL 发布并逐字段给出 nullReason， 不能沿用其他日期或来源的值伪装完整。
  • 开发可分阶段，但承载股票中心导航的 Web 版本必须等同步、API、Web 的真实 E2E 全部通过才部署，不发布“基础版假数据”或半条链。
  • 非 test profile 拒绝 fake/fixture/demo provider；每条可见数据都能从 dataVersion 追溯 component publication 和 sourceBatchId。

跨服务一致性与失败边界

  • service-web 只相信 API release/meta/header，不根据当前时间推测版本，不调用同步写接口。
  • service-api 不跨库、不查供应商、不缓存市场权威；只经 typed client 访问 data-sync。
  • data-sync publication 指针是数据回滚单元；历史 revision 和 superseded publication 保留。
  • 详情允许多个 dataset 处于不同 dataVersion；独立 partial/stale，不制造全页同版本。
  • discovery cursor 链严格单 dataVersion；变化返回 snapshot-expired，Web 清 cursor 后重启第一页一次。

9. 性能、分页、K 线生命周期与 Bundle 预算

列表分页 默认 50，最大 100；服务端 cursor；禁止全量拉取和客户端跨页排序。
列表响应 目标压缩后 ≤ 512 KiB / 页；component metadata 不逐行重复。
K 线首屏 初次 240 根，历史向前每页最多 500；请求可取消。
路由 JS 股票列表新增 gzip JS ≤ 120 KiB，不包含独立图表引擎 chunk。
图表 Bundle KLineChart 与 ECharts 分别懒加载；相对当前引擎基线不得增长超过 10%。
桌面体验 目标 LCP ≤ 2.5s、交互响应 ≤ 200ms；实施前先记录现有构建基线。

真实容量实测（首发前执行，不能用估算替代）

  • data-sync 的全市场目录请求允许 600 秒墙钟上限；该值是异常边界，不是把 600 秒当作已证明的常态性能或公开 SLA。
  • 每个 dataset/capability + exchange + period 必须在生产等价 egress 记录真实来源 p50/p95、成功率、重试次数和样本量；Web 不以开发机一次成功替代这些证据。
  • 容量报告还必须记录 DB 写入/事务 p50/p95、WAL 字节与 checkpoint、对象存储 PUT/HEAD p50/p95 和字节量、worker CPU throttling、RSS/内存上限及 OOM=0。
  • 以实测并发和重试余量计算 EOD 临界路径：目录、来源抓取、DB/WAL、对象存储、discovery build 与 publication 的 p95 总预算不得超过收盘后 120 分钟；超预算不推进新 current pointer，页面保留上一版本并标记 STALE。

KLineChart 生命周期

  1. 进入“行情”页签时才动态 import KLineChart；股票列表不加载任何图表引擎。
  2. 每个详情 route 只有一个 KLineChart 实例；symbol / period / adjust 变化复用实例并 reset data。
  3. DataLoader 按时间向过去分页；请求绑定 exchange、symbol、period、adjust 和 dataVersion。
  4. 用户快速切换证券/周期时取消旧请求；晚到响应必须校验 query identity 后才可写入。
  5. cursor 出现 snapshot-expired 时清空当前 bars，使用新 publication 从首屏重载。
  6. 页签卸载或 route 离开时 dispose 精确实例，释放 Canvas、ResizeObserver 和事件监听器。
  7. MA、VOL 等 overlay 状态归图表实例；只有明确可分享的 period/adjust/date range 进入 URL。

ECharts 生命周期

  • 只在财务趋势、估值、资金流等非 K 线页签加载，使用 Canvas renderer 和 ARIA。
  • 同页多个小图共享已加载 chunk，但每个实例按容器 resize，并在卸载时 dispose。
  • 大表默认不同时渲染多张图；用户选择 metric 后才构建 series，避免隐藏图表占用内存。

缓存预算与降载

  • 内存只保留当前证券、前后最近访问证券和当前列表页；超过预算由 Query GC 回收。
  • K 线超过 3,000 根时优先淘汰远离可视窗口的内存页；精确阈值在实现压测后校准。
  • 详情页签关闭后不预取其全部历史；只允许预取身份头和默认行情首屏。
  • 无 publication / 403 / 404 不进行级联请求；identity 未成功前不启动详情其他 query。

  • 若 component publication 不一致或质量门失败，不推进 discovery 当前指针。

  • 股票代码、名称前缀、交易所和生命周期搜索/筛选符合契约。

  • 完整列表所有排序/筛选均由同一 discovery publication 在服务端执行。
  • 分页、URL 刷新与分享不拼接两个 dataVersion。
  • 无 publication 与合法空结果文案、动作和埋点不同。
  • 旧 symbol-only route 不按代码前缀猜交易所。

  • 资金流当前显示明确 UNAVAILABLE；未来只有 validated publication 才显示 supplier/methodology/version/bucket/window，且禁止静默 fallback。
  • 估值标明供应商观察 finality，不宣传为官方最终值。
  • partial/stale 只影响对应面板，identity 失败才阻断详情。
  • 中国市场红涨绿跌，同时有 +/−、↑/↓ 或文字。
  • 1440×900 与 1280×720 桌面视口无页面横向溢出。
  • 列表、K 线和各页签达到 payload、Bundle、缓存与交互预算。
  • 键盘顺序、焦点可见、表头语义、图表 aria-label 与错误提示可访问。
  • 未引入实时、WebSocket、Level-2 或未冻结 endpoint。

11. 已冻结决策与执行责任

代码实现没有待选方向，首发仍有明确验证项：逐 cell 的真实来源批次、coverage、质量与 publication、 容量实测和三服务 E2E。它们不是“代码已实现”可以自动跳过的数据事实；无 publication 时入口显示稳定状态而非示例数据。

D1
产品频率：只承诺最近合格 EOD

已发布的价格、涨跌、成交额、换手、市值与估值显示 tradeDate；资金流当前只显示 UNAVAILABLE。不出现实时、盘中或 Level-2 暗示。

D2
Discovery 先保证 BASE 真实可用，宽字段允许显式 PARTIAL

身份、名称和交易所必须覆盖全部证券；生命周期与交易状态按来源覆盖返回事实或 NOT_COVERED。行情、市值、估值、资金流与分类缺失时必须为 null 并带原因和组件状态，不得伪造，也不得阻断基础证券发现。

D3
分类体系并列显示，不互相替代

Eastmoney industry/concept 与 SW2021 分开筛选和标注；默认行业展示 SW2021 三级，未覆盖时显示原因，不回退到公司自由文本。

D4
列表估值默认口径

默认展示 PE_TTM 与 PB 的 provider observation 仅在其来源批次、质量、coverage 与 publication 全部通过时显示；列头和数据说明展示来源标签与 method/version，不宣传为官方最终值。

D5
资金流列表默认口径

当前没有默认口径：方法学尚未达到 validated，列表与详情固定显示 UNAVAILABLE。只有完成连续探针、可比性验证、完整 EOD 来源批次和方法学晋级后，才以新 publication 显示。

D6
权限沿用已认证市场数据读取

普通已认证用户可读股票中心；同步、回填、回滚继续走数据运维 RBAC，查看页面不会隐式触发写操作。

D7
分享语义

列表 URL 默认表达查询意图；可选 dataVersion 用于审计级快照分享。详情 URL 不强塞统一版本，各面板显示自己的 dataVersion。

D8
事件身份解析

固定使用 POST /api/v1/equities/:exchange/:symbol/events/search；data-sync 内部解析身份，Web 永不接触 entityRef UUID。

D9
实施顺序与上线责任

data-sync 先完成真实 source batch、coverage 与 publication，API 再完成严格数据版本投影，Web 最后接入；平台 owner 在质量、容量与三服务真实 E2E 全通过后部署包含股票中心入口的 Web 版本。
