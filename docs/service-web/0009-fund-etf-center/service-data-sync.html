一期只生产 SSE/SZSE 交易所上市 ETF 的 profile、未复权日线、NAV 和三维状态。 使用真实上游、不可变原始证据、canonical revision、质量门禁和 typed publication； 不通过代码前缀归类，不用目录差异制造退市，不用其他字段补造缺失事实。

2. 真实来源与标准化矩阵

dataset 冻结来源 来源事实 标准化与禁止项
fund.etf.profile.reported SSE： 上交所官方当前基金列表的显式 CATEGORY=F100 ETF 范围与官方分类树；SZSE：官方基金工作簿中的显式 基金类别=ETF 行。 SSE 直报代码、简称、官方分类、上市日期、管理人与标的指数；SZSE 直报代码、简称、投资类别、上市日期与管理人。 venue 由专属 endpoint 固定；SSE 必须属于官方 ETF 分类树，SZSE 必须按来源显式“ETF”类别过滤。REITs/LOF/其他基金拒绝进入 ETF。旧的按日期份额接口不再充当 目录；目录缺席不写 DELISTED。

fund.etf.trading_state.reported 现有 Eastmoney ETF 资料页中明确报告的申购/赎回状态。 SUBSCRIPTION、REDEMPTION；当前没有可信 TRADING 状态来源。 只发布来源实际维度；TRADING 缺失保持未发布，不从成交量或 K 线缺口推断停牌。

3. 模型、publication 与 reader v2

对象 持久化变更 publication 分区 v2 公共字段
Profile 为 profile revision 增加 displayName、名称来源、生效时间；上市状态接受显式证据，允许 UNKNOWN。 venue:{SSE|SZSE}；观察日进入 release coverage，不用日期拆散当前目录 cursor。 身份、名称、类型、列表状态/日期、管理人/托管人及真实空值。
Bar 复用现有 OHLC/volume/amount/unit/currency/tradeStatus revision。 etf:{uuid}；coverage 保留请求日期窗口。 OHLC、volume/unit、amount/currency、tradeStatus、UNADJUSTED。
NAV 复用 UNIT/ACCUMULATED、currency、finality；不接收 IOPV。 etf:{uuid}；coverage 保留请求日期窗口。 navDate、navKind、nav、currency、finality。
State 复用三维独立状态与 effectiveFrom；补齐可空 effectiveTo/reason。 etf:{uuid}；部分维度发布是合法结果。 dimension、state、有效期、来源实际理由。
  • 同一标准化内容重放不产生重复事实；内容变化追加 revision，旧 revision 关闭 known_to，不原地覆盖。
  • 只有质量状态 PASSED/WARNED 且 release 完整时更新 current publication；失败批次保留 raw 与质量证据但不公开。
  • cursor 绑定 dataset/schemaVersion/partition/dataVersion/filter/sort；publication 变化后旧 cursor 返回 409。
  • 目录快照只证明“本次观察到”；没有明确生命周期事件时不写 DELISTED。

4. 控制面 executor 与依赖顺序

executor selector / mode 前置 结果
ETF profile 单 venue=SSE|SZSE，或显式 scope=ALL_VENUES。 来源启用、交易所日历、profile source 配置。 ALL_VENUES 固定生成 SSE/SZSE 两个独立分区与 publication；一方失败不伪造另一方成功。
ETF bar 单 etf，或 scope=ALL_ETFS。 预检冻结 SSE/SZSE 两份 profile dataVersion、全集记录数和哈希；日期窗口合法。 每个 ETF 是独立 fenced partition；成功分区发布 bar release。
ETF NAV 单 etf，或同样冻结的 ALL_ETFS。 profile 全集存在且非空；日期窗口明确；预检同时冻结可同步集合和来源语义明确但当前合同不支持的集合。 可同步 ETF 独立发布 NAV release；货币收益型 NAV 生成带稳定 reason 的审计跳过分区， 不伪造 UNIT NAV，也不令其他 ETF 失败。
ETF state 单 etf，或同样冻结的 ALL_ETFS。 profile 全集存在且非空。 仅发布来源实际报告的状态维度；缺少 TRADING 不补造。

4.1 代码接入点

  1. 已在 register_canonical_executors 注册四个 dataset executor，复用控制面的 global fencing、attempt、checkpoint、日志和取消语义。
  2. executor 通过现有 composition root 构造 EtfMasterSyncService、bar/NAV/status service、仓储和 raw store。
  3. bar/NAV/state selector 只接受 profile publication 返回的 entityRef + 显式 exchange/symbol；拒绝裸 symbol。
  4. ALL_ETFS 预检从两份不可变 profile publication 生成稳定全集并固化哈希；每 ETF 独立 partition，局部失败不回滚其他 ETF publication。NAV 预检的 universe hash 同时覆盖 eligible 与 currentlyUnsupported 两个有序集合；重试不得重新分类。
  5. 货币市场 ETF 只能依据官方产品分类或已观察到的收益型 NAV 语义进入 CURRENTLY_UNSUPPORTED 集合，禁止依据 symbol 前缀识别。该分区以 NAV_SEMANTICS_UNSUPPORTED_MONEY_MARKET 完成审计，不能触发全局 provider circuit。
  6. 旧 data-sync-etf CLI 保持拒绝，避免出现两套执行/锁/恢复语义。

5. 调度、全量回填与恢复

任务 冻结调度（Asia/Shanghai） 首轮全量 增量与重试
Profile 计划任务使用一个 ALL_VENUES selector，触发时精确拆成 SSE/SZSE 两个独立分区。 抓取当前交易所目录；不伪造历史目录。 每个分区独立失败、重试和 publication；成功分区不因另一分区失败而丢失。
Bar 计划任务使用冻结 profile 版本的 ALL_ETFS fan-out。 FULL 对每只 ETF 提交一个 1990-12-19 至冻结锚点的来源窗口；checkpoint 粒度是实体 partition，不虚构年度子窗口。 成功/失败/cancelled partition 精确汇总；重试继承已成功分区且不重复发布。
NAV 计划任务使用冻结 profile 版本的 ALL_ETFS fan-out。 FULL 对每只 ETF 提交同一冻结历史窗口；来源 adapter 负责其协议内的分页。 来源不可用标失败；来源明确返回合法空时分区成功、记录 EMPTY availability 且不生成空 publication。
State 计划任务使用冻结 profile 版本的 ALL_ETFS fan-out。 只保存来源可报告历史；没有历史时从首次观察日起积累。 状态变化追加 revision，未返回维度不自动关闭；取消语义按已有进度区分 PARTIAL/CANCELLED。

调度复用仓库既有 Data Operations schedule 机制，不引入第二套 scheduler。所有窗口含首尾日期； checkpoint 粒度为 dataset + partition + window。重跑使用相同 selector，成功后原子切换 publication。

5.1 故障恢复

  • 网络/限流：按 provider policy 指数退避并尊重 Retry-After；超过 attempt 预算记录 SOURCE_UNAVAILABLE，不发布空事实。
  • schema 漂移：不可重试，隔离原始载荷，阻止 current publication 更新并告警。
  • 合法空集：记录 EMPTY + no_matching_facts；必须与来源故障、解析后全被拒绝区分。
  • 错误 publication：消费端切回前一 dataVersion；修复后新 revision/release，禁止删除历史或直接改生产表。
  • 部分 ETF 失败：成功分区继续发布；目录级失败则不启动依赖 fan-out。

6. 质量门禁与可观测

dataset 硬门禁 连续性门禁
Profile venue 证据 100%；symbol 六位且非空；displayName 非空；SZSE 来源类别明确 ETF；entityRef/代码无重复。 当前实现不含基于历史 publication 数量的自动阈值。待积累真实基线后再评审连续性 门禁；在此之前只陈述已实现的逐行、唯一性、来源与 release 质量校验。
Bar 日期唯一；high ≥ max(open,close,low)；low ≤ min(open,close,high)；价格正数；volume/amount 非负且单位/币种明确。 交易日日历缺口形成 coverage warning，不自动补零；回读窗口变化记录修订率。
NAV 日期 + navKind 唯一；NAV 正数；kind/currency/finality 显式；拒绝 IOPV。 缺少来源公告时间保持 OBSERVED_ONLY；不可伪造 sourcePublishedAt。
State dimension/state 枚举匹配；有效期顺序合法；同维度同起始日唯一。 只统计来源覆盖维度；缺少 TRADING 不使 SUBSCRIPTION/REDEMPTION 失败。

指标按 provider/dataset/partition/attempt 输出：抓取耗时、原始行数、接受/拒绝数、内容哈希、 inserted/unchanged/revised、availability、quality、publishedAt/publicUsableAt、source lag、当前 publication age。 告警必须携带 requestId/attemptId/dataVersion/raw evidence 定位，不能携带凭据。

7. 真实全链路验收

  1. 在隔离验收环境启用真实 AKShare adapter；数据库为空，不加载 seed、静态产品清单或测试业务记录。
  2. 通过 Data Operations 控制面提交 SSE 与 SZSE profile；等待成功并记录两个真实 dataVersion。
  3. 从 profile publication 选择第一条返回的真实 ETF entityRef；不得在测试中硬编码 symbol、名称或数值。
  4. 用该 entityRef 提交 bar、NAV、state；状态允许只出现来源真实报告的维度。
  5. 分别执行四个内部 typed query，核对每条 record 可追到 canonical revision、source observation 和 raw hash。
  6. 通过 service-api 已认证公开 POST 读取同一 dataVersion，逐字段与内部响应比对。
  7. service-web E2E 从列表第一条真实记录进入详情，断言页面文字/图点均来自公开响应；无 publication 时只渲染真实空态。
  8. 停止来源或注入 schema 漂移，验证旧 publication 仍可读、新 publication 不切换、页面准确显示延迟/不可用。
“全量打通”验收定义为四个一期 dataset 从真实来源、控制面执行、canonical、publication、内部 reader、 公开 API 到 Web 的全链路均有可追溯证据；不等于把仓库尚无来源的规模、折溢价、资金流或普通基金伪造成一期数据。
