基金与 ETF 中心：公开查询技术方案

复用现有 typed market-data 公开 POST，不新建 ETF 聚合快照、不访问同步库、不计算业务指标。 API 负责认证、严格合同、防腐转发、错误映射和可观测；所有业务值逐字段来自合格 publication。

公开入口POST /api/v1/market-data/query
内部依赖POST /internal/v1/market-data/query
一期数据集profile / bar / NAV / trading state

1. 能力卡与边界

Actor 已通过 service-api 全局认证的 QUANT V2 用户。
Consumer service-web 的 ETF 查询适配层；不向浏览器暴露 data-sync 内部地址或服务令牌。
Owner service-api：公开合同、认证、限流与错误；service-data-sync：dataset 语义、publication 与记录事实。
成功条件 公开响应通过 dataset + schemaVersion 判别式校验，release/dataVersion/cursor 与下游一致，业务记录不被改写。
兼容策略 v1 字段与语义保持不变；ETF 新字段只在 schemaVersion 2 发布。未知字段、未知版本和未知数据集 fail-closed。
非目标 不直连数据库，不缓存业务聚合，不计算规模、折溢价、换手率、资金流，不拼接“综合详情 publication”。

现有 MarketDataAccessModule、MarketDataAccessController、 MarketDataAccessService 和 MarketDataAccessClient 保持单向依赖。 client 使用服务令牌、透传 X-Request-Id、执行超时并验证内部响应的 X-Data-Version 与 release 一致；公开 controller 只返回严格响应体与 Cache-Control: private, no-store，不声明额外公开版本 header。

3. schemaVersion 2 公开合同

dataset 严格 record 字段 查询硬约束 API 响应处理
fund.etf.profile.reported etfEntityRef、exchange、symbol、displayName、etfType、managementMode、managerName、custodianName、listedOn、delistedOn、listingStatus、quoteCurrency、navCurrency、sourceTimePrecision；允许合同声明的真实空值。 exchange 必须单值 EQ；limit ≤ 50；symbol/name/status 只在 descriptor 明示时可过滤。 作为列表和详情身份入口；不把目录缺席转换为退市。
fund.etf.bar.1d.reported tradeDate、etfEntityRef、open、high、low、close、volume、volumeUnit、amount、currency、tradeStatus、adjustment。 exact entityRef；日期窗口；最多 366 条；adjustment 固定 UNADJUSTED。 原样返回；不产生 latest quote，不从零成交量推断状态。
fund.etf.nav.1d.reported navDate、etfEntityRef、navKind、nav、currency、finality；来源发布时间允许为空。 exact entityRef；日期窗口；navKind 显式；最多 366 条。 NAV 与 IOPV 语义隔离；不与收盘价计算折溢价。
fund.etf.trading_state.reported etfEntityRef、stateDimension、state、effectiveFrom、effectiveTo、reason。 exact entityRef；允许真实来源只发布部分维度。 TRADING/SUBSCRIPTION/REDEMPTION 独立；缺失维度保持未发布。

3.1 响应不变量

  • AVAILABLE：release 必须存在；内部依赖的 X-Data-Version 必须等于 release.dataVersion；公开 records 必须通过对应严格 schema。
  • 尚无 publication：SOURCE_UNAVAILABLE + PUBLICATION_NOT_AVAILABLE；来源确认的合法空窗口：EMPTY。二者 records 都为空、release 都不含 dataVersion，并保留 reasonCode、observedAt 和 warnings。
  • 来源已明确报告货币市场 ETF 的收益型净值语义、但当前 UNIT/ACCUMULATED 合同无法安全承载时： CURRENTLY_UNSUPPORTED + NAV_SEMANTICS_UNSUPPORTED_MONEY_MARKET。响应仍为 200、records 为空且没有 dataVersion/cursor；不得改写为来源故障、普通空结果或伪造单位净值。
  • AVAILABLE + records=[] 表示筛选无匹配；不得改写为 404、退市或来源故障。
  • opaque cursor、coverage、quality、sources、publishedAt、knowledgeCutoff、publicUsableAt 原样保留。

4. 安全、可靠性与错误合同

主题 明确设计 验证
认证 沿用全局 bearer 认证；内部调用只使用服务身份令牌，浏览器不可见。 未认证公开请求拒绝；公开凭据不能调用内部路由。
授权与最小化 dataset/schemaVersion/fields/filter/sort allowlist；只返回公共 descriptor 声明字段。 越权字段、未知字段和未知 dataset 统一 400。
超时 沿用 dataSyncInternalRequestTimeoutMs；超时映射依赖不可用，不隐藏已有卡片。 注入超时，公开 Problem Details 不泄露 provider、堆栈和服务令牌。
限流 沿用公开边界限流；429 保留 Retry-After，Web 不制造重试风暴。 限流合同测试与 header 断言。
幂等 查询是只读 POST，不要求 Idempotency-Key；publication/dataVersion/cursor 保证可重复读取边界。 相同 CURRENT 请求在 publication 未变时响应一致。
响应边界 内部响应只接受 JSON；Content-Length 与流式累计字节均限制为 2 MiB，并使用严格 UTF-8/JSON 解析。 错误媒体类型、声明超限、无长度流式超限和坏 UTF-8 全部 fail-closed。
存储与缓存 不新增 Prisma 模型或 Redis 业务缓存；API 不保存 ETF 事实。 架构测试禁止 service-api 引用 data-sync persistence。

4.1 统一错误映射

  • 400/422 下游合同错误 → 公开 400；404 → 404；409 snapshot/cursor 失效 → 409。
  • 429 → 429 并保留 Retry-After；其他下游失败、超时或响应合同漂移 → 503。
  • availability 是成功响应状态，不转换成异常；包括 CURRENTLY_UNSUPPORTED。四个详情查询可部分成功。

5. 性能、可观测与变更清单

调用数

列表 1 次；详情首个 profile 完成后并发 3 次，共 4 次。列表禁止逐行查询 bar/NAV/state。

负载上限

列表 50 条；bar/NAV 各 366 条。API 请求体和响应体继续受全局限制。

指标

按 dataset/schemaVersion/availability/status 记录 QPS、p50/p95、超时、合同拒绝、409 与 503。

5.1 已实施范围

  • 已扩展 data-sync 市场数据合同镜像：四个 ETF v2 record 判别式 schema 与 descriptor allowlist。
  • 已增强 MarketDataAccessClient：在通用 envelope 校验后按 dataset/schemaVersion 校验 records、availability/release 和响应大小。
  • 已增加 controller/service/client 单元测试、data-sync 合同测试与 POST-only 架构测试；真实 E2E 作为最终门禁记录。
  • 不新增数据库迁移、不新增 Redis key、不新增 ETF 专用公开 controller。

5.2 Data Operations 公共控制面

  • profile 支持精确 ALL_VENUES selector，一次预检显式枚举 SSE/SZSE 两个独立分区；不从 symbol 或当前目录推断交易所。
  • bar/NAV/state 支持 ALL_ETFS selector；预检冻结 SSE/SZSE 两份 profile dataVersion、全集记录数与哈希，提交时只使用服务端预检结果。NAV 还冻结可同步集合与 “当前口径不支持”集合；后者生成可审计的跳过分区，不令整个命令变成 PARTIAL。
  • dataset 与 operation 固定映射为 profile→MASTER、bar→BARS、NAV→NAV、state→STATUS；不匹配在 API 边界直接拒绝。
  • 预检、提交、计划任务和重试均复用既有认证 POST 路由；API 不重建 selector、不枚举产品、不直接访问同步库。

6. 无卡点实施与验收

  1. 先合入版本化 ADR 与 YAML 合同，锁定四个 v2 record、查询上限、availability 和错误语义。
  2. data-sync v2 reader 合同测试通过后，service-api 更新 schema 镜像与严格响应验证。
  3. 用同步服务实际 publication 执行内部查询，再通过已认证公开 POST 查询同一 dataset/dataVersion。
  4. 逐字段比对公开 records 与内部 typed reader；任何新增、缺失、重命名、单位变化都使测试失败。
  5. 注入无 publication、空结果、cursor 失效、429、超时和合同漂移，验证状态与 Problem Details。
  6. service-web E2E 只能读取公开 POST；构建产物扫描不得出现 provider URL、内部令牌或硬编码产品记录。
上线范围固定为已认证的内部产品环境。当前真实来源的外部再分发权不作为技术实现中的隐含假设； 若未来开放给外部用户，必须先完成 entitlement 与来源授权，但不会改变本页已冻结的 API 结构。

Implemented / 验证中 公开查询与运维控制面均已落入生产代码；没有等待前端临时聚合、人工补数据或静态业务记录兜底的步骤。
