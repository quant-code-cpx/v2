Service Web · Technical solution 0006

数据运维控制台

为管理员提供统一的数据资产目录、来源血缘、新鲜度、串行同步任务、健康检查、自动计划和主动操作记录。 选择复用现有白色桌面壳层，以五个任务型 Tab 组织信息；Contract 0023 的 19 条公开 POST 与状态语义已完成跨服务收口，生命周期仍保持 Proposed，生产接入前继续用 fixture / MSW 验证。

问题

数据可用性无法在一个界面判断

当前数据能力分散在 CLI、任务、checkpoint、quality 与 publication 中，Web 没有统一运维入口。

决策

一个路由、五个任务型工作区

顶部常驻全局运行条；资产、任务、健康度、自动计划、操作记录各自保留清晰责任边界。

主要风险

全局串行仍受 Lock gate 约束

旧 CLI / Celery / schedule 未全部收口前，只能显示“互斥迁移中”，不能仅凭界面承诺全局唯一。

摘要与跨服务边界

Web 决策

路由与信息架构

新增 /data-operations。页面标题下先显示全局唯一运行任务与排队数量，再提供 “数据资产 / 同步任务 / 健康度 / 自动计划 / 操作记录”五个 Tab。

权限决策

首版严格只读 / 写分层

ADMIN 与 SUPER_ADMIN 可读；同步、主动健康检查、取消 / 重试和计划管理 仅 SUPER_ADMIN 可用。服务端始终再次授权。

契约决策

19 条公开 POST，语义固定

Web adapter 只实现 Contract 0023 的 19 条路径并复用共享 POST transport； 业务调用方不能选择 HTTP method。合同仍为 Proposed，表示尚未实现 / 接受，不表示字段可自行改写。

契约与生产门禁

ADR-0024、 Architecture 0002 与 Contract 0023 已收口权限、submission 交付 / 运行状态、全局串行语义、数据时间口径、健康规则与计划并发控制。 正式开放写操作仍需 Contract 0023 进入 Accepted、实现通过契约测试，并完成全局互斥 Lock gate。

目标

  • 30 秒内回答“当前有哪些数据、来自哪里、是否新鲜、最近同步是否成功”。
  • 支持单个或批量下发，并按每个数据集 capability 配置增量、全量、日期范围或观察日；同一批次 datasetCode 唯一。
  • 明确展示全局一次只运行一个子任务；批量命令拆分后按队列顺序串行。
  • 聚合健康检查、自动计划和可审计的主动操作结果。
  • 严格消费 19 条公开 POST，不由 Web 聚合批次、推算 freshness 或猜测计划模式。
  • 保持桌面键盘、焦点、语义、对比度与 reduced-motion 可用。

非目标

  • 不让浏览器直连数据库、AKShare、Tushare 或任何上游来源。
  • 不在 Web 中解释、修复或下载 raw / quarantine 私有证据。
  • 不消费或展示 0022 内部 checkpoint、Provider cursor、token 或原始 payload；0023 未公开这些字段。
  • 不在未冻结合同上伪造生产 endpoint、WebSocket 或权限常量。
  • 不在首版提供任意 cron 文本、工作流编排器或跨任务依赖 DAG。
  • 不设计、生成或验收移动端、平板、触控或窄屏布局。

业务理解简报

维度 结论 设计影响
Actor 与入口 平台管理员从桌面侧栏“数据管理 / 数据运维”进入。 复用受保护 AppShell、权限路由和顶部账号上下文。
首要业务问题 哪些数据可用、来源是否可信、是否足够新、当前是否有故障或任务占用。 首屏顺序固定为全局运行条、资产摘要、筛选与数据目录。
首要任务 定位异常数据集并安全下发修复性同步或健康检查。 行详情保留上下文；写动作先 capability preflight，再确认进入串行队列。
次要任务 调整自动计划、复核失败原因、追踪命令 / 运行结果、审计谁做了什么。 分别进入任务、健康度、自动计划、操作记录 Tab，避免首屏堆叠。
成功 授权意图持久化不等于下游已受理，更不等于同步成功；必须持续看到 delivery 与权威 run 结果。 先显示 submission ID；只有 deliveryStatus=ACCEPTED 才显示下游已受理，并可跳到权威资源。
失败恢复 网络未知结果复用幂等键；异步拒绝需重新预检；运行失败保留安全错误码与最近成功版本。 保留旧数据、显示 stale / partial；刷新或重进批次只查询 commands/detail，不靠本地选择恢复。
权威来源 service-api 是 Web 唯一边界；service-data-sync 持有运行、质量、发布与内部恢复水位等权威状态。 commands/detail 是批量聚合与有序 child runs 唯一来源；health/checks/detail 是主动健康检查批次恢复 来源；Web 不接触内部 checkpoint。
新鲜度与时间 必须区分最近尝试开始 / 结束、最近成功、最近发布和数据截至时间。 直接展示服务端 freshnessStatus、lag、reason 与 evaluatedAt；禁止本地日期运算。
权限与敏感性 目录和安全摘要可读；raw、内部 URI、秘密、未脱敏样本不可见。 列表只展示稳定错误码和安全摘要；详情不展示 payload_ref 或供应商凭据。
分享 / 重访 Tab 与目录筛选需要可分享；批量选择和未提交表单不应写 URL。 URL 持有 tab、q、provider、upstream、status、health、cursor；临时选择留本地。
桌面与可访问性 默认 1440×900，最低宽度 1200；鼠标与键盘并重。 表格内部滚动、Dialog 焦点锁定、Drawer 恢复焦点、状态不只靠颜色。

分类 此工作新增路由、主要任务与信息架构，属于新页面，必须通过桌面原型门禁后才可写生产页面。

现状调研

调研依据为当前仓库源码、service-web README、 service-data-sync README 与已实现模型；以下只把已验证现状标为事实。

事实 · Web

已有可复用管理页骨架

  • React 19、React Router 7、MUI 7、TanStack Query。
  • 白色 300px 侧栏、72px 顶栏、浅灰内容区。
  • 路由 lazy、默认拒绝权限守卫、URL 驱动筛选。
  • 管理表格、720px Dialog、360px Drawer 与全局反馈已有主题几何。
  • 共享传输固定 POST，复用现有 access-token 注入 Authorization: Bearer …，并只暴露安全 Problem code；Refresh Cookie 仅用于刷新 access token，绝不授权业务路由。
事实 · Data Sync

已有运维事实，但未统一投影

  • 运行、内部 checkpoint、publication、质量评估、逐规则结果与 quarantine 均有持久模型；公开 0023 不投影 checkpoint。
  • 同步 RunDetail 的 ingestion qualityGate=BLOCKED 会阻止新版本发布；旧 publication 继续可见。
  • 多条链路有 CLI / Celery 入口、重试、租约或受控回填能力。
  • 部分来源默认关闭、research-only 或仍需生产观测门禁。
  • 成功 AKShare 批次采取“仅失败留证”，Web 不能承诺成功 raw 可回放。
实现缺口

统一合同已形成，控制面尚未落地

  • service-web 当前无数据运维路由、页面或 query adapter。
  • Contract 0023 已定义 19 条公开 POST，但生命周期仍为 Proposed。
  • 人工与计划模式分别来自 supportedModes / scheduleSupportedModes。
  • 不能从 CLI 参数、dataset code 或日期差反推表单与 freshness。

来源展示原则

“供应商”指平台接入 SDK / adapter 的提供者；“上游来源”指其进一步抓取或代理的站点 / 机构。 二者都必须由 service-data-sync 的注册与血缘投影提供，Web 不从函数名或错误消息猜测。

页面与组件架构

页面采用现有管理页模式：路由页只编排信息顺序和页面级状态；远程状态、表单副作用、URL 解析与可测试派生各有归属。

数据资产目录、来源、服务端 freshness、observationState、最近状态、健康与计划摘要。
同步任务扁平队列 / 历史；批量恢复与聚合只消费 commands/detail。
健康 / 计划发布后健康“严重”语义；计划模式与 targetPolicy 均来自服务端 capability。
操作记录主动操作人、动作、目标、结果、submission / request 关联。
建议模块 唯一职责 状态 / 依赖 失败边界
DataOperationsView.tsx 组合标题、全局运行条、Tab 与页面级 loading / forbidden 分支。 读取页面 model；不发请求、不持有表单。 壳层和其他管理页不受本路由失败影响。
DataOperationsRunBar.tsx 展示 ExecutionSlot、active run、processed / estimated records 与 queued count。 只消费 overview / queue snapshot。 RECOVERING 显示“恢复中，暂不领取下一任务”；快照失败不推断 IDLE。
DatasetCatalogPanel.tsx 筛选、批量选择、目录表格和分页。 URL 筛选 + Query；选择集合为本地临时状态。 保留旧页并显示 stale；错误与无结果分开。
DatasetDetailDrawer.tsx 展示二级来源、观测状态、五类时间、服务端 freshness、健康、计划和最近操作。 URL 中 dataset key 打开；详情 Query 独立。 单个详情失败不影响目录；关闭恢复到触发行焦点。
SyncCommandDialog.tsx 预检后按数据集 capability 配置并确认命令。 表单与 preflight 结果由专用 Hook 管理。 preflight 过期或异步 rejected 时不显示为成功 run。
TaskQueuePanel.tsx 显示 active / queued / recent runs；打开批次时呈现权威有序 child runs。 queue、submission、run 与 command detail Query；取消 / 重试显式选择 COMMAND 或 RUN。 局部刷新失败保留最近快照；操作失败回滚乐观标记。
RunDetailDrawer.tsx 展示 target、受理时来源快照、运行状态、进度、分区、时间线及 ingestion qualityGate。 独立 RunDetail Query；来源只读 sourceSnapshot，未发布原因只读 qualityGate。 与 post-publication health 分栏；CRITICAL 只描述已发布版本的健康严重程度。
HealthEvaluationsPanel.tsx 发布后不可变评估、逐规则结果、当前开放问题投影与主动检查。 evaluation search/detail Query；summary 读取 currentOpenIssueCount / issueProjectionAsOf。 严重、警告、未知与读取失败不能合并；CRITICAL 不改变 publication。
HealthCheckDetailDrawer.tsx 恢复主动健康检查批次，按原 target 顺序展示 status、 resolvedDataVersion、evaluationId 与 error。 Submission ACCEPTED 且 authorityResource=HEALTH_CHECK 后，以 healthCheckId 独立轮询 health/checks/detail。 批次失败不覆盖已成功 target；成功 target 才可按 evaluationId 打开不可变评估详情。
SchedulePanel.tsx 计划列表、启停和短表单编辑。 只渲染 scheduleSupportedModes；targetPolicy / policyVersion 由服务端提供；版本并发保护。 冲突时重新加载并要求复核，禁止覆盖他人修改。
DataOperationAuditPanel.tsx 筛选主动操作与关联 submission / authority resource / run / request。 URL 筛选 + cursor Query。 按服务端可见范围投影，不在客户端过滤敏感记录。

React / MUI 取舍

路由动态加载；MUI 从包导出直接导入。单实例布局使用 sx，可复用复杂壳层再用 styled()；不为此页改全局 theme。同步表单使用显式 capability 组合，不增加 isFull、hasDate 等布尔 prop 链。

核心流程

单个 / 批量同步

  1. 选择：用户从目录行或批量选择进入同步 Dialog；普通管理员看不到写入口。
  2. 预检：Web 请求语义上的“同步预检”，获取每个数据集允许的 incremental、full、date-range 或 observation-date、边界、预计子任务、queueDepth 与 ExecutionSlot；预检不承诺 queuePosition。
  3. 配置：每个子任务独立展示能力；混合批次不能用一个通用日期范围覆盖全部数据集。 不支持的模式或 selectorKinds 不渲染；selector 只能由服务端 capability 给出的严格 GLOBAL、证券、板块、交易所、合约或专项结构构造，绝不输入 Provider 参数、URI 或凭据。Web 保持原顺序并先按 datasetCode 去重，服务端重复目标返回 422。
  4. 确认：明确提示“批量将拆成 N 个子任务并串行执行”，同时展示当前 active 与 queued count。
  5. 持久化意图：公开写操作返回 SubmissionReceipt。UI 先展示 submission ID； 初始 toast 固定为“已提交，等待同步服务受理”；PENDING 不能写“已接受”或“同步成功”。
  6. 跟踪：活动 submission 短轮询；只有 ACCEPTED 且返回 authorityResource 后才写“同步服务已受理”。异步 REJECTED / DEAD_LETTER 显示安全原因；若权威资源为 COMMAND，则立即查询 commands/detail。
  7. 恢复与完成：刷新、重进、分享批次详情均以 commands/detail 的 CommandDetailView.childRuns 为唯一聚合来源；终态后精确失效相关 Query。

健康检查

  1. 选择数据集或规则范围；请求按数据集组装 targets[]， 同批 datasetCode 唯一，服务端重复目标返回 422。
  2. 每个 target 独立绑定 { datasetCode, dataVersion | null }，批量操作禁止共享一个版本值。
  3. 展示规则、severity、阈值与数据时间口径。
  4. 主动检查先创建可追踪 Submission；只有 deliveryStatus=ACCEPTED 且 authorityResource.resourceType=HEALTH_CHECK，才按 healthCheckId 轮询 health/checks/detail。
  5. HealthCheckDetailView.targets 按原 target 顺序展示 status、resolvedDataVersion、evaluationId 与 error；刷新、深链和跨会话 都可恢复批次，成功 target 才进入 evaluation detail。
  6. HealthEvaluation 是绑定 dataVersion、releaseId、policyVersion 与 evaluatedAt 的不可变事实；HealthDetail 另呈现查询时当前开放问题投影。
  7. 发布后 CRITICAL 统一显示“严重”，只标记已发布 dataVersion，不撤销或阻止 publication。
  8. 同步未发布原因只在 RunDetail 的 ingestion qualityGate=BLOCKED 区域展示。

自动计划

  1. 列表显示频率、策略、时区、下次运行与启停状态。
  2. v1 每个 datasetCode 至多一个计划；创建重复返回 409，编辑时 datasetCode 只读且不可改绑。
  3. 用受控预设表达交易日 / 每日 / 周期，不首版暴露任意 cron。
  4. 表单模式只读 scheduleSupportedModes；v1 不渲染 DATE_RANGE。
  5. OBSERVATION_DATE 必选 targetPolicy；policyVersion 与默认策略由服务端带入，Web 不自造。
  6. 保存前再次验证 capability、expectedVersion 与策略版本。
  7. 计划触发后仍进入同一串行队列。

主动操作审计

  1. 记录 actor、action、target、request、submission、权威资源、结果和时间。
  2. ADMIN 与 SUPER_ADMIN 读取同一数据运维操作投影；它不等同于平台完整 AuditLog。
  3. submission 投递、下游受理 / 拒绝和最终 run 结果均可追踪。
  4. 不展示 raw 错误 detail、token 或内部对象 URI。

契约、状态与所有权

合同状态为 Proposed

Contract 0023 的路由与字段已完成本轮跨服务收口；x-contract-status=Proposed 表示尚未实现 / 接受。开发期由 DataOperationsGateway 的 fixture / MSW 提供；生产 adapter 只可实现合同列出的 19 条路径，并由共享 requestJson 固定发送 POST。

资产目录最小视图模型

字段语义 用途 约束
datasetCode / displayName / domain 稳定身份、名称与业务域。 key 不使用数据库自增 ID；名称变化不改变 key。
sourceBindings[].providerId / upstreamSource / sourceDataset 供应商、进一步来源与具体上游能力。 受控词汇；未知值明确显示“未声明”，禁止 Web 猜测。
RunDetail sourceSnapshot[] 运行受理时冻结的 Provider、真实上游、adapter 与方法学版本。 历史运行必须读快照；禁止用当前 dataset sourceBindings 回填旧 run。
lifecycleStatus / availability 区分 PRODUCTION / CANDIDATE / RESEARCH / RETIRED 与 ENABLED / DISABLED / SOURCE_UNAVAILABLE / UNKNOWN。 研究观察不能与可发布数据混为同一绿色“正常”。

lastSuccessAt 最近完成成功同步的时间。 只取最近 SUCCEEDED.finishedAt；PARTIAL 永不计入“最近成功”。

MODEL_ONLY 与公开 RunDetail 边界 MODEL_ONLY 表现为 freshnessStatus=NOT_APPLICABLE 且 freshnessPolicy=null；公开分区不含 checkpoint。 显示“模型数据 / 新鲜度不适用”，不显示 lag / stale；不消费 0022 内部 checkpoint、cursor 或 fencing token。

批量命令恢复与聚合

commands/detail 是唯一批量权威

接口直接返回扁平 CommandDetailView： commandId、submissionId、status、requested / started / finished 时间、按原 target 顺序排列的 childRuns、requestedBy 与 error。刷新、深链、浏览器后退和跨会话恢复均以 commandId 重查； 禁止从 runs/search、客户端选择集合或 runId 前缀重建批次。

health/checks/detail 是主动健康检查批次权威

HealthCheckDetailView 返回 healthCheckId、nullable submissionId、status、requested / started / finished 时间、 requestedBy、按原提交顺序的 targets 与 error。每个 target 展示原始 datasetCode / dataVersion、resolvedDataVersion、status、evaluationId 和 error；禁止从 evaluation search 或客户端选择重建批次。

queuePosition 与取消结果不能混用

queuePosition 只在 SYNC_SUBMIT / SYNC_RETRY 被 ACCEPTED 后，表示新命令首个 child 的受理快照位置；其余 child 查询 commands/detail，cancel / health / schedule 与未接受交付均为 null。 cancel_too_late 显示取消动作 operationResult=FAILED、error.stage=CANCEL， 真实目标仍可保持 SUCCEEDED。

RunStatus 文案与动作矩阵

RunStatus 固定中文文案 允许的页面动作
QUEUED 已排队 查看队列；可提交合作式取消，必须选择 RUN 或 COMMAND 作用域。
RUNNING 运行中 查看进度 / 详情；可请求取消此 RUN 或整批 COMMAND，不承诺立即停止。
CANCEL_REQUESTED 取消处理中 禁用重复取消与重试；继续轮询到真实终态。
SUCCEEDED 成功 查看详情；不显示重试，可另行创建新同步。
PARTIAL 部分成功 展示成功 / 未成功范围；仅在权威错误可重试时开放 RUN 或 COMMAND 重试。
FAILED 失败 展示安全错误；仅 retryable=true 时开放显式作用域重试。
CANCELLED 已取消 终态详情；不把“重新同步”伪装成 retry。
INTERRUPTED 已中断 ExecutionSlot=RECOVERING 时仅等待 / 查看恢复；结算后按权威 retryable 决定是否重试。
SKIPPED 已跳过 展示计划合并 / 目标失效等原因；不显示成功，不直接重试无效 target。

取消 / 重试 Dialog 必须显式展示 target={resourceType: COMMAND|RUN, resourceId}。COMMAND 作用整批，RUN 只作用单个 child； 不能由当前页面、选中行或服务端猜测作用域。

权限、安全、可靠性与性能

权限

默认拒绝 + 服务端强制

  • ADMIN、SUPER_ADMIN 可进入只读页面。
  • 首版写动作只向 SUPER_ADMIN 展示。
  • 直接路由、过期权限和并发撤权仍处理 403。
  • 两类角色读取同一运维操作投影；不能前端过滤后称为授权，也不能把它称为完整 AuditLog。
安全

最小安全投影

  • 受保护业务 POST 复用现有 access-token 注入 Authorization: Bearer …；Refresh Cookie 只用于刷新， 不能授权数据运维路由。
  • 不展示 token、secret、raw URI、payload_ref 或数据库键。
  • Run timeline 与操作记录只消费 ActorDisplay；SYSTEM 显示 systemKind 对应名称，actorId 为 null，不接触 actorRef。
  • 失败原因使用稳定 code + 服务端安全摘要。
  • 质量 sample 默认仅计数；脱敏样本另行权限决定。
  • 操作记录包含 request / submission / authority resource 关联，不包含请求 Body 全量镜像。
可靠性

旧数据可见，动作不虚假成功

  • 读取失败保留最近快照并标 stale / partial。
  • submission 持久化、delivery accepted 与 run 成功分为三层反馈。
  • ErrorSummary 展示安全 code、stage、retryable、message；stage 还覆盖 DELIVERY、HEALTH_EVALUATION、SCHEDULE，完整集合以 0022 为准。
  • 队列多 active 属于严重一致性异常，显式告警。
  • 计划编辑使用服务端版本或 ETag 等价并发保护。

性能预算（提议）

指标 预算 设计措施

可访问性与桌面布局

  • 页面唯一 h1，Tab、table、Dialog、Drawer 和 alert 使用对应语义。
  • 状态同时使用文字、图标 / 符号和颜色，不依赖红绿区分。
  • 批量 checkbox、行操作、关闭与重试均有可访问名称。
  • Dialog 打开后锁定焦点，关闭后恢复至触发控件。
  • 1440×900 无页面级横向溢出；1200 宽时只允许表格内部横向滚动。

  • 时间展示含时区，数字使用 tabular numerals，code 使用等宽字体。
  • 仅覆盖 PC 桌面鼠标和键盘，不新增移动、触控或窄屏行为。

实施、验证与回滚

  1. 阶段 0 · 合同门禁：已收口 19 条公开 POST、数据集词汇、submission delivery / operation result、CommandDetail、全部 RunStatus、ExecutionSlot、时间、health、schedule 与 audit 投影。 退出条件：Contract 0023 进入 Accepted 并通过契约测试。
  2. 阶段 1 · 只读 fixture：在 feature flag 下实现路由、壳层、五个 Tab、URL 状态和 MSW 场景。 退出条件：组件测试、1440×900 视觉回归、键盘路径通过。
  3. 阶段 2 · 只读真实合同：接共享 POST transport，引入 schema 校验，开放 ADMIN 与 SUPER_ADMIN。退出条件：目录、队列、健康、计划、审计在 staging 对账通过。
  4. 阶段 3 · 超级管理员写动作：依次开放预检 / 同步、健康检查、取消 / 重试、计划管理。 退出条件：异步拒绝、并发冲突、审计、幂等和串行约束 E2E 通过。
  5. 阶段 4 · 观测与收口：确认轮询负载、任务完成延迟、错误码覆盖、未授权尝试与审计完整率。 满足 SLO 后移除 fixture feature flag。

验收标准

  • 首屏 30 秒内可判断有哪些数据、来源、新鲜度、最近同步与全局任务占用。
  • provider 与 upstream source 可分别筛选、展示和在详情复核。
  • 历史 RunDetail 使用 sourceSnapshot，不用当前 sourceBindings 回填。
  • lastAttempt started / finished、仅 SUCCEEDED 的 lastSuccess、lastPublished、dataAsOf 不混用。
  • freshnessStatus、lag、reason 与 evaluatedAt 直接来自服务端，不做客户端日期推导。
  • PRESENT、合法空集、异常空集、从未同步与 UNKNOWN 可筛选且不会合并。
  • 批量命令拆成可见子任务，任何时刻最多一个 run 处于运行中。
  • 批量恢复与聚合只消费 commands/detail；runs/search 不重建 child 顺序。
  • 全部九种 RunStatus 与三种 ExecutionSlot 状态有固定中文文案和动作。
  • 取消 / 重试提交明确 COMMAND 或 RUN 作用域。
  • 同步表单按 capability 展示模式；观察日与日期范围不互相替代。
  • 发布后健康只使用“健康 / 警告 / 严重 / 未知”；CRITICAL 保持既有 publication 可见。
  • RunDetail 单独展示 ingestion qualityGate 的 BLOCKED 与新版本未发布原因。
  • 健康检查批量 target 各自绑定 dataVersion；不能共享一个版本值。
  • 自动计划只显示 scheduleSupportedModes；v1 禁 DATE_RANGE，观察日必选服务端 targetPolicy / policyVersion。
  • 初始写反馈为“已提交，等待同步服务受理”；异步 REJECTED 明确告警。
  • 进度使用 processedRecords / estimatedRecords；估算未知时不显示百分比。
  • 每个主动操作可关联 actor、request、submission、authorityResource、run 与最终结果。
  • 19 条真实 service-api 路径全部经共享 transport 固定为 POST。
  • 1440×900 与最低 1200px 桌面宽度无页面级横向溢出。
  • 键盘、焦点、语义、对比度和 reduced-motion 验收通过。
  • 生产写操作前 Contract 0023 Accepted、契约测试与全局 Lock gate 均通过。
