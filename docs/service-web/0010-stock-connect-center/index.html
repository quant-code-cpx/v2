2. 产品边界与当前可实现范围

2.1 本模块负责

  • 四条通道、北向/南向方向、交易日和通道交易状态。
  • 日终买入、卖出、成交额、可披露/可计算时的净买入或净卖出。
  • 日终额度状态、披露阈值下的真实剩余额度及其 CNY 语义。
  • 官方活跃证券榜、成交活跃顺序，以及榜内可计算的净买入/净卖出排序。
  • 精确交易日与 latest 查询、来源、source publication、平台 publication、更新时间、质量与 lineage。
  • 互联互通所需的最小稳定证券身份与上下文页。

4. 现状调研与 typed market-data 判断

核对项 当前事实 结论 落地动作
market.stock_connect.market_stat.reported 领域/仓储有 buy、sell、turnover、net_buy、quota_balance、currency、availability；typed reader 仅输出 tradeDate/channel/direction/turnover/netBuy，且描述固化 CNY。 存储模型部分可复用，现有 reader 不能支撑四通道完整页面。 扩展 reader，保留原币和逐字段 availability；状态/日历独立数据集。
market.stock_connect.active_security.snapshot 模型有 source rank/code、buy/sell/turnover/currency；reader 只输出 rank/turnover/entityRef。 它只是官方/供应商公布的活跃证券榜，不是全市场排行。 恢复完整字段、release 关联和范围标签。
净流入/净流出排行 现有 active dataset 没有正式派生 net publication；当前 source 也无可用真实榜。 不能用 turnover 推导，不能把榜外证券纳入。 在同一不可变 bundle 内增加带 buy-minus-sell-v1 lineage 的活跃榜净额 projection，仅 buy/sell 同时 reported 时计算；不伪装成独立 canonical dataset。
四通道拆分 领域键已有 channel/direction，但当前真实 source 未实现、reader 信息不完整。 语义模型可复用，采集与查询链必须补齐。 按四 canonical channels 建分区、bundle 和专用 query。
缺失净买入 2024-08-19 后北向制度上不再披露买卖拆分。 只能展示真实成交额和明确未披露状态。 NOT_DISCLOSED_BY_REGIME；净额 tab 禁用。
港股身份 当前没有覆盖本模块所需的稳定 HKEX identity ingestion。 南向深链接目前不可靠。 接入最终可交易的 HKEX Securities Master fixed-length 主档，以来源稳定 Securities ID 建立最小 entity，并把 trading code 建成有生效区间的 identifier version；主档缺稳定 ID 时必须保持未解析。T+2 to-be-listed JSON 不替代正式主档。
通道目录、状态、额度 缺少专用目录、EOD 状态和官方 quota publication。 现状无法真实展示通道运行与额度。 固定接入 OMD-C、SSE MDGW、SZSE STEP，并新增 EOD 数据集。
交易日 内地与香港交易/结算日可能不同；当前 stock-connect 查询没有官方共同日索引。 不能用自然日或抓取时间判定 latest。 接入 HKEX 官方 annual CSV，bundle 生成共同完成日索引。

6. 三服务全链路架构

HKEX Data Marketplace SFTP ─┐
HKEX Calendar / Master ─────┼→ provider adapters → canonical datasets → quality gates
HKEX OMD-C / SSE / SZSE ────┘ ↓
market.stock_connect.overview.bundle publication（不可变、版本化）
↓ POST internal API
service-api StockConnectModule（鉴权、DTO、预算、熔断、公开 POST API）
↓ shared Web transport
service-web（URL state、TanStack Query、MUI PC pages、publication/quality 可见）

official calendar + delivery/run/publication evidence → persisted readiness snapshot
└─ 独立 dataVersion → data-sync/API readiness POST → 页面候选日与就绪日说明

6.1 原子一致性

  • 一个单通道日包引用 calendar、market stat、active security、derived net、channel status 和 identity coverage 的不可变 release；所选 channel set 全部齐套后才创建对应 overview publication。
  • 总览查询只读一个 bundle，不把四个独立 latest 响应临时拼在一起。
  • MARKET+ALL 不是跨全部通道和日期的长数据库事务：中途失败时已完成的 单通道 publication 可读，四通道 latest-common 指针保持旧版；幂等补齐后才一次前移。
  • service-api 响应体 publication.dataVersion 必须等于 X-Data-Version。
  • Web query key 包含 URL filters、actorRef、collection/data version；翻页游标绑定 dataVersion。
  • 活跃证券请求必须把父 overview 或 channel 的 dataVersion 作为 parentPublicationDataVersion 传到同步服务；父版本不匹配返回 409 并整体复核，禁止出现“旧统计 + 新榜单”。
  • 源文件修订创建新 revision；回滚切 visible bundle pointer，历史不覆写。
  • readiness 不从业务查询是否 409 反推：同步服务持久化官方日历、entitlement、 object、运行与 publication 证据，规范序列化后生成独立 SHA-256 dataVersion；无快照返回 409 READINESS_NOT_OBSERVED。

8. service-api 方案摘要

完整设计见 service-api.html。

公开 POST 路由 页面消费者 关键语义
/api/v1/market/stock-connect/readiness/query 总览、通道详情 独立持久化证据；区分候选交易日、共同就绪日、休市、待交付、失败和来源缺失； 64 KiB。
/api/v1/market/stock-connect/overview/query 总览 共同交易日、四通道同 bundle；最多 4×250 趋势点，2 MiB。
/api/v1/market/stock-connect/channels/query 通道详情 单通道 latest/exact、趋势 ≤ 250；1 MiB。
/api/v1/market/stock-connect/active-securities/query 两页面榜单 父 publication 版本锁定、游标分页 ≤ 100、512 KiB；范围恒为来源活跃榜。
/api/v1/market/stock-connect/securities/context/query 证券上下文 稳定 entityRef；不存在返回 404；响应上限 1 MiB。
  • ACTIVE 用户复用现有鉴权，无新业务表或 Redis business cache。
  • 3 秒下游总预算；仅网络/502/503 最多重试一次；5 次失败/30 秒打开熔断 30 秒。
  • 400/401/403/404/409/429/503 使用 RFC 9457；制度未披露仍是 200 字段状态。
  • 浏览器回传上一响应的强 ETag 作为 If-None-Match，命中返回 POST 204； X-Data-Version 仍单独传播；Cache-Control private, no-cache。

10. 市场统计、活跃证券与身份的关联

market_stat release (trade_date + channel)
├─ 1:N → active_security rows（source_rank + source_code）
│ └─ 0..1 → instrument_entity_ref（无法解析时保留源身份）
├─ 1:N → derived net rows（仅 buy/sell reported）
├─ 1:1 → channel_status EOD
└─ N:1 → overview bundle publication / dataVersion
  1. 源榜单行先以 trade_date + channel + source_rank + source_code 保持原始唯一性。
  2. 北向通过 SSE/SZSE identity；南向仅在当日/历史 Securities Master 提供获许可 profile 明确标出的稳定 Securities ID 时，以该 ID 解出稳定 instrumentEntityRef。trading code 只作为有日期的 identifier version，不能单独决定实体。
  3. 派生净额引用 active row release 与 buy-minus-sell-v1，排序前先按 availability 过滤。
  4. Web 深链接只使用非空稳定 entityRef；原始代码永远不直接拼路由。
  5. 完整港股详情不存在时，稳定身份仍可进入本模块证券上下文；未来由 route registry 无缝接港股详情。

11.2 回滚

  1. 先关闭 service-api 公开开关；Web 保留路由、筛选和明确不可用状态， 无需重建镜像，现有市场功能不受影响。
  2. 停用 stock-connect schedule；保留当前和历史 release，禁止删除或覆写。
  3. 若是数据修订问题，visible bundle pointer 切回上一 APPROVED dataVersion；必须使用受控 data-sync-stock-connect-rollback，携带 operation UUID、actor、 reason、requestId 与当前 fencing 证据，禁止裸调 repository。
  4. expand schema、旧 reader 和新 reader 保持一个发布窗口兼容；确认无读流量后才 contract。

11.3 不允许使用假数据的真实验收

下表是启用公开开关前必须全部完成的发布门禁，不是当前环境的完成声明。本仓库可自动验证合同、失败关闭和三端代码； 获许可 HKEX/交易所交付的源到 DOM 实数对账，必须在部署方注入真实 entitlement 后执行，未完成时 STOCK_CONNECT_API_ENABLED 保持 false。
✓ 输入为实际获许可 HKEX SFTP 文件与真实官方状态流/文件；保存可核验产品名、来源 publication 可用性、来源明确提供时的发布时间、独立接收时间和 SHA-256。
