SERVICE-API · POST-ONLY · IMPLEMENTATION READY

沪深港通业务 API 技术方案

新增独立 StockConnectModule，把 service-data-sync 的已批准 bundle 转换为面向 Web 的稳定业务合同。 API 不自行抓取、不计算未知净额、不混合币种、不访问同步库，也不缓存或制造业务事实。

状态：Proposed · 可实施 应用路由：全部 POST 鉴权：ACTIVE 用户 协议：OpenAPI 3.1 无新增业务数据库表
无卡点设计：模块、端点、DTO、超时、重试、错误映射、缓存语义、响应预算和上线顺序均已冻结。 数据未发布时返回可观察错误或官方不可用状态，不会回退到旧 generic query、浏览器拼接或模拟响应。

1. 模块边界与依赖方向

service-web
→ POST /api/v1/market/stock-connect/*/query
→ StockConnectController → StockConnectService → StockConnectClient
→ POST /internal/v1/stock-connect/*/query
→ service-data-sync approved bundle publication 或独立 persisted readiness snapshot
组件 职责 禁止事项
StockConnectModule 导入 Auth 与 DataSyncModule；注册 controller、service 与限流服务。 不导入 data-sync 源码，不连接 data-sync PostgreSQL。
StockConnectController POST-only 路由、DTO 校验、当前主体、request id、响应头。 不写业务逻辑，不暴露内部来源路径。
StockConnectService 日期语义、权限、响应预算、可用性透传、ETag 判断。 不从 turnover 推导 net，不跨币种聚合。
StockConnectClient 调用内部版本化合同；超时、有限重试、熔断、Zod 响应校验。 不以 generic market-data query 代替专用合同。
stock-connect.contract 严格解析请求与响应，保留 amount/currency/unit/availability/lineage，以及 sourcePublicationAvailability、 nullable sourcePublicationAt 与独立 sourceObservedAt。 不把 null 改成 0，不把 observedAt 改成 tradeDate，也不把 SFTP mtime 或接收时间冒充来源 publication。

公开与内部 DTO 的业务形状保持同构，减少错误映射；service-api 的内部合同本身不含路径、凭证或原始上游响应，API 在严格解析后原样转发业务正文并补充公开错误、授权和缓存头。 金额统一为 { amount: decimal-string, currency: CNY|HKD, unit: BASE }。

2.1 日期解析

请求 解析 无对应 publication
readiness LATEST candidate 为所选通道有持久化证据的最近共同官方 OPEN 日；仅全部 READY 时才给出 readyTradeDate。 无持久化快照返回 409 READINESS_NOT_OBSERVED。
readiness EXACT 仅有该日日历记录时回显 candidate；休市、待交付、失败和来源缺失分别返回证据状态。 不从业务 409 或服务器当前日期猜测原因。
总览 LATEST 所选通道最后一个全部完成并已发布的共同交易日。 409 PUBLICATION_NOT_READY，不拼接不同日期。
通道 LATEST 该通道最后一个完成且已发布交易日。 409 PUBLICATION_NOT_READY。
EXACT + YYYY-MM-DD 只读取该日期 publication。 409 EXACT_DATE_NOT_PUBLISHED，不回退前一日。

2.2 可用性与排名

  • REPORTED：官方源直接报告；DERIVED：可追溯公式与输入 release 齐备。
  • NOT_DISCLOSED_BY_REGIME：制度性不披露，HTTP 200；前端展示“— 未披露（制度）”。
  • SOURCE_MISSING：component 非强制展示事实缺失，HTTP 200 并带 publication quality；整体 bundle 未发布则 409。
  • rankingScope 恒为 SOURCE_ACTIVE_SECURITIES_ONLY；API 名称与文案不得出现“全市场净流入排行”。
  • 请求北向新制度日的 NET_BUY/NET_SELL 时返回 200、空 items 和 rankingAvailability=NOT_DISCLOSED_BY_REGIME。

3. 鉴权、授权与输入防护

  • 复用现有 JWT session guard；主体必须存在且状态为 ACTIVE。不新增 Prisma permission 或 Redis 安全状态。
  • 所有 DTO 使用全局 validation pipe：whitelist、forbidNonWhitelisted、transform；日期、枚举、数组大小、cursor 长度严格校验。
  • entityRef 是不透明稳定引用，只允许合同长度和字符集；绝不接受 SQL、provider、文件路径或任意 dataset code。
  • 单用户限流：readiness/overview/channel 60 req/min，active/context 120 req/min；超限返回 429 与 Retry-After。
  • 日志脱敏：记录 actor id、operation id、channel、date mode、resolved date、data version、latency；不记录 access token 和源路径。

4. 下游可靠性与一致性

机制 冻结值 说明
调用超时 含一次安全重试在内的端到端总预算 3 秒 超时返回 503 UPSTREAM_UNAVAILABLE。
重试 最多 1 次；仅网络中断、502、503；100–250ms jitter 只读 POST 携带同 request id；不重试 4xx、schema 错误或超出总预算。
熔断 30 秒内连续 5 次失败后打开 30 秒；半开 1 个探测 不返回过期伪成功；Web 保留自身上一成功视图并显示失联状态。
版本校验 业务响应 publication.dataVersion 必须等于 X-Data-Version；readiness 删除顶层 dataVersion 后按合同规范序列化并重算 SHA-256，正文与响应头必须三者一致 不一致视为协议错误，503 并报警。
响应 schema Zod 严格解析，未知枚举或非法 money 拒绝 防止源系统漂移污染公开合同。
缓存 不使用 Redis 保存业务数据；客户端 If-None-Match 命中返回 204 Cache-Control: private, no-cache，避免跨用户共享。
service-api 不做“多请求后在内存求共同日期”的临时拼装。overview 必须由同一个 bundle publication 返回， 否则无法证明四通道属于同一数据版本。

5. 错误合同

HTTP code 用户语义 重试
400 VALIDATION_FAILED URL/请求状态非法。 修正请求后再试。
401 AUTHENTICATION_FAILED 会话失效。 重新登录。
403 AUTHORIZATION_FAILED 账号不可用。 不自动重试。
404 SECURITY_CONTEXT_NOT_FOUND 稳定证券引用不存在或无互联互通事实。 返回榜单页。
409 EXACT_DATE_NOT_PUBLISHED 指定日期非有效交易日或 publication 尚不存在。 用户选择已发布日期。
409 PUBLICATION_NOT_READY latest 尚无完整 bundle。 按 Retry-After 重新查询。
409 READINESS_NOT_OBSERVED 尚无可核验的日历、交付、运行或 publication 就绪快照。 等待同步侧产生持久化证据；API 不推测状态。
409 PARENT_PUBLICATION_MISMATCH 活跃榜请求绑定的总览或通道 publication 已变化或不属于该日期/通道。 整体重取一次父查询；不得拼接新旧版本。
429 RATE_LIMITED 请求过密。 指数退避。
503 UPSTREAM_UNAVAILABLE 同步服务不可达或合同校验失败。 有限重试；不清空 Web 上一成功值。

Problem Details 不包含堆栈、内部 URL、源文件名、账号、凭证、原始下游响应。

6. 性能与容量

  • controller 在读取下游和序列化公开响应时分别检查字节；overview 2 MiB、channel/context 1 MiB、active 512 KiB、readiness 64 KiB。预算覆盖合同允许的 4×250 个总览趋势点，超预算视为 服务错误并报警，避免正常一年窗口被误拒绝，也防止大响应拖垮 Node 进程。
  • 不允许无限时间区间。趋势和证券历史最多 250 个交易日；活跃榜数据本身受官方榜单规模约束。
  • 游标编码 dataVersion + tradeDate + channel + ranking + sortKey + stableTieBreaker 并签名；版本变化后旧游标返回 409。
  • 活跃证券 POST 还携带 parentPublicationDataVersion。同步服务按父 overview 的组成 bundle 或单通道 bundle 精确读取；找不到或不匹配时返回 PARENT_PUBLICATION_MISMATCH，不再解析当前 latest。
  • 每次内部读取共享 3 秒总预算并使用 AbortSignal.timeout； 只对网络中断、502、503 有界重试一次，不启动后台工作。
  • 通过现有 HTTP 与依赖监控采集各 operation p50/p95/p99、downstream latency、timeout/retry/circuit、409 分类、response bytes、schema failures。

8. 发布、回滚与真实链路验收

  1. 先发布向后兼容的 data-sync 内部合同和真实 bundle；内部端点保持暗上线。
  2. 部署 service-api 模块，STOCK_CONNECT_API_ENABLED=false；运行合同、故障和真实数据对账。
  3. 部署始终可访问且失败关闭的 Web 路由，执行浏览器端到端真实链路；全部通过并已有 approved publication 后才开启 API 运行时开关。
  4. 回滚只关闭 API 运行时开关并停用同步计划；Web 保留明确不可用状态和可分享 URL， 内部旧 bundle 仍可审计，已有其他 market-data 路由不受影响。
✓ OpenAPI lint、DTO 生成/类型检查、controller POST-only 架构测试全部通过。
✓ 用真实 bundle 和 persisted readiness snapshot 对五公开端点做 contract test；业务响应的 X-Data-Version 与 publication 完全一致，readiness 的正文、重算摘要和响应头完全一致。
✓ 逐字段对账：交易日、channel、rank、source code、金额字符串、币种、availability、来源 publication 可用性与独立接收时间不发生语义变换。
✓ 北向新制度日期响应无 buy/sell/net 数值；南向 net 仅透传带 lineage 的 derived 值。
✓ 验证超时、一次重试、熔断、409、429、非法游标、非法 entityRef、版本不一致和超大响应。
✓ 端到端网络记录中不存在样本接口、mock worker、AKShare/Eastmoney 或浏览器直连 data-sync。
