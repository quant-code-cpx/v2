SERVICE-DATA-SYNC · IMPLEMENTATION READY

沪深港通全量同步技术方案

本方案把四条互联互通通道的官方历史文件、日终统计、通道状态、额度、交易日历和证券身份收敛为一个不可变 bundle publication。正式同步只接受官方或获许可交付；上游未披露的字段写入明确可用性，不以零值、估算值或模拟数据补齐。

状态：Proposed · 可实施 所有金额：十进制字符串 + 原币 + BASE 时区：Asia/Hong_Kong 回补：沪 2014-11-17 起；深 2016-12-05 起
无数据卡点原则：交付凭证、账号、主机地址是已冻结的部署输入。凭证未配置或官方文件未到时不产生 publication； 系统保持上一已批准版本并报警，绝不切换到 AKShare、网页抓取或本地样本。

1. 职责、边界与现状结论

service-data-sync 拥有来源接入、标准化、身份解析、派生计算、质量门禁、发布和历史回补。它不提供完整港股行情、全量港股主数据、 汇率、跨境持仓、交易订单、结算、实时额度、新闻公告或融资融券。

现有能力 实测结论 本方案闭环动作
market.stock_connect.market_stat.reported 模型已有买、卖、成交额、净买入、额度、币种和 availability；当前 typed reader 丢弃多数列并把币种固化为 CNY。 保留数据集，扩展 reader 原样输出完整事实、原币和字段可用性，禁止固定币种描述。
market.stock_connect.active_security.snapshot 本质是供应商/交易所公布的活跃证券榜，不是全市场排行；当前 reader 只读 rank 与 turnover。 明确 SOURCE_ACTIVE_SECURITIES_ONLY 范围，恢复 buy/sell/currency/identity/release 关联。
AKShare stock-connect adapter 市场成交额为空、活跃证券为空且币种固化，不能支撑真实发布。 从该能力的 approved source map 移除；生产只注册下述官方适配器。
数据运维控制面 已有命令账本、租约、fencing、计划、重试与健康检查，可承载标准任务。 注册 market.stock_connect.overview.bundle fenced executor；不恢复 legacy CLI 直跑。

状态与额度接口依据： HKEX OMD-C MMDH Binary v2.1、 上交所 IS117 1.09 / IS124 3.50 技术文件入口、 深交所 STEP 行情接口 Ver1.17。

3.1 2024 披露制度不是数据故障

自 2024-08-19 起，北向盘后只公布总成交额、成交笔数、ETF 成交额与活跃证券总成交额，不再公布买入、卖出和可据此计算的净额； 南向盘后继续公布买入、卖出和总额。因此：

  • 北向新制度日：buy/sell/net = NOT_DISCLOSED_BY_REGIME，真实 turnover 正常发布。
  • 南向：保留 reported buy/sell；net_buy = buy - sell 进入独立派生数据集。
  • 旧制度历史：只有同一官方文件同时报告 buy 与 sell 时才计算净额。
  • 净买入/净卖出排序只在“官方活跃证券榜内”执行；绝不声称全市场排名。

规则依据： 上交所沪深港通交易信息披露机制调整通知、 HKEX 公告、 深交所公告。

4.1 不变量

  • turnover = buy + sell 只在三者均为 reported 时校验；不反推任一缺失值。
  • 金额数据库列使用 numeric(38, 6)，合同输出十进制字符串；禁止 float。
  • 事实币种来自源行：NB 为 CNY、SB 成交为 HKD、所有 quota 为 CNY。
  • trade_date 来自官方文件/消息业务日期并通过交易日历验证；observed_at 独立保存。
  • 每条来源引用显式保存 sourcePublicationAvailability。仅源内容/消息明确提供时， sourcePublicationAt 才非空；接收/抓取时刻进入独立 sourceObservedAt，SFTP mtime 不得冒充 publication。
  • 一个 release 不可变；修订创建新 revision，bundle 指向新组件，旧版本可追溯。

5. 适配器与执行链路

年度日历 → HKEX SFTP 文件落地与 SHA-256 → Securities Master 身份投影
→ 市场统计 / 官方活跃榜 → 榜内净额派生 → OMD-C / SSE / SZSE 日终状态
→ 单通道日包质量门禁 → 所选 channel set 齐套 overview publication → 内部只读 API
日历/交付/运行/publication 持久化事件 → readiness snapshot → 独立内部只读 API

每个 provider adapter 仅负责下载与解析成 provider-neutral DTO，不得写数据库。application service 在同一 fenced execution 内完成标准化、持久化与发布；repository 以 lease_token 和 fencing_token 拒绝迟到写入。

组件 固定实现 失败行为
HkexMarketplaceSftpAdapter host key pinning、只读账号、产品目录 allowlist、临时下载后 SHA-256 校验。 文件未稳定或重复 checksum 冲突：重试并阻止新 publication。
HkexOmdcDqbAdapter 按 MMDH v2.1 的 20-byte TCP frame 与 24-byte business body 解析 MsgType 80，保存 sequence、DQB 业务时间与 final snapshot。 frame 长度、sequence 或最终快照不完整：拒绝本次状态组件并阻止新 bundle publication。
SseMdgwStatusAdapter 解析 MD402 / trdses04，联合 PosAmt、ThresholdAmount、MktStatus。 未知枚举进入隔离区，schema drift 告警。
SzseStepStatusAdapter 解析 390019，联合 AmountStatus、PosAmt、ThresholdAmount、session。 未知 session/status 进入隔离区，禁止猜测。
HkexCalendarManifestAdapter 按逐年 manifest 读取精确 HKEX HTTPS 对象或受控本地官方归档； HTTPS 校验证书，所有对象校验 SHA-256，只解析官方年度 Stock Connect Calendar CSV。 年度文件变更产生新 revision 并定向重算受影响日期。
HkexSecuritiesMasterFixedWidthAdapter 通过同一严格 SFTP 边界读取正式 Securities Master；校验 profile manifest SHA-256、记录长度、稳定 Securities ID、代码、名称编码、发行日与 T+1 生效交易日。entity 以 Securities ID 为 key，代码只生成有日期的 identifier version；snapshot 缺席会关闭旧代码/可交易生命周期。 未提供获许可 layout profile、区间缺失/重叠或 profile/hash 漂移时预检 fail-closed；已声明有效 profile 下的单日主档缺件或单证券未映射按 SOURCE_UNRESOLVED 降级，绝不猜字段位置。

5.1 源文件保留

获许可文件进入私有加密对象区 licensed/stock-connect/<product>/<trade-date>/，不得进入 Git、日志或公开 API。 retention_mode 是合同配置：允许保留时保存源文件与 manifest；不允许时发布成功后删除字节，只永久保存产品名、SHA-256、 大小、交付时间、解析器版本和 Marketplace 可重取标识。两种模式都保持可审计且不阻塞生产。

6. 调度、幂等、回补与恢复

任务 时间/范围 策略
当日 bundle 18:20 Asia/Hong_Kong；18:35、19:00、20:00 重试；20:15 截止告警 父命令展开四个 trade-date/date:channel 分区；共同 publication 在全部必需分区成功后创建。
年度日历 每年文件发布后；每日任务前轻量校验 checksum 变化即新 revision，重算受影响 latest/common-date 索引。
Securities Master 每日 03:20；历史回补前先完成目标区间 按主档 T+1 生效日落库，只投影互联互通事实引用的 HKEX 代码，不扩展为完整港股主数据产品。
全量回补 沪线从 HKEX Daily Statistics 官方 back issues 起点 2014-11-17 开始；深线 2016-12-05 起 不可变分页清单、按页和日/通道分区续跑，最近日期优先；限流不影响当日任务。

标准 executor：market.stock_connect.overview.bundle。 data-operations 的 STOCK_CONNECT selector 固定为 operation=MARKET； channel=ALL 且 direction=null 是一次覆盖四通道的全量入口，避免同一 datasetCode 需要提交两次。 ALL+NORTHBOUND|SOUTHBOUND 覆盖两条同向通道， SH|SZ+null 覆盖所选市场双向。分区键： trade-date:{date}:channel:{SH|SZ}:direction:{NB|SB}。幂等键由 dataset、source product、trade date、channel、源 SHA-256、schema mapping version 确定性生成。

FULL 预检不会把约三千个交易日的来源证据复制到 command、run 或 broker payload。 data-sync 先原子保存一个不可变 delivery manifest header，再按最多 20 个交易日、256 个 target 分页；每页有独立 SHA-256，header 保存有序页摘要、root hash、target/page count、availableUntil 与最小剩余窗口。preflight 与 execution intent 只保存 manifestId/rootHash/count 引用；Celery 唤醒消息不携带清单正文。

executor 每次只校验并加载当前页，分批完成后持久化 checkpoint；正常 YIELDED 续跑不消耗 worker-loss 恢复预算，进程丢失才写独立 recovery attempt。重复 preflight/submit 复用相同摘要，页面被改写、重排、过期或剩余窗口不足都在创建 command/run 前拒绝，避免排队后才发现持牌文件已从 SFTP 清理。

MARKET+ALL 由一个 fenced run 编排，但不使用跨全部日期和通道的长事务。 某通道失败时，已完成单通道 publication 保持可读，四通道 latest-common 指针不前移； 同一执行幂等重跑补齐后，四通道 overview 才一次前移。

每次日历、delivery entitlement/object、preflight、execution 或 bundle publication 状态改变时，同一事务更新对应 readiness 证据并生成规范快照。 快照删除顶层 dataVersion 后递归按对象键字典序、数组原序、保留 null、UTF-8、无空白且不转义 Unicode 序列化，SHA-256 小写摘要同时写正文和 X-Data-Version。observedAt 只取持久化证据时间最大值； 无快照严格返回 409，不以服务器当前时间补造。

  1. 同 key、同 payload：返回已有运行；同 key、不同 payload：409。
  2. 下载、解析或质量失败：隔离 staging，记录结构化错误；已批准 release 不变。
  3. 进程终止：租约到期后由 recovery worker 重领；旧 fencing token 无法提交。
  4. 源修订：创建新 revision，定向重算 derived 与 bundle；回滚只切换可见 bundle 指针。

8. 内部 API 与精确日期

实现五个 POST-only 只读端点，机器合同见 docs/contracts/0024-data-sync-stock-connect-internal.openapi.yaml。

  • /internal/v1/stock-connect/readiness/query：返回独立持久化 readiness 快照；LATEST 区分 candidate 与全部所选通道 READY 的 readyTradeDate，EXACT 不回退。无证据返回 409 READINESS_NOT_OBSERVED。
  • /internal/v1/stock-connect/overview/query：LATEST 解析为所选通道最后一个共同完成且已发布交易日。
  • /internal/v1/stock-connect/channels/query：LATEST 解析为单通道最后已发布交易日。
  • /internal/v1/stock-connect/active-securities/query：来源榜或榜内净额排序，游标分页。
  • /internal/v1/stock-connect/securities/context/query：只按稳定 entityRef 查询；无身份的历史行不伪造引用。

EXACT 无 publication 返回 409 EXACT_DATE_NOT_PUBLISHED，不得悄悄改成前一日。响应携带 X-Data-Version、component lineage、source publication 时间和 quality。readiness 的 X-Data-Version 则必须与规范快照摘要一致，不借用任一业务 publication 版本。

10. 可直接交付的四类清单合同

下列 {{PLACEHOLDER}} 是部署占位符，不是样本业务数据，也不能直接进入生产。 所有值必须由获许可交付、交易所规格或变更单填写；严格解析器拒绝未知键。原始文件的换行或编码发生变化会改变 SHA-256，生成摘要后不得再格式化文件。

10.1 年度 Stock Connect Calendar manifest

{
  "manifestSchema": "quant-v2.hkex-stock-connect-calendar-manifest.v1",
  "entries": [{
    "year": {{YEAR_INTEGER}},
    "sourceKind": "{{HTTPS_OBJECT_OR_LOCAL_ARCHIVE_OR_CURRENT_YEAR_HTTPS_TEMPLATE}}",
    "url": {{OFFICIAL_HTTPS_URL_OR_NULL}},
    "relativePath": {{SAFE_RELATIVE_PATH_OR_NULL}},
    "sha256": "{{RAW_CALENDAR_CSV_SHA256_LOWERCASE}}",
    "sourcePublicationAt": "{{RFC3339_WITH_TIMEZONE}}",
    "observedAt": "{{RFC3339_WITH_TIMEZONE}}"
  }]
}

顶层只能有 manifestSchema/entries，entry 七个键也必须完整。year 为 2013–2100 的唯一整数。 HTTPS_OBJECT 只接收 HKEX 官方 HTTPS 精确对象并要求 relativePath=null；LOCAL_ARCHIVE 要求 url=null 且路径不能绝对、回退或逃逸清单目录； HTTPS_TEMPLATE 的两个位置均为 null，且只允许运行时 UTC 当前年。 sha256 覆盖年度 CSV 原始字节；两个时间都必须带时区。HTTP 明确提供来源时间时必须与 sourcePublicationAt 相同。

10.2 HKEX SFTP entitlement 分页 manifest

{
  "manifestSchema": "quant-v2.hkex-sftp-delivery-manifest.v1",
  "rootHash": "{{CANONICAL_PAGES_ROOT_SHA256}}",
  "pages": [{
    "pageNo": {{ZERO_BASED_CONTIGUOUS_INTEGER}},
    "relativePath": "{{SAFE_PAGE_JSON_RELATIVE_PATH}}",
    "sha256": "{{RAW_PAGE_JSON_SHA256_LOWERCASE}}"
  }]
}
{
  "pageSchema": "quant-v2.hkex-sftp-delivery-manifest-page.v1",
  "pageNo": {{SAME_PAGE_NUMBER}},
  "entries": [{
    "remotePath": "{{LICENSED_REMOTE_PATH}}",
    "orderReference": "{{LICENSED_ORDER_REFERENCE}}",
    "availableUntil": "{{RFC3339_WITH_TIMEZONE}}"

}

page 编号必须从 0 连续且路径只能位于 header 同目录；每个 page ref 的 sha256 覆盖 page 文件原始字节。entry 只能有 remotePath/orderReference/availableUntil，远端路径唯一且不得含 ..。rootHash 覆盖按 pageNo 排序后的 {"pages":[...]}：UTF-8、键排序、无空白分隔、 ensure_ascii=false；不包含 manifestSchema，page 内容通过 page 原始摘要间接覆盖。

10.4 HKEX Securities Master fixed-length profile set

{
  "manifestSchema": "quant-v2.hkex-securities-master-fixed-length-profile-set.v1",
  "profiles": [{
    "effectiveFrom": "{{ISO_DATE}}",
    "effectiveTo": {{INCLUSIVE_ISO_DATE_OR_NULL}},
    "profileId": "{{APPROVED_PROFILE_ID}}",
    "specificationReference": "{{APPROVED_SPEC_REFERENCE}}",
    "recordLengthBytes": {{POSITIVE_INTEGER}},
    "lineEnding": "{{LF_OR_CRLF}}",
    "fileName": {
      "pattern": "{{REGEX_WITH_NAMED_ISSUED_DATE_GROUP}}",
      "issuedDateGroup": "{{GROUP_NAME}}",
      "issuedDateFormat": "{{DATE_FORMAT}}",
      "dateRole": "ISSUED_DATE"
    },
    "dataRecord": {
      "selector": {{NULL_OR_SELECTOR_OBJECT}},
      "securityId": {{FIXED_FIELD_OBJECT}},
      "instrumentCode": {{FIXED_FIELD_OBJECT}},
      "displayName": {{FIXED_FIELD_OBJECT}},

selector 非空时 exact 结构为 {"field": FIXED_FIELD_OBJECT, "equals": "..."}。普通 fixed field 只能有 offsetBytes/lengthBytes/encoding/trim；日期字段再增加 dateFormat。securityId 是 entity key，instrumentCode 只是日期化 identifier；前者缺失时该行只能 SOURCE_UNRESOLVED。offset 从 0 计、length 大于 0、字段不得越界或互相重叠， codec 必须存在，trim 仅允许 BOTH/LEFT/NONE/RIGHT。profile id 唯一，inclusive 生效区间不得重叠，目标日必须唯一命中。整个 profile manifest 原始字节的 SHA-256 必须等于 DATA_SYNC_HKEX_SECURITIES_MASTER_PROFILE_MANIFEST_SHA256。

10.5 摘要生成与只读验证

rtk python -c 'import hashlib,sys; print(hashlib.sha256(open(sys.argv[1],"rb").read()).hexdigest())' FILE
rtk python -c 'import hashlib,json,sys; p=json.load(open(sys.argv[1])); v={"pages":sorted(p["pages"],key=lambda x:x["pageNo"])}; print(hashlib.sha256(json.dumps(v,ensure_ascii=False,separators=(",",":"),sort_keys=True).encode()).hexdigest())' SFTP_HEADER_JSON

第一条命令用于 calendar 原文件、page、status landing/sidecar 和整个 master profile；第二条只计算 SFTP header 的 canonical rootHash。两条命令都只读且不输出文件内容。独立清单 validator 在 worker 启动前运行；随后必须对真实授权范围调用 POST /internal/v1/data-operations/commands/preflight，确认每个 target eligible=true 后才允许 submit。preflight 失败或任何 manifest 摘要漂移都必须保持零 command/run。
