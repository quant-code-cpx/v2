1. 核心结论与固定决策

可消费事实不是代码状态 Controller、DTO、typed client 与路由测试只证明可调用代码。所有事实响应还必须命中 data-sync 的真实 sourceBatch、质量通过、完整 coverage、current publication 与容量/E2E 证据；否则返回明确不可用，不因路由已存在放行。
三条 additive 公开能力 固定新增 POST /api/v1/equities/search、 POST /api/v1/equities/:exchange/:symbol/events/search、 POST /api/v1/equities/:exchange/:symbol/data-status。
列表不聚合逐证券 API search 只调用 data-sync 的 equity.discovery.eod 内部查询； 禁止 service-api 并发请求数千条 bars/valuation/money-flow 再拼接。
详情继续独立查询与失败隔离 AVAILABLE 的身份、行情、复权、行动、概况、财务、估值、分类和事件保留各自 dataVersion；资金流当前为 UNAVAILABLE、dataVersion=null， 不制造虚假的“全页同版本”。
内部 UUID 永不公开 event search 先以 exchange+symbol 在 data-sync publication 内解析稳定身份； Web 不读取或持久化 equityEntityRef。
无 publication 有稳定语义 search 返回 200 availability envelope；叶子详情 API 返回 503 publication-unavailable。合法空集只在已有 publication 时返回。
无假数据通道 非 test profile 不注册 mock controller、MSW/fixture provider 或 demo seed。 真实 E2E 必须从 data-sync sourceBatch 到浏览器响应可追溯。

真实发布读取规则（按 batch / coverage 判定）

非目标

  • 不提供实时、WebSocket、Level-2、分钟线或盘中自动刷新。
  • 不在 API 侧计算未冻结的量化指标，不把价格涨跌解释成资金流。
  • 不允许 service-api Prisma 保存 market canonical；Redis 仍只保存短期鉴权安全状态。
  • 不修改既有公开路由语义；新能力全部 additive。

3. 模块归属与三服务调用链

service-web共享 POST transport；JWT；TanStack Query。
EquityWorkspaceControllerDTO 校验、鉴权、requestId、条件读取。
EquityWorkspaceService业务边界、限额、公开投影、错误映射。
EquityWorkspaceClientservice bearer、deadline、Zod、ETag。
service-data-syncpublication、cursor、canonical reader；唯一市场数据权威。

模块决定

  • 新增 EquityWorkspaceController、EquityWorkspaceService 与 DTO， 归入现有 StockModule；不新建第二个股票领域 module。
  • 新增 EquityWorkspaceClient 归入 DataSyncModule，只调用三条新增 internal v1 路由。
  • 既有 EquityInstrumentClient、EquityMarketDataClient、 FinancialDataClient、MoneyFlowClient、sector clients 保持职责。
  • 不引入 Prisma model；本方案无 service-api 数据迁移。访问日志继续走既有请求链。

调用顺序

  1. 全局认证、限流与 request id middleware 先执行；DTO 使用严格白名单和 transform。
  2. Service 校验跨字段约束、日期、排序列、methodology 和分页上限。
  3. Client 以 service bearer 调用 data-sync，透传 request id，不透传用户 JWT。
  4. 下游成功响应经过 Zod 严格解析并裁剪内部标识；contract 漂移统一 fail closed。
  5. Controller 写 ETag、X-Data-Version、Cache-Control，并返回公开 DTO 或 Problem Details。

4. 新增公开 POST 契约

以下路径、字段和状态作为本轮三服务实现决定冻结，并已按严格 DTO/Zod 与消费者契约测试落地。 遵守任务约束，本轮不新建或修改 OpenAPI 文件；后续治理同步只能做 additive 记录，不得改变本方案运行语义。 路由可注册不代表已有数据：只有命中真实 source batch、coverage、质量与 current publication 的事实才可成为 AVAILABLE 响应。

POST /api/v1/equities/search 在单一 equity.discovery.eod publication 上搜索、筛选、排序和 cursor 分页。 不替换既有 POST /api/v1/equities 轻量身份目录。
POST /api/v1/equities/:exchange/:symbol/events/search 以公开证券身份查询公司行动、业绩预告、业绩快报、龙虎榜和大宗交易； 由 data-sync 内部解析 immutable identity。
POST /api/v1/equities/:exchange/:symbol/data-status 返回详情页数据集 availability、freshness、publication、可显示的 source label 与 methodology， 不返回事实记录。

5. 字段、时间、分页与兼容语义

公开身份

  • 路径 exchange 只接受 SSE|SZSE|BSE，symbol 使用 6 位规范代码；服务端拒绝从代码前缀猜交易所。
  • exchange 可解析身份不推导 K 线 coverage：/bars 与复权只读取具有效 coverage 的 SSE/SZSE cell；BSE 请求固定失败关闭，不能以事件、目录或其它交易所的成功替代。
  • 搜索结果同时返回 display exchange、规范 route identity 与日期型 identityAsOf；不返回 data-sync securityId/instrumentId。
  • 事件、财务和公司概况叶子读取先用 exchange + symbol + asOf 解析永久身份，再按该身份选择 publication；禁止先选“当前代码”的 publication。
  • 旧 /instruments/:symbol 的解析由 Web 调用轻量目录确认唯一交易所；0 或多条均不猜测。

时间与状态

概念公开字段解释
横截面业务日effectiveAsOf / tradeDate数据对应的 EOD 日期，不是 HTTP 请求时间
平台知识截止knowledgeCutoff构建 publication 时允许使用的最晚证据时间
发布时间publishedAt该版本开始对消费者可见的时间

暂停上市listingStatus=SUSPENDED冻结枚举只表示交易所明确的上市生命周期状态；当前没有已验证 producer，不代表已有可消费事实
普通停牌tradingStatus=TRADE_SUSPENDED目标交易日没有正常交易的停牌事实

排序和空值

  • 公开白名单与 data-sync 内部白名单一一对应；未知字段在 DTO 层 400，不能透传任意列名。
  • 价格、百分比、金额、股本、估值和资金流用 decimal string，避免 JavaScript 浮点损失；Web 负责本地化展示。
  • 所有 null 同时返回受控 nullReason：NOT_APPLICABLE、LEGITIMATE_EMPTY、NO_PRIOR_VALUE、NOT_COVERED。
  • null 排序固定 LAST；ASC/DESC 都不把无值证券排在首部。
  • 跨页请求若 publication 变化，data-sync 返回 409；API 映射为 snapshot-expired，不自行重放或拼页。

现有 API 兼容

  • POST /api/v1/equities 继续作为轻量身份目录，不增加行情宽字段。
  • 现有 bars/factors/actions/money-flow 路由保持事实语义，并以日期窗口约束身份；profile/financial/valuation 只 additive 增加 asOf 选择，不改变默认当前读取。
  • 通用 POST /api/v1/market-data/query 保留给受控通用消费者；Web 股票中心不直接依赖内部 entityRef。
  • 精确 dataVersion 读取只先加入 discovery；详情叶子 API 是否需要历史版本由既有合同逐项 additive 扩展，不阻断当前工作区。

Problem Details 固定字段

type、title、status、code、 requestId、可选 retryAfterSeconds、可选公开 datasetFamily。禁止返回 service token、内部 URL、SQL、stack、provider 原始错误和 entity UUID。

重试政策

  • 交互读取总 deadline 2.5 秒；单次 data-sync timeout 2 秒。
  • 仅在建立连接失败且未收到任何响应时自动重试 1 次；400/401/403/404/409/429/503 不在 API 内重试。
  • 所有新 POST 都是只读、无副作用；客户端重试不会触发同步或写 operation。
  • 普通查询永不隐式调用数据运维控制面；查看权限与同步权限严格分开。

7. 认证、授权、限流与安全

权限矩阵

操作认证授权决定审计
股票 search 与详情读必须登录沿用现有 authenticated market-data read；不新增临时角色名requestId、userId、route、status、duration；不记录完整筛选文本以外的敏感信息

输入与输出防护

  • DTO whitelist=true、forbidNonWhitelisted=true；数组数量、字符串长度、日期跨度、decimal 范围均有上限。
  • q 只作为 data-sync 参数，不拼 SQL；sort/column/scheme/metric 全部枚举白名单。
  • cursor 只透传 opaque 值，API 不解码也不记录完整正文；日志最多记录摘要。
  • service bearer 仅由 config service 注入，永不进入响应或 error cause；出站只允许配置的 data-sync base URL。
  • 公开响应经过 Zod schema 解析和显式 projection；未知下游字段不自动透传。

限流

  • search：单用户 60 次/分钟；高成本多条件查询另设 20 次/分钟桶。
  • 详情 facts：单用户 120 次/分钟；data-status 60 次/分钟。
  • 限流 key 使用已认证 user id + route family；不使用可伪造 IP 作为唯一身份。
  • 429 返回有界 Retry-After；Web 不并发重试，避免放大 data-sync 压力。

8. 缓存、条件读取、性能与依赖策略

Search SLOP95 ≤ 400 ms、P99 ≤ 900 ms；默认 50、最大 100；压缩响应 ≤ 512 KiB。
详情状态 SLOP95 ≤ 250 ms；最多 18 个 family，一次内部元数据查询。
事件查询 SLOP95 ≤ 400 ms；最大跨度 10 年、最大 100 条。
可用性月度读取可用性目标 99.9%；数据 publication 新鲜度由 data-sync 独立 SLO 衡量。

真实容量实测（首发前执行）

  • API 的 400/250 ms 读取 SLO 不能替代同步侧容量证明。data-sync 输出真实容量报告后，API 才可将相应 capability 标为容量已验证。
  • 报告必须含目录请求 600 秒墙钟异常上限、每个数据集 cell 的来源 p50/p95/成功率/重试、DB 写入与 WAL、对象存储 PUT/HEAD、worker CPU throttling/RSS/内存上限/OOM=0。
  • 按实测并发与重试余量计算的 EOD 临界路径（目录、来源、DB/WAL、对象、discovery build、publication）必须在收盘后 120 分钟内完成；未测量或超预算即返回不可用，不以 API 缓存遮蔽。
  • API 只记录/展示来源批次、coverage、质量状态和 dataVersion；不向浏览器暴露供应商原始指标、内部容量详情、URI、凭据或原始来源载荷。

缓存决定

  • PostgreSQL 仍是 API 用户与安全状态权威；Redis 只保留既有短期鉴权安全状态，禁止缓存市场事实。
  • service-api 首版不持久化或跨实例缓存行情；依赖 data-sync 索引、ETag 与 Web TanStack Query，避免双重失效协议。
  • 成功响应返回强 ETag，基于 route contractVersion + request hash + dataVersion + page cursor 生成。
  • 公开 POST 条件读取命中 If-None-Match 时返回 204，沿用现有 transport 语义；204 不是空结果。
  • Cache-Control: private, no-cache 允许浏览器保存但每次复验；禁止公共代理跨用户缓存。
  • UNAVAILABLE envelope 短期可缓存 30 秒，避免用户连续刷新；依赖故障 503 不缓存。

下游隔离

  • EquityWorkspaceClient 使用独立并发上限 64；超限快速 503，不挤占认证与账户模块线程。
  • search、event、status 三类记录独立断路器指标但不在 Redis 保存权威状态。
  • 详情页由 Web 并行调用多个 API；API 每个请求只访问一个明确 internal reader，不做扇出聚合。
  • data-sync schema 校验失败立即 503 contract-drift 并告警，绝不宽松解析旧/新字段混合响应。

9. 观测、审计与 SLO

结构化日志

  • requestId、traceId、userId、routeFamily、status、durationMs、downstreamDurationMs、attemptCount。
  • search 记录 filterHash、sort、limit、dataVersion、availability、recordCount；不记录 cursor 正文。
  • 详情记录 exchange、symbol、datasetFamily、dataVersion、freshness；不记录 source raw payload。
  • 错误记录公开 code 与内部分类枚举；stack 只进受限服务日志，不进响应。

指标

  • http_request_duration_seconds、equity_search_records、equity_publication_unavailable_total。
  • data_sync_client_duration_seconds、data_sync_contract_error_total、data_sync_timeout_total。
  • equity_snapshot_expired_total、equity_stale_response_total、equity_rate_limited_total。

告警

条件级别处置
5 分钟内 search 503 比例 > 2%高检查 data-sync /ready、contract drift 与连接池；必要时回滚 Web 入口版本
publication-unavailable 在首发后持续 10 分钟高联系数据运维，不自动触发同步
P95 超 400 ms 连续 15 分钟中检查 sort 索引、payload、下游等待与并发
contract-drift 任意发生高阻断新响应，回滚 API 或 data-sync 合同版本
snapshot-expired 突增中检查 publication 频率和 cursor TTL，不放宽版本绑定

10. 实施顺序、发布与回滚

PHASE 0

严格合同与 DTO

任务禁止修改 OpenAPI；在 service-api 内以 strict Zod、class-validator DTO、problem codes 和消费者契约测试固化三条路径。

校验：POST-only guard + schema tests
PHASE 1

DataSync Client

实现三条严格 client，覆盖 service bearer、deadline、304/204、409、503、Zod 漂移与内部标识裁剪。

校验：client unit + integration
PHASE 2

StockModule 公开能力

实现 Controller/Service/DTO、auth、限流、ETag、availability 和 Problem Details；既有路由不变。

校验：全量 unit + build
PHASE 3

真实 publication 集成

对 data-sync 0032 的真实首发执行 search、事件和状态 E2E；随机抽样与 sourceBatch、coverage、质量、publication 对账，禁止 MSW/fixture。首发前执行该验证。

校验：来源批次 + coverage + 质量 + 真实 E2E + 容量预算
PHASE 4

Web 联调与灰度

部署 additive API；Web 只读取 current publication。内部用户验证后观察 24 小时再扩大；无 publication 时返回稳定不可用状态。

校验：错误率、延迟、无假数据、BSE K 线 fail closed

回滚

  • 回滚到上一 Web 构建产物以移除导航流量；additive API 可保留，既有 API 不受影响。
  • API 镜像回滚到上一版本；因为无 Prisma 变更，不需要业务库回滚。
  • data-sync contract 仅 additive；若新 contract drift，回滚双方镜像或切回上一 discovery publication。
  • 绝不在回滚时启用 mock response；没有 publication 就返回明确不可用。

11. 验收标准

  • 新增业务与健康之外的所有 Controller 路由均为 POST；架构测试禁止其他 method decorator。
  • search 所有筛选、排序、分页都来自单一 discovery dataVersion，不发生逐证券 N+1。
  • 代码、名称、交易所、上市生命周期、普通停牌、行业/概念/申万、行情、市值和估值字段语义完整；资金流在方法学未完成 validated 阶段必须返回明确不可用，不能伪造为零。
  • 合法空结果、无 publication、stale、partial、404、409、429、503 均有不同稳定表现。
  • cursor 与 filter/sort/dataVersion 绑定；版本变化不会拼接两次 publication。
  • event search 能按 SSE/SZSE/BSE + symbol 查询，不向公开响应泄漏内部 UUID。
  • data-status 能独立报告所有详情 family 的来源标签、更新时间、publication、dataVersion 和方法学；内部 URI、凭据、原始载荷和数据库键不出现在公开响应。
  • 所有输入有界且白名单化；所有下游响应经过严格 schema 与 projection。
  • Redis 未用于行情权威或缓存；API 未新增市场数据 Prisma 表。
  • 每个公开事实 cell 同时具有 sourceBatch、provider、methodology、coverage、质量通过与真实 publication 追溯；非 test profile 无 fixture/mock/demo 或手工构造来源。
  • BSE K 线和复权请求固定 fail closed；只有 SSE/SZSE 在实测容量、质量和 E2E 通过后能返回 K 线数据。
  • 目录 600 秒异常上限、来源 p50/p95、DB/WAL、对象存储、CPU/内存与收盘后 120 分钟 EOD 临界路径均有真实容量验收记录。
  • 满足 search、status、events 的延迟和 payload 预算；限流与下游隔离有效。
  • 在 service-api 目录完成 format:check、lint、typecheck、test、build；Docker test/local 镜像构建通过。
上线判定：service-api 能“被部署”不等于股票中心已有数据。每个数据集 cell 的 sourceBatch、coverage、质量与真实 BASE publication（可选组件可显式 PARTIAL）、容量实测和 service-web 0007 的无 fixture E2E 一起通过后，API 才投影新的 current dataVersion。
