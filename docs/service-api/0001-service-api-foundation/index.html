API 服务最小基础架构方案

摘要

事实

最小后端已落地

已交付可迁移、可容器化运行的 User/Auth API；没有异步任务、行情业务或兼容包袱，继续保持边界最小。

决策

单进程 + User/Auth 双边界

Node.js 24 LTS + NestJS 11 + Express 5。保留 UserModule 与 AuthModule；PostgreSQL 保存权威状态，Redis 只保存短期鉴权安全状态。

主要风险

后续账号策略仍待产品决定

公共注册、跨站 Cookie、角色粒度与密码找回尚未进入首期；变更前需要单独评审安全、schema 与接口影响。

一句话结论 先把用户、凭证、会话和权限做对；Redis 只服务鉴权安全，没有当前需求的其他模块、进程、基础设施、目录和依赖都不进入工程。

目标与边界

目标
  • 建立可启动、可测试、可迁移、可部署的 NestJS 单 API 骨架。
  • 实现用户生命周期、密码凭证、登录、Token 刷新、退出、角色与会话撤销边界。
  • 从第一天启用 strict、配置校验、标准错误、结构化日志和数据库迁移。
  • Nest 依赖使用核验过的最新精确版本，直接依赖必须有当前源码使用者。
明确不做
  • 行情、研究、自选、策略、回测、组合、提醒、通知、Agent 和数据同步接入。
  • Worker、Scheduler、Queue、Outbox、Cron、WebSocket、SSE 和多进程入口。
  • 通用业务缓存、事件平台、Prometheus Nest 集成和分布式追踪 SDK。
  • OAuth、MFA、短信、邮件、密码找回、多租户和公共注册，除非评审后加入。
  • 为未来模块创建空目录、port、配置项或依赖。
硬约束
  • 服务只有一个 main.ts、一个 AppModule，业务模块仅有 User 与 Auth。
  • RedisModule 是鉴权基础设施，不承载用户、凭证或会话的权威状态。
  • API 不调用财经供应商，也不读取 service-data-sync 数据库。
  • 数据库、账号、迁移和备份由 service-api 独占。
  • 秘密只从环境变量或 secret 注入；日志禁止记录密码、Token、Cookie。
  • 新增模块或基础设施时先证明当前必要性，再更新方案。
假设

Redis 只做共享安全控制

PostgreSQL 承担用户与会话校验；Redis 提供跨副本登录/刷新限流、失败计数和短期锁定。 Redis 不做用户资料缓存，也不改变 PostgreSQL 的权威来源地位。

演进规则

未来能力不在当前树中预留

新业务模块、Worker、队列、通用缓存或实时通道出现真实用例时，再新增编号方案并引入对应目录与依赖。

参考项目继承与删减

参考项目仍作为工程样本，但只迁移当前范围能直接验证的设计。以下删减是有意决策，不是遗漏。

参考设计 处理 当前方案 原因
NestJS Module、DTO、Guard、Filter、Prisma 生命周期和测试结构 保留思路 只服务 User/Auth 垂直切片；不复制整个 src。 已有工程经验可复用，但新边界需要重新建模和 strict 化。
独立 Auth 与 User 模块 保留并收紧 AuthModule → UserModule 单向依赖；User 不反向调用 Auth。 职责清楚；用户状态变化通过 securityVersion 使旧 Token/Session 失效，避免循环依赖。
Prisma + PostgreSQL 保留 只保存 users、credentials、sessions、audit_logs。 满足用户与会话事务、约束、审计和迁移需求。
API、Queue Worker、Agent Worker、Scheduler 多入口 删除 只有 HTTP API 入口。 当前没有长任务、计划任务或独立扩缩容需求。
Redis 保留但限权 独立 RedisModule；只做鉴权限流、失败计数和短期安全标记。 这些状态需要跨副本共享和自动过期；用户与会话仍以 PostgreSQL 为准。
BullMQ、Socket.IO、通用缓存与 Outbox 删除 不创建 Queue、Realtime、Cache 或事件抽象。 当前没有异步任务、实时推送或业务缓存需求。
Stock、Market、Backtest、Portfolio、Agent 等业务模块 删除 仓库内不创建对应目录或接口。 当前范围只有用户管理与鉴权。
所有端点只使用 POST 不沿用 使用标准 GET/POST/PATCH/DELETE 语义。 保留缓存、幂等、代理、审计和客户端工具的标准语义。
全局成功响应包装 不沿用 直接返回资源；错误采用 Problem Details。 避免双重包装，并保持 HTTP 状态、204 与 OpenAPI 类型清晰。
宽松 TypeScript 与 BigInt 全局转 Number 不沿用 strict: true；跨 JSON 边界的 ID 显式使用字符串。 新项目没有兼容负担，不接受静默类型和精度错误。
Winston 文件轮转与 Prometheus Nest 集成 延后 Nest 结构化 stdout、requestId、基础错误计数。 先满足诊断；监控平台和指标需求确定后再增加依赖。

一个入口

API 进程

加载：HTTP、配置、数据库、Redis、健康检查、User、Auth。

不加载：Processor、Cron、实时 gateway、通用缓存。

失败边界：PostgreSQL 或 Redis 不可用时 readiness 失败；进程不提供不可信降级认证。

用户边界

UserModule

负责：用户、资料、角色、状态、密码凭证和 securityVersion。

导出：只读认证查询接口，不导出 Prisma repository。

边界：不依赖 AuthModule；改密、禁用或改角色只更新自身聚合版本。

鉴权边界

AuthModule

负责：登录、JWT、Refresh Session、退出、Guard 与安全审计。

依赖：UserModule 的窄查询接口、RedisModule 和 DatabaseModule。

边界：校验用户状态及 securityVersion；不直接修改用户资料。

安全基础设施

RedisModule

负责：连接生命周期、命名空间、TTL、原子计数和健康检查。

保存：登录/刷新限流、失败计数、短期锁定与重放标记。

边界：不保存权威用户、凭证或会话；业务代码不直接使用 Redis client。

权威存储

PostgreSQL

保存：User/Auth 全部权威状态。

迁移：部署阶段执行 Prisma migrate；应用启动不自动改生产 schema。

恢复：依赖备份与迁移回滚窗口；Redis 丢失只影响短期安全状态，不用于恢复业务数据。

禁止“先建空壳以后再用” 未进入当前业务范围的模块、目录、配置、接口和包全部不创建。后续扩展通过新增方案演进，不通过预留复杂度演进。

功能划分

组件 唯一职责 输入 / 输出 状态 依赖与失败边界
UserModule 用户生命周期、资料、角色、状态、密码凭证与安全版本。 User HTTP 请求；用户资源与供 Auth 使用的窄认证视图。 users、credentials；自身产生的 audit_logs。 依赖 DatabaseModule；不依赖 AuthModule，不导出 repository 或密码哈希。
AuthModule 登录、Token 签发验证、Refresh Session 轮换、退出和请求鉴权。 Auth HTTP 请求与 Bearer/Cookie；授权上下文。 sessions；自身产生的 audit_logs。 单向依赖 UserModule、RedisModule、DatabaseModule；关键校验失败一律拒绝授权。
RedisModule 提供命名空间化的短期安全状态、TTL、原子计数和连接健康。 Auth 安全策略调用；计数、锁定和短期重放结果。 可过期、可重建的安全 key，不含权威业务数据。 Redis 不可用时登录/刷新 fail closed，readiness 变红；已鉴权请求仍必须通过 PostgreSQL 校验。
DatabaseModule 提供 Prisma 生命周期、事务入口和连接健康，不暴露全局业务查询。 User/Auth repository 调用；事务结果与数据库错误。 无应用内状态；连接池属于进程资源。 数据库失败使 User/Auth 请求失败、readiness 变红；liveness 仍用于判断进程存活。
HTTP Foundation 配置、版本、校验、错误、requestId、日志、安全头、CORS 和优雅停机。 HTTP 请求/响应；结构化日志与健康状态。 仅进程生命周期状态。 配置非法时 fail fast；日志或 requestId 失败不得泄露凭证，也不得改变授权结果。

核心流程

1. 登录

  1. 客户端调用 POST /api/v1/auth/login；AuthModule 使用 Redis 按 IP/账号组合执行共享限流与短期锁定。
  2. 通过 UserModule 导出的认证查询接口读取用户与凭证；不存在、被禁用、密码错误均返回相同外部错误。
  3. 使用 Argon2id 验证密码；成功后在 PostgreSQL 事务中创建带 securityVersion 的 session 与审计记录，并清理 Redis 失败计数。
  4. 返回短期 access token；refresh token 写入 Secure、HttpOnly Cookie，数据库只保存其摘要。
  5. Redis、数据库、签名或审计关键写入失败时不签发任何 Token；认证入口不做宽松降级。

2. 访问受保护资源

Client ── Authorization: Bearer <access-token> ──▶ AuthModule / JwtAuthGuard
   1. 验证签名、issuer、audience、exp
   2. 读取 PostgreSQL session 与 UserModule 认证视图
   3. 检查 session 未撤销、用户 ACTIVE、securityVersion 一致
   4. 构造 AuthContext { userId, sessionId, role }
                                  │
                                  ▼
                         Application Use Case
                                  │
                     资源归属 / ADMIN 权限校验
                                  ▼
                              Response

首期每次受保护请求查询 PostgreSQL，确保禁用用户和撤销会话立即生效。只有测量证明数据库压力不可接受时， 才评审用户/会话缓存及其撤销一致性；当前 RedisModule 不承担这类业务缓存。

3. Refresh Token 轮换

  1. 客户端调用 POST /api/v1/auth/refresh，服务校验 Cookie、Origin/CSRF，并通过 Redis 执行刷新限流。
  2. 锁定 session，核对 refresh token 摘要、过期、撤销状态和 securityVersion。
  3. 事务内撤销旧 refresh token、生成新 token 摘要、记录轮换关系和审计。
  4. 发现旧 token 被再次使用时，在 PostgreSQL 撤销该会话族，并向 Redis 写入短期重放标记。

4. 管理员禁用用户

  1. ADMIN 调用 PATCH /api/v1/users/{id}，应用层校验权限与目标状态。
  2. UserModule 在自身事务内更新用户为 DISABLED、递增 securityVersion 并写安全审计，不反向调用 AuthModule。
  3. 后续 access token 虽未过期，也因 token/session 版本与用户版本不一致而被 AuthModule 拒绝。

接口与数据约定

首期端点

方法与路径 用途 权限 主要结果
POST /api/v1/auth/login 密码登录并创建会话。 Public + 严格限流 200 + access token；refresh cookie。
POST /api/v1/auth/refresh 轮换 refresh token。 有效 refresh session 200 + 新 access token/cookie。
POST /api/v1/auth/logout 撤销当前会话。 Authenticated 204。
GET /api/v1/users/me 读取当前用户。 Authenticated 200 + UserResource。
PATCH /api/v1/users/me 修改允许自助维护的资料。 Authenticated 200 + UserResource。
POST /api/v1/users/me/password 校验旧密码后修改密码，使现有会话失效。 Authenticated 204。
GET /api/v1/users 管理员分页查询用户。 ADMIN 200 + cursor page。
POST /api/v1/users 管理员创建用户；首期不开放公共注册。 ADMIN 201 + UserResource。
PATCH /api/v1/users/{id} 修改角色或账户状态。 ADMIN 200 + UserResource。
HTTP
  • 统一前缀 /api/v1；资源 ID 放 path，过滤和 cursor 放 query。
  • 安全读取用 GET，创建用 POST，局部修改用 PATCH，退出/改密等动作用 POST。
  • 单资源直接返回；列表返回 { items, page }；错误使用 Problem Details。
  • DTO 拒绝未知字段；生产错误不暴露 stack、SQL、Token 或用户枚举信息。
数据类型
  • 外部 ID 使用不透明字符串；时间点使用 RFC 3339 UTC。
  • 邮箱存规范化值与展示值；唯一约束作用于规范化标识。
  • 角色首期只有 USER、ADMIN；状态只有 ACTIVE、DISABLED。
  • 乐观锁使用 version；审计 metadata 必须脱敏且有大小上限。

最小持久化模型

表 核心字段 约束与说明
users id、email、display_name、role、status、security_version、version、timestamps 规范化 email 唯一；禁用、改密或改角色时递增 security_version。
credentials user_id、password_hash、password_changed_at 与 user 一对一；密码哈希永不进入普通用户查询 DTO。
sessions id、user_id、security_version、refresh_token_hash、expires_at、revoked_at、rotated_from_id 支持轮换、撤销与重用检测；版本不一致即失效；索引活动会话和到期清理查询。
audit_logs actor_id、action、target_id、request_id、occurred_at、metadata 追加写；禁止保存密码、完整 Token、Cookie 或敏感请求体。
契约交付规则 已提交版本化 OpenAPI 契约， 运行时同时提供 /openapi-json。契约变更必须同步更新两处并经接口验证。

依赖 不安装原因 允许引入条件

安全、可靠性与可观测性

主题 最小方案 验证
配置 启动时校验端口、数据库 URL、Redis URL/namespace、JWT issuer/audience/key、Cookie 属性；业务代码不散读 process.env。 合法最小配置、缺失 secret、错误 URL 和生产不安全 Cookie 均有测试。
密码 Argon2id，参数可配置但有安全下限；错误消息不暴露账号是否存在。 正确/错误密码、升级哈希参数、超长输入和时序差异回归测试。
Token 与会话 短期 access token；refresh token 轮换、摘要存储、重用检测、服务端撤销；用户与 session 携带 securityVersion。 过期、撤销、版本不一致、并发刷新、旧 token 重放、用户禁用和改密测试。
Cookie / CSRF / CORS Secure + HttpOnly + 最小 Domain/Path；SameSite 根据部署拓扑确定；refresh 校验 Origin/CSRF。 同站、跨站、非法 Origin、缺失凭证和预检请求测试。
授权 默认需要认证，显式 Public；ADMIN 与资源所有权在 application use case 校验。 普通用户访问管理端点、横向越权、禁用账户和角色修改回归测试。
数据库 User/Auth 各自 repository、明确事务、唯一约束、连接池预算；生产启动不自动迁移。 迁移 dry-run、并发创建、securityVersion 更新、连接失败和备份恢复演练。
Redis 只保存带 TTL 的限流、失败计数、锁定和短期重放 key；统一 namespace，禁止无 TTL 写入。 原子计数、TTL、key 隔离、Redis 中断/恢复；登录和刷新在 Redis 故障时 fail closed。
健康与停机 /health 只看进程；/ready 检查 PostgreSQL 与 Redis；SIGTERM 先停止接流量再关闭 Prisma/Redis。 PostgreSQL/Redis 中断、恢复、滚动发布和超时关闭测试。
日志 Nest 结构化 JSON stdout；requestId、userId、sessionId 关联；敏感字段集中脱敏。 自动扫描日志，确保无密码、Authorization、refresh token、Cookie 或完整请求体。

方案取舍

决策点 采用 不采用 / 延后 原因
业务边界 UserModule + AuthModule 合并 IdentityModule，或 User/Auth 双向依赖 保留清晰业务职责；Auth 单向读取 User，securityVersion 负责跨边界立即失效，避免 forwardRef()。
进程模型 一个 HTTP API Worker、Scheduler、多入口 当前没有对应工作负载。
会话权威状态 PostgreSQL 权威 + Redis 安全控制 Redis-only session 或通用缓存 会话事务和恢复依赖 PostgreSQL；Redis 只处理适合 TTL/原子计数的跨副本短期状态。
JWT 集成 @nestjs/jwt + Passport JwtStrategy 完全自建认证协议层 沿用成熟 Nest 集成；角色与资源授权仍由 application use case 显式完成。
健康检查 普通 Controller + Prisma/Redis ping Terminus 当前仅两个外部依赖，少量显式检查无需新增 Nest 包。
接口语义 标准 HTTP + Problem Details 全部 POST + 全局成功 envelope 契约清晰，减少框架魔法与特殊旁路。
未来扩展 需求出现后新增方案 预建空模块、port 和依赖 让复杂度由真实用例驱动，降低当前维护面。

实施与验收

当前状态 阶段 0 至阶段 2 已实现并通过容器化迁移、health/ready、管理员引导、登录、刷新、登出、lint、typecheck 和单元测试验证。 阶段 3 属于首次共享环境上线前的运维工作，不在本次本地基础架构交付范围。
  1. 阶段 0 — 冻结必要范围： 评审 ADR-0005，决定账号创建方式、登录标识、首个管理员、Cookie 拓扑、Redis 部署方式和首期角色。 退出条件：所有会影响 schema/安全的待决项有结论。
  2. 阶段 1 — 最小空骨架： 初始化单一 Nest API、strict、配置校验、结构化日志、错误模型、/health 和测试命令； 只安装工程骨架依赖。 退出条件：build、lint、unit、e2e、容器启动和 SIGTERM 冒烟通过。
  3. 阶段 2 — User/Auth 垂直切片： 加入 Prisma/PostgreSQL、RedisModule、UserModule、AuthModule、JWT/Passport、限流、OpenAPI；实现登录、刷新、退出、自助资料、 改密与管理员用户管理。 退出条件：数据库迁移、Redis 故障策略、契约、安全、越权、会话轮换和日志脱敏测试通过。
  4. 阶段 3 — 上线准备： 完成备份恢复、Cookie/CORS、边缘限流、TLS、密钥轮换、审计保留、灰度与回滚演练。 退出条件：上线清单通过；无未使用直接依赖和预留模块。

发布

  • 单一不可变 API 镜像。
  • 部署前执行 Prisma migrate；应用不自动迁移。
  • schema 使用 expand/contract，兼容窗口覆盖一次回滚。
  • PostgreSQL、Redis 配置和 secret 变更与镜像版本一起审计。

回滚

  • 认证 5xx、越权、Token 异常或数据错误触发回滚。
  • 回滚镜像与配置，不立即撤销兼容性 schema 扩展。
  • 密钥问题优先切换密钥版本并撤销受影响会话。
  • 回滚后验证登录、刷新、禁用和 readiness。

参考代码迁移

  • 只迁移 Auth/User 相关规则和测试思路。
  • Redis 只迁移鉴权限流/锁定思路；不复制 BullMQ、业务缓存或 Worker。
  • 不复制 Tushare、其他业务模块、Queue、WebSocket 和全局 SharedModule。
  • 路由改为标准 HTTP；DTO 与错误模型重新定义。
  • strict 通过后才进入新服务。

验收标准

类别 可验证条件
范围 业务源码只有 UserModule、AuthModule；基础设施只保留当前必需项（含 RedisModule），无 Worker、Scheduler、Queue、通用 Cache、Realtime 或其他业务目录。
依赖 直接依赖全部有源码/测试 import；禁止清单中的包不存在；只有一个 pnpm lock。
运行 只有一个 main.ts 和一个 API 启动命令；无进程角色配置。
架构 Auth 单向依赖 User/Redis，User 不依赖 Auth；Controller 不访问 Prisma/Redis client；模块外无法 import credentials/session repository。
类型与契约 strict: true 无忽略通过；DTO 拒绝未知字段；版本化 OpenAPI 契约与 /openapi-json 可访问。
安全 密码、登录枚举、Token 轮换/重放、securityVersion、CSRF/CORS、越权、Redis fail-closed、限流和日志脱敏测试通过。
数据库 迁移、唯一约束、事务、并发、备份恢复和生产不自动迁移验证通过。
运维 PostgreSQL/Redis health/readiness、结构化日志、SIGTERM、灰度和回滚演练通过。

待决问题

问题 当前默认 负责人 决定触发点
用户如何创建？ 首期仅 ADMIN 创建，不开放公共注册。 产品 / 项目维护者 未来公共注册需求评审前。
首个 ADMIN 如何安全生成？ 一次性部署脚本读取 secret，成功后不可再次运行。 项目维护者 / 运维 首个共享环境部署前。
登录标识是什么？ 规范化 email + password。 产品 / 项目维护者 引入其他登录标识前。
Web 与 API 是否同站？ 同站部署，refresh Cookie 使用 SameSite=Lax 或 Strict。 前端 / 运维 跨站 Web 部署评审前。
是否需要 MFA、OAuth、邮件验证或密码找回？ 首期全部不做。 产品 / 项目维护者 出现明确用户流程和通道责任后，新建方案。
是否需要多租户？ 单租户，不预留 tenant 字段。 项目维护者 首次多租户需求前；需 ADR 与数据迁移方案。
Redis 采用什么部署与隔离方式？ 本地单实例；生产使用托管高可用实例、独立 ACL 用户和 service-api key namespace。 项目维护者 / 运维 首个共享环境部署前。
