Technical solution · service-api · 0005

高价值市场数据访问的 service-api 影响方案

在不改变任何现有公开 API 的前提下，设计一组领域化、认证后、POST-only 的市场数据路由。 service-api 只通过新的 MarketDataAccessClient 消费 data-sync 拟议合同，严格映射公开 DTO、用户权限、PIT、成本、错误、缓存和免责声明。

1. 结论

公开边界

只提供领域 POST API

用户不会看到 dataset 通用查询器、Provider 字段、raw URI、内部 record union 或 data-sync 错误细节。

内部边界

一个严格客户端

DataSyncModule 新增 POST-only 客户端；现有客户端和 GET 合同保持，迁移不共享游标。

发布策略

latest 先行，PIT 逐域解锁

PIT/bulk/derivatives 默认 fail-closed，只有 coverage、权限与 golden fixture 门禁通过才注册路由。

推荐实施形态 新建 MarketDataModule 作为八域公开查询边界；它导入 DataSyncModule， 不访问 Prisma 业务表，不创建市场数据副本。公开 Controller 先鉴权与限额，领域 Service 再把 DTO 映射为稳定 dataset code + 独立整数 schemaVersion，客户端最后调用内部 POST。

本文只设计影响，不修改现有 route、OpenAPI、代码、配置、依赖或 Redis/Prisma schema。

3.1 路由注册元数据

每条 Controller route 在服务端注册表中固定下列元数据；Controller 不接受用户改写这些值。 启动时验证静态映射完整性，运行时由 dataset allowlist 与 catalog availability 共同决定是否服务。

5. 鉴权、权限与请求限额

现状与兼容 当前有效 JWT + ACTIVE 用户 +角色检查可继续作为认证基础，但仓库没有本方案的新 entitlement。 新 scope 是 Proposed 服务端策略，不声称已存在于 token；映射未实现时相关路由不注册或返回 403， 不能因用户是 ADMIN/SUPER_ADMIN 就自动绕过来源许可。
拟议 scope能力默认安全行为
market-data:read低成本 latest / current history，字段受来源许可约束只有 entitlement 明确授予才开放
market-data:pitPUBLIC_PIT、修订历史、knownAt/asOf默认拒绝；dataset G3 通过后才可授予
market-data:bulk较高身份数、窗口或页大小，但不突破内部硬上限默认拒绝；独立成本桶和审计
market-data:derivatives期货/期权/连续序列默认拒绝；来源与免责声明独立
market-data:operations:replaydata-sync 审计重放永不映射到公开用户 API

5.1 双层授权

  1. service-api 校验用户 JWT、ACTIVE 状态、route scope、来源许可、字段投影、时间窗口和成本。
  2. service-api 用独立 service bearer 调 data-sync；不转发用户 token，只传最小化规范请求。
  3. data-sync 再校验 service identity 的 dataset/字段/PIT 能力。任一层拒绝都不能走旧路径或 DB 旁路。

5.2 公开限额起点

基础 read 建议低于内部上限：单请求最多 20 个身份、32 个公开字段、默认页 100、日频 366 天； bulk entitlement 可提高到内部合同的身份 100、字段 64、页 500，但响应仍不超过 2MiB。 路由按“dataset 成本 × 时间跨度 × 身份数 × 字段数 × PIT 系数”计费和限流，不能只按 IP/QPS。

6.1 灰度期旧 GET fallback

仅当新 POST 返回 404/405/501、明确表示能力尚未部署时，才可由 dataset allowlist 触发一次有界旧 GET fallback；400/401/403/409/429/5xx 一律不 fallback。旧、新游标 不互换，公开响应仍按新 DTO 投影。新 POST 全量后删除 fallback 需独立兼容审计。

7. 对外错误、缓存与兼容语义

7.1 错误映射

场景公开 HTTP / code说明
公开 DTO/范围/字段无效400 MARKET_DATA_INVALID_REQUEST返回有界 field errors；无内部路径名
用户未登录/状态无效401 AUTH_REQUIRED 或现有认证 code保持现有认证合同
用户无 route/source/PIT scope403 MARKET_DATA_FORBIDDEN不能由下游 403 直接透传
单资源身份不存在404 MARKET_DATA_NOT_FOUND列表合法无数据仍 200 空页
公开 cursor/dataVersion 冲突409 MARKET_DATA_CURSOR_CONFLICT用户重新从第一页开始或固定版本
PIT/质量/覆盖不可安全服务422 MARKET_DATA_PIT_UNAVAILABLE不退回当前值冒充历史值
用户/路由成本限流429 MARKET_DATA_RATE_LIMITED有界 Retry-After；不自动重试
下游 401/403、schema drift、无发布、熔断、超时503 MARKET_DATA_UNAVAILABLE统一脱敏并带 requestId；服务端告警保留内部原因

所有公开 Problem 采用现有统一 envelope，至少含 type/title/status/code/detail/requestId； errors 数组有界、additionalProperties=false。未知内部 code 一律 503，不猜测为用户错误。

7.2 私有缓存

  • 首期优先用 knownDataVersion 做应用层重验证；它不是 If-None-Match，也不产生共享 POST 缓存语义。
  • 若启用进程内有界 LRU，key 必含 route version、规范 DTO、用户 entitlement/source-policy hash、dataset schema、方法学和 dataVersion。
  • Proposed 初值：CURRENT 最多 30s；固定 dataVersion/PIT 最多 5min。实际 TTL 由新鲜度 SLO 与压测校准。
  • 缓存只保存公开投影，不保存内部 record/raw；命中仍执行用户状态与权限校验。
  • 缓存损坏、权限 hash 变化、publication 归档或 schema 不符即 miss/清除；不得回退为跨用户 key。

9. 兼容、契约治理、灰度与回滚

9.1 兼容规则

  • 所有新公开路由为 additive POST；现有路由、OpenAPI、客户端行为本方案不改。
  • 公开 DTO 不直接引用内部 YAML；内部 optional 字段也按 consumer-first 部署，严格 Zod 更新在前。
  • HTTP URI major、公开合同 SemVer、dataset schemaVersion、UUID dataVersion、methodologyVersion 独立。
  • 字段类型/单位/空值/时间、枚举收窄、分页排序、权限、错误语义变化视为 breaking，进入公开 `/v2`。
  • Proposed 弃用下限：并行 ≥90 天、≥2 稳定发布周期、旧版连续 30 天调用量为 0；实施评审可延长。

9.2 分阶段发布

  1. Fixture：冻结内部 YAML、公开 DTO 样例、八域 fake Provider/canonical fixture。
  2. Client shadow：新 client 只校验，不进入公开响应；对可比旧能力双读 rows/time/dataVersion。
  3. Route dark launch：模块部署但 route/dataset allowlist 默认关闭，验证 auth、cost、Problem、审计。
  4. P0 latest：按 dataset 与用户 cohort 1% → 10% → 50% → 100%，不一次启用八域。
  5. PIT / P1 / P2：分别满足来源、PIT、容量与权限门禁后独立启用。

9.3 回滚

route/dataset feature policy 切回旧 client（仅存在等价旧能力时）或关闭路由并返回 503；清除该 route 私有缓存和新游标，不回写 data-sync，不删除不可变 publication。若权限、未来函数或 schema drift 触发回滚，无安全旧路径时必须 fail-closed，禁止 DB/Provider 旁路。

11. 假设、未决事项与关联产物

11.1 显式假设

  • A1 首期是有界交互查询，不提供导出、订阅或用户自定义 SQL。
  • A2 data-sync 的 catalog、publication UUID、PIT 与质量门禁先就绪。
  • A3 公开 entitlement 由服务端策略映射；不要求立即改变现有 JWT claim 结构。
  • A4 Proposed 限额和缓存 TTL 可按压测调整，但不得放宽无直连、PIT、质量和版本不变量。

11.2 未决事项

  • 各 route 最终命名与公开字段集需在 public OpenAPI 实施评审定稿；
  • USER/ADMIN/SUPER_ADMIN 到新 entitlement 的产品映射；
  • 每域公开免责声明、授权字段与历史窗口；
  • 进程内缓存是否必要，以及基于实测的新鲜度 TTL。

公开读取不因 AKShare 缺数而失败 依 ADR-0022，内部 client 接受 EMPTY 与 SOURCE_UNAVAILABLE 成功响应。领域 API 返回 200、空数组 或 null 可选字段；前端使用普通空状态，不显示系统错误。

503 仅表示 data-sync 本身不可达、响应合同漂移或读取无法安全执行。若已有可用发布，来源暂不可用不能覆盖该历史版本；若没有发布，响应保持空但带 availability，便于运维区分。
