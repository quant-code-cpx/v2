审核结论

可复用基座

数据治理模型已较完整

仓库已有 canonical dataset、source batch、质量评估、隔离、release、publication、 checkpoint、部分 run/partition 租约；无需另建第二套数据事实模型。

关键缺口

没有平台级串行保证

现有 CLI、Celery task、beat schedule 与部分领域 run 账本可走不同入口。 单 worker 或前端按钮禁用都不能证明任意时刻只有一个同步任务。

推荐方案

PostgreSQL 权威队列 + 租约/fence

所有入口只提交 command；唯一执行槽、心跳租约和单调 fencing token 共同保证跨进程串行， Celery/Redis 仅唤醒，不保存最终事实。

调研边界：仓库目前只实现 AKShare Adapter，没有 Tushare Adapter。 根环境模板中的多数来源和调度开关默认关闭，因此“代码中存在能力”不能推导为目标环境已启用、 已获来源批准或已经存有数据。界面必须显示真实运行时状态，不用静态清单冒充现状。

现有数据与来源调研

第一层 Provider 表示接入库或商业供应商；第二层 upstream source 表示数据真正来自哪个网站、指数公司或交易所。 两层必须同时展示，来源方法学不同的数据不得静默混用。

界面必须区分的事实口径

Last attempt 最近尝试 分别返回 startedAt / finishedAt；活跃尝试的 finishedAt 为 null。
Last success 最近成功 最近 SUCCEEDED 的 finishedAt；PARTIAL 不计为成功，也不等于数据已发布。
Last publication 最近发布 消费者可见 dataVersion 的发布时间。
Data as of 事实日期 数据内部最大业务日期；data-sync 同时返回 freshness 状态、落后量和原因。

状态不能合并

合法空集 异常空集 从未同步 来源不可用 任务失败 健康未知

这些状态的处理动作完全不同；统一显示为“异常”会误导操作者。

错误信息分层

Web 只接收稳定 code、失败阶段、retryable 和脱敏摘要。 堆栈、原始 Provider 响应、raw URI、查询参数及凭据只进入受限诊断面。 阶段覆盖投递、Provider 拉取、质量门、健康评估、持久化、计划与取消， 不用同步阶段代填其他失败。

详细方案

全局串行同步

权威机制

唯一执行槽 + 短租约

PostgreSQL 唯一 global-sync 行保存 run、owner、lease、heartbeat 和单调 fencing token。dispatcher 短事务锁行，按优先级 + FIFO 原子领取一条 queued run。

僵尸防护

发布写入必须验 fence

worker 失去租约后即使恢复，也不能写 checkpoint、publication 或终态。 reaper 把旧尝试标为 interrupted，再按策略重排或终止。 

parent command
  ├─ child run A: QUEUED ──claim(fence=41)──▶ RUNNING ─▶ SUCCEEDED
  ├─ child run B: QUEUED ──────────────────────────────claim(fence=42)──▶ RUNNING
  └─ child run C: QUEUED

running cancellation: RUNNING ─▶ CANCEL_REQUESTED ──safe point──▶ CANCELLED
lease expiry:         RUNNING ─▶ INTERRUPTED ─▶ QUEUED 或 FAILED

不变量：任意时刻最多一个有效 global-sync 持有者；
       只有当前 run_id + fencing_token 能推进 publication/checkpoint。
启用门槛：只有旧 CLI、Celery task、beat schedule、重试和恢复全部改为提交 command， 且架构测试证明不存在绕过 handler 的生产入口，才能对外宣称“同步任务一次只能运行一个”。 在此之前界面应标为“互斥迁移中”并保持写操作灰度。

主动同步与批量语义

FULL

使用数据集冻结的全历史边界。必须填写原因，不能用任意固定日期作为所有数据的默认起点。

INCREMENTAL

从成功 publication checkpoint 加版本化修订回看窗口计算；失败或质量阻断不推进 checkpoint。

DATE_RANGE / OBSERVATION_DATE

区间包含两端且校验日历和最大跨度；快照数据只接受观察日，不伪装成范围同步。

  1. 用户选择一个或最多 100 个数据集；每个 target 只显示自身支持的模式，批量快捷预设仅应用于交集。
  2. 无副作用 preflight 返回解析范围、预计分区/Provider 调用、日历风险、当前队列和警告。
  3. 确认后 API 保存 submission/outbox/audit 并先返回 PENDING；独立 dispatcher 只使用该 submission 冻结的内部 key 投递。
  4. data-sync 建立一个 parent command 与有序 child runs；每个 child 分别竞争同一个全局槽。
  5. v1 中某个 child 失败仍继续后续 child，不自动并行补偿；用户可显式重试失败 child。
preflight 不是资源预留，也不是成功承诺。真正受理时必须再次校验数据集开关、来源资格、 日期上限和幂等请求摘要；data-sync 内部 key 配不同请求体返回冲突。parent command 详情接口 权威返回聚合状态与有序 child runs，页面不从分页 run 列表猜测批次。

每个 run 在受理时冻结 Provider、真实上游、adapter 与方法学版本的 sourceSnapshot；历史详情不得用当前目录来源覆盖。 partitions 与 timeline 分别使用独立 cursor，默认 100、单页最多 200，并返回总数与 nextCursor，避免长任务突破响应上限。checkpoint 只返回不含 Provider cursor、token 或原始 payload 的哈希摘要；公开 timeline 将内部 actorRef 投影为 ActorDisplay。

取消与重试请求显式携带 COMMAND 或 RUN 作用域。整批取消会取消未开始 child 并合作式取消活跃 child；整批重试只复制可重试的失败、部分成功或中断 child，单 child 操作不影响同批其他任务。动作回执同时返回原 target、targetStatus 与结果 command；若命令在创建 child 前被 REJECTED，命令详情允许空 childRuns。 queuePosition 仅表示 submit/retry 新命令首个 child 在受理事务快照中的位置；cancel 为 null，其余 child 从命令详情读取。 取消动作与目标终态分开：只有目标进入 CANCELLED 才算达成；publication 已提交时记录 cancel_too_late 与 FAILED 动作结论，但目标继续显示真实 SUCCEEDED 状态。

同步质量门

在发布前运行，决定 passed / warned / blocked；blocked 保留上一 production publication。

发布后健康评估

绑定不可变 release/dataVersion，允许主动重跑；与 Provider 写任务分队列、默认检查并发 1。 CRITICAL 表示既有发布版本“严重”，不会撤销或阻断 publication。

HealthEvaluation 保存不可变评估事实。列表 summary 与详情另带查询时的 currentOpenIssueCount 和 issueProjectionAsOf；ACK/RESOLVED 不改写历史评估。详情最多返回 500 条脱敏规则结果，并用独立 cursor 每页返回最多 100 条当前开放问题。

主动健康检查支持单个或最多 100 个 target。批次详情按原提交顺序返回 目标状态、绑定 dataVersion、evaluationId 或脱敏错误；API reconciler 按 healthCheckId 对账到终态，评估也保留反向关联。

可调整的自动同步计划

结构化频率

交易日、每日、每周、每月或受限间隔；显式保存 IANA 时区、本地时间和日历，不接收原始 cron。

冲突与补偿

固定 scheduler tick 查找到期计划并投递同一队列；同时到期只排队。misfire 支持 SKIP 或 RUN_ONCE。

变更治理

乐观版本阻止静默覆盖；每次修改生成不可变 revision，并展示未来五次执行时间。创建时 scheduleId / expectedVersion 同为 null，更新时两者都非 null 且版本匹配。v1 每个 datasetCode 至多一个计划；重复创建返回 409，更新不可改绑。禁用优先于删除。

动态计划不是修改环境变量或 Celery beat 文件。环境变量仅保留总开关与安全上限； 数据库计划是运行时权威，计划触发也必须经过同一 command queue。数据集单独声明计划支持模式； v1 禁止自动 DATE_RANGE，OBSERVATION_DATE 必须选择“计划本地日期”或“最近已完成交易日”的解析策略。capability 按 mode 返回允许的版本化 targetPolicy 及唯一默认项，Web 不自行拼装策略。

可靠投递与双层审计

SUPER_ADMIN 提交操作
  │
  ├─ API 数据库同一事务
  │    ├─ DataOperationSubmission（授权/交付意图）
  │    ├─ ApiOutbox（submissionId 派生的内部 Idempotency-Key + request hash）
  │    └─ AuditLog（request.authorized）
  │
  └─ 提交事务成功 ─▶ 202 delivery=PENDING + queuePosition=null
                              │
                              ▼
               dispatcher FOR UPDATE SKIP LOCKED
               同一内部 key 指数退避投递 → ACCEPTED / REJECTED
                                 └─ 超限 → DEAD_LETTER

终态对账：submissionId / requestId 关联 data-sync operational events；
健康检查按 healthCheckId 查询批次详情并对账有序目标结果；
人工 replay 复用原 submission 的内部 key，不重新授权、不生成第二个业务命令。

API 安全审计

回答谁经过什么角色授权、请求了什么、理由与 request ID。与业务写入同事务，避免“操作成功但审计缺失”。

authorityResource 固定映射：submit/retry 指向新 command，cancel 指向原 COMMAND/RUN target，健康检查与计划动作指向各自权威资源。

自动计划、legacy 与恢复命令没有 API submission：submissionId 为 null、delivery 为 NOT_APPLICABLE；actor 分别显示“系统计划”“遗留任务”“系统恢复”， 不能落入“已删除用户”兜底。

data-sync 运维事件

回答命令何时受理、排队、开始、成功、部分成功、失败或取消。只保存 opaque actorRef，不接收用户 JWT/邮箱。

API 写入前只校验身份、角色、结构、限流、公开幂等与 preflight 引用形状，不复制实时 capability 或计划资格。preflight 在 data-sync 不可用时返回 503；其他结构合法意图可先 PENDING，再由权威服务异步拒绝。

对应合同： data-sync 内部 OpenAPI、 service-api 公开 POST OpenAPI。

数据资产

结构化编辑频率、预览未来执行时间；按操作者、动作、投递状态和最终结果检索。

实施顺序、回滚与验收

阶段 data-sync service-api / Web 退出条件
1. Expand 增加 profile、command/run、slot、schedule、health 与 event 表；只读目录上线 契约 DTO、权限、只读投影与 fixture/MSW 迁移可回滚；旧运行路径不变
2. Shadow 旧 CLI/Celery/schedule 双写账本，对比来源、状态和时间 API 只读灰度；Web 显示“互斥迁移中” 状态一致，未遗漏生产入口
3. Enforce 逐 capability 切 dispatcher；publication/checkpoint 强制 fence 启用 API outbox，先开放单数据集写操作 故障注入证明 max concurrent sync = 1
4. Operate 批量、计划、健康、reaper 与告警完成 开放批量/计划；操作记录终态对账 SLO、权限、审计、恢复演练通过

关键验收

  • 双 worker + CLI + schedule 竞态下最大并发为 1。
  • 旧 fence worker 无法发布或推进 checkpoint。
  • 同 actor + 公开 key + 同请求只产生一个 submission 和一个命令；异请求返回 409。
  • API 超时后仍可从 PENDING 对账到终态。
  • 质量阻断不替换上一个 production publication。

回滚

关闭公开写操作并停止 dispatcher，保留 submission、command、run 与审计历史。 已启用 fencing 的 capability 不回退到绕过执行槽的旧 writer，只允许向前修复。

待冻结参数

  • 每个数据集的 full 边界与修订回看。
  • freshness SLO、Provider 调用预算与批量上限。
  • 操作事件保留期与 DEAD_LETTER 告警渠道。
  • 独立数据运维角色及工作负载身份方案。
  • 真实上游许可、再分发边界与生产 SLA 证据。
v1 不把 publication 回滚、来源切换或强制进程 kill 放进界面。它们影响消费者一致性或可能产生 不安全副作用，继续保留为双人复核的受控运维流程。
