# 0010：行业、概念板块分类与派生数据边界

- 状态：Proposed
- 日期：2026-07-26
- 决策者：项目维护者（待评审）
- 关联方案：[行业与板块数据同步技术方案](../service-data-sync/0012-industry-and-sector-data-sync/index.html)
- 继承决策：[ADR-0002](0002-data-sync-ownership-and-access.md)、
  [ADR-0003](0003-data-sync-runtime-stack.md)、
  [ADR-0004](0004-market-data-provider-adapters.md)

## 背景

行业与板块数据包含三类不能直接等同的语义：

1. 东方财富行业板块、概念板块及其当前成份和指数行情；
2. 申万一级、二级、三级行业层级及供应商展示的估值快照；
3. 东方财富和同花顺按自有方法推导的行业、概念资金流。

AKShare 是采集库，不是这些分类或算法的所有者。同一只股票可以同时属于一个东方财富行业、
多个东方财富概念和一个申万行业；同名行业也不证明代码、成份、调整时间或方法论一致。
资金流中的“主力”“超大单”“流入/流出”属于供应商派生指标，名称相同不代表方向判定、
分桶阈值、样本池、占比分母或修订方式相同。

2026-07-26 的调研确认 AKShare 文档提供东方财富行业/概念清单、当前成份、日/周/月行情、
当前行情快照，提供申万三级行业信息，并提供东方财富与同花顺板块资金流候选。当前 Docker
探针中东方财富板块清单请求出现 `RemoteDisconnected`；此前两轮资金流探针还出现
`RemoteDisconnected`、`ReadTimeout` 和 `JSONDecodeError`。这些接口尚未获得生产稳定性批准。

## 约束

- `service-data-sync` 独占原始响应、标准数据、迁移和发布状态。
- 供应商 SDK、URL、原字段、单位修正和异常兼容只能存在于对应 adapter。
- adapter 只能输出 provider-neutral batch，不能直接写 canonical 数据库。
- 生产启用前必须确认上游许可、商业用途、保存期、频率和再分发边界。
- 本次明确不接入分钟或其他分时数据。

## 候选方案

1. 将东方财富行业、概念和申万行业统一成一张“行业表”，按名称合并。
   - 优点：查询简单。
   - 缺点：名称碰撞会掩盖分类体系、成份和历史差异，无法审计来源变化。
2. 每种分类体系保留独立 scheme、代码、层级、成份观测和来源血缘；跨体系映射另建人工审核能力。
   - 优点：语义清晰，可追溯分类修订，不制造伪等价。
   - 缺点：消费者必须显式选择 scheme，未来跨体系比较需要独立映射。
3. 东方财富资金流失败时自动用同花顺同名字段补洞。
   - 优点：表面可用率较高。
   - 缺点：不同方法论被拼接成一条序列，结果不可解释且无法稳定回测。
4. 东方财富与同花顺资金流分别保存为独立方法论序列，缺失时暴露缺口。
   - 优点：来源、算法与窗口可见，可独立研究和对照。
   - 缺点：不能承诺一条无缺口的通用“板块资金流”。
5. 只同步日线，由日线聚合周线和月线。
   - 优点：调用和存储较少，周期边界可由内部统一控制。
   - 缺点：丢失供应商直接提供的周/月口径，无法保留其独立修订和周期标签。
6. 日线、周线、月线分别调用供应商接口并独立存储。
   - 优点：完整保留上游三个周期的原始口径、历史和修订。
   - 缺点：调用量、存储、质量规则和运维状态增加约三套。

## 决策

分类采用方案 2，资金流采用方案 4，周期行情采用方案 6。

### 分类体系

- `eastmoney.industry`、`eastmoney.concept`、`sw.industry` 是三个独立 scheme。
- canonical 身份使用 `scheme + source_code`，名称只作为可修订属性，不能作为主键。
- 东方财富当前成份保存为带观测时间的完整快照。来源未提供生效时间时，只能表达“本次观测到”，
  不把两次观测之间推断成精确的加入或移出日期。
- 申万接口只用于层级、成份数量和估值快照。未验证到申万成份明细接口前，不用东方财富成份补齐。
- 跨 scheme 的同名、近似名或成份重合只用于差异报告；自动合并或替换必须由后续 ADR 明确批准。

### 行情与快照

- 东方财富行业、概念板块的日线、周线、月线分别进入
  `sector.bar.1d.raw`、`sector.bar.1w.raw`、`sector.bar.1mo.raw` 数据集。
- 三个周期分别调用 AKShare 上游周期参数，保存供应商原始周期结果；分别拥有 checkpoint、revision、
  publication 和 canonical 表。周/月数据禁止由日线聚合、回填或替换。
- 三个周期均使用未复权参数。周期来源失败只影响对应周期，不能用另一个周期计算补洞。
- `stock_board_*_name_em` 的批量当前行情在收盘后保存为 `sector.quote.eod.snapshot`。
  `stock_board_*_spot_em` 不做逐板块定时抓取，避免重复字段和 N+1 请求；仅保留为诊断候选。
- 不接入 `stock_board_*_hist_min_em`，不创建分钟分区、分钟 checkpoint 或盘中调度。

### 资金流

- 东方财富 `stock_sector_fund_flow_rank` 与同花顺
  `stock_fund_flow_industry` / `stock_fund_flow_concept` 共享中立 capability，
  但以不同 `upstream_source`、`methodology_id`、`window_type` 和 `source_policy` 独立发布。
- 资金流归入 `trade_direction_flow` 或 `order_size_flow` 语义族。方法论无法验证时，
  `methodology_status=unknown`，禁止声称为市场真实现金净流入。
- 即时、3/5/10/20 日和东方财富 5/10 日结果是供应商报告的快照或滚动窗口，
  不能当成内部日数据求和结果，也不能相互回填。
- 主来源缺失时发布缺口、`partial` 或 `quarantine`；禁止跨来源静默 fallback。
- 资金流只有在连续探针、单位、分桶、占比分母和最终态验收通过后才能退出 research profile。

### 来源与生产准入

- AKShare 版本、adapter 版本、上游来源、接口标识、schema fingerprint 和原始 payload hash
  必须进入批次血缘。
- 研究通过不等于生产许可。source policy 默认关闭；生产只能启用已完成许可和连续验收的 capability。
- 来源切换、分类 scheme 变更或资金流方法论变更必须双跑、生成差异报告、升级数据版本并由新 ADR 审批。

## 后果

- 消费者必须显式指定 scheme、数据版本和资金流方法论，不能只按中文名称查询。
- 当前成份可从首次采集日开始形成无幸存者偏差的观测历史，但不能回造首次采集前的历史成份。
- 日、周、月维护三套供应商周期事实，增加调用量和存储，但完整保留上游周期口径。
- 三个周期之间不得互相回填；供应商周期定义或修订差异作为独立观测保留。
- 资金流稳定性或方法论未通过时，行业和概念基础数据仍可独立上线，不被派生指标阻塞。
- 需要新增 scheme、板块、成份快照、日线、估值、资金流及运行控制表，并扩展现有
  `source_batch` / `dataset_publication` 血缘字段。

## 替代关系

本决策保留 ADR-0004 的 provider-neutral port 与 adapter 边界。对于行业、概念和资金流能力，
它将 ADR-0004 中泛化的来源优先级收窄为“按 scheme 与方法论分别认证，无跨口径自动 fallback”。
本决策不修改 ADR-0009 的个股日线来源、复权或 API 决策。
