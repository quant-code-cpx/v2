# 0009：A 股个股数据来源、复权语义与服务边界

- 状态：Proposed
- 日期：2026-07-26
- 决策者：项目维护者（待评审）
- 关联方案：[个股数据同步、存储与 API 技术方案](../service-data-sync/0011-equity-data-sync-and-api/index.html)
- 关联契约：
  [同步服务内部接口](../contracts/0003-data-sync-equity-internal.openapi.yaml)、
  [service-api 对外接口](../contracts/0004-service-api-equity.openapi.yaml)

## 背景

首个业务同步能力需要覆盖沪、深、北 A 股个股主数据、未复权日线、周/月聚合、复权因子、公司行动、
估值和财务数据，并由 `service-api` 向已认证用户提供查询。AKShare 是采集库，不是单一数据源：
不同接口分别访问交易所、腾讯、新浪、巨潮和东方财富，稳定性、单位、修订与许可边界不同。

2026-07-26 在 Python 3.13、AKShare 1.18.78 的独立 Docker 探针中：

- 新浪交易日历返回 1990-12-19 至 2026-12-31；前/后复权因子可读。
- 上交所列表请求超时，深交所列表出现 TLS EOF，北交所列表成功；全市场主数据不能被当成一次原子抓取。
- 东方财富 `stock_zh_a_hist` 四次调用均断连；腾讯 `stock_zh_a_hist_tx` 成功返回日线。
- 腾讯接口源码对 `sz000xxx` 股票误按指数分支处理，成交量没有乘以 100；仅信文档或 DataFrame
  字段名会造成百倍量纲错误。
- 巨潮公司概况、东方财富分红和估值可读。
- 东方财富单只股票完整资产负债表、利润表、现金流量表分别约 319、203、254 列，调用约
  34–45 秒；按报告期的全市场摘要约 5,220 行，约 40–48 秒。

一次探针只能证明当前候选与失败模式，不能替代生产许可、长期稳定性或完整性验收。

## 约束

- `service-data-sync` 独占个股数据、迁移、备份和原始对象；`service-api` 不读取其数据库或对象存储。
- 供应商 SDK、URL、字段和量纲修正只存在于 adapter。
- AKShare 官方声明数据主要用于学术研究；生产启用前必须完成上游授权与商业使用评审。
- 当前需求明确不采用 Tushare，也不从旧项目契约反推本次 schema。
- 来源切换、复权算法变化和财务口径变化不得静默污染连续序列。

## 候选方案

1. 所有能力统一使用东方财富接口，失败时返回空数据。
   - 优点：字段风格相对集中。
   - 缺点：当前日线连续失败；空响应会把来源故障伪装成市场事实。
2. 按 capability 选择 AKShare 上游来源，保存统一 canonical 数据与完整血缘。
   - 优点：每类数据可按权威性、覆盖和实测稳定性独立选择；故障可隔离。
   - 缺点：需要多套 adapter 映射、质量规则和来源健康治理。
3. 将多个来源的同名字段自动拼接成一条序列。
   - 优点：表面可用率高。
   - 缺点：量纲、复权、修订和财务方法不同，容易生成不可检测的错误结果。

## 决策

采用方案 2；方案 3 明确禁止。

### 首期 capability 路由

| Capability | 首期来源 | 使用方式 |
| --- | --- | --- |
| `equity.master` | 上交所、深交所、北交所列表 | 分交易所独立抓取和发布；失败保留上次成功版本，不自动退市 |
| `equity.discovery` | 腾讯全市场快照 | 只发现候选代码和名称；不能单独激活、退市或覆盖权威字段 |
| `market.calendar` | 新浪交易日历 | 每周重拉并与当前年度范围校验；缺失未来日期时阻断自动日终判定 |
| `equity.bar.1d.raw` | 腾讯日线 | 首期 pilot 主来源；adapter 按证券类型修正成交量单位并用 VWAP 不变量验证 |
| `equity.bar.1d.raw.shadow` | 东方财富日线 | 仅健康探针和对账；通过连续验收前不做 fallback |
| `equity.adjustment_factor` | 新浪后复权因子 | 保存稀疏、可修订的累计因子；前复权因子只用于对账 |
| `equity.profile` | 巨潮资讯 | 保存公司概况版本；交易所列表仍负责上市身份 |
| `equity.corporate_action` | 东方财富分红送配 | 事件化保存，用于因子变更触发和对账 |
| `equity.valuation.1d` | 东方财富估值 | 独立方法论序列，不与其他来源估值拼接 |
| `financial.statement` | 东方财富完整报表 | 全市场季度摘要做变更清单，逐股完整报表按变更刷新 |
| `financial.metric` | 东方财富主要指标 | 供应商指标与内部派生指标使用不同 methodology/version |

腾讯日线候选必须先完成至少 5 个交易日、300 只证券、覆盖三所及主要板块的连续验收。东方财富日线
只有在同样验收通过，且与腾讯未复权 OHLC、成交量和成交额证明等价后，才可通过新 ADR 成为受控
fallback。任何失败都发布 `partial` 或缺口，不用未认证来源静默补洞。

### 行情与复权

- canonical 日线只保存未复权市场事实。周线和月线由已发布日线按中国交易日历计算，不同步供应商
  周/月结果作为权威数据。
- 新浪累计后复权因子记为 `F(d)`，按生效日向后填充：
  - 后复权价格：`raw_price(d) × F(d)`。
  - 以前复权锚点 `A` 计算前复权价格：`raw_price(d) × F(d) ÷ F(A)`。
- API 必须返回 `adjustmentMode`、`adjustAsOf`、`factorVersion` 和 `formulaVersion`。前复权历史随
  `A` 与新公司行动变化，不保存为永久不变的价格事实。
- 调整日/周/月时先调整每日 OHLC，再聚合周期；不得对已聚合的周/月 OHLC 只乘期末因子。
- 成交量保持真实成交股数，不随价格复权。

### 财务版本

- 资产负债表是时点数据；利润表和现金流量表按报告期原始累计口径保存。
- 完整报表使用 `REPORT_DATE`、`REPORT_TYPE`、`NOTICE_DATE`、`UPDATE_DATE`、币种、合并范围和来源
  更新版本共同标识。更新同一报告期时关闭旧版本并追加新版本，不覆盖审计历史。
- 单季度、TTM、同比和派生比率写入独立 metric 数据集，记录公式版本和输入报表版本；不得覆盖源报表。
- 新增或未知数值字段触发 schema quarantine；不得静默丢弃或塞入未治理的通用字段。

### 服务与 API 边界

- `service-data-sync` 新增 FastAPI 内部读/控制接口；仅接受受网络策略保护的服务凭据。
- `service-api` 新增 `StockModule`，通过版本化 HTTP client 调用同步服务。不得复用 Prisma 查询同步库。
- 对外个股业务接口继续使用 `/api/v1`，默认要求有效 Bearer Session；所有当前角色均可读取。
- 首期 `service-api` 不建立行情读模型、不使用 Redis 缓存业务数据。GET 只在安全重试预算内重试一次；
  下游不可用映射为 503，不返回未标记的陈旧数据。
- Redis 可保存短期、可丢失的个股查询防滥用计数，但不得保存行情、财务或同步状态权威数据。

### 来源与生产准入

- AKShare 版本固定并进入镜像锁文件；升级必须重跑 schema fixture、量纲和连续探针。
- 原始响应先写 S3 兼容对象存储，再标准化入 PostgreSQL；每批保存 payload hash、schema fingerprint、
  adapter 版本和上游来源。
- 生产 source policy 只有在许可评审和连续验收通过后才能激活。未通过时能力仅允许
  research/local profile，方案仍可实施但不得宣称生产数据可用。

## 后果

- 首期需要交易所、腾讯、新浪、巨潮和东方财富多套 adapter，但每个 adapter 的风险和修订范围可隔离。
- 日线与复权语义可重放；周/月结果可由同一日线和因子版本重建。
- 财务完整回补是数日到数周的后台任务，日常更新依赖摘要清单触发，避免每天逐股全历史抓取。
- `service-api` 增加一个下游依赖和 503 失败模式，但不与同步数据库迁移耦合。
- 来源许可、腾讯日线连续验收和交易所列表稳定性是生产启用前硬门槛。

## 替代关系

本决策保留 [ADR-0004](0004-market-data-provider-adapters.md) 的 provider-neutral port、adapter 与 registry
边界；仅针对本方案个股 capabilities，替代其中“`akshare → tushare` 默认路由”。本方案不使用 Tushare。
本决策扩展 [ADR-0005](0005-service-api-runtime-and-architecture.md) 的业务范围：新增 `StockModule`
和短期查询防滥用计数，但不改变 User/Auth 单向依赖或 Redis 非权威边界。
